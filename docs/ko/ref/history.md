`GanttHistoryApi`는 ref 핸들에서 실행 취소/다시 실행을 담당하는 쪽이에요. Undo/Redo 툴바를 만들
때 쓰는 메서드 두 개와 플래그 두 개가 전부예요. [`GanttHandle`](handle.md)이 확장하는 세 인터페이스
중 하나라서, 여기 나온 멤버는 모두 `ref.current`에서 바로 닿아요. 타입은 패키지 루트에서 가져와요.
세션 중에 어떻게 동작하는지는 [명령형 API](../imperative-api.md)를 봐요.

```tsx
import type { GanttHandle, GanttHistoryApi } from '@jaeungkim/gantt-chart';
```

## GanttHistoryApi

```ts
/** 명령형 실행 취소/다시 실행 API */
export interface GanttHistoryApi {
  /** 가장 최근 제스처를 되돌리고 `onTasksChange`를 발생시켜요. 스택이 비어 있으면 아무 일도 하지 않아요. */
  undo: () => void;
  /** 가장 최근에 되돌린 제스처를 다시 실행하고 `onTasksChange`를 발생시켜요. 스택이 비어 있으면 아무 일도 하지 않아요. */
  redo: () => void;
  /** 되돌릴 제스처가 있는지 여부 */
  canUndo: boolean;
  /** 다시 실행할 제스처가 있는지 여부 */
  canRedo: boolean;
}
```

| 멤버 | 시그니처 | 의미 |
|---|---|---|
| `undo` | `() => void` | 가장 최근 단계의 이전 값을 다시 써넣고 `onTasksChange`를 발생시켜요. 스택이 비어 있으면 아무 일도 없고, 콜백도 예외도 없어요 |
| `redo` | `() => void` | 가장 최근에 되돌린 단계의 값을 다시 써넣고 `onTasksChange`를 발생시켜요. 스택이 비어 있으면 아무 일도 없어요 |
| `canUndo` | `boolean` | 실행 취소 스택이 비어 있지 않은 동안 `true` |
| `canRedo` | `boolean` | 다시 실행 스택이 비어 있지 않은 동안 `true` |

`undo`와 `redo`는 `void`를 반환해요. 새 작업 배열은 `onTasksChange`로 호스트 앱에 전달돼요.
이 콜백은 단계가 실제로 적용됐을 때만 발생해요.

ref 객체에서 `canUndo`와 `canRedo`는 복사된 불리언이 아니라 getter로 정의돼 있어요. 프로퍼티에
접근할 때마다 현재 스택을 읽어요.

```tsx
const ref = useRef<GanttHandle>(null);

<button onClick={() => ref.current?.undo()} disabled={!ref.current?.canUndo}>Undo</button>
<button onClick={() => ref.current?.redo()} disabled={!ref.current?.canRedo}>Redo</button>
```

## historyLimit

```ts
/**
 * 실행 취소 단계를 몇 개까지 보관할지 (기본값 100)
 *
 * 완료된 제스처 하나가 한 단계이고, 막대를 몇 개 옮겼는지는 상관없어요. 0이면 실행 취소를 꺼요.
 */
historyLimit?: number;
```

| 값 | 효과 |
|---|---|
| 생략 | `100`단계 |
| 양의 정수 | 그 개수만큼 보관하고, 가득 찬 뒤 새 단계가 쌓이면 가장 오래된 단계를 버려요 |
| `0` | 기록을 끄고, 값이 적용되는 순간 두 스택을 모두 비워요 |
| 음수 | `0`과 똑같아요 |

한도를 낮추면 실행 취소 스택이 최신 `historyLimit`개 단계만 남게 잘려요. 다시 실행 스택은 자르지
않아서, 현재 한도보다 많은 단계 동안 `canRedo`가 `true`로 남을 수 있어요.

`historyLimit`은 첫 렌더링이 아니라 이펙트에서 적용돼요. 차트는 `100`으로 시작했다가 한 커밋 뒤에
프롭 값을 받아들여요.

## 한 단계로 세는 기준

완료된 제스처 하나가 한 단계예요. 작업을 몇 개 바꿨는지는 상관없어요. 행 스무 개를 옮긴 하위 트리
드래그도, 의존성 사슬을 타고 재일정이 번진 이동도 각각 한 단계예요.

한 단계는 작업 배열의 복사본이 아니라, 바뀐 작업에서 달라진 필드만 담아요.

다음 제스처는 단계로 기록돼요.

| 제스처 | 기록 여부 |
|---|---|
| 막대 이동이나 크기 조절. 하위 트리 전체 드래그와 뒤따르는 재일정 포함 | 예 |
| 진행률 핸들 드래그 | 예 |
| 행 순서 변경, 들여쓰기, 내어쓰기, 부모 변경 | 예 |
| 의존성 링크 그리기 | 예 |
| 의존성 화살표 삭제 | 예 |
| 키보드 미세 이동(이동 또는 크기 조절)과 키보드 진행률 `+` / `-` | 예 |
| 작업 위에서 키보드 `Delete` / `Backspace` | 커밋되지만 스택을 비워요 — [제약](#제약) 참고 |
| 배율 변경, 확대, 스크롤, 접기, 펼치기, 선택 | 아니요 — 작업 데이터 변경이 아니에요 |

제스처가 끝났을 때 작업 데이터가 그대로면 단계로 남지 않아요. 객체나 배열을 담은 필드는 참조로
비교해요. 그래서 배열을 새로 만들지 않고 제자리에서 변경한 제스처는 아무것도 기록하지 않아요.
내장 제스처는 모두 새 배열을 만들어요.

새 단계를 쌓으면 다시 실행 스택이 비워져요.

## 제약

- 차트가 들고 있는 내용과 다른 `tasks` 프롭이 들어오면 두 스택이 모두 비워져요. 비교는 양쪽에
  `JSON.stringify`를 써요. 그래서 다시 직렬화된 날짜, 선택 키의 추가나 삭제, 키 순서 차이가 모두
  다른 내용으로 잡혀요. `onTasksChange`가 준 값을 그대로 돌려주는 제어형 부모는 히스토리를 지키고,
  배열을 다시 만드는 부모는 제스처마다 히스토리를 잃어요.
- 행 개수를 바꾸거나 작업 id를 사라지게 하는 커밋은 스택 전체를 비워요. 단계 모델은 기존 행의 필드
  변경만 표현해요. 실제로는 키보드 `Delete` / `Backspace` 제스처가 여기에 해당해요. 이 제스처는
  포커스된 작업과 그 하위 트리를 지우고, 삭제 자체는 되돌릴 수 없으며, 그 전에 기록한 단계는 모두
  버려져요.
- `historyLimit`이 `0` 이하면 두 스택이 비워져요. 한도를 다시 올려도 되살아나지 않아요.
- 스택은 언마운트에서도, 페이지 새로고침에서도, 호스트가 `tasks`를 교체할 때도 살아남지 못해요.
  아무것도 저장하지 않아요.
- `undo`와 `redo`는 `onBeforeTaskChange`를 건너뛰어요. 차트 자체 상태에 바로 쓰기 때문에 거부하거나
  값을 고쳐 쓸 수 없어요. [이벤트와 취소 가능한 변경](../events.md)을 봐요.
- 실행 취소와 다시 실행은 `onTasksChange`로만 드러나고, 드래그 커밋과 구분되지 않아요. `onUndo`,
  `onRedo`, `onHistoryChange`는 없어요.
- `canUndo`와 `canRedo`는 아무것도 구독하지 않아요. 값을 읽어도 리렌더링은 일어나지 않아요. 구조 분해로
  받은 값(`const { canUndo } = ref.current!`)은 그 순간의 낡은 불리언이에요. 툴바는 `onTasksChange`에서
  리렌더링해요. 이 콜백은 두 값이 바뀔 때마다 발생해요.
- 핸들에는 `clearHistory`도, 단계를 직접 쌓는 방법도, 스택을 읽는 방법도 없어요. `canUndo`와
  `canRedo`가 관찰할 수 있는 유일한 히스토리 상태예요.
- 트랜잭션이나 배치 API는 없어요. 한 단계는 완료된 제스처 하나예요. 호스트 앱이 여러 제스처를 한
  단계로 합치거나, 한 제스처를 여러 단계로 쪼갤 수 없어요.
- `Ctrl/Cmd+Z`와 `Ctrl/Cmd+Y` / `Ctrl/Cmd+Shift+Z`는 같은 메서드 두 개를 부르지만, 포커스가 차트
  안에 있을 때만 동작해요. `input`, `textarea`, `select`, `contenteditable` 안에서는 절대 동작하지
  않아요. 전체 키 맵은 [키보드와 스크린 리더](../accessibility.md)에 있어요.

## 참고

이 타입들 뒤에 있는 내부 구현은 패키지에서 내보내지 않아요. 단계 목록, 패치 형태, 기본 한도 상수,
`useGanttHistoryApi` 훅이 모두 그래요. `GanttHistoryApi`는 타입으로만 내보내서, 변수에 타입 주석으로
붙일 수는 있어도 값으로는 쓸 수 없어요.
