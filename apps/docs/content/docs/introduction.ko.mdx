프로젝트 타임라인은 표 옆에 색깔 사각형이 늘어선 화면처럼 보여요. 그러다 첫 막대를 끌게 돼요.
드래그는 배율마다 달라지는 단위에 맞춰 붙어야 해요. 그 뒤의 막대는 선행 작업(predecessor)이라
후행 작업(successor)도 같이 움직여야 해요. 그렇게 옮기면 다른 의존성이 깨지는 경우만 빼고요.
가운데 낀 주말은 이틀치 작업이 아니에요. 두 막대 사이의 화살표는 그 사이 행들을 피해 다시 그려야
해요. 그리고 프로젝트에 행이 4,000개라, 이 중 무엇도 DOM 노드를 4,000개 만들면 안 돼요.

표처럼 보이던 것 아래에는 스케줄링 엔진, 가상화된 그리드, 드래그 시스템, 의존성 라우터, 근무일
달력이 깔려 있어요.

`@jaeungkim/gantt-chart`는 그 스택을 React 컴포넌트 하나로 묶은 것이에요. 차트를 그리고, 제스처를
처리하고, 무언가 확정될 때마다 호스트 앱에 새 `tasks` 배열을 넘겨요. 막대가 어디에 놓일지 정하는
날짜 연산은 같은 패키지 안에 있는 별도 계층이고, React를 쓰지 않아요. 그래서 서버나 워커가 아무것도
렌더링하지 않고 호출할 수 있어요.

```ts
import { ReactGanttChart, scheduleTasks, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';
```

런타임 의존성은 `dayjs`, `zustand`, `@tanstack/react-virtual` 셋뿐이에요. `react`와 `react-dom`은
peer dependency로 받고, `^18` 또는 `^19`예요. 모든 prop은 선택이고, `tasks`의 기본값은 빈 배열이에요.
설치 명령과 처음 동작하는 차트는 [빠른 시작](quick-start)에 있어요.

## 무엇이 들어 있나요

### 렌더링

- 행은 가상화되고 오버스캔은 5행이에요. 가로 화면 밖의 막대도 함께 걸러내요.
- 왼쪽에는 작업 목록 패널이 있고, 직접 정의한 컬럼과 끌 수 있는 분할선을 써요 — [작업 목록과 계층](task-list) 참고.
- 타임라인 배율은 시간부터 연까지 여섯 가지이고, 배율마다 눈금 단위와 드래그 단위, 라벨 형식이 따로 있어요 — [타임라인](timeline) 참고.
- 의존성 화살표는 꺾은선으로 그려지고, 네 가지 링크 타입을 모두 지원해요 — [의존성](dependencies) 참고.
- 날짜 마커, 구간 밴드, 비근무일 음영, 베이스라인 막대를 그려요 — [타임라인](timeline) 참고.

### 편집

- 막대를 끌어 옮기고, 양쪽 가장자리를 끌어 크기를 바꾸고, 핸들을 끌어 진행률을 정해요 — [작업 편집](editing) 참고.
- 빈 행 공간을 끌면 새 작업을 그려요. 차트는 초안을 제안할 뿐, 행을 직접 추가하지는 않아요.
- 막대의 링크 핸들에서 다른 막대로 끌면 의존성이 생겨요. 화살표를 클릭해 선택한 뒤 Delete를 누르면 지워져요 — [의존성](dependencies) 참고.
- 작업 목록에서 행 순서를 바꾸고, 들여쓰기와 내어쓰기를 해요 — [행 순서 바꾸기](reordering) 참고.
- 실행 취소와 다시 실행은 `ref` 핸들이나 Ctrl/Cmd+Z로 하고, 기본 100단계예요 — [명령형 API](imperative-api) 참고.

### 스케줄링

- `schedulingPolicy`는 옮긴 막대 뒤로 이어지는 모든 것을 어떻게 할지 정해요 — [스케줄링](scheduling) 참고.
- 근무 달력을 두면 주말과 공휴일은 날짜로 세지 않아요.
- 임계 경로(critical path)를 구하고, 작업마다 총 여유(slack)와 자유 여유도 함께 구해요.
- 의존성 순환은 해소하지 않고 피해 가요. 순환에 속한 작업은 있던 자리에 그대로 남아요.
- 같은 함수들이 일반 함수로도 export되어, 렌더링 없이 호출할 수 있어요 — [헤드리스 코어](headless-core) 참고.

### 접근성

- 차트 전체가 하나의 ARIA treegrid예요. 각 행은 `aria-level`, `aria-posinset`/`aria-setsize`, `aria-rowindex`를 가져요.
- 그리드 본문은 로빙 탭 스톱 하나예요. 방향키로 행 사이를, 그리고 한 행의 셀 사이를 오가요. 툴바 버튼과 패널 분할선은 별도의 탭 스톱이에요.
- 막대는 키보드로 옮기고, 크기를 바꾸고, 진행률을 단계별로 조절해요 — [키보드와 스크린 리더](accessibility) 참고.
- 막대의 접근성 이름은 작업 이름과 날짜, 진행률로 만들어져요.

### 테마

- `theme`은 `'light'`, `'dark'`, `'system'`을 받아요. 생략하면 테마 클래스가 붙지 않고, 직접 쓴 CSS가 결정해요 — [테마](theming) 참고.
- 테마 토큰은 `--gantt-*` 커스텀 속성이고, `:root`가 아니라 `.gantt-container`에 한정돼요. 그래서 앱의 변수와 충돌하지 않아요. box-shadow 두 개와 `#fff` 값 두 개는 리터럴로 남아 있어요.
- 작업별 `color` 값 하나로 막대와 진행률 채움, 호버 음영 색이 정해져요 — [커스텀 렌더링](custom-rendering) 참고.
- `renderBar`, `renderTooltip`, `renderHeaderCell`, `renderBaseline`이 기본 요소를 대체해요.
- `locale`은 헤더와 툴팁, 드래그 가이드 날짜를 `Intl.DateTimeFormat`으로 그려요. `formats`는 그 셋을 배율마다 덮어써요 — [로케일과 날짜 형식](i18n) 참고.

## 하지 않는 것

**서버도 없고, 데이터 페칭도 없어요.** 소스 어디에도 `fetch`, `XMLHttpRequest`, `WebSocket`이 없어요.
작업은 prop으로 들어와요. 렌더링된 타임라인 범위가 바뀌면 `onRangeChange`가 발생하고, 더 불러오는
지점이 바로 여기예요.

**저장은 거의 하지 않아요.** 선택한 배율만 `storageKey` 아래 `sessionStorage`에 쓰고, 기본값은
`"gantt-scale"`이에요. 그 밖에는 아무것도 저장하지 않아요. 작업 데이터도, 패널 너비도, 접힌 행도,
스크롤 위치도, 테마도, 실행 취소 스택도요.

**리소스나 비용 모델이 없어요.** `Task`에는 담당자도, 공수도, 단가도, 비용 필드도 없어요 —
[작업 데이터](task-data) 참고. 리소스 패널도, 히스토그램도, 부하 평준화도 없어요. 스윔레인은
넘겨준 문자열로 행을 묶을 뿐, 사람이 무엇인지는 몰라요.

**검증도 거의 하지 않아요.** id가 유일한지, `endDate`가 `startDate` 뒤인지, 날짜 문자열이 파싱되는지
아무것도 확인하지 않아요. 잘못된 값은 예외를 던지지 않고 조용히 어긋나요. 파싱되지 않는 날짜는
타임라인 전체를 가로지르는 막대를 그려요. 유일한 예외는 `sequence`예요. 이 값이 없는 작업은 렌더링
도중 `TypeError`를 던지는데, 행 정렬이 그 문자열을 split하기 때문이에요.
[작업 데이터](task-data)를 참고하세요.

**행 삭제는 되돌릴 수 없어요.** 포커스된 행에서 Delete나 Backspace를 누르면 그 작업과 아래 항목이
모두 사라지고, 이어서 `onTasksChange`가 발생해요. 행 개수가 바뀌면 실행 취소 스택 두 개가 모두
비워져요. 필드 패치로는 행을 다시 만들 수 없기 때문이에요. [명령형 API](imperative-api)를
참고하세요.

**인쇄는 PNG 한 장이에요.** `exportToPng`는 PNG `Blob`으로 resolve되고, 내보내기는 그게 전부예요.
SVG도, PDF도, CSV도, 클립보드도, 인쇄용 스타일시트도 없어요. blob이 다운로드되지도 않아요. 그걸
어떻게 할지는 호출한 쪽이 정해요. [명령형 API](imperative-api)를 참고하세요.

**React 전용이에요.** `react`와 `react-dom`은 peer dependency예요. 스케줄링 코어는 React도 DOM 접근도
쓰지 않고 만들었어요. 하지만 패키지는 진입점이 하나뿐이고 `./core` 서브패스가 없어요. 그래서 Node에서
`scheduleTasks`를 import해도 React peer가 있어야 하는 번들로 이어져요.

**내장 문구는 영어이고, 대부분 고정이에요.** 배율 버튼은 배율 키를 그대로 찍어요. ARIA 라벨과 스크린
리더 안내는 하드코딩되어 있어요 — `"Gantt chart"`, `"Timeline scale"`, `"Collapse task list"`,
`"Resize task list"`, `"Delete FS dependency"`, `"<name>, milestone, <date>"` — 문자열 번들도
`messages` prop도 없어요. prop으로 바꿀 수 있는 라벨은 `ungroupedLabel`과 `columns` 헤더뿐이에요.
RTL도 지원하지 않아요. 스타일시트가 전부 물리 속성을 쓰기 때문이에요.

### 호스트 앱이 하는 일

- `tasks` 배열을 소유하고 저장해요. 차트는 스스로 행을 추가하지 않아요.
- 커밋을 하나씩 반영해요. 확정된 제스처는 새 배열과 함께 `onTasksChange`로 끝나요.
- 차트에서 그려진 작업에 `id`, `parentId`, `sequence`를 채워 줘요.
- 날짜와 id를 `tasks` prop에 닿기 전에 검증해요.
- `onRangeChange`에서 데이터를 더 불러오고, `exportToPng`가 준 blob을 저장하거나 업로드해요.

## 어디부터 읽을까요

먼저 [개념과 용어](concepts)부터 읽어 보세요. 나머지 문서가 쓰는 말을 여기서 고정해요. 작업, 막대,
행, 눈금, 레인, 선행 작업 같은 말들이요. 그래서 뒤 페이지들이 짧게 끝나요.

그다음은 [빠른 시작](quick-start)이에요. 패키지를 설치하고 실제 데이터로 차트를 그려요.

그 뒤로는 만들려는 것에 해당하는 페이지로 가면 돼요.

| 만들려는 것 | 읽을 페이지 |
|---|---|
| 읽기 전용 타임라인 뷰 | [작업 데이터](task-data), 그다음 [타임라인](timeline) |
| 편집 가능한 계획 | [작업 편집](editing), 그다음 [이벤트와 취소 가능한 변경](events) |
| 스스로 일정을 다시 잡는 계획 | [의존성](dependencies), 그다음 [스케줄링](scheduling) |
| WBS 형태의 개요 | [작업 목록과 계층](task-list), 그다음 [행 순서 바꾸기](reordering) |
| 팀별 또는 단계별 보드 | [그룹화와 스윔레인](grouping) |
| 디자인 시스템에 맞춘 차트 | [테마](theming), 그다음 [커스텀 렌더링](custom-rendering) |
| 차트 없는 날짜 연산 | [헤드리스 코어](headless-core) |

모든 prop은 [Props](ref/props) 한 곳에 정리되어 있어요.
