`GanttInteractionConfig`는 상호작용 설정 중 차트 전체에 걸리는 쪽이에요. 권한 플래그 여섯 개,
전체를 덮는 `readOnly` 하나, 드래그 경계 두 개로 이루어져요. 타입은 패키지 루트에서 export되지만,
차트는 이 아홉 개 필드를 각각 별도 prop으로 받아 객체를 직접 조립해요. `interaction` prop은 없어요.

```ts
import type { GanttInteractionConfig } from '@jaeungkim/gantt-chart';
```

## GanttInteractionConfig

```ts
// src/types/task.ts
/**
 * 차트 전체에 걸리는 상호작용 설정
 *
 * 모든 필드는 선택이고, 같은 이름의 작업 필드가 이 값을 이겨요.
 * 아무것도 설정하지 않으면 모든 제스처가 허용되고 드래그 경계도 없어요 - 단
 * 새 작업 그리기만은 `onTaskCreate` 콜백이 있어야 동작해요.
 */
export interface GanttInteractionConfig {
  readOnly?: boolean;
  allowMove?: boolean;
  allowResize?: boolean;
  allowProgressChange?: boolean;
  allowLinkCreate?: boolean;
  allowLinkDelete?: boolean;
  allowTaskCreate?: boolean;
  minDate?: string;
  maxDate?: string;
}
```

| 필드 | 타입 | 기본값 | 의미 |
|---|---|---|---|
| `readOnly` | `boolean` | `undefined` | 모든 작업의 모든 제스처를 막아요. 어느 단계에서든 권한 플래그를 설정하면 그 플래그가 이겨요. |
| `allowMove` | `boolean` | `undefined` | 타임라인을 따라 막대를 끌어 옮기는 동작이에요. |
| `allowResize` | `boolean` | `undefined` | 막대의 어느 쪽 끝이든 끌어 크기를 바꾸는 동작이에요. |
| `allowProgressChange` | `boolean` | `undefined` | 진행률 핸들을 끄는 동작이에요. |
| `allowLinkCreate` | `boolean` | `undefined` | 막대의 핸들에서 의존성 드래그를 시작하는 동작이에요. |
| `allowLinkDelete` | `boolean` | `undefined` | 의존성 화살표를 선택해 지우는 동작이에요. |
| `allowTaskCreate` | `boolean` | `undefined` | 빈 행 공간에 새 작업을 그리는 동작이에요. 차트 전체 설정만 있어요. |
| `minDate` | `string` | `undefined` | 막대를 끌어 갈 수 있는 가장 이른 날짜예요. UTC ISO 문자열이에요. |
| `maxDate` | `string` | `undefined` | 막대를 끌어 갈 수 있는 가장 늦은 날짜예요. UTC ISO 문자열이에요. |

모든 필드를 비워 두면 모든 제스처가 허용되고 드래그 경계도 없어요. 예외는 `allowTaskCreate`
하나인데, `onTaskCreate` 콜백까지 있어야 해요. 아래 [작업 생성](#작업-생성)을 참고하세요.

같은 이름을 가진 `GanttProps`의 prop 아홉 개가 이 객체를 채워요.
[GanttProps](props)를 참고하세요. 이 값을 덮어쓰는 작업별 필드는
[Task](task)에 있어요.

## 권한 해석

작업별 권한 다섯 가지는 각각 내부 함수 `resolveTaskInteraction`이 해석해요. 이 함수는 패키지
루트에서 **export되지 않아요**. 해석 순서를 여기 적는 이유는 호출할 수 있어서가 아니라, 이 순서가
차트의 동작을 결정하기 때문이에요.

```ts
// src/types/task.ts
/**
 * 작업 하나가 무엇을 허용하는지 가장 구체적인 설정부터 해석해요:
 *
 * `task.allowX` > `task.readOnly` > `config.allowX` > `config.readOnly` > 허용
 *
 * 같은 단계에서는 권한 플래그가 전체를 덮는 `readOnly`를 항상 이겨요. 그래서
 * 차트에 `readOnly`를 걸고 작업 하나에 `allowProgressChange: true`를 주면
 * "그 진행률 막대만 빼고 전부 잠금"이 돼요.
 *
 * 구조적인 규칙 두 가지는 플래그가 아니고, 플래그로 다시 켤 수도 없어요. 제스처가
 * 값을 쓸 곳이 없기 때문이에요. 마일스톤은 크기를 바꿀 수 없고(한 점이니까요),
 * 요약 행은 크기를 바꿀 수 없고 진행률도 끌 수 없어요(둘 다 자식에서 집계한
 * 값이라, 편집해도 곧바로 되돌아가요). 요약 행 이동은 괜찮아요 - 하위 트리
 * 전체를 함께 데려가요.
 */
export function resolveTaskInteraction(
  task: Pick<
    Task,
    | 'type'
    | 'readOnly'
    | 'allowMove'
    | 'allowResize'
    | 'allowProgressChange'
    | 'allowLinkCreate'
    | 'allowLinkDelete'
    | 'minDate'
    | 'maxDate'
  > & { isSummary?: boolean },
  config: GanttInteractionConfig = NO_INTERACTION_CONFIG
): ResolvedTaskInteraction {
  const resolve = (
    taskFlag: boolean | undefined,
    configFlag: boolean | undefined
  ): boolean => {
    if (taskFlag !== undefined) return taskFlag;
    if (task.readOnly !== undefined) return !task.readOnly;
    if (configFlag !== undefined) return configFlag;
    return !config.readOnly;
  };

  const derived = task.isSummary === true;

  return {
    canMove: resolve(task.allowMove, config.allowMove),
    canResize:
      !isMilestoneTask(task) &&
      !derived &&
      resolve(task.allowResize, config.allowResize),
    canChangeProgress:
      !derived &&
      resolve(task.allowProgressChange, config.allowProgressChange),
    canCreateLink: resolve(task.allowLinkCreate, config.allowLinkCreate),
    canDeleteLink: resolve(task.allowLinkDelete, config.allowLinkDelete),
    minDate: task.minDate ?? config.minDate,
    maxDate: task.maxDate ?? config.maxDate,
  };
}
```

가장 구체적인 것부터, 순서는 이래요:

1. `task.allowX` — 작업이 이 권한의 플래그를 직접 들고 있으면, 그 값이 답이에요.
2. `task.readOnly` — 설정돼 있으면 그 값을 뒤집은 것이 답이에요.
3. `config.allowX` — 차트 전체에 걸리는 이 권한의 플래그예요.
4. `config.readOnly` — 이 값을 뒤집은 것이 답이에요. 비어 있으면 `false`로 읽혀서, 손대지 않은 차트는 제스처를 허용해요.

아래 표의 `—`는 그 필드가 `undefined`라는 뜻이에요.

| `task.allowX` | `task.readOnly` | `config.allowX` | `config.readOnly` | 결과 | 결정 단계 |
|---|---|---|---|---|---|
| `true` | 무엇이든 | 무엇이든 | 무엇이든 | 허용 | 1 |
| `false` | 무엇이든 | 무엇이든 | 무엇이든 | 차단 | 1 |
| — | `true` | 무엇이든 | 무엇이든 | 차단 | 2 |
| — | `false` | 무엇이든 | 무엇이든 | 허용 | 2 |
| — | — | `true` | 무엇이든 | 허용 | 3 |
| — | — | `false` | 무엇이든 | 차단 | 3 |
| — | — | — | `true` | 차단 | 4 |
| — | — | — | `false` | 허용 | 4 |
| — | — | — | — | 허용 | 4 |

### 다섯 가지 권한

권한마다 위 사슬을 따라 필드 한 쌍을 읽어요. 그다음 마지막 열의 구조적 마스크가 그 결과 앞에
`&&`로 붙어요.

| 해석된 권한 | `Task` 필드 | `GanttInteractionConfig` 필드 | 구조적 마스크 |
|---|---|---|---|
| `canMove` | `allowMove` | `allowMove` | 없음 |
| `canResize` | `allowResize` | `allowResize` | `!isMilestoneTask(task) && !isSummary` |
| `canChangeProgress` | `allowProgressChange` | `allowProgressChange` | `!isSummary` |
| `canCreateLink` | `allowLinkCreate` | `allowLinkCreate` | 없음 |
| `canDeleteLink` | `allowLinkDelete` | `allowLinkDelete` | 없음 |

해석기는 이 값들을 `ResolvedTaskInteraction`에 담아 돌려줘요. 이 타입도 패키지 루트에서
**export되지 않아요**. 필드 이름이 소스와 이 표에 나오기 때문에 여기 옮겨 적었어요.

```ts
// src/types/task.ts
export interface ResolvedTaskInteraction {
  canMove: boolean;
  canResize: boolean;
  canChangeProgress: boolean;
  canCreateLink: boolean;
  canDeleteLink: boolean;
  minDate?: string;
  maxDate?: string;
}
```

### 드래그 경계

`minDate`와 `maxDate`는 이 사슬을 쓰지 않아요. 한 단계만 nullish 병합해요:

```ts
// src/types/task.ts
minDate: task.minDate ?? config.minDate,
maxDate: task.maxDate ?? config.maxDate,
```

작업 자신의 경계가 차트의 경계를 대신해요. `readOnly`와 권한 플래그는 둘 중 어느 쪽에도 영향을 주지
않아요. 드래그 중에 이 경계가 무엇을 어디까지 제한하는지는 [작업 편집](../editing)에서 다뤄요.

### 작업 생성

새 작업 그리기는 차트 전체 설정만 있어서, 두 단계짜리 해석기를 따로 써요. 이것도 내부용이고
export되지 않아요:

```ts
// src/types/task.ts
/**
 * 빈 타임라인 공간에 새 작업을 그리는 것을 허용할지 정해요
 * 차트 전체 설정만 있어요 - 제스처가 작업이 아니라 행에서 시작하니까요
 */
export function canCreateTasks(
  config: GanttInteractionConfig = NO_INTERACTION_CONFIG
): boolean {
  return config.allowTaskCreate ?? !config.readOnly;
}
```

| `config.allowTaskCreate` | `config.readOnly` | 결과 |
|---|---|---|
| `true` | 무엇이든 | 허용 |
| `false` | 무엇이든 | 차단 |
| — | `true` | 차단 |
| — | `false` | 허용 |
| — | — | 허용 |

`Task`에는 `allowTaskCreate` 필드가 없어서 작업별 단계가 없어요. 차트는 이 결과를 콜백이 있는지와
AND로 묶어요:

```ts
// src/components/Gantt/Gantt.tsx
const canDrawTasks = onTaskCreate !== undefined && canCreateTasks(interaction);
```

`onTaskCreate`가 없으면 플래그를 어떻게 두든 제스처는 꺼져 있어요.
[작업 편집](../editing)을 참고하세요.

## 제약

규칙 두 가지가 해석기 결과 앞에 `&&`로 붙어요. 그래서 어느 단계의 플래그로도 다시 켤 수 없어요.

1. **마일스톤은 절대 크기를 바꿀 수 없어요.** `type: 'milestone'`인 작업은 `canResize`가
   `false`예요. `allowResize: true`를 준 작업도 마찬가지예요.
2. **요약 행은 절대 크기를 바꿀 수 없고 진행률도 끌 수 없어요.** `isSummary`가 `true`면
   `canResize`와 `canChangeProgress`가 둘 다 `false`예요. 작업이 `allowResize: true`와
   `allowProgressChange: true`를 줘도 그대로예요. `canMove`는 영향을 받지 않아요. 요약 행 이동은
   허용되고, 하위 트리 전체를 함께 데려가요.

`isSummary`는 `hierarchy` prop이 켜져 있을 때만 설정돼요. 그래서 규칙 2는 계층 없는 차트에는 해당하지
않아요. `readOnly`는 여전히 요약 행 전체를 잠가요.

## 참고

패키지 루트에서 export되는 것: `GanttInteractionConfig`(타입만).

export되지 않고, 차트의 동작을 설명하려고 이 문서에서만 이름을 꺼낸 것:
`resolveTaskInteraction`, `canCreateTasks`, `ResolvedTaskInteraction`, `NO_INTERACTION_CONFIG`,
`isMilestoneTask`. import하지 마세요.

이 플래그들이 다루는 제스처는 [작업 편집](../editing)과
[의존성](../dependencies)에서 설명해요.
