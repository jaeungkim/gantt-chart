`buildTaskTree`, `collectSubtreeIds`, `rollUpTasks`는 `parentId` 계층 뒤에서 도는 헤드리스 헬퍼예요.
부모 링크를 정규화하고, 서브트리를 훑고, 모든 부모를 요약 행(summary row)으로 다시 계산해요.
`TaskTree`는 이 함수들이 서로 주고받는 정규화된 형태예요. 넷 다 패키지 루트에서 나오고, React도 DOM도
건드리지 않아요.

```ts
import {
  buildTaskTree,
  collectSubtreeIds,
  rollUpTasks,
  type TaskTree,
} from '@jaeungkim/gantt-chart';
```

차트가 화면에서 계층을 어떻게 다루는지는 [작업 목록과 계층](../task-list)에 있어요.
React 밖에서 이 함수들을 돌리는 방법은 [헤드리스 코어](../headless-core)를 보세요.

## TaskTree

```ts
/**
 * parentId로 만든 정규화된 트리
 *
 * 고아(데이터에 없는 부모 id), 자기 참조, 순환 체인은 모두 부모 링크가 끊기고 루트가 돼요.
 * 그래서 나오는 parentOf/childIds는 언제나 비순환이에요. 아래 함수들과 렌더는 무한 루프
 * 걱정 없이 위아래로 걸어 다닐 수 있어요.
 */
export interface TaskTree {
  /** 부모 id -> 자식 id 목록(입력 순서) */
  childIds: Map<string, string[]>;
  /** 작업 id -> 정규화된 부모 id(루트, 고아, 순환이면 null) */
  parentOf: Map<string, string | null>;
  /** 작업 id -> 루트로부터의 깊이 */
  depthOf: Map<string, number>;
  /** 루트 id 목록, 입력 순서 - childIds에 키가 없는 형제 목록이에요 */
  rootIds: string[];
}
```

| 필드 | 타입 | 내용 |
|---|---|---|
| `childIds` | `Map<string, string[]>` | 부모 id에서 자식 id 목록으로, 입력 배열 순서예요. 자식이 하나라도 있는 부모에만 키가 생겨요 — `childIds.has(leafId)`는 `false`예요. `null` 키는 없고, 깊이 0의 형제는 `rootIds`에 있어요. |
| `parentOf` | `Map<string, string \| null>` | 입력 작업 **전부**에 항목이 하나씩 있어요. `null`은 루트, 고아, 자기 참조, 또는 순환의 일원이라는 뜻이에요. |
| `depthOf` | `Map<string, number>` | 루트로부터의 단계 수예요. 루트는 `0`이에요. 상한은 없어요. |
| `rootIds` | `string[]` | `parentOf`가 `null`인 모든 id예요. 입력 배열 순서를 따라요. |

정렬은 전혀 하지 않아요. `childIds.get(parent)`와 `rootIds`는 넘긴 배열의 순서를 그대로 따라요.

## buildTaskTree

```ts
export function buildTaskTree(tasks: TaskNode[]): TaskTree
```

`TaskNode`는 `Pick<Task, "id" | "parentId">`예요. 구조적 타입이라
`{ id: string; parentId: string | null }`인 객체라면 무엇이든 만족해요. `Task`도 `TaskTransformed`도
그대로 들어맞아요. [Task](task)를 보세요.

### 부모 해석

각 작업의 `parentId`가 부모 id와 `null` 중 무엇으로 해석되는지 정리할게요.

| 입력 조건 | 해석된 부모 |
|---|---|
| `parentId`가 `null`, `undefined`, `""` | `null` — 그 작업은 루트예요 |
| `parentId === task.id`(자기 참조) | `null` — 그 작업은 루트예요 |
| `parentId`가 `tasks`에 없는 id를 가리킴(고아) | `null` — 그 작업은 루트예요 |
| 그 부모에서 원본 `parentId` 체인을 따라 올라가다 이미 본 id를 다시 만남(순환) | `null` — 그 작업은 루트예요 |
| 그 밖의 경우 | `parentId` |

링크가 끊겨도 알려주는 건 없어요. 콜백도, 콘솔 경고도, 그 작업을 표시하는 `TaskTree` 필드도 없어요.
순환 탐색은 지나간 id를 모두 기록해서, 어떤 입력이든 *n*단계 안에 끝나요.

순환 검사는 이미 해석된 `parentOf`가 아니라 각 조상의 원본 `parentId`를 읽어요. 그래서 조상 체인이
순환을 지나는 작업도 루트가 돼요. `a`와 `b`가 서로를 가리키고 `c`가 `a`를 가리키면, 셋 다
`parentOf === null`에 `depth 0`으로 끝나요.

`Task`에서 `parentId`는 필수이면서 널을 허용해요. 선택 속성이 아니라 `string | null`이에요.

### 중복 id

`tasks`에 두 번 나오는 id는 중복 제거도, 보고도 되지 않아요. 내부 조회 맵은 마지막 것을 남기지만,
작업별 순회는 배열 요소마다 한 번씩 돌아요. 그래서 그 id는 `parentOf`와 `depthOf`에 두 번 쓰이고,
`childIds`나 `rootIds`에도 두 번 들어가요.

## collectSubtreeIds

```ts
/**
 * 루트 자신을 포함한 서브트리의 id 목록(너비 우선)
 * 트리에 없는 id는 빈 배열을 돌려줘요
 */
export function collectSubtreeIds(
  tasks: TaskNode[],
  rootId: string,
  tree: TaskTree = buildTaskTree(tasks)
): string[]
```

| 매개변수 | 타입 | 기본값 | 의미 |
|---|---|---|---|
| `tasks` | `TaskNode[]` | — | `tree`를 생략했을 때만 읽어요. |
| `rootId` | `string` | — | 서브트리를 모을 대상 id예요. |
| `tree` | `TaskTree` | `buildTaskTree(tasks)` | 미리 만들어 둔 트리예요. 넘기면 O(n) 빌드를 건너뛰어요. `tasks`를 생략하는 오버로드는 없어요. |

| 경우 | 결과 |
|---|---|
| `rootId`가 `tree.parentOf`에 있음 | `[rootId, ...descendants]`, 너비 우선 |
| `rootId`가 `tree.parentOf`에 없음 | `[]` |
| `rootId`가 끊긴 순환 위에 있음 | `[rootId]` — 자식들이 루트로 떨어져 나갔어요 |

순서는 깊이 우선이 아니라 너비 우선이에요. `root → (a → a1, a2), b`라면 이렇게 나와요.

```ts
collectSubtreeIds(tasks, 'root'); // ['root', 'a', 'b', 'a1', 'a2']
collectSubtreeIds(tasks, 'a');    // ['a', 'a1', 'a2']
collectSubtreeIds(tasks, 'a1');   // ['a1']
```

## rollUpTasks

```ts
/**
 * 모든 부모를 요약 행으로 다시 계산한 작업 목록
 *
 * 시작과 끝은 데이터에 적힌 값이 아니라 언제나 자식에서 나와요
 * (min(자식 start)..max(자식 end); 마일스톤 자식은 startDate 하나만 반영돼요).
 * 깊은 쪽부터 처리해서, 손자의 이동이 부모를 거쳐 조부모까지 올라가요.
 * 명시된 progress는 그대로 두고, 빠진 것만 자식에서 굴려 올려요.
 */
export function rollUpTasks(
  tasks: Task[],
  tree: TaskTree = buildTaskTree(tasks)
): Task[]
```

입력은 `TaskNode`가 아니라 완전한 `Task`예요. `startDate`, `endDate`, `type`, `progress`를 읽어요.

### 부모가 받는 값

| 필드 | 반환된 부모의 값 |
|---|---|
| `startDate` | 언제나 `min(child startDate)`예요. 부모 자신의 값은 버려요. |
| `endDate` | 언제나 `max(child endDate)`예요. 단 `type: 'milestone'`인 자식은 대신 자기 `startDate`를 내놓아요. |
| `progress` | `parent.progress ?? rollUpProgress(children)`예요. 명시된 값은 `0`을 포함해 그대로 살아남고, 범위를 자르지도 않아요. |
| 그 밖의 모든 것 | 그대로 펼쳐서 넘겨요. |

두 날짜 모두 `dayjs(ms).toISOString()`으로 다시 직렬화해요. 그래서 자식의 `'2025-03-04'`는 부모에서
`'2025-03-04T00:00:00.000Z'`로 돌아와요.

부모는 깊은 쪽부터 처리하고, 각 부모는 이미 다시 쓰인 자식을 읽어요. 그래서 손자의 날짜가 한 번의
호출로 조부모까지 올라가요.

자식의 날짜가 전부 파싱되지 않는 부모는 원래 모습 그대로 남아요.

### 굴려 올린 progress

부모에 `progress`가 없을 때만 써요. 자식은 밀리초 단위 기간 `max(0, endDate - startDate)`로 가중치를
받아요. 이 값은 자식의 원본 `endDate`로 계산해요. 위의 마일스톤 예외는 구간에만 적용되고, 이
가중치에는 적용되지 않아요.

| 규칙 | 값 |
|---|---|
| 자식의 `progress` | 가중치를 매기기 전에 `0`–`100`으로 잘라요. |
| `progress`가 없거나 숫자가 아닌 자식 | `0`으로 세고, 보고된 값으로는 치지 않아요. |
| `progress`를 보고한 자식이 하나도 없음 | `undefined`를 돌려주고, 부모는 `progress: undefined`를 유지해요. |
| 모든 자식의 기간이 0 | 자식 수로 나눈 단순 평균으로 물러나요. |
| 결과 | `Math.round`로 정수 퍼센트가 돼요. |

100%인 10일에 0%인 30일을 더하면 `25`가 나와요. 기간이 0인 자식 둘이 100%와 0%면 `50`이 나와요.

### 반환 동일성

| 경우 | 반환되는 배열 |
|---|---|
| `tree.childIds`가 비어 있음(부모가 아예 없음) | 넘겨받은 것과 같은 배열 인스턴스 |
| 다시 쓰인 부모가 하나도 없음 | 넘겨받은 것과 같은 배열 인스턴스 |
| 그 밖의 경우 | 새 배열. 다시 쓰인 부모는 새 객체이고, 나머지 요소는 동일성을 유지하며 순서도 그대로예요 |

## 예제

```ts
import { buildTaskTree, collectSubtreeIds, rollUpTasks } from '@jaeungkim/gantt-chart';
import type { Task } from '@jaeungkim/gantt-chart';

const tasks: Task[] = [
  {
    id: 'p', name: 'Phase 1', parentId: null, sequence: '1',
    startDate: '2025-03-01', endDate: '2025-03-02',
  },
  {
    id: 'c1', name: 'Design', parentId: 'p', sequence: '1.1',
    startDate: '2025-01-01', endDate: '2025-01-11', progress: 100,
  },
  {
    id: 'c2', name: 'Build', parentId: 'p', sequence: '1.2',
    startDate: '2025-01-11', endDate: '2025-02-10', progress: 0,
  },
];

const tree = buildTaskTree(tasks);
tree.depthOf.get('c1');              // 1
tree.childIds.get('p');              // ['c1', 'c2']
tree.rootIds;                        // ['p']
collectSubtreeIds(tasks, 'p', tree); // ['p', 'c1', 'c2']

const rolled = rollUpTasks(tasks, tree);
rolled[0].startDate;                 // '2025-01-01T00:00:00.000Z'
rolled[0].endDate;                   // '2025-02-10T00:00:00.000Z'
rolled[0].progress;                  // 25
```

## 참고

- `getVisibleTasks`는 접힌 조상을 가진 작업을 걸러내는 접기 필터예요. 같은 코어 모듈에 있고 내부
  `src/core` 배럴에서 내보내지만, 패키지 루트에서는 내보내지 **않아요**. 즉
  `@jaeungkim/gantt-chart`에서 import할 수 없어요. 차트가 내부에서 호출하고, 호스트 앱은
  `collapsedIds`와 `defaultCollapsedIds` prop으로 같은 동작을 제어해요. 두 prop은
  [작업 목록과 계층](../task-list)에 설명돼 있어요.
- `TaskNode`와 `rollUpProgress`는 내부용이에요. 둘 다 패키지 루트에서 내보내지 않아요. 이 페이지는 위
  시그니처를 설명하려고 이름만 쓴 거예요.
- 세 함수 모두 순수 함수라 입력을 바꾸지 않아요. `buildTaskTree`는 호출할 때마다 새 `TaskTree`를,
  `collectSubtreeIds`는 새 배열을 돌려줘요. 받은 배열 인스턴스를 그대로 돌려줄 수 있는 건
  `rollUpTasks`뿐이에요.
- 어느 함수도 행 순서를 정하지 않아요. 행 순서는 `sequence`에서 나오고, `parentId`는 깊이만 정해요.
  둘이 맞는지 검사하는 곳은 없어요 — [작업 데이터](../task-data)를 보세요.
- 스케줄러는 `TaskTree`가 아니라 원본 `parentId` 값으로 요약 행을 고정해요. 그래서 끊긴 순환이나 자기
  참조에 있는 id를 스케줄러는 고정하지만, 이 모듈은 루트로 봐요. [스케줄링](../scheduling)을
  보세요.
