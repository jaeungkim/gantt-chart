`Task`는 `tasks` prop에 넣는 한 행의 형태예요. `TaskTransformed`는 차트가 그 행을 계산한 뒤
렌더러에 돌려주는 값이고요. 이 둘과 `TaskDependency`, `DependencyType`, `TaskType`은 모두
패키지 루트의 타입 전용 export예요.

```ts
import type {
  DependencyType,
  Task,
  TaskDependency,
  TaskTransformed,
  TaskType,
} from '@jaeungkim/gantt-chart';
```

동작은 가이드에서 다뤄요. 날짜와 `sequence`는 [작업 데이터](../task-data), 상호작용 플래그는
[작업 편집](../editing), `manuallyScheduled`와 베이스라인은 [일정 계산](../scheduling)을
보세요.

## `TaskType`과 `DependencyType`

```ts
export type TaskType = 'task' | 'milestone';

export type DependencyType = 'FS' | 'SS' | 'FF' | 'SF';
```

| 값 | 첫 글자 | 둘째 글자 |
|---|---|---|
| `'FS'` | 선행 작업(predecessor)의 종료 | 후행 작업(successor)의 시작 |
| `'SS'` | 선행 작업의 시작 | 후행 작업의 시작 |
| `'FF'` | 선행 작업의 종료 | 후행 작업의 종료 |
| `'SF'` | 선행 작업의 시작 | 후행 작업의 종료 |

## `TaskDependency`

의존성은 **후행 작업** 쪽에 저장하고, `targetId`가 선행 작업을 가리켜요.

```ts
export interface TaskDependency {
  /** 선행 작업의 id - 작업의 `dependencies`는 그 작업이 기다리는 작업들이에요 */
  targetId: string;
  type: DependencyType;
  /**
   * 링크 양 끝 사이의 부호 있는 지연, 단위는 일
   *
   * 양수는 지연(lag, 선행 작업 뒤로 그만큼 기다림), 음수는 lead(겹침)예요.
   * 근무일 달력이 켜져 있으면 근무일로, 꺼져 있으면 달력일로 계산해요.
   */
  lag?: number;
}
```

| 필드 | 타입 | 필수 | 의미 | 읽는 시점 |
|---|---|---|---|---|
| `targetId` | `string` | 예 | 선행 작업의 id예요. `tasks`에 없는 id는 조용히 버려요. 화살표도 없고 일정 계산 간선도 없어요. 자기 자신과 같은 id는 일정 계산 그래프에서만 버려요. 화살표 레이어에는 자기 참조 검사가 없어서, 자기 링크는 같은 행으로 되돌아오는 화살표를 그대로 그려요. | 항상 |
| `type` | `DependencyType` | 예 | 링크가 두 작업의 어느 끝에 붙는지 정해요. 네 값 밖의 값은 건너뛰어요. `console.warn`은 값마다 한 번씩, DEV 빌드에서만 찍혀요. | 항상 |
| `lag` | `number` | 아니요 | 부호 있는 일수, 기본값 `0`이에요. 달력일이고, `workingCalendar`를 켜면 근무일이에요. | `schedulingPolicy`가 `'shift-on-overlap'`이나 `'maintain-gap'`이거나, `criticalPath`가 켜졌을 때 |

네 가지 링크 타입과 화살표를 그리고 지우는 방식은 [의존성](../dependencies)에서 다뤄요.

## `Task`

```ts
export interface Task {
  id: string;
  name: string;
  startDate: string;
  endDate: string;
  parentId: string | null;
  sequence: string;
  /** 작업 종류 - 'milestone'은 startDate 자리에 마름모로 그려요 (기본값 'task') */
  type?: TaskType;
  /** 진행률 0-100 (%) - 생략하면 진행률을 표시하지 않아요 */
  progress?: number;
  /**
   * 막대 색 - CSS 색상 값이면 무엇이든
   *
   * 진행률 채움과 hover 음영을 이 값에서 뽑아내요. 값 하나가 막대 전체를 칠하는
   * 셈이에요. 생략하면 기존처럼 `--gantt-*` 테마 토큰이 결정해요.
   */
  color?: string;
  /** 이 작업의 막대와 작업 목록 행에 함께 붙는 추가 클래스 이름 */
  className?: string;
  /**
   * 이 작업이 행을 공유하는 스윔레인
   *
   * 같은 그룹 안에서 레인이 같은 작업들은 한 행에 나란히 그려요. 겹치는 작업은
   * 자동으로 추가 행에 쌓여요. 생략하면 기존처럼 작업이 자기 행을 하나 가져요.
   */
  lane?: string;
  dependencies?: TaskDependency[];
  /** 이 작업의 모든 제스처를 막아요 - 차트의 `readOnly` prop보다 우선해요 */
  readOnly?: boolean;
  /** 이 작업의 이동을 허용/차단해요 - 양쪽 `readOnly` 설정보다 우선해요 */
  allowMove?: boolean;
  /** 이 작업의 크기 조절을 허용/차단해요 - 양쪽 `readOnly` 설정보다 우선해요 */
  allowResize?: boolean;
  /** 이 작업의 진행률 핸들 드래그를 허용/차단해요 - 양쪽 `readOnly` 설정보다 우선해요 */
  allowProgressChange?: boolean;
  /** 이 작업에서 의존성 드래그를 시작하는 것을 허용/차단해요 - 양쪽 `readOnly` 설정보다 우선해요 */
  allowLinkCreate?: boolean;
  /** 이 작업이 가진 의존성을 지우는 것을 허용/차단해요 - 양쪽 `readOnly` 설정보다 우선해요 */
  allowLinkDelete?: boolean;
  /** 이 작업을 드래그할 수 있는 가장 이른 날짜 (ISO 문자열) - 차트의 `minDate`보다 우선해요 */
  minDate?: string;
  /** 이 작업을 드래그할 수 있는 가장 늦은 날짜 (ISO 문자열) - 차트의 `maxDate`보다 우선해요 */
  maxDate?: string;
  /** 일정 계산 엔진이 이 작업을 절대 옮기지 않아요. 후행 작업은 그래도 제약해요 */
  manuallyScheduled?: boolean;
  /** 계획 시작 스냅샷 - 실제 막대 아래에 얇은 막대로 그려요 (UTC ISO 문자열) */
  baselineStart?: string;
  /** 계획 종료 스냅샷 (UTC ISO 문자열) */
  baselineEnd?: string;
}
```

필수 필드는 여섯 개예요. `id`, `name`, `startDate`, `endDate`, `parentId`, `sequence`.

| 필드 | 타입 | 필수 | 의미 | 읽는 시점 |
|---|---|---|---|---|
| `id` | `string` | 예 | 링크와 롤업, 실행 취소 패치가 쓰는 고유 키예요. 고유한지는 검사하지 않아요. id로 만든 맵은 마지막 항목만 남겨요. | 항상 |
| `name` | `string` | 예 | 막대 레이블, 작업 목록 셀, ARIA 레이블에 쓰여요. | 항상 |
| `startDate` | `string` | 예 | `dayjs.utc()`가 파싱하는 문자열이면 다 돼요. `'2025-06-01'`은 UTC 자정이고, 시간대 없는 `'2025-06-01T09:00'`은 UTC 벽시계 시각이에요. | 항상 |
| `endDate` | `string` | 예 | 파싱 방식은 같아요. 마일스톤에서는 렌더링, 롤업, 레인 패킹, 일정 계산이 이 값을 무시해요. 다만 타임라인 범위와 마커의 `warnOnOverrun`은 여전히 이 값을 계산에 넣어요. | 항상 |
| `parentId` | `string \| null` | 예 | 부모의 id예요. 루트면 `null`이고요. 부모가 없거나, 자기 자신을 가리키거나, 순환이면 그 연결을 끊고 작업을 루트로 만들어요. | `hierarchy`가 켜졌을 때 |
| `sequence` | `string` | 예 | 점으로 구분한 숫자예요. 예를 들면 `'2.10'`. 행 순서를 정해요. 구간은 숫자로 비교하고, 빠진 구간도 숫자가 아닌 구간도 `0`으로 봐요. `hierarchy`가 꺼져 있으면 `depth`도 여기서 나와요. | 항상 |
| `type` | `TaskType` | 아니요 | 기본값 `'task'`예요. 정확히 `'milestone'` 문자열일 때만 마일스톤이 돼요. | 항상 |
| `progress` | `number` | 아니요 | 0–100 (%)예요. 거부하지 않고 잘라내요. `-10` → `0`, `150` → `100`, `Infinity` → `100`. 숫자가 아니거나 `NaN`이면 진행률을 표시하지 않아요. 반올림은 없어요. | 항상 |
| `color` | `string` | 아니요 | CSS 색상이면 무엇이든 돼요. `--gantt-bar-color`를 설정하고, `#000`을 섞어 86%짜리 hover 음영과 62%짜리 진행률 채움을 함께 만들어요. 빈 문자열이나 공백뿐인 문자열은 무시해요. | 항상 |
| `className` | `string` | 아니요 | 막대와 작업 목록 행 양쪽에 붙어요. | 항상 |
| `lane` | `string` | 아니요 | 한 그룹 안에서 레인을 공유하는 작업들은 한 행에 모여요. 겹치는 작업은 추가 행에 쌓이고요. 없거나 비어 있으면 자기 행을 하나 가져요. | 항상 |
| `dependencies` | `TaskDependency[]` | 아니요 | 이 작업의 선행 작업들이에요. 기본값은 `[]`. | 항상 |
| `readOnly` | `boolean` | 아니요 | 이 작업의 모든 제스처를 막아요. | 항상 |
| `allowMove` | `boolean` | 아니요 | 이동 제스처에서 두 단계의 `readOnly`를 모두 덮어써요. | 항상 |
| `allowResize` | `boolean` | 아니요 | 크기 조절도 같아요. 마일스톤과 요약 행에서는 `false`로 고정돼요. | 항상 |
| `allowProgressChange` | `boolean` | 아니요 | 진행률 핸들도 같아요. 요약 행에서는 `false`로 고정돼요. | 항상 |
| `allowLinkCreate` | `boolean` | 아니요 | 의존성 드래그를 시작할 때도 같아요. | 항상 |
| `allowLinkDelete` | `boolean` | 아니요 | 이 작업이 가진 의존성을 지울 때도 같아요. | 항상 |
| `minDate` | `string` | 아니요 | 드래그할 수 있는 가장 이른 지점이에요. UTC ISO고요. 없으면 차트의 `minDate`로 돌아가요. 권한 체인은 적용되지 않아요. | 항상 |
| `maxDate` | `string` | 아니요 | 드래그할 수 있는 가장 늦은 지점이에요. UTC ISO고요. 폴백도 같아요. | 항상 |
| `manuallyScheduled` | `boolean` | 아니요 | 일정 계산 엔진이 이 작업을 절대 옮기지 않아요. 후행 작업은 그래도 제약해요. 사용자가 막대를 드래그하는 것까지 막지는 않아요. | `schedulingPolicy`가 `'shift-on-overlap'`이나 `'maintain-gap'`일 때 |
| `baselineStart` | `string` | 아니요 | 계획 시작이에요. UTC ISO고요. 이 값이 있기만 하면 베이스라인 막대를 그리고 타임라인 범위도 넓혀요. | 항상 |
| `baselineEnd` | `string` | 아니요 | 계획 종료예요. UTC ISO고요. `baselineStart`가 없으면 무시해요. `baselineStart`만 있고 `baselineEnd`가 없으면 베이스라인은 점 하나가 돼요. | 항상 |

작업 단위 플래그가 `readOnly`를 이기고, `readOnly`가 차트 단위의 같은 설정을 이겨요. 전체 해석
순서는 [`GanttInteractionConfig`](interaction-config)를 보세요.

## `TaskTransformed`

추가된 필드는 모두 차트가 계산하고, 전부 읽기 전용이에요. `TaskTransformed`는 출력 전용이에요.
`tasks`는 언제나 `Task[]`이고, 값을 바꾼 `TaskTransformed`는 다시 읽히지 않아요.

```ts
export interface TaskTransformed extends Task {
  barLeft: number;
  barWidth: number;
  depth: number;
  order: number;
  originalOrder: number;
  /**
   * 자식이 있는 요약 행 (hierarchy가 켜졌을 때만 true)
   *
   * 시작/종료를 자식에서 다시 계산해요. 그래서 크기 조절과 진행률 편집이 막히고,
   * 막대를 드래그하면 하위 트리 전체가 움직여요.
   */
  isSummary?: boolean;
  dependencies?: TaskDependency[];
  /** 베이스라인 막대의 좌표 - 작업에 베이스라인 날짜가 있을 때만 들어와요 */
  baselineLeft?: number;
  baselineWidth?: number;
  /** CPM 결과 - `criticalPath` prop이 켜져 있는 동안에만 들어와요 (읽기 전용) */
  earlyStart?: string;
  earlyFinish?: string;
  lateStart?: string;
  lateFinish?: string;
  totalSlack?: number;
  freeSlack?: number;
  critical?: boolean;
  /** 달력일 기준 기간, 근무일 달력이 켜져 있으면 근무일 기준 */
  duration?: number;
}
```

| 필드 | 타입 | 계산 값 | 들어오는 시점 |
|---|---|---|---|
| `Task`의 모든 필드 | — | 그대로 복사해요 | 항상 |
| `barLeft` | `number` | 타임라인 원점에서 떨어진 px. 타임라인에 셀이 없으면 `0` | 항상 |
| `barWidth` | `number` | px. 최소 `1`로 잘라내요. 타임라인에 셀이 없을 때만 `0` | 항상 |
| `depth` | `number` | `hierarchy`가 켜지면 `parentId` 체인의 깊이, 아니면 `sequence`의 점 개수 | 항상 |
| `order` | `number` | 그룹과 레인 패킹을 마친 뒤의 1부터 시작하는 행 번호 | 항상 |
| `originalOrder` | `number` | `order`를 다시 쓰기 전, sequence로 정렬한 배열에서의 1부터 시작하는 인덱스 | 항상 |
| `isSummary` | `boolean` | 작업에 자식이 있으면 `true`. `hierarchy`가 꺼지면 항상 `false`. 타입은 선택이지만 모든 작업에 써 넣어요. | 항상 |
| `baselineLeft` | `number` | 베이스라인 막대의, 타임라인 원점에서 떨어진 px | 키는 항상 써요. `baselineStart`가 없으면 값이 `undefined` |
| `baselineWidth` | `number` | 베이스라인 막대의 px 너비 | 같아요 |
| `earlyStart` | `string` | UTC ISO | `criticalPath`가 켜졌을 때 |
| `earlyFinish` | `string` | UTC ISO | `criticalPath`가 켜졌을 때 |
| `lateStart` | `string` | UTC ISO | `criticalPath`가 켜졌을 때 |
| `lateFinish` | `string` | UTC ISO | `criticalPath`가 켜졌을 때 |
| `totalSlack` | `number` | `lateShift - earlyShift`, 단위는 일. `workingCalendar`를 켜면 근무일 | `criticalPath`가 켜졌을 때 |
| `freeSlack` | `number` | 나가는 링크들 중 가장 작은 float 값. 하한은 `0`. 후행 작업이 없으면 `totalSlack`과 같아요 | `criticalPath`가 켜졌을 때 |
| `critical` | `boolean` | `totalSlack === 0`이고 진행률이 100이 아닐 때 | `criticalPath`가 켜졌을 때 |
| `duration` | `number` | 시작과 종료 사이의 일수. 달력일이고, `workingCalendar`를 켜면 근무일이에요. 마일스톤은 `0`이에요. | `criticalPath`가 켜졌을 때 |

의존성 순환에 걸린 작업은 CPM 순서에서 빠져요. 그래서 `criticalPath`를 켜도 그 작업의 CPM 필드
여덟 개는 비어 있어요. 여유(slack)와 임계 여부는 [일정 계산](../scheduling)과
[`computeCriticalPath`](core-critical-path)에서 다뤄요.

## 참고 사항

`isMilestoneTask`와 `normalizeProgress`는 **패키지 루트에서 내보내지 않아요**. 소스에 있고
`src/types/task.ts`가 다시 내보내지만, `src/index.tsx`가 이 둘을 나열하지 않아요. 그래서
`import { isMilestoneTask } from '@jaeungkim/gantt-chart'`는 실패해요. 대신 호스트 앱에서
`task.type === 'milestone'`과 `Math.min(100, Math.max(0, progress))`를 직접 쓰세요.
`RenderedDependency`도 내보내지 않아요.

`Task`에는 런타임 검증이 없어요. 필수 필드 검사도, 날짜 파싱 검사도, id 고유성 검사도, 입력
`progress`의 범위 검사도 없어요. 모델 전체에서 런타임 진단은 인식할 수 없는 `DependencyType`을
만났을 때 뜨는 DEV 전용 경고 하나뿐이에요.

없을 때 예외를 던지는 필드는 `sequence` 하나뿐이에요. 레이아웃 도중 `sequence.split('.')`가
실행돼요. 그래서 이 값 없이 손으로 만든 작업은 차트를 조금씩 망가뜨리는 대신 통째로 터뜨려요.

날짜는 `dayjs.utc()`가 파싱하는 값이면 무엇이든 들어가고, `Dayjs.toISOString()` 형태로 나와요.
`YYYY-MM-DDTHH:mm:ss.sssZ` 형식이에요. 로컬 시간대 모드는 없어요.

관련 문서: [`GanttProps`](props), [`GanttInteractionConfig`](interaction-config),
[작업 데이터](../task-data).
