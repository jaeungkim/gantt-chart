작업이 3월부터 11월까지 이어져요. 차트는 화면에서 하루가 몇 픽셀인지 정해야 해요. 첫 칸이 어디서 시작하고 마지막 칸이 어디서 끝나는지도 정해야 하고요. 타임라인은 이 두 질문에 답하는 계층이에요.

## 여섯 가지 배율

배율은 고정된 표의 한 행이에요. 그 행이 헤더 칸에 무엇을 쓸지 정해요. 눈금 하나가 덮는 시간과 드래그 한 단계의 픽셀 값도 함께 정하고요. 배율은 여섯 개이고, 표는 모듈 상수예요.

`GanttScaleKey`는 `'hour' | 'day' | 'week' | 'month' | 'quarter' | 'year'`예요. 차트는 `month`로 시작해요.

| 배율 | `labelUnit` | `tickUnit` | `unitPerTick` | `dragStepUnit` | `dragStepAmount` | `basePxPerDragStep` |
|---|---|---|---:|---|---:|---:|
| `hour` | `day` | `hour` | 1 | `minute` | 15 | 30 |
| `day` | `day` | `hour` | 1 | `hour` | 1 | 32 |
| `week` | `month` | `day` | 1 | `hour` | 6 | 54 |
| `month` | `month` | `day` | 1 | `day` | 1 | 32 |
| `quarter` | `quarter` | `month` | 1 | `day` | 3 | 24 |
| `year` | `year` | `month` | 1 | `day` | 7 | 28 |

`unitPerTick`은 내장 배율 여섯 개 모두에서 `1`이에요. `dragStepUnit`과 `dragStepAmount`는 막대 드래그가 걸리는 스냅 격자이기도 해요. 스냅은 [작업 편집](editing)에서 다뤄요. 각 배율에 붙은 라벨 포매터는 배율마다 바꿀 수 있고, [로케일과 날짜 형식](i18n)에서 다뤄요. 타입 자체는 [배율](ref/scales)에 있어요.

### 눈금 너비는 저장하지 않고 계산해요

픽셀 너비를 들고 있는 배율은 없어요. 눈금 하나하나는 칸을 만들 때 측정해요:

```ts
// src/utils/timeline.ts, createBottomRowCells
const dragStepRatio = basePxPerDragStep / dragStepAmount;
const nextTick = current.add(unitPerTick, tickUnit);
const tickDuration = nextTick.diff(current, dragStepUnit);
const widthPx = tickDuration * dragStepRatio;
```

실제 숫자로는 이렇게 나와요:

| 배율 | 드래그 단계 단위당 px | 눈금 하나가 덮는 범위 | 눈금 너비 | 하루당 px |
|---|---|---|---|---:|
| `hour` | 2 px/min | 60분 | 120px | 2880 |
| `day` | 32 px/h | 60분 | 32px | 768 |
| `week` | 9 px/h | 24시간 | 216px | 216 |
| `month` | 32 px/day | 1일 | 32px | 32 |
| `quarter` | 8 px/day | 달력상 한 달 | 224–248px | 8 |
| `year` | 4 px/day | 달력상 한 달 | 112–124px | 4 |

quarter와 year 배율은 `month` 눈금을 써요. 그래서 칸 너비가 실제 달력상 한 달만큼이에요. 2025년 2월은 quarter 배율에서 224px, 31일짜리 달은 248px이에요.

### 시작 배율은 어디서 오나요

`defaultScale`은 씨앗 값이에요. 마운트할 때 한 번만 읽고, 그 뒤의 prop 변경은 무시해요. 차트가 최종적으로 쓰는 배율은 `gantt-scale` 키로 `sessionStorage`에 기록돼요 — 사용자가 고른 값, 그리고 마운트 시점의 씨앗 값이 `month`가 아닐 때는 그 씨앗 값이요. 저장된 값은 다음 마운트에서 우선해요. 한 페이지의 차트들이 배율을 공유하면 안 된다면 각 차트에 `storageKey`를 따로 주세요.

## 렌더링되는 범위

범위 prop이 없으면 차트가 데이터에 타임라인을 맞춰요. 모든 작업을 훑어서 `startDate`와 `baselineStart`의 최솟값, `endDate`와 `baselineEnd`의 최댓값을 찾아요. 베이스라인도 계산에 들어가서, 막대 밖으로 나간 베이스라인이 잘리지 않아요. 롤업이 먼저 돌기 때문에, 자식 때문에 넓어진 요약 행은 범위도 함께 넓혀요.

그다음 여백을 붙여요. 버퍼는 현재 배율의 눈금 다섯 개씩, 양쪽에 붙어요:

| 배율 | 한쪽 버퍼 |
|---|---|
| `hour` | 5시간 |
| `day` | 5시간 |
| `week` | 5일 |
| `month` | 5일 |
| `quarter` | 5개월 |
| `year` | 5개월 |

칸은 여백이 붙은 시작점부터 깔리고, 눈금 경계로 내림 정렬돼요. 반복은 눈금 시작이 여백 붙은 끝보다 앞일 동안 돌아요. 그래서 마지막 칸은 그 끝을 넘어가서 마칠 수 있어요.

`2025-01-10 → 2025-01-12` 작업은 `month` 배율에서 `2025-01-05 … 2025-01-17`로 여백이 붙어요. 칸은 `2025-01-05`부터 `2025-01-16`까지 12개이고, 막대는 왼쪽에서 160px 지점에 놓여요.

### visibleStart와 visibleEnd로 창 고정하기

`visibleStart`와 `visibleEnd`는 ISO 문자열이에요. 고정된 끝은 그대로 쓰여요. 그쪽에서는 작업에 맞추는 일도, 버퍼가 붙는 일도 없어요.

양쪽을 다 고정하면 레이아웃에서 작업 날짜는 의미가 없어져요. 창 밖으로 나간 작업도 행은 받지만, 막대는 가장 가까운 가장자리에 1px 조각으로 눌려요. 한쪽만 고정하면 반대쪽은 여전히 눈금 다섯 개 버퍼로 자동 맞춤돼요.

고정된 시작도 눈금 경계로 내림 정렬돼요. quarter나 year 배율에서 `visibleStart`가 `2025-03-14`면 `2025-03-01`이 돼요. 마지막 칸은 여전히 `visibleEnd`를 넘어갈 수 있어요.

> [!WARNING]
> 작업이 하나도 없고 한쪽 끝만 고정하면, 차트는 아무것도 그리지 않아요 — 칸도, 헤더도, 오류도 없어요. 빈 달력을 그리려면 양쪽 끝을 다 고정하세요.

### infiniteScroll로 범위 늘리기

`infiniteScroll`의 기본값은 `false`예요. 꺼져 있으면 범위는 작업에 버퍼를 더한 만큼이고, 스크롤 컨테이너도 거기서 멈춰요.

켜면 차트가 `scrollLeft`를 지켜봐요. 뷰가 어느 한쪽 끝에서 뷰포트 절반 안까지 들어오면, 그쪽에 뷰포트 하나 분량의 눈금을 더해요. 정확한 덩어리는 `ceil(viewportPx / pxPerTick)` 눈금이고 최소 한 개예요. 여기서 `pxPerTick`은 현재 배율의 평균 눈금 너비예요. 앞쪽을 먼저 확인하기 때문에, 한 번에 양쪽이 같이 늘어나지는 않아요.

확장은 한쪽당 눈금 2000개로 제한돼요. 앞쪽에 칸이 추가되면 차트가 추가된 너비만큼 `scrollLeft`를 밀어요. 그래서 화면에 보이던 것은 그 자리에 그대로 있어요.

알아 둘 결과가 세 가지 있어요:

- 확인은 리스너가 붙는 즉시 돌아요. 아직 아무 스크롤도 하기 전이고요. `scrollLeft: 0`으로 마운트한 차트는 이미 앞쪽 뷰포트 절반 안이라, 곧바로 확장돼요.
- 고정된 끝은 절대 늘어나지 않아요. `visibleStart`와 `visibleEnd`를 둘 다 주면 `infiniteScroll`은 아무 일도 하지 않아요.
- 누적된 확장량은 눈금 단위로 재고, 잰 배율이 함께 붙어요. 배율을 바꾸면 그 값은 버려지고 작업 기준으로 다시 맞춰요.

### onRangeChange로 되읽기

`onRangeChange`는 `Dayjs` 값 두 개가 담긴 `GanttDateRange`를 받아요. `start`는 첫 칸의 시작이에요. `end`는 마지막 칸의 배타적 끝, 즉 마지막 칸 시작에 눈금 단위 하나를 더한 값이에요. `[start, end]`를 닫힌 구간으로 조회하면 마지막 눈금을 두 번 세요.

```tsx
// Roadmap.tsx
import { useCallback } from "react";
import {
  ReactGanttChart,
  type GanttDateRange,
  type Task,
} from "@jaeungkim/gantt-chart";
import "@jaeungkim/gantt-chart/style.css";

const tasks: Task[] = [
  {
    id: "spec",
    name: "Spec",
    startDate: "2025-06-10",
    endDate: "2025-06-13",
    parentId: null,
    sequence: "1",
  },
];

export function Roadmap() {
  const handleRangeChange = useCallback((range: GanttDateRange) => {
    const from = range.start.toISOString();
    const to = range.end.toISOString();
    void fetch(`/api/tasks?from=${from}&to=${to}`);
  }, []);

  return (
    <ReactGanttChart
      tasks={tasks}
      defaultScale="month"
      infiniteScroll
      zoomOnWheel
      onRangeChange={handleRangeChange}
    />
  );
}
```

콜백은 칸이 만들어진 첫 렌더에서 불리고, 그 뒤로는 두 날짜가 바뀔 때마다 불려요. 시작과 끝의 밀리초 값으로 중복을 걸러서, 같은 날짜로 다시 만들어지면 조용해요.

이 중복 제거 때문에 줌 다섯 단계 중 세 단계는 아무것도 알리지 않아요. `hour`와 `day`는 `tickUnit`이 `hour`로 같고, `week`와 `month`는 `day`, `quarter`와 `year`는 `month`로 같아요. 짝지어진 배율은 칸 날짜가 똑같고 너비만 달라서, 서로 오갈 때 콜백이 불리지 않아요.

핸들러는 의존성이 아니라 ref로 읽어요. 그래서 신원이 바뀌어도 다시 불리지 않고, 첫 렌더 뒤에 넘긴 핸들러는 다음 실제 변경부터 보게 돼요.

## 줌

`zoomOnWheel`의 기본값은 `false`예요. Ctrl과 휠은 브라우저 자체의 페이지 줌이기 때문이에요. 켜면 차트가 자기 영역 안에서 그 제스처를 가져가요.

사다리는 배율 표 순서 그대로, 촘촘한 쪽부터예요: `hour`, `day`, `week`, `month`, `quarter`, `year`. 휠을 아래로 굴리면 축소되고, 브라우저와 방향이 같아요. 사다리는 양쪽 끝에서 멈춰요. `hour`에서 더 확대해도 아무 일이 없어요. 배율 선택 버튼은 대신 방향키에서 순환하고, [키보드와 스크린 리더](accessibility)에서 다뤄요.

단계는 이벤트마다 세지 않고 누적해요. 한 휠 제스처가 한 단계를 움직이려면 `deltaY` 누적값이 24에 닿아야 해요. 한 번 단계를 넘기면 제스처가 잠기고, 120ms 쉴 때까지 이후 이벤트는 전부 삼켜져요. 이벤트 스무 개짜리 트랙패드 핀치는 한 단계예요. 160ms 간격의 두 번 튕김은 두 단계고요.

커서 아래의 날짜는 배율이 바뀌어도 같은 x 위치에 남아요. 작업 목록 패널 위의 커서는 타임라인 왼쪽 가장자리로 제한돼요. 마지막으로 그려진 칸을 지나친 커서는 줌을 통째로 취소해요. 거기에는 기준 삼을 날짜가 없기 때문이에요.

`zoomOnWheel`이 켜져 있든 꺼져 있든, 맨 휠은 여전히 세로로 스크롤하고 Shift와 휠은 가로로 스크롤해요. 의미가 바뀌는 건 Ctrl과 Cmd 조합뿐이에요.

보이는 막대를 전부 한 번에 뷰포트에 맞추려면 차트 ref의 `zoomToFit()`을 쓰세요. [명령형 API](imperative-api)에서 다뤄요.

## 마커와 범위 밴드

마커는 한 날짜에 세우는 세로선이에요. 범위 밴드는 두 날짜 사이를 칠한 블록이고요. 둘 다 `color`나 `className`을 받고, 둘 다 장식이에요. `aria-hidden`이고, 포인터 이벤트를 받지 않고, 클릭이나 호버 콜백도 없어요.

`GanttMarker`:

| 필드 | 타입 | 하는 일 |
|---|---|---|
| `id` | `string` | React key. 날짜와 배열 인덱스를 합한 값이 기본 |
| `date` | `string \| Date \| Dayjs` | 선을 그릴 위치 |
| `label` | `string` | 선 위쪽의 작은 알약 라벨. 없으면 선만 그려요 |
| `className` | `string` | 요소에서 `gantt-marker` 옆에 추가돼요 |
| `color` | `string` | 아무 CSS 색상. `--gantt-marker-color`로 인라인 기록돼요 |
| `warnOnOverrun` | `boolean` | 작업이 이 날짜를 넘겨 끝나면 마커에 표시해요 |
| `taskIds` | `string[]` | `warnOnOverrun` 검사를 이 작업들로 한정해요 |

`GanttRangeBand`:

| 필드 | 타입 | 하는 일 |
|---|---|---|
| `id` | `string` | React key. 시작 날짜와 배열 인덱스를 합한 값이 기본 |
| `startDate` | `string \| Date \| Dayjs` | 왼쪽 가장자리 |
| `endDate` | `string \| Date \| Dayjs` | 오른쪽 가장자리, 배타적 |
| `label` | `string` | 밴드 왼쪽 위의 작은 캡션 |
| `className` | `string` | `gantt-range-band` 옆에 추가돼요 |
| `color` | `string` | 아무 CSS 색상. `--gantt-band-color`로 인라인 기록돼요 |

전체 타입 정의는 [마커](ref/markers)에 있어요.

```tsx
// ReleasePlan.tsx
import {
  ReactGanttChart,
  type GanttMarker,
  type GanttRangeBand,
  type Task,
} from "@jaeungkim/gantt-chart";

const tasks: Task[] = [
  {
    id: "spec",
    name: "Spec",
    startDate: "2025-06-10",
    endDate: "2025-06-13",
    parentId: null,
    sequence: "1",
  },
  {
    id: "build",
    name: "Build",
    startDate: "2025-06-16",
    endDate: "2025-06-27",
    parentId: null,
    sequence: "2",
  },
];

const markers: GanttMarker[] = [
  { id: "ga", date: "2025-07-01", label: "GA", color: "#0ea5e9" },
  {
    id: "freeze",
    date: "2025-06-25",
    label: "Code freeze",
    warnOnOverrun: true,
    taskIds: ["build"],
  },
];

const rangeBands: GanttRangeBand[] = [
  {
    id: "sprint-12",
    startDate: "2025-06-09",
    endDate: "2025-06-23",
    label: "Sprint 12",
  },
];

export function ReleasePlan() {
  return (
    <ReactGanttChart tasks={tasks} markers={markers} rangeBands={rangeBands} />
  );
}
```

날짜가 렌더링 범위 밖인 마커는 버려져요. 파싱되지 않는 날짜는 건너뛰어요. 밴드는 가장자리에 걸치면 보이는 부분만 남기고 잘려요. `endDate`가 `startDate`와 같거나 그보다 앞이면 버려지고요 — 길이가 0인 밴드는 아무것도 그리지 않아요.

### 오늘 선

차트는 넘긴 목록 앞에 자기 마커를 하나 붙여요: `id: "today"`, `className: "gantt-today-marker"`, 라벨 없음. 이걸 숨기거나 이름을 바꾸는 prop은 없어요. 배치 코드는 똑같이 거치기 때문에, 오늘이 렌더링 범위 밖이면 사라져요.

날짜는 마커 목록을 다시 계산할 때 읽어요. 타이머가 없어서, 자정이 되어도 선이 알아서 움직이지는 않아요.

피해야 할 충돌이 두 가지예요. 직접 만든 마커에 `id: "today"`를 쓰면 React key가 중복돼요. 직접 만든 마커에 `className="gantt-today-marker"`를 쓰면 `--gantt-today-marker`로 선을 바로 칠하는 규칙이 붙어요. 그러면 `color`는 선까지 닿지 못하고, 라벨만 그 값을 따라요.

### 초과 경고

`warnOnOverrun: true`는 마커 날짜를 모든 작업의 `endDate`와 비교해요. 비교 연산은 초과(`>`)라서, 마커 날짜에 정확히 끝나는 작업은 초과가 아니에요. `warnOnOverrun`은 `===`로 검사해서, `true`가 아닌 truthy 값은 아무 일도 하지 않아요.

`taskIds`가 없으면 차트의 모든 작업을 검사해요. 접힌 하위 트리 안에 숨은 작업까지 포함해서요. `taskIds`가 있으면 나열된 id만 검사해요.

표시된 마커는 요소에 `data-warning="true"`를 받아요. 기본 스타일시트는 그 요소의 `--gantt-marker-color`가 `--gantt-marker-warning`을 가리키게 해요. 그 변수의 기본값은 앰버색이고요. 마커의 다른 부분은 바뀌지 않아요.

```css
/* app.css - @jaeungkim/gantt-chart/style.css 다음에 불러와요 */
:root {
  --gantt-marker-warning: #dc2626;
}

.gantt-marker[data-warning="true"] {
  width: 3px;
}
```

같은 마커에 준 `color`는 경고 스타일을 이겨요. `color`는 `--gantt-marker-color`를 인라인 스타일로 쓰고, 경고 규칙은 같은 변수를 스타일시트에서 정하기 때문이에요. 그런 마커는 커스텀 색을 계속 유지하고, 상태는 DOM의 `data-warning`으로만 드러나요. 앰버색으로 바뀌어야 하는 마커에는 `color`를 주지 마세요. 나머지 테마 토큰은 [테마](theming)에 있어요.

## 비근무일

`showNonWorkingDays`의 기본값은 `true`예요. 주말과 공휴일을 막대 뒤 배경 레이어로 칠해요.

`holidays`는 ISO `YYYY-MM-DD` 문자열 목록이고, 각 눈금의 UTC 날짜와 대조해요. 기본 판별식은 일요일, 토요일, 또는 `holidays` 항목이에요.

`isNonWorkingDay`는 그 판별식을 통째로 갈아치워요. 이 prop을 넘긴 차트는 `holidays`를 아예 읽지 않아요. 판별식이 그렇게 말하지 않는 한 주말 규칙도 적용하지 않고요.

```tsx
// SixDayWeek.tsx
import { ReactGanttChart, type Task } from "@jaeungkim/gantt-chart";

const tasks: Task[] = [
  {
    id: "spec",
    name: "Spec",
    startDate: "2025-06-10",
    endDate: "2025-06-13",
    parentId: null,
    sequence: "1",
  },
];

const HOLIDAYS = ["2025-06-06", "2025-08-15"];

export function SixDayWeek() {
  return (
    <ReactGanttChart
      tasks={tasks}
      showNonWorkingDays
      // 일요일과 나열한 공휴일만 - 여기서 토요일은 근무일이에요.
      isNonWorkingDay={(date) =>
        date.day() === 0 || HOLIDAYS.includes(date.format("YYYY-MM-DD"))
      }
    />
  );
}
```

음영은 배율 이름이 아니라 배율의 `tickUnit`으로 정해져요:

| 배율 | `tickUnit` | 음영 |
|---|---|---|
| `hour` | `hour` | 예 |
| `day` | `hour` | 예 |
| `week` | `day` | 예 |
| `month` | `day` | 예 |
| `quarter` | `month` | 아니요 |
| `year` | `month` | 아니요 |

quarter나 year로 축소하면 음영이 사라져요. 한 달짜리 눈금이 절반만 비근무일일 수는 없어서, 그 배율에서는 레이어를 건너뛰어요.

이웃한 비근무 눈금은 한 블록으로 합쳐져요. 그래서 `month` 배율의 주말은 64px 띠 하나예요. `hour`와 `day` 배율에서는 판별식을 시간 눈금마다 한 번씩 물어봐요. 그래서 비근무일 하루는 연속된 눈금 24개가 한 블록으로 합쳐진 모습이에요.

이건 칠하기일 뿐, 그 이상은 아니에요. 기간이나 의존성을 계산할 때 비근무일을 실제로 반영하는 건 `workingCalendar`이고, [일정 계산](scheduling)에서 다뤄요.

## 한계

- **하루당 픽셀을 조절할 수 없어요.** 눈금 너비는 `basePxPerDragStep / dragStepAmount`에서 나오고, 둘 다 prop이 아니에요. `pxPerDay`도, 줌 퍼센트도, 소수 단위나 애니메이션 줌도 없어요 — 줌은 여섯 배율 사이를 건너뛰는 이산적인 동작이에요.
- **일곱 번째 배율은 없어요.** 배율 표는 모듈 상수예요. 2주 단위 컬럼이 필요한 호스트 앱도 그걸 추가할 수 없어요.
- **타임라인 내부는 내보내지 않아요.** 배율 설정, 사다리, 칸 생성 유틸리티는 패키지 안에 남아요. `GanttMarker`, `GanttRangeBand`, `GanttDateRange`, `GanttScaleKey`는 내보내지만, 기하 계산은 아니에요.
- **오늘 선은 prop으로 끌 수 없어요.** `.gantt-today-marker`에 CSS를 거는 것이 숨기는 유일한 방법이고, 자정에 갱신해 주는 것도 없어요.
- **마커와 밴드는 상호작용하지 않아요.** 클릭도, 호버도, 툴팁도, 스크린 리더 텍스트도 없어요. 상호작용하는 마감선은 호스트 앱이 직접 얹는 오버레이예요.
- **렌더링 범위 밖은 조용히 버려져요.** 마지막 작업보다 여섯 달 뒤인 마감 마커는 그려지지 않고, 경고도 없어요. `visibleEnd`나 `infiniteScroll`로 범위를 먼저 넓히세요.
- **여기서 날짜를 검증하지는 않아요.** 잘못된 마커 날짜는 건너뛰고, 뒤집힌 밴드는 버려져요. 날짜가 전부 파싱되지 않는 작업들은 오류 대신 빈 타임라인을 만들어요.
- **음영과 일정 계산은 별개 스위치예요.** `showNonWorkingDays={false}`는 띠만 숨기고 그 외에는 아무것도 바꾸지 않아요. `workingCalendar`가 켜져 있으면 `holidays`와 `isNonWorkingDay`는 여전히 모든 날짜 계산을 움직여요 — [일정 계산](scheduling)을 보세요.
- **내장 주말은 토요일과 일요일이에요.** `firstDayOfWeek`는 week 배율 헤더의 묶음만 바꾸고 음영은 옮기지 않아요. 금요일–토요일 주말에는 `isNonWorkingDay`가 필요해요.
- **`zoomOnWheel`은 Ctrl과 Cmd 휠 이벤트를 전부 가져가요.** `preventDefault`가 누적기보다 먼저 돌아서, 배율 단계를 만들지 않는 이벤트에서도 차트 안에서는 페이지 줌이 막혀요.
- **고정은 가로 방향뿐이에요.** `visibleStart`, `visibleEnd`, `infiniteScroll`은 행에는 아무 영향도 주지 않아요.
- **스크롤 위치는 제어되지 않아요.** `scrollLeft` prop도 `onScroll`도 없어요. `onRangeChange`는 픽셀이 아니라 날짜를 알리고, 프로그램으로 스크롤하려면 차트 ref를 거쳐요.
