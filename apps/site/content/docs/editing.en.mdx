Let people update a schedule directly on the timeline. They can move a task or resize its dates.

## Connect edits to your state

Pass your task state to the chart and update it through `onTasksChange`. Move, resize, and progress editing are enabled by default. Progress is edited only in the [detail panel](detail-panel), which is off until you turn it on.

```tsx title="src/ProjectPlan.tsx"
import { useState } from 'react';
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function ProjectPlan({ initialTasks }: { initialTasks: Task[] }) {
  const [tasks, setTasks] = useState(initialTasks);

  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
    />
  );
}
```

A completed edit sends the full next array once, after the chart has applied it. Pass it back as `tasks` so your state holds the change too. Saving to a server and applying business rules belong in your app; see [Events](events).

## Change dates and progress

| Goal | Gesture |
|---|---|
| Move a task without changing its duration | Drag the middle of the bar |
| Change its start date | Drag the left edge |
| Change its end date | Drag the right edge |
| Update completion | Drag the Progress slider in the [detail panel](detail-panel) |

Date edits move in steps determined by the [timeline scale](timeline). They shift dates by whole steps rather than aligning them to midnight, so with a step of a day or more the time of day is kept. Resizing keeps at least one drag step of duration, so resizing a shorter task can make it longer.

`Escape` does not cancel a move or resize; the edit commits when the pointer is released.

With [hierarchy](task-list) enabled, moving a summary bar moves its descendants together. A descendant marked `readOnly` or `allowMove: false` moves too, so lock the summary to keep it in place. Its dates and progress come from its children, so those fields cannot be resized or edited directly.

For precise typed values, use the [detail panel](detail-panel).

## Choose what people can edit

For a viewing-only chart, start with `readOnly`:

```tsx
<ReactGanttChart tasks={tasks} readOnly />
```

<GanttDemo preset="readOnly" />

For a chart where people can report progress but cannot change dates, show the detail panel and disable the date gestures:

```tsx
<ReactGanttChart
  tasks={tasks}
  onTasksChange={setTasks}
  showDetail
  allowMove={false}
  allowResize={false}
/>
```

Tasks can override chart settings with their own permission fields. For example, `readOnly: true` locks a task, while `allowProgressChange: true` on that same task allows progress updates. Explicit task permissions can also override chart-wide `readOnly`.

See [interaction configuration](ref/interaction-config) for precedence and [props](ref/props) for the full set of controls. These flags control chart interactions; enforce application permissions when saving data too.

## Keep dates within a window

Use `minDate` and `maxDate` to limit moves and resizes:

```tsx
<ReactGanttChart
  tasks={tasks}
  onTasksChange={setTasks}
  minDate="2026-03-01T00:00:00Z"
  maxDate="2026-04-01T00:00:00Z"
/>
```

Each task can supply its own bounds. Moving a summary bar respects the tightest bound among its descendants. A task longer than its allowed window keeps its duration and can extend past `maxDate`.

A [working calendar](working-calendar) can also snap dates to working days. Bounds apply after that snap, so a date held at a bound can fall on a non-working day. A drag released where it started skips both and commits nothing, even for a bar that sits outside its bounds or on a non-working day. A resize of a bar shorter than one drag step is the exception: it still lengthens the bar to at least one step. Drawn task drafts do not use these bounds.

## Use touch and larger timelines

On touch screens and with a pen, hold a bar for 400 ms before dragging. A swipe scrolls the timeline. Narrow bars have no touch resize zones; use the detail panel or a more detailed scale to change their dates.

Moving or resizing near the timeline's horizontal edges scrolls it automatically. Set `autoScrollOnDrag={false}` to disable this behavior.

## Related workflows

The chart does not support selecting and editing multiple bars at once. Moving a summary bar is the way to move a whole project phase together.
