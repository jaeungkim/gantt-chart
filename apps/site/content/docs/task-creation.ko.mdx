아직 없는 행이 필요해요. 어디에서 손을 뻗는지는 저마다 달라요. 작업 목록, 직접 만든 툴바, 마지막
행 아래 빈 공간이요. 하지만 차트가 그것으로 하는 일은 언제나 같아요.

들어가는 길은 셋, 나오는 길은 하나예요. 작업 목록 아래 버튼, 차트 ref의 `addTask()`, 그리고 마지막
행 아래에 그린 범위. 셋 다 같은 것을 제안해요. `onTaskCreate`로 넘어가는 초안이에요. 무엇으로
했든 차트가 스스로 추가하는 건 없어요.

## 작업 목록 아래 버튼

`showTaskList`를 켜면 목록 패널 발치에 **Add task** 띠가 서요. 누르면 오늘이 놓인 눈금 하나를
제안해요. 그리기로 나올 수 있는 가장 짧은 범위예요. 오늘이 렌더링된 타임라인 밖에 있으면 대신 첫
눈금을 제안해요.

키보드로 들어가는 유일한 길이기도 해요. 이 띠는 treegrid 바깥에 그려지니까, 격자 안의 두 번째 탭
정지가 아니라 격자 다음에 오는 평범한 탭 정지예요. 목록 패널이 없는 차트에는 이 버튼도 없어요. 범위를
그리거나 `addTask()`를 부르세요.

라벨은 차트의 다른 크롬과 마찬가지로 하드코딩된 영어 문자열 `Add task`예요 —
[로케일과 날짜 형식](i18n)을 보세요.

## 차트 ref의 `addTask()`

직접 만든 툴바나 단축키에서 부르는 같은 제안이에요.

```tsx
ganttRef.current?.addTask();
```

생성이 꺼져 있는 동안에는 조용히 지나가니, 여기에 연결한 버튼에는 따로 가드를 둘 필요가 없어요.
핸들의 나머지는 [명령형 API](imperative-api)에 있어요.

## 마지막 행 아래에 범위 그리기

마지막 행 아래 빈 공간을 누르고, 옆으로 끌고, 떼세요. 점선 고스트가 포인터를 따라오고, 손을 떼면
차트가 그려진 범위를 호스트 앱에 넘겨요.

누름은 마지막 행 아래에 닿아야 해요. 행 위에서는 아무것도 그려지지 않아요. 막대든 화살표든
핸들이든, 행의 빈 부분이든 마찬가지예요. 행은 이미 작업의 것이니까요. 마우스는 곧바로 그리기를
시작하고, 터치와 펜은 막대 드래그와 같은 400ms 길게 누르기가 필요해요.
[작업 편집](editing)을 참고하세요.

빈 공간 전체가 하나의 대상이에요. 빈 행이 여러 개 쌓여 있는 게 아니라서, 그 안 어디를 누르든
고스트는 마지막 행 바로 아래 칸에 서요. 호스트 앱이 작업을 추가하면 새 행이 서는 자리거든요.

가로 거리만 따지므로 대각선으로 끌어도 달라지는 건 없어요. 4px보다 짧은 드래그는 아무것도
제안하지 않아요.

`Escape`는 진행 중인 그리기를 취소해요. 막대나 진행률 드래그에는 아무 영향이 없어요.

## 그린 범위는 드래그 단계가 아니라 눈금에 맞춰져요

[작업 편집](editing)이 설명하는 드래그 단계와 스냅 단위가 다른 유일한 곳이에요. 그린 범위는 현재 배율의 눈금 단위까지 바깥으로
넓어져요.

| 배율 | 그린 범위가 맞춰지는 단위 |
|---|---|
| `day` | 하루의 1/4 (6시간 칸) |
| `week` | 일 |
| `month` | 주 |
| `quarter` | 월 |
| `year` | 분기 |

그래서 월 배율에서 막대는 1일 단위로 끌리지만 그리기는 주 단위로 나오고, 연 배율에서는 28일 단위로
끌리지만 그리기는 분기 하나로 나와요. 눈금 하나 안에 머무는 범위도 눈금 하나 길이로 나와요.

드래그 경계는 적용되지 않아요. [작업 편집](editing)을 참고하세요. 그린 범위는 `minDate`보다 앞에서 시작할 수 있어요.

## 초안, 그리고 차트가 그것으로 하는 일

아무것도 하지 않아요. 차트는 작업을 만들지 않고, 배열을 쓰지 않고, `onTasksChange`를 발생시키지
않아요. 초안을 담아 `onTaskCreate`를 호출하고 거기서 멈춰요. 새 행은 호스트 앱이 작업을 만들어 새
`tasks` 배열을 다시 넘겨줄 때만 나타나요.

`GanttTaskDraft`에는 필드가 둘 있어요. 배율에 맞춰진 UTC ISO 문자열인 `startDate`와 `endDate`예요.
행은 담기지 않아요. 범위는 행이 없는 자리에서만 그려지고, 버튼과 `addTask()`도 어떤 행을 가리키지
않으니까요. 새 작업이 트리의 어디에 들어갈지는 어느 입구도 알려줄 수 있는 게 아니라 호스트 앱이 정할
일이에요.

```tsx title="src/PlanBoard.tsx"
import { useState } from 'react';
import {
  ReactGanttChart,
  type GanttTaskDraft,
  type Task,
} from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function PlanBoard({ initial }: { initial: Task[] }) {
  const [tasks, setTasks] = useState<Task[]>(initial);

  const handleTaskCreate = ({ startDate, endDate }: GanttTaskDraft) => {
    const name = window.prompt('Task name');
    if (!name) return; // 아무것도 추가되지 않아요 - 차트는 스스로 아무것도 추가하지 않아요

    setTasks((current) => [
      ...current,
      {
        id: crypto.randomUUID(),
        name,
        startDate, // UTC ISO, 현재 배율의 눈금 단위에 맞춰진 값
        endDate,
        parentId: null, // 초안에는 행이 없어요 - 어디에 넣을지는 직접 정하세요
        sequence: `${current.length + 1}`,
      },
    ]);
  };

  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
      onTaskCreate={handleTaskCreate}
    />
  );
}
```

## 작업 생성 끄기

`allowTaskCreate`는 차트 전체에 걸리고, 세 입구를 한꺼번에 여닫는 스위치예요. 끄면 띠가 그려지지
않고, `addTask()`는 아무 일도 하지 않고, 그리기 제스처도 없어요. 두 단계만 거쳐 결정돼요. 자기 값,
그다음 `!readOnly`예요. `Task`에는 `allowTaskCreate` 필드가 없고, 거기에 넣어도 무시돼요.

> [!IMPORTANT]
> 작업 생성에는 `onTaskCreate`도 필요해요. 이 콜백이 없으면 `allowTaskCreate`가 무엇이든 띠도,
> 십자선 커서도, 고스트도, 제스처 자체도 없어요. `allowTaskCreate`만으로는 아무 일도 하지 않아요.

작업이 하나도 없는 차트에서는 `visibleStart`와 `visibleEnd`로 창을 고정하지 않는 한 셋 다 닿을 수
없어요. 작업도 고정된 창도 없으면 타임라인 자체가 없고, 범위를 맞출 눈금도 없거든요.

## 한계

- **차트는 작업을 만들지 않아요.** 띠도, `addTask()`도, 그린 범위도 초안을 제안할 뿐이고 결정은
  호스트 앱이 해요. 포인터로 작업을 지우지도 않아요. 삭제는 키보드 계층에만 있어요.
- **초안은 행을 가리키지 않아요.** `GanttTaskDraft`에는 `startDate`와 `endDate`뿐이라, 새 작업이
  트리의 어디에 들어갈지는 호스트 앱이 정할 일로 남아요.
- **`onTaskCreate`가 없으면 아무것도 만들어지지 않아요.** 세 입구 모두 이 콜백에 매달려 있어서,
  `allowTaskCreate`만으로는 달라지는 게 없어요.
- **그리기 제스처에는 키보드 대응이 없어요.** 같은 초안에 키보드로 닿는 길은 **Add task** 띠이고,
  거기에 묶인 키는 없어요.
