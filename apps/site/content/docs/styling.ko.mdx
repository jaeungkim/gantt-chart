`Task`에는 스타일용 필드가 두 개 있어요. `color`와 `className`이에요. 이 페이지는 각 필드가 바꾸는 범위, 파생 색을 계산하는 방식, 렌더 prop, `showTooltip`을 다뤄요.

## 작업별 색상

`color`는 `Task`의 선택 필드예요. CSS 색상 값이면 무엇이든 쓸 수 있고 `var(--brand)`나 `rgb(255 0 0 / 50%)`도 돼요. 문자열은 손대지 않고 그대로 전달돼요. 나머지 필드는 [작업 데이터](task-data)를 참고하세요.

```tsx title="src/App.tsx"
import { useState } from 'react';
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const initial: Task[] = [
  {
    id: 'design',
    name: 'Design',
    startDate: '2026-03-02T00:00:00Z',
    endDate: '2026-03-06T00:00:00Z',
    parentId: null,
    sequence: '1',
    progress: 40,
    color: '#2563eb',
  },
  {
    id: 'build',
    name: 'Build',
    startDate: '2026-03-09T00:00:00Z',
    endDate: '2026-03-20T00:00:00Z',
    parentId: null,
    sequence: '2',
    progress: 0,
    color: 'var(--brand-amber)',
  },
];

export function App() {
  const [tasks, setTasks] = useState<Task[]>(initial);
  return <ReactGanttChart tasks={tasks} onTasksChange={setTasks} />;
}
```

위 데모는 스니펫이 아니라 사이트 공용 픽스처를 그려요. 그 안의 작업은 `color`를 설정하지 않아서 막대마다 아래 표의 폴백 열에 있는 테마 회색을 써요. 작업에 `color`를 주면 막대와 호버 음영, 진행률 채움, 라벨이 모두 그 값 하나에서 파생돼요.

색을 지정한 작업은 막대 노드에 CSS 커스텀 속성 네 개를 인라인으로 설정해요. 호버 음영과 진행률 채움, 라벨에 두 번째 토큰을 읽지 않아서 색을 지정한 막대에는 테마 회색이 섞이지 않아요.

| 커스텀 속성 | 값 |
|---|---|
| `--gantt-bar-color` | 앞뒤 공백을 없앤 `color`, 그대로 |
| `--gantt-bar-color-hover` | `color-mix(in srgb, <color> 86%, #000)` |
| `--gantt-progress-color` | `color-mix(in srgb, <color> 62%, #000)` |
| `--gantt-bar-text-color` | `oklch(from <color> clamp(0, (l / 0.5637 - 1) * -infinity, 1) 0 h)` |

차트는 문자열의 앞뒤 공백을 먼저 제거해요. `color`가 `undefined`이거나 `''`이거나 공백뿐이면 속성을 하나도 설정하지 않아요. 그 막대는 색을 주지 않은 막대처럼 그려져요.

### 선언

각 선언은 작업 속성을 먼저 쓰고 테마 토큰을 `var()` 폴백으로 둬요.

| 요소 | 선언 |
|---|---|
| 막대 배경 | `var(--gantt-bar-color, var(--gantt-bar-bg))` |
| 호버 시 막대 배경 | `var(--gantt-bar-color-hover, var(--gantt-bar-bg-hover))` |
| 링크를 그리는 동안 유효한 대상이 된 막대 | `var(--gantt-bar-color-hover, var(--gantt-bar-bg-hover))` |
| 요약 막대 배경 | `var(--gantt-bar-color, var(--gantt-summary-bg))` |
| 호버 시 요약 막대 | `var(--gantt-bar-color-hover, var(--gantt-summary-bg-hover))` |
| 진행률 채움 | `var(--gantt-progress-color, var(--gantt-progress-bg))` |
| 요약 막대의 진행률 채움 | `var(--gantt-progress-color, var(--gantt-foreground))` |
| 막대 안의 작업 이름 | `var(--gantt-bar-text-color, var(--gantt-bar-text))` |

요약 막대는 요약 토큰으로 폴백해요. 막대 토큰은 요약이 아닌 막대에 적용돼요. 이 차이는 작업에 `color`가 없을 때만 보여요.

### 라벨 색

라벨 색은 섞지 않고 계산해요. `#fde68a`처럼 밝은 막대에 거의 흰 테마 라벨이 얹히면 읽을 수 없어서 라벨은 테마가 아니라 막대 색에서 파생해요. `l`은 그 색의 밝기예요. 이 값을 임계값으로 나눈 뒤 `-infinity`를 곱하면 양 끝 중 한쪽으로 고정돼요. 밝은 막대에는 검은 라벨이 붙고 어두운 막대에는 흰 라벨이 붙어요.

임계값 `0.5637`은 검정과 흰색의 WCAG 대비가 같아지는 상대 휘도를 OKLab 밝기로 옮긴 값이에요. 그래서 라벨은 항상 둘 중 대비가 높은 쪽이 돼요. 임계값을 더 높이면 중간 톤 색에서 잘못된 쪽을 고르게 돼요. `0.7`에서는 Tailwind `#ef4444` 막대가 흰 라벨을 받아 3.76:1이 돼요. 검정을 골랐다면 5.58:1이 돼요.

계산을 JavaScript가 아니라 CSS에서 하는 이유는 `var(--brand)`도 `color`에 쓸 수 있는 값이기 때문이에요. 브라우저가 치환하기 전에는 그 밝기를 알 수 없어요.

그래서 라벨에는 상대 색상 문법이 필요해요. Chrome 125와 Firefox 128, Safari 18부터 쓸 수 있어요. 음영 두 개가 쓰는 `color-mix`보다 지원 범위가 좁아요. 그 버전보다 낮은 브라우저에서는 속성이 계산되지 않아서 라벨이 `--gantt-bar-text`로 폴백해요.

라벨은 순수한 검정 아니면 순수한 흰색이라 경계 근처의 막대는 4.5:1을 조금만 넘겨요. `#2277d3`은 4.65:1이에요.

라벨은 `#000` 쪽으로 62% 섞인 진행률 채움 위에 놓여요. 밝은 막대에서는 채워진 구간에서 검은 라벨의 대비가 떨어져요.

이 계산은 막대 안에 있는 라벨에만 적용돼요. 폭이 56px보다 좁으면 라벨이 오른쪽 가장자리 바깥으로 나가요. 이때는 `color`와 상관없이 테마의 흐린 색을 받아요.

라벨 색을 직접 정하려면 작업에 `className`을 주고 명시도가 더 높은 규칙을 쓰세요.

```css title="src/gantt-overrides.css"
.gantt-task-bar.mine .gantt-task-name {
  color: #fff;
}
```

### 우선순위

`color`는 위 표의 모든 테마 토큰보다 우선해요. 토큰은 `var()` 폴백이라 작업 속성이 없을 때만 참조돼요. 테마로 `--gantt-bar-bg`를 차트 전체에 지정해도 작업의 `color`가 그대로 유지돼요. 토큰 목록은 [테마](theming)를 참고하세요.

`color`가 바꾸는 것은 위 표의 선언 여덟 개뿐이에요.

- 막대의 모서리 반경과 그림자, 선택 외곽선, 의존성 화살표는 스타일시트와 테마 토큰이 정해요.
- 작업 목록은 테마와 `className`만 반영해요.

## className

작업에 준 `className`은 그 작업의 막대와 작업 목록 행에 붙어요. 두 클래스 문자열 모두에서 맨 뒤에 붙어요. `class` 속성 안의 이름 순서는 캐스케이드와 무관해요.

직접 쓴 규칙은 명시도로 이겨요. 명시도가 같으면 뒤에 선언된 쪽이 이겨요. `.gantt-task-bar.blocked`는 `.gantt-task-bar`보다 명시도가 높아요. 예제는 그 형태를 써요.

한 레인에 여러 작업을 담은 행은 첫 번째 작업의 `className`을 받아요. 각 막대는 자기 `className`을 그대로 써요. [레인](lanes)을 참고하세요.

```tsx
const task: Task = {
  id: 'audit',
  name: 'Security audit',
  startDate: '2026-04-06T00:00:00Z',
  endDate: '2026-04-10T00:00:00Z',
  parentId: null,
  sequence: '3',
  className: 'blocked',
};
```

```css title="src/gantt-overrides.css"
.gantt-task-bar.blocked {
  background: repeating-linear-gradient(
    45deg,
    #b45309,
    #b45309 6px,
    #92400e 6px,
    #92400e 12px
  );
}

.gantt-grid-row.blocked .gantt-grid-cell {
  font-style: italic;
}
```

## 렌더 prop

렌더 prop은 `renderDetail` 하나예요. 도킹된 상세 패널의 본문을 교체해요. 내장 본문은 고정된 필드 목록이라 prop으로 늘릴 수 없어요.

스타일링용 훅은 아니에요. 패널을 여는 방법과 그리는 내용, 제어 방식은 [상세 패널](detail-panel)에 있고 타입은 [상세 렌더러](ref/renderers)에 있어요.

차트의 다른 부분은 커스텀 렌더러를 받지 않아요. 막대, 툴팁, 헤더 셀, 작업 목록 행, 드래그 날짜 표시, 드롭 표시, 의존성 화살표는 CSS로만 스타일을 바꿀 수 있어요.

## showTooltip

`showTooltip`의 기본값은 `true`예요. 마우스를 올리면 잠깐 뒤에 뜨는 툴팁과 진행률 드래그 중 표시되는 `%` 값을 제어해요. 툴팁에는 이름과 날짜, 기간, 진행률이 나와요. `false`로 설정하면 둘 다 사라져요.

이동과 크기 조절은 `showTooltip` 값과 상관없이 툴팁을 보여주지 않아요. 그 표시는 드래그 중인 가장자리의 눈금 셀에 쓰이는 날짜예요. 헤더의 일부라서 `showTooltip`이 영향을 주지 않아요. 무엇이 표시되는지는 [로케일과 날짜 형식](i18n)을 참고하세요.

`false`는 포인터 드래그가 만드는 라이브 영역 알림도 모두 없애요. 진행률 표시가 `role="status"` 요소이고 이동과 크기 조절도 시각적으로 숨긴 `role="status"` 요소를 하나 유지하거든요. 키보드로 날짜를 편집할 때의 알림은 별도 라이브 영역이 맡고 `showTooltip`의 영향을 받지 않아요. [키보드와 스크린 리더](accessibility)를 참고하세요. prop과 기본값은 [GanttProps](ref/props)를 참고하세요.

## 한계

- `color`는 대신 계산해 주지 않아요. 차트는 `task.color`를 읽어 값 세 개를 파생해요. 팔레트나 범례는 제공하지 않아요. 작업을 넘기기 전에 상태를 색으로 매핑하세요. 예를 들어 `tasks.map((t) => ({ ...t, color: PALETTE[t.status] }))`로 매핑할 수 있어요.
- 음영 두 개에는 `color-mix`가 필요해요. 호버와 진행률 음영은 `color-mix(in srgb, ...)` 형태로 출력돼요. 이 문법을 해석하지 못하는 브라우저에서는 둘 다 계산되지 않아요. `--gantt-bar-color`는 일반 색상 값이라 그런 브라우저에서도 그대로 쓸 수 있어요.
- 라벨에는 상대 색상 문법이 필요해요. `color-mix`보다 지원하는 브라우저가 적어요. 지원하지 않는 브라우저에서는 라벨이 `--gantt-bar-text` 그대로예요.
- 헤더 셀은 텍스트만 담아요. `formats`가 내용을 바꾸고 `.gantt-top-group`과 `.gantt-bottom-cell`에 건 CSS가 모양을 바꿔요. 마크업은 넣을 수 없어요. 44px 그룹 행과 28px 눈금 행은 높이가 고정이에요.
- 작업 목록은 작업별 상세 정보를 보여주지 않아요. 셀 하나가 `task.name`을 그리고 `showRowNumbers`를 켜면 행의 `sequence`가 더해져요. [작업 목록과 계층](task-list)을 참고하세요. 나머지 필드는 [상세 패널](detail-panel)에 두세요.
