막대가 담는 것은 이름과 날짜 둘, 그리고 진행률 채우기예요. 그 작업에 대해 갖고 있는 나머지 필드는
놓을 자리가 없어요. 상세 패널은 차트 오른쪽에 붙는 패널이고, 한 번에 작업 하나를 보여줘요. 타임라인
위에 얹히는 레이어가 아니라 타임라인의 형제라서, 패널이 열려 있는 동안 타임라인이 가려지는 게 아니라
좁아져요. 그리고 뒤의 차트는 계속 조작할 수 있어요. 모달이 아니고, 안에 갇히는 것도 없고, 다음 클릭을
삼키는 배경막도 없어요.

## 패널 켜기

패널은 기본적으로 꺼져 있어요. `showDetail`이 패널을 켜요. `showDetail`을 생략하면 `renderDetail`을
넘기는 것만으로 패널이 켜져요. [작업 목록과 계층](task-list)에서 `showTaskList`가 그 패널의 스위치인
것처럼, 여기서는 렌더러가 스위치예요.

| `showDetail` | `renderDetail` | 패널 | 본문 |
|---|---|---|---|
| 생략 | 생략 | 숨김 | — |
| 생략 | 지정 | 표시 | 지정한 렌더러 |
| `true` | 생략 | 표시 | 내장 본문 |
| `true` | 지정 | 표시 | 지정한 렌더러 |
| `false` | 생략 | 숨김 | — |
| `false` | 지정 | 숨김 | — |

명시적인 `false`가 `renderDetail`보다 우선해요.

패널을 켜면 행 선택도 함께 켜져요. 상세가 열린 행이 곧 강조되는 행이 되도록요. 명시적인
`selectable={false}`는 여전히 이겨요. 패널은 평소대로 열리고 닫히지만 아무 행도 강조되지 않아요.
선택이 무엇이고 어떤 콜백을 실행하는지는 [이벤트](events)에 있어요. 여기 나온 prop의 시그니처와
기본값은 [GanttProps](ref/props)에 있어요.

## 기본 본문이 그리는 것

패널을 켜고 `renderDetail`을 주지 않으면 내장 본문은 맨 위의 `task.name` 아래에 짧은 필드 목록을 그려요.
작업이나 차트에 `readOnly`가 걸려 있지 않으면 그 이름은 텍스트 입력이에요.

| 캡션 | 값 | 표시 조건 | 입력이 되는 조건 |
|---|---|---|---|
| Start, End | 날짜예요. 현재 배율의 툴팁 포매터, 즉 호버 툴팁이 쓰는 그 포매터를 거치니까 `locale`과 `formats`가 이미 그 표기를 정해요 | 항상 | `allowResize`가 작업의 크기 조절을 허용할 때 |
| Duration | 두 날짜 사이의 기간이에요. 하루 미만은 시간 단위, 그 위로는 일 단위이고, 호버 툴팁이 찍는 것과 같은 값이에요 | 항상 | 없음. 계산된 값이에요 |
| Progress | `task.progress`를 0–100으로 잘라낸 값이에요 | 작업에 진행률이 있을 때 | `allowProgressChange`가 진행률 핸들 드래그를 허용할 때 |
| Depends on | 이 작업의 `dependencies`가 가리키는 작업들의 이름이에요. 어떤 작업도 가리키지 않는 id는 id 그대로 찍혀요 | 의존성이 있을 때 | 없음. 계산된 값이에요 |

이 입력 칸 안에서 누르는 `Escape`는 패널을 닫지 않고 그 필드만 되돌려요.

기본 본문은 여기까지예요. 작업의 다른 필드는 보여주지 않고, 그걸 추가하는 prop도 없어요. 필드에는
캡션이 필요한데, 그 캡션이 무엇이어야 하는지는 호스트 앱만 알거든요. 위 캡션은 패널과 닫기 버튼의
접근성 이름처럼 고정된 영어 문자열이고, 번역하는 prop도 없어요. 캡션을 번역해야 하거나 다른 필드를
보여주고 싶다면 아래의 `renderDetail`로 본문을 직접 그려요.

## 그 자리에서 편집하기

내장 본문은 작업의 상호작용 플래그가 이미 대응하는 제스처를 허용하는 곳에서만 편집할 수 있어요.
패널이 자기 플래그를 추가하지 않아요. 이름은 작업이, 작업에 없으면 차트가 `readOnly`가 아닌 한 텍스트
입력이에요. 이름만을 위한 더 좁은 플래그는 없어요. Start와 End는 작업의 크기를 조절할 수 있을 때 날짜
입력이에요. 날짜 하나를 바꾸는 것이 곧 크기 조절이라서요. 그래서 요약 행의 날짜는 텍스트로 남아요.
Progress는 진행률 핸들을 드래그할 수 있을 때 숫자 입력이에요. 이 플래그들이 작업과 차트 사이에서
어떻게 해석되는지는 [작업 편집](editing)에 있어요. Duration과 Depends on은 계산된 값이라 누구에게나
텍스트예요.

필드는 블러와 `Enter`에서 커밋되고, 변경은 모든 드래그처럼 `onTasksChange`로 도착해요. 같은 배열,
같은 형태이고, 별도의 콜백은 없어요. `Escape`는 패널을 닫지 않고 필드만 되돌려요. 커밋할 수 없는
값은 조용히 되돌아가요. 빈 이름, 불완전한 날짜, 시작 뒤에 놓이지 않는 종료, 비워진
진행률 필드가 그래요. 빨갛게 깜빡이는 것도 없어요.

날짜 편집은 날짜 부분만 바꿔요. 작업은 자기 시각을 유지하고, 결과는 드래그가 따르는 것과 같은
`minDate`/`maxDate`로 잘려요. 진행률은 0–100으로 잘려요. 날짜를 편집할 수 있는 동안에는 네이티브
날짜 입력이 포맷된 텍스트 대신 `YYYY-MM-DD`를 그대로 보여줘요. 크기 조절이 꺼진 곳에서는 위의 툴팁
포맷이 돌아와요.

## 무엇이 패널을 여는가

막대나 작업 목록 행을 한 번 클릭하거나, 포커스된 행에서 `Enter`나 `Space`를 누르면 열려요. 다만
펼칠 수 있는 행에서는 그 키들이 패널 대신 행을 접고 펼쳐요. 제스처는 이게 전부예요. 더블 클릭
모드도 없고, 다른 트리거를 고르는 prop도 없어요.

한 번 클릭인 이유는, 더블 클릭이 *모달* 작업 편집기의 관례이기 때문이에요. Bryntum의
TaskEdit은 `triggerEvent: 'eventdblclick'`이 기본이고, DHTMLX는 `dblclick`에 lightbox를 열어요. 그런
편집기는 끝내거나 취소해야 하는 폼을 여니까 비싸고, 그래서 의도적인 제스처를 요구해요. 도킹된 패널은
양쪽 다 싸요. 이미 행을 선택하는 그 클릭으로 열리고 `Escape`로 닫혀요. frappe-gantt의 `popup_trigger`는
아예 더블 클릭을 선택지로 두지도 않고 `'click'`과 `'hover'`만 제공해요.

패널을 여는 클릭에서도 `onTaskClick`은 늘 그렇듯 가장 먼저 실행되고, 패널은 그 뒤에 열려요. 이미
열려 있는 작업의 행을 다시 클릭하면 아무 일도 일어나지 않아요. 호스트의 코드만 패널을 열게 하려면
아래의 제어 모드처럼 `detailTaskId`를 직접 들고 있으면 돼요. 그러면 클릭은 `onDetailChange`로 알려질
뿐이고, 따를지는 호스트가 정해요.

패널은 `<aside role="complementary" aria-label="Task details">`이고 dialog가 아니에요. 포커스 트랩도
배경막도 없어요. treegrid 바깥에 놓여 있어서 차트는 탭 정지점을 정확히 하나만 갖고, 패널이 그다음
정지점이 돼요. `Escape`가 패널을 닫는데, 리스너가 document에 있어서 포커스가 페이지 어디에 있어도
동작해요. 키를 삼키지도 않아서 호스트 자신의 `Escape` 핸들러도 그대로 실행돼요. 닫을 때 포커스는
패널이 열리던 순간 포커스를 갖고 있던 곳으로 돌아가요. 다만 그사이 포커스가 페이지의 다른 곳으로
옮겨갔다면 그대로 둬요. 사용자가 옮겨간 입력 칸에서 포커스를 빼앗아 오지 않아요. 이 모든 것에 새
키는 하나도 늘지 않아요. 포커스된 행에서 누르는 `Enter`는 원래 행을 읽어주던 키였고, 이제 패널도
함께 열어요. 키 전체는 [키보드와 스크린 리더](accessibility)에 있어요.

## 제어 방식과 비제어 방식

열린 작업은 id 하나예요. 두 모드 모두요.

| `prop` | 모드 | 규칙 |
|---|---|---|
| `detailTaskId` | 제어 | 여기 넘긴 `string`이나 `null`이 차트가 보여주는 상태이고, 내부 상태는 갱신을 멈춰요 |
| `detailTaskId` 생략 | 비제어 | 차트가 열린 작업을 직접 들고 있어요 |
| `onDetailChange` | 둘 다 | 열고 닫을 때마다 작업 또는 `null`과 함께 실행돼요 |

모드를 가르는 것은 `detailTaskId !== undefined`예요. 여기서 `null`은 다른 곳처럼 기능을 끄는 수단이
아니에요. "제어 방식이고, 닫힌 상태"를 뜻해요. 그래서 차트는 `??`로 되돌아가지 않고 `undefined`인지를
검사해요.

> [!WARNING]
> 제어 모드에서 차트는 스스로 아무것도 열지 않아요. 새로운 `detailTaskId`를 기다려요.
> `onDetailChange`를 처리하지 않고 `detailTaskId`만 넘기면 모든 클릭이 무시되는 것처럼 보여요.

`onDetailChange`는 제어 모드와 비제어 모드에서 똑같이 실행돼요. 열린 작업이 실제로 바뀔 때만요. 이미
열려 있는 행을 클릭하면 아무 일도 일어나지 않아요. 마운트 시점에는 절대 실행되지 않고, 패널 내용이
바뀌었다고 알리는 이벤트도 아니에요. 상세가 열린 막대를 옮겨도 실행되지 않아요.

## 코드에서 직접 열기

`GanttHandle`은 `openDetail(taskId)`와 `closeDetail()`을 갖고 있어요. 모르는 id는 `scrollToTask`가
무시하는 것과 같은 방식으로 무시하고, 패널이 꺼져 있는 동안에는 둘 다 아무 일도 하지 않아요. 제어
모드에서는 클릭과 같은 규칙을 따라요. `onDetailChange`로 알리기만 하고, 패널을 여는 것은 새로 넘긴
`detailTaskId`예요. 나머지 ref 멤버와 함께 [GanttHandle](ref/handle)에 정리돼 있어요.

## 본문 갈아 끼우기

`renderDetail`은 패널 안쪽을 통째로 대체해요. `<aside>` 자체는 차트의 것으로 남아요. 너비, `role`,
접근성 이름, 닫을 때의 포커스 처리는 잃어버릴 수 없어요. 바뀌는 것은 자식 노드뿐이고, 그래서 닫기
버튼은 직접 그려야 해요. `close`는 내장 버튼이 호출하는 바로 그 함수이고, 버튼을 그리든 말든
`Escape`는 계속 동작해요.

렌더러는 `GanttDetailRenderProps`를 받아요. 차트가 변환한 형태의 열린 `task`, `close`, 현재
`scale`, 그리고 `update`예요. `update(patch)`는 모든 제스처와 같은 커밋 경로로 — 스토어, 그다음
`onTasksChange`로 — 열린 작업에 패치를 적용해요. 그래서 커스텀 폼은 배열을 직접 들고 있지 않아도
저장할 수 있어요. 상호작용 플래그는 전혀 검사하지 않아요. 위의 게이트는 내장 본문의 것이고, 커스텀
본문은 자기 규칙을 직접 지켜요. 타입 정의는 [상세 렌더러](ref/renderers)에 있어요.

```tsx title="ProjectChart.tsx"
import { useState } from 'react';
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { GanttDetailRenderProps, Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  { id: 'p1', name: 'Phase 1', parentId: null, sequence: '1',
    startDate: '2025-03-03', endDate: '2025-03-28' },
  { id: 't1', name: 'Design', parentId: 'p1', sequence: '1.1',
    startDate: '2025-03-03', endDate: '2025-03-12', progress: 100 },
  { id: 't2', name: 'Build', parentId: 'p1', sequence: '1.2',
    startDate: '2025-03-12', endDate: '2025-03-28', progress: 40 },
];

function TaskDetail({ task, close }: GanttDetailRenderProps) {
  return (
    <>
      <div style={{ display: 'flex', justifyContent: 'space-between', gap: 8 }}>
        <h2 style={{ margin: 0, fontSize: 14 }}>{task.name}</h2>
        <button type="button" onClick={close} aria-label="Close task details">
          ✕
        </button>
      </div>
      <p style={{ margin: 0, fontSize: 12 }}>
        {task.startDate.slice(0, 10)} → {task.endDate.slice(0, 10)}
      </p>
      <p style={{ margin: 0, fontSize: 12 }}>{task.progress ?? 0}% done</p>
    </>
  );
}

export function ProjectChart() {
  const [detailTaskId, setDetailTaskId] = useState<string | null>(null);

  return (
    <ReactGanttChart
      tasks={tasks}
      showTaskList
      hierarchy
      renderDetail={(props) => <TaskDetail {...props} />}
      detailTaskId={detailTaskId}
      onDetailChange={(task) => setDetailTaskId(task?.id ?? null)}
      height={420}
    />
  );
}
```

`renderDetail`은 차트의 유일한 렌더 prop이에요. 차트의 다른 어떤 것도 갈아 끼울 수 없어요. 막대의
색과 클래스 이름은 작업의 필드이고, [스타일링](styling)에 있어요.

## 패널 너비

패널의 너비는 커스텀 속성 `--gantt-detail-width`이고, 기본값은 나머지 토큰들과 함께
[테마](theming)에 정리돼 있어요. 패널은 그 값으로 `flex: 0 0` 배치라서 늘지도 줄지도 않고, 변화는
타임라인이 전부 흡수해요.

## 예외 상황

**열려 있는 작업이 `tasks`에서 빠짐.** 열린 id가 더 이상 어떤 작업으로도 해석되지 않으니 패널도 함께
닫혀요. `onDetailChange`는 이때 일부러 실행하지 *않아요*. `tasks`를 바꾼 건 호스트 자신이라서, 호스트에게
새로운 소식이 아니에요.

**배열에 없는 작업을 가리키는 `detailTaskId`.** 결과는 같아요. 패널은 닫혀 있고 오류도 나지 않아요.
해석되는 id가 들어오는 순간 열려요.

**`Escape`는 행 선택을 남겨둬요.** 패널만 닫아요. `onTaskSelect`는 실행되지 않아요.

**빈 타임라인 공간 클릭.** 선택이 해제되고 패널*도* 닫혀요.

**열려 있는 작업의 부모를 접기.** 패널은 열린 채로 있어요. id는 보이는 행이 아니라 차트가 들고 있는
모든 작업에 대해 해석돼요. 그래서 숨겨진 행도 자기 패널을 유지해요.

**패널이 열린 상태에서 다른 행 클릭.** 패널은 그 자리에서 그 작업으로 바뀌고, 포커스를 도로 가져오지
않아요. 포커스 복원은 패널이 언마운트될 때만 일어나요.

**패널은 선택 변화가 아니라 클릭에 반응해요.** 일부러 그렇게 했어요. 선택은 이미
선택된 행의 클릭을 무시해요. 그래서 선택에 끌려가는 패널은 `Escape`로 닫은 뒤 같은 행을 아무리 다시
클릭해도 닫힌 채로 있게 돼요.

## 한계

패널은 크기가 조절되지 않아요. 드래그 핸들도 없고 너비 prop도 없어요. `--gantt-detail-width`가 유일한
손잡이이고 그건 CSS라서, 스프링처럼 애니메이션으로 밀어 넣고 싶은 호스트에게는 방법이 없어요.

위치는 오른쪽으로 고정돼 있어요. 왼쪽, 아래쪽, 떠 있는 형태의 변형은 없고, 패널을 별도 창으로 떼어내는
prop도 없어요.

한 번에 작업 하나만 보여줘요. 탭도, 히스토리도, 작업 사이를 오가는 뒤로 가기 버튼도, 다중 선택 패널도
없어요.

편집은 패널이 보여주는 필드에서 끝나요. Duration과 Depends on은 절대 입력이 되지 않고, 행을 추가하는
prop도 없고, 내장 본문이 나열하지 않는 작업 필드는 거기서 편집할 수 없어요. 더 풍부한 폼은
`renderDetail`로 그리고 `update`로 커밋해요.

슬라이드는 손잡이가 아니에요. 패널은 `flex-basis`를 200ms 동안 전환하며 열리고 닫히고, 타임라인은
그에 맞춰 다시 흘러요. 그 시간을 바꾸거나 끄는 prop은 없어요. `prefers-reduced-motion`은 차트의 다른
모든 전환처럼 이것도 즉시로 줄여요. 패널이 열린 채로 작업을 바꾸면 본문이 그 자리에서 바뀌고,
슬라이드는 없어요.

그래서 호스트 앱이 책임지는 것은 이래요. `showDetail`을 토글하는 컨트롤 만들기, 제어 모드를 쓰려면 열린
id를 상태로 들고 있기, `renderDetail`에 놓은 폼이 하는 모든 일, 그리고 사용자가 패널 너비를 바꿀 수 있어야
한다면 그 너비를 직접 저장하기.

다음은 제스처가 실행하는 모든 콜백을 — `onDetailChange`까지 포함해서 — 인자와 함께 정리한
[이벤트](events)예요.
