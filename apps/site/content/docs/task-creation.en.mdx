Three entry points create a task draft: the **Add task** button, `addTask()` on the chart ref, and
a range drawn below the last row. Each one calls `onTaskCreate` with the draft. The chart adds no
row itself. This page covers the three entry points, tick snapping, and `allowTaskCreate`.

## The Add task button

With `showTaskList` on, the **Add task** button is rendered at the foot of the pane. A click sends
a draft one tick long at today. That is the shortest range the drawing gesture produces. When today
is outside the rendered timeline, the draft starts at the first tick.

The button is the keyboard path to a draft. It is rendered outside the `treegrid`, so it takes its
own tab stop after the grid. A chart without the pane has no button. Draw a range or call
`addTask()` instead.

The label is the hardcoded English string `Add task`, like every other string the chart renders.
See [Locale and date formats](i18n).

## `addTask()` on the chart ref

Call `addTask()` from your own toolbar or keyboard shortcut for the same draft.

```tsx
ganttRef.current?.addTask();
```

The call does nothing while creation is off, so a button wired to it needs no guard.
[Imperative API](imperative-api) describes the rest of the handle.

## Drawing a range

Press in the blank space below the last row, drag sideways and release. A dashed ghost follows the
pointer, and the release sends the drawn range to `onTaskCreate`.

The press has to land below the last row. A press on a row draws nothing, whether it lands on the
bar, on an arrow, on a handle or on the empty part of the row. A mouse starts drawing at once.
Touch and pen need the same 400 ms long press as a bar drag. [Editing tasks](editing) describes
that long press.

The blank space is one target rather than a stack of empty rows. The ghost is drawn directly under
the last row wherever the press lands, because your app adds the new task there.

Vertical movement is ignored, so a diagonal drag draws the same range as a horizontal one. A drag
shorter than 4px sends nothing. `Escape` cancels a draw in progress and has no effect on a bar or
progress drag.

## Tick snapping

A drawn range expands outwards to whole ticks of the current scale. A bar moves and resizes in the
drag step [Editing tasks](editing) describes.

| Scale | A drawn range snaps to whole |
|---|---|
| `day` | quarter-days (6-hour cells) |
| `week` | days |
| `month` | weeks |
| `quarter` | months |
| `year` | quarters |

On the month scale a bar drags in 1-day steps and draws in whole weeks. On the year scale it drags
in 28-day steps and draws in whole quarters. A range that stays inside a single tick comes out one
tick long.

Drag bounds are not applied to a drawn range, so it can start before `minDate`. See
[Editing tasks](editing).

## The draft

The chart does not create the task and does not fire `onTasksChange`. It calls `onTaskCreate` with
a draft and does nothing else. The row appears when your app adds a task to the `tasks` array.

`GanttTaskDraft` has two fields, `startDate` and `endDate`, UTC ISO strings snapped to the current
scale. The draft names no row. A range is only drawn where there is no row, and the button and
`addTask()` do not start on a row.

```tsx title="src/PlanBoard.tsx"
import { useState } from 'react';
import {
  ReactGanttChart,
  type GanttTaskDraft,
  type Task,
} from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function PlanBoard({ initial }: { initial: Task[] }) {
  const [tasks, setTasks] = useState<Task[]>(initial);

  const handleTaskCreate = ({ startDate, endDate }: GanttTaskDraft) => {
    const name = window.prompt('Task name');
    if (!name) return; // nothing is added - the chart adds nothing itself

    setTasks((current) => [
      ...current,
      {
        id: crypto.randomUUID(),
        name,
        startDate, // UTC ISO, snapped to whole ticks of the current scale
        endDate,
        parentId: null, // the draft names no row - you decide where it lands
        sequence: `${current.length + 1}`,
      },
    ]);
  };

  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
      onTaskCreate={handleTaskCreate}
    />
  );
}
```

## Turning task creation off

`allowTaskCreate` is chart-wide and controls all three entry points. With `allowTaskCreate` set to
`false`, the button is not rendered, `addTask()` does nothing and the drawing gesture is off. It
resolves from its own value, then from `!readOnly`. `Task` has no `allowTaskCreate` field, and a
value set there is ignored.

> [!IMPORTANT]
> Creation also needs `onTaskCreate`. Without that callback `allowTaskCreate` has no effect. The
> button, the crosshair cursor and the ghost are not rendered, and the drawing gesture is off.

With no tasks and no pinned window, none of the three produces a draft. The chart renders no
timeline, so there are no ticks to snap a range to. Pin the window with `visibleStart` and
`visibleEnd` to render one.

## Limitations

- Creation stops at the draft. The button, `addTask()` and a drawn range each call `onTaskCreate`,
  and your app adds the row.
- Task deletion has no pointer path. A task is deleted from the keyboard layer.
- `GanttTaskDraft` carries `startDate` and `endDate` and nothing else, so your app decides where
  the new task goes in the tree.
- `allowTaskCreate` on its own changes nothing. All three entry points need `onTaskCreate`.
- The drawing gesture has no keyboard equivalent. The **Add task** button produces the same draft,
  and no key is bound to it.
