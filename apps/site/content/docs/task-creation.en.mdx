---

Someone wants a row that does not exist yet. Where they reach for it differs — the task list, your
own toolbar, the blank space below the last row — but what the chart does with it never changes.

Three ways in, one way out. The button under the task list, `addTask()` on the chart ref, and a
range drawn below the last row all propose the same thing: a draft handed to `onTaskCreate`. The
chart adds nothing itself, whichever one the user reached for.

## The button under the task list

With `showTaskList` on, an **Add task** strip sits at the foot of the pane. A click proposes one
tick at today — the shortest range a drawn one can come out as. When today is outside the rendered
timeline, it proposes the first tick instead.

It is also the only way in from a keyboard. The strip is rendered outside the treegrid, so it is an
ordinary tab stop after the grid rather than a second one inside it. A chart with no pane has no
button: draw the range, or call `addTask()`.

Its label is the hardcoded English string `Add task`, like the rest of the chart's chrome — see
[Locale and date formats](i18n).

## `addTask()` on the chart ref

The same proposal from your own toolbar, or your own keyboard shortcut:

```tsx
ganttRef.current?.addTask();
```

It is inert while creation is off, so a button wired to it needs no guard of its own. The rest of
the handle is in [Imperative API](imperative-api).

## Drawing a range below the last row

Press in the blank space below the last row, drag sideways, and release. A dashed ghost follows
the pointer, and on release the chart hands your app the range that was drawn.

The press has to land below the last row. A press on a row draws nothing at all — not on its bar,
not on an arrow or a handle, and not on the empty part of the row either. Rows belong to tasks. A
mouse starts drawing immediately; touch and pen need the same 400 ms long press as a bar drag;
see [Editing tasks](editing).

The whole blank region is one target, not a stack of empty rows. Wherever in it the press lands,
the ghost sits in the band directly under the last row, because that is where the new task will
appear once your app adds it.

Only horizontal distance counts, so a diagonal drag changes nothing. A drag shorter than 4px
proposes nothing.

`Escape` cancels a draw in progress. It has no effect on a bar or progress drag.

## Drawn ranges snap to ticks, not to drag steps

This is the one place where the snapping unit differs from the drag step
[Editing tasks](editing) describes. A drawn range
expands outwards to whole ticks of the current scale.

| Scale | A drawn range snaps to whole |
|---|---|
| `day` | quarter-days (6-hour cells) |
| `week` | days |
| `month` | weeks |
| `quarter` | months |
| `year` | quarters |

So on the month scale a bar drags in 1-day steps but draws in whole weeks, and on the year scale it
drags in 28-day steps but draws as a whole quarter. A range that stays inside a single tick still
comes out one tick long.

Drag bounds are not applied; see [Editing tasks](editing). A drawn range can start before `minDate`.

## The draft, and what the chart does with it

Nothing. The chart creates no task, writes no array, and fires no `onTasksChange`. It calls
`onTaskCreate` with a draft and stops there. The new row appears only when your app builds a task
and passes a new `tasks` array back in.

`GanttTaskDraft` has two fields: `startDate` and `endDate`, UTC ISO strings snapped to the scale.
It names no row. A range can only be drawn where no row is, and the button and `addTask()` point at
no row either — where the new task goes in the tree is your app's decision, not something an entry
point can report.

```tsx title="src/PlanBoard.tsx"
import { useState } from 'react';
import {
  ReactGanttChart,
  type GanttTaskDraft,
  type Task,
} from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function PlanBoard({ initial }: { initial: Task[] }) {
  const [tasks, setTasks] = useState<Task[]>(initial);

  const handleTaskCreate = ({ startDate, endDate }: GanttTaskDraft) => {
    const name = window.prompt('Task name');
    if (!name) return; // nothing is added - the chart adds nothing itself

    setTasks((current) => [
      ...current,
      {
        id: crypto.randomUUID(),
        name,
        startDate, // UTC ISO, snapped to whole ticks of the current scale
        endDate,
        parentId: null, // the draft names no row - you decide where it lands
        sequence: `${current.length + 1}`,
      },
    ]);
  };

  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
      onTaskCreate={handleTaskCreate}
    />
  );
}
```

## Turning task creation off

`allowTaskCreate` is chart-wide, and it is one switch for all three entry points: off, the strip is
not rendered, `addTask()` does nothing, and there is no drawing gesture. It resolves through two
rungs only: its own value, then `!readOnly`. `Task` has no `allowTaskCreate` field, and putting one
there is ignored.

> [!IMPORTANT]
> Creation also needs `onTaskCreate`. Without that callback there is no strip, no crosshair cursor,
> no ghost, and no gesture at all, whatever `allowTaskCreate` says. `allowTaskCreate` on its own
> does nothing.

All three are also unreachable in a chart with no tasks, unless the window is pinned with
`visibleStart` and `visibleEnd`: with neither tasks nor a pinned window there is no timeline, and
so no ticks to snap a range to.

## Limits

- **The chart never creates a task.** The strip, `addTask()` and a drawn range all propose a draft;
  your app decides. The chart never deletes one with the pointer either — deletion exists only in
  the keyboard layer.
- **The draft names no row.** `GanttTaskDraft` carries `startDate` and `endDate` and nothing else,
  so where the new task lands in the tree stays your app's decision.
- **Without `onTaskCreate` nothing is created.** All three entry points hang off that callback, so
  `allowTaskCreate` on its own changes nothing.
- **The drawing gesture has no keyboard equivalent.** The **Add task** strip is the keyboard way to
  the same draft, and no key is bound to it.
