작업 목록은 행마다 작업 이름을 보여주는 왼쪽 패널이에요. `hierarchy`를 켜면 자식이 있는 작업은
요약 행으로 그려지고, 날짜는 자식에서 계산돼요. 이 페이지는 패널과 스플리터, `parentId` 트리를
다뤄요.

## 패널 켜기

패널은 기본으로 꺼져 있어요. `showTaskList`를 켜면 나타나요. 패널 내용을 바꾸는 다른 스위치는
`showRowNumbers`예요. 아래에서 설명해요.

| `showTaskList` | 패널 |
|---|---|
| 생략 | 숨김 |
| `true` | 표시 |
| `false` | 숨김 |

`false`면 타임라인만 렌더링해요. 패널을 숨기는 컨트롤은 차트에 없어요. 사용자가 패널을 숨길 수
있어야 하면 호스트 앱에서 버튼을 만들고 그 상태로 `showTaskList`를 넘기세요. prop과 기본값은
[GanttProps](ref/props)에 있어요.

아래 예제는 패널을 켠 채로 작업 세 개짜리 트리를 렌더링해요.

```tsx title="ProjectChart.tsx"
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  { id: 'p1', name: 'Phase 1', parentId: null, sequence: '1',
    startDate: '2025-03-03', endDate: '2025-03-28' },
  { id: 't1', name: 'Design', parentId: 'p1', sequence: '1.1',
    startDate: '2025-03-03', endDate: '2025-03-12', progress: 100 },
  { id: 't2', name: 'Build', parentId: 'p1', sequence: '1.2',
    startDate: '2025-03-12', endDate: '2025-03-28', progress: 40 },
];

export function ProjectChart() {
  return <ReactGanttChart tasks={tasks} showTaskList height={420} />;
}
```

## 패널 내용

이름을 열 하나에 보여줘요. 시작 너비는 220px이에요.

`showRowNumbers`를 켜면 이름 앞에 좁은 번호 열이 붙어요. 번호 열에는 차트가 행 순서를 정할 때
쓰는 `task.sequence`가 표시돼요. 2번 작업의 첫 번째 자식은 `2.1`로 보여요. 레인 하나를 통째로
담은 행은 첫 번째 작업의 번호만 표시해요.

| `showRowNumbers` | 번호 열 |
|---|---|
| 생략 | 숨김 |
| `true` | 표시, `task.sequence`가 들어감 |
| `false` | 숨김 |

<GanttDemo preset="rowNumbers" />

번호는 작업이 가진 필드예요. 그래서 부모를 접어도 번호는 바뀌지 않아요. 행 순서를 바꾸면
달라지는데 이동이 `sequence`를 다시 쓰기 때문이에요. [행 순서 바꾸기](reordering)를 참고하세요.

날짜 열 prop은 없고 추가할 계획도 없어요. 막대가 이미 기간을 보여줘요. 날짜 열을 넣으면 이름에
남는 폭이 절반으로 줄어요. 원하는 형식의 날짜, 담당자, 상태, 커스텀 위젯은 오른쪽
[상세 패널](detail-panel)에 두세요.

헤더 행에는 보이는 글자가 없어요. 패널의 유일한 헤더 셀에는 스크린 리더용 이름 `Task name`만 있고
트리 셀 안에 그려지는 번호 열에는 헤더 셀이 없어요. 패널에서 눈에 보이는 글자는 **Add task** 버튼
라벨 하나뿐이에요. 차트 주변 UI와 마찬가지로 영어로 하드코딩돼 있어요.
[로케일과 날짜 형식](i18n)을 참고하세요.

**Add task** 버튼은 패널 푸터에 있어요. 작업 생성이 켜져 있는 동안 렌더링돼요. 즉 `onTaskCreate`가
있고 `allowTaskCreate: false`나 단독 `readOnly`가 생성을 끄지 않을 때예요. 스플리터처럼
`treegrid` 바깥에 그려져서 그리드는 탭 스톱 하나를 유지하고 버튼은 그다음의 평범한 탭 스톱이
돼요. 누르면 초안과 함께 `onTaskCreate`가 호출돼요. 초안의 내용과 초안을 만드는 다른 두 방법은
[작업 생성](task-creation)에 있어요.

## 이름 셀

행이 가진 그리드 셀은 트리 셀 하나뿐이에요. 번호도 두 번째 셀이 아니라 이 셀 안에 그려져요. 셀
안에는 최대 여섯 가지가 순서대로 들어가요.

- 드래그 그립. 차트 어디서든 행 순서 바꾸기가 켜져 있고 그 행에 호버하거나 포커스가 있을 때만
  보여요. 움직일 수 없는 행에는 20px 여백이 대신 들어가요. [행 순서 바꾸기](reordering)를
  참고하세요.
- 행의 `sequence`. `showRowNumbers`가 켜져 있을 때 들여쓰기보다 앞에 놓여서 깊이와 상관없이 같은 x
  위치를 유지해요.
- `depth * 16` 픽셀의 들여쓰기 여백
- 펼칠 수 있는 행의 확장 버튼, 그 밖의 행에서는 20px 여백
- 작업 이름. 셀에 같은 문자열이 네이티브 `title` 속성으로도 붙어 있어서 패널에 다 들어가지 않는
  이름도 호버하면 읽을 수 있어요.
- `+N` 배지. 한 행이 작업을 여러 개 담을 때 나머지 개수를 세요. [레인](lanes)에서 생기는
  일이에요.

셀은 패널 너비 전체를 차지해요. 스플리터로 넓힌 만큼 이름에 공간이 생겨요. 그래도 들어가지 않는
이름은 말줄임표로 잘려요.

## 패널 크기 조절

| 컨트롤 | 동작 |
|---|---|
| 스플리터 드래그 | 누른 순간의 너비에 포인터 이동량을 더한 값, 120px에서 800px로 제한 |
| 스플리터 더블클릭 | 보이는 행 중 가장 긴 이름 전체에 맞게 조절, 같은 범위 제한 |
| 스플리터 키보드 | `ArrowLeft` / `ArrowRight`로 16px씩, `Enter`는 더블클릭과 같은 맞춤, 같은 범위 제한 |
| 스플리터 시맨틱 | `role="separator"`, `aria-orientation="vertical"`, 라벨 `Resize task list` |

너비 맞춤은 화면에 보이는 행만 측정해요. 뷰포트 밖으로 가상화된 행은 DOM에 없어서 더 아래에 있는
긴 이름은 스크롤해서 나타나기 전까지 패널을 넓히지 않아요.

스플리터는 `treegrid` 바깥에 렌더링돼요. 그래서 그리드는 탭 스톱 하나를 유지하고 스플리터는
별도의 두 번째 탭 스톱이 돼요. [키보드와 스크린 리더](accessibility)를 참고하세요. 패널이 보이는
동안에만 렌더링되니 `showTaskList={false}`면 스플리터도 사라져요.

패널 너비는 컴포넌트 로컬 상태예요. 초기값을 주는 prop도 없고 값이 바뀔 때 호출되는 콜백도 없어요.
리마운트하면 유지되지 않아요.

## parentId로 정하는 깊이

`hierarchy`의 기본값은 `false`예요. 꺼져 있으면 `parentId`는 렌더링에 영향이 없고 들여쓰기는
`sequence`의 점 개수로 정해져요.

| | `hierarchy: false` | `hierarchy: true` |
|---|---|---|
| 행 순서 | `sequence` | `sequence`, 그대로 |
| 행 깊이 | `sequence`의 점 개수 | `parentId` 체인을 거슬러 올라간 단계 수 |
| `isSummary` | 없음 | 자식이 하나 이상인 작업 |
| 요약 날짜 | 원래 값 그대로 렌더링 | 자식에서 다시 계산 |
| 행 접기 | 확장 버튼 없음, 작업 id에 `collapsedIds` 무효 | 동작 |

행 순서는 두 모드 모두 `sequence`가 정해요. `parentId`는 행을 옮기지 않아요. `sequence` 정렬
규칙은 [작업 데이터](task-data)를 참고하세요.

## 요약 행의 날짜

요약 행의 `startDate`는 자식 중 가장 이른 `startDate`이고, `endDate`는 자식 중 가장 늦은
`endDate`예요. 데이터에 있던 부모의 날짜는 렌더링할 때마다 버려져요.

롤업은 가장 깊은 곳부터 실행돼요. 그래서 손자를 옮기면 부모를 거쳐 조부모까지 반영돼요. 타임라인이
범위를 맞추기 전에 실행되기 때문에 부모의 원래 날짜를 넘어가는 자식도 타임라인을 넓혀요.

새로 계산한 값은 완전한 UTC ISO 문자열로 직렬화돼요. `renderDetail`이나 클릭 콜백이 받은 작업을
원본 문자열과 비교하면 이 점이 문제가 돼요. [트리 헬퍼](ref/core-tree)를 참고하세요.

자식의 날짜를 하나도 파싱할 수 없으면 부모는 자기 날짜를 유지해요. 오류는 나지 않아요.

## 요약 행의 진행률

부모에 `progress`가 명시돼 있으면 그대로 둬요. 값이 없을 때만 자식의 기간 가중 평균으로 롤업해요.
가중치와 반올림 규칙은 [트리 헬퍼](ref/core-tree)에 있어요.

## 요약 행의 제스처

요약 행에서는 크기 조절과 진행률 드래그가 꺼져 있고 작업별 플래그로도 다시 켤 수 없어요.
[GanttInteractionConfig](ref/interaction-config)를 참고하세요. 진행률 채우기는 그대로 그려지고
드래그 핸들만 숨겨져요.

이동은 영향을 받지 않아요. 요약 막대를 드래그하면 하위 트리 전체가 같은 델타만큼 움직여요. 이동
범위는 구성원 각자가 움직일 수 있는 구간의 교집합으로 제한돼요. [작업 편집](editing)을 참고하세요.

요약 행은 그리드 행과 막대 양쪽에 `summary` 클래스가 붙어요. 접근성 이름에는 작업 이름과 날짜
범위 사이에 `summary`라는 단어가 들어가요.

## 행 접기

접힘 상태는 id 목록 하나예요. 제어 모드와 비제어 모드 모두 쓸 수 있어요.

| Prop | 모드 | 규칙 |
|---|---|---|
| `collapsedIds` | 제어 | 넘긴 배열이 차트에 보이는 상태예요. 내부 상태는 업데이트를 멈춰요 |
| `defaultCollapsedIds` | 비제어 | 초기 상태로 한 번만 읽어요. 이후 변경은 무시해요 |
| `onCollapsedChange` | 둘 다 | 토글할 때마다 다음 배열 전체와 함께 호출돼요 |

모드는 `collapsedIds !== undefined`로 갈려요. `null`은 이 prop의 타입에 없고 제어를 끄지도
않아요. `null`을 넘기면 패널은 내부 목록으로 그리지만 거기에 쓰지 않아서 `onCollapsedChange`는
계속 호출되는데 확장 버튼은 모두 멈춰요. 두 prop을 함께 넘기면 `collapsedIds`가 이기고
`defaultCollapsedIds`는 아무도 읽지 않는 상태만 채워요.

`onCollapsedChange`는 두 모드에서 똑같이 호출돼요. 마운트 시점이나 `defaultCollapsedIds` 때문에
호출되지는 않아요. 페이로드는 델타가 아니라 다음 배열 전체예요. 새로 접힌 id는 끝에 추가되고 펼친
id는 걸러져요.

접힘 목록이 바뀌는 경우는 거의 다 토글이에요. 나머지 하나는 행 이동이에요. 드래그한 행을 접힌
부모에 놓으면 그 부모가 펼쳐져서 옮긴 행이 보이고, 이 펼침에도 `onCollapsedChange`가 호출돼요.
[행 순서 바꾸기](reordering)를 참고하세요.

> [!WARNING]
> 제어 모드에서 차트는 스스로 아무것도 접지 않아요. 새 `collapsedIds` 배열을 기다려요.
> `onCollapsedChange`를 처리하지 않고 `collapsedIds`만 넘기면 모든 확장 버튼이 고장 난 것처럼
> 보여요.

접힌 행은 화면에 남고 하위 작업만 사라져요. 자식이 없는 id를 접으면 아무것도 숨겨지지 않고 id는
목록에 그대로 남아요.

토글은 이름 셀의 확장 버튼으로 해요. 키보드로는 첫 셀에서 `ArrowRight` / `ArrowLeft`를 누르거나
행 어디서든 `Enter` / `Space`를 누르세요. [키보드와 스크린 리더](accessibility)를 참고하세요.

한 레인에 작업 여러 개를 담은 행의 id는 `a+b`이고 어떤 작업과도 일치하지 않아요.
[레인](lanes)을 참고하세요. 확장 버튼이 붙을지는 첫 번째 작업만 보고 정해요. 레인을 공유하는 요약
행에는 아무것도 숨기지 않는 토글이 붙어요.

아래 예제는 접힌 목록을 상태로 들고, 처음에 `p1`을 접어 둬요.

```tsx title="ProjectChart.tsx"
import { useState } from 'react';
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  { id: 'p1', name: 'Phase 1', parentId: null, sequence: '1',
    startDate: '2025-03-03', endDate: '2025-03-28' },
  { id: 't1', name: 'Design', parentId: 'p1', sequence: '1.1',
    startDate: '2025-03-03', endDate: '2025-03-12', progress: 100 },
  { id: 't2', name: 'Build', parentId: 'p1', sequence: '1.2',
    startDate: '2025-03-12', endDate: '2025-03-28', progress: 40 },
];

export function ProjectChart() {
  const [collapsedIds, setCollapsedIds] = useState<string[]>(['p1']);

  return (
    <ReactGanttChart
      tasks={tasks}
      showTaskList
      hierarchy
      collapsedIds={collapsedIds}
      onCollapsedChange={setCollapsedIds}
      height={420}
    />
  );
}
```

## 예외 상황

망가진 `parentId`(배열에 없는 부모, 자기 참조, 빈 문자열, 순환)는 패널이 그리기 전에 경고 없이
루트로 정규화돼요. 규칙은 [트리 헬퍼](ref/core-tree)에 있어요.

`progress`가 명시된 요약 행은 값을 그대로 유지하고 `0`도 마찬가지예요. 롤업이 `null`이나
`undefined`만 채우기 때문이에요. 값을 범위 제한하지도 않아서 저장된 `250`은 `renderDetail`과 클릭
콜백에 `250` 그대로 전달되고 막대는 100%로 그려져요. 어느 쪽이든 진행률 핸들은 숨겨진 채예요.

중복된 `id`는 제거되지 않아요. 중복 항목은 부모의 자식 목록에 두 번 들어가고 롤업에서도 두 번
계산돼요.

깊이 제한은 없어요. 25단계 체인의 마지막 행은 깊이가 24이고 들여쓰기는 384px이에요.

## 한계

- 패널은 이름만 보여줘요. 열 API, 정렬, 필터는 없어요.
- 이름 셀은 읽기 전용이에요. 인라인 편집기, `onCellChange`, 그리드 행 렌더러가 없어요.
  `renderDetail`은 차트의 유일한 렌더 prop이고 행이 아니라 상세 패널을 그려요. 행이 작업에서
  가져오는 것은 `className`뿐이에요. [스타일링](styling)을 참고하세요.
- 패널 너비는 prop이 없고 저장되지도 않아요. 언제나 220px로 열리고 스플리터로만 바꿀 수 있어요.
- 레이아웃 상수(행 높이, 시작 너비, 120px에서 800px의 스플리터 범위, 16px 들여쓰기)는 내보내지
  않아요. 그래서 호스트 앱이 자기 UI에 맞추려고 가져올 수 없어요.
- 트리는 행을 정렬하지 않고 `sequence`가 `parentId`와 맞는지도 확인하지 않아요. `sequence`가
  부모보다 위로 정렬되는 자식은 부모 위에 들여쓰기된 채로 렌더링되고, ARIA 위치는 틀리고 경고도
  없어요.
- 끊어진 부모 연결은 콜백, 콘솔 메시지, 행의 플래그 없이 복구돼요.
- 롤업은 `startDate`, `endDate`, 비어 있는 `progress`만 다뤄요. `color`, `className`,
  `dependencies`는 롤업하지 않아요.
- `hierarchy`가 꺼져 있으면 `collapsedIds`와 `defaultCollapsedIds`는 아무 일도 하지 않아요.

호스트 앱은 `sequence`를 `parentId`와 맞게 유지하고 패널 너비를 직접 저장해야 해요. 제어 모드로
접기를 쓰려면 접힌 목록도 상태로 들어야 해요. 패널을 숨기는 컨트롤과 렌더링 전 부모 연결 검증도
호스트 앱의 몫이에요. 마지막 항목에는 차트가 내보내는 `buildTaskTree`를 쓰세요. 작업별 상세 정보는
상세 패널에 담으세요. [헤드리스 코어](headless-core)를 참고하세요.
