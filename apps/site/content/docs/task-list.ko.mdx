막대는 무언가가 언제 일어나는지만 알려줘요. 그게 무엇인지는 알려주지 않고요. 작업 목록은 왼쪽에
있는 패널이에요. 모든 행 옆에 작업 이름을 놓아요. `parentId`가 눈에 보이는
곳도 여기예요. `hierarchy`를 켜면 자식이 있는 작업은 요약 행으로 그려지고, 그 날짜는 자기 레코드가
아니라 자식들에게서 와요.

## 패널 켜기

패널은 기본적으로 꺼져 있어요. `showTaskList`가 패널을 켜요. 패널이 보여주는 내용은 정해져 있어요 —
나머지 스위치 하나인 `showRowNumbers`는 아래에서 다뤄요.

| `showTaskList` | 패널 |
|---|---|
| 생략 | 숨김 |
| `true` | 표시 |
| `false` | 숨김 |

`false`는 타임라인만 렌더링해요. 차트는 패널을 숨기는 자체 컨트롤을 제공하지 않아요. 최종 사용자가
패널을 숨길 수 있어야 한다면, 호스트 앱이 버튼을 만들어 자기 상태로 `showTaskList`를 몰아주면 돼요.
여기 나온 prop의 시그니처와 기본값은 [GanttProps](ref/props)에 있어요.

```tsx title="ProjectChart.tsx"
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  { id: 'p1', name: 'Phase 1', parentId: null, sequence: '1',
    startDate: '2025-03-03', endDate: '2025-03-28' },
  { id: 't1', name: 'Design', parentId: 'p1', sequence: '1.1',
    startDate: '2025-03-03', endDate: '2025-03-12', progress: 100 },
  { id: 't2', name: 'Build', parentId: 'p1', sequence: '1.2',
    startDate: '2025-03-12', endDate: '2025-03-28', progress: 40 },
];

export function ProjectChart() {
  return <ReactGanttChart tasks={tasks} showTaskList height={420} />;
}
```

## 패널이 보여주는 것

`task.name`을 열 하나에, 시작 패널 너비 220px로 보여줘요.

`showRowNumbers`는 그 앞에 좁은 번호 열을 붙여요. 차트가 이미 행 순서로 쓰는 개요 경로인
`task.sequence`를 찍으니, 2번 작업의 첫 번째 자식은 `2.1`로 읽혀요. 레인 하나를 통째로 담은 행은
첫 번째 작업의 번호만 찍고, 나머지 작업의 번호는 찍지 않아요.

| `showRowNumbers` | 번호 열 |
|---|---|
| 생략 | 숨김 |
| `true` | 표시, `task.sequence`를 찍음 |
| `false` | 숨김 |

<GanttDemo preset="rowNumbers" />

번호는 화면에 보이는 행의 개수가 아니라 작업 자신의 필드예요. 그래서 부모를 접어도 번호는 다시
매겨지지 않아요. 행을 옮기면 달라지는데, 이동이 `sequence`를 다시 쓰기 때문이에요 —
[행 순서 바꾸기](reordering)를 보세요.

날짜 열을 위한 prop은 없고, 추가할 계획도 없어요. 막대가 이미 기간을 보여주는데 그 옆의 날짜
열은 차트를 반복하면서 이름이 쓸 폭을 절반으로 줄여요. 작업에 관한 나머지 전부는 — 원하는 형식의
날짜, 담당자, 상태, 커스텀 위젯까지 — 오른쪽 상세 패널의 몫이에요. 거기에는 공간이 있고, 이름과
자리를 다투지도 않아요. [상세 패널](detail-panel)을 보세요.

그 위의 헤더 행은 아무것도 찍지 않아요. 패널의 유일한 헤더 셀에는 스크린 리더용 이름 `Task name`만
붙고, 트리 셀 안에 그려지는 번호 열에는 헤더 셀 자체가 없어요. 그래서 패널이 눈에 보이게 그리는
문자열은 **Add task** 버튼의 라벨 하나뿐이에요. 차트의 다른 크롬과 마찬가지로 하드코딩된
영어예요 — [로케일과 날짜 형식](i18n)을 보세요.

패널이 그리는 나머지 하나는 발치의 **Add task** 띠예요. 작업 생성이 켜져 있는 동안, 즉 `onTaskCreate`가
있고 `allowTaskCreate: false`나 단독 `readOnly`가 생성을 끄지 않는 동안 나타나요. 스플리터와 마찬가지로 treegrid 바깥에
그려지니, 격자는 하나뿐인 탭 정지점을 지키고 버튼은 그다음의 평범한 정지점이 돼요. 누르면 작업을
제안해요. 무엇을 제안하는지, 같은 것을 제안하는 다른 두 길은 [작업 생성](task-creation)에 있어요.

## 이름 셀

셀 하나가 곧 트리 셀이에요. 번호도 두 번째 셀이 아니라 이 셀 안에 그려져서, 행은 격자 셀 하나를
그대로 지켜요. 최대 여섯 가지가 그 안에 들어 있어요.

- 차트 어딘가에서 행 순서 바꾸기가 켜져 있을 때의 드래그 그립. 행에 호버하거나 포커스가 있을 때만
  보이고, 움직일 수 없는 행에서는 20px 여백으로 대체돼서 텍스트가 밀리지 않아요.
  [행 순서 바꾸기](reordering)를 보세요.
- `showRowNumbers`가 켜져 있을 때 행의 `sequence`. 들여쓰기보다 앞에 있어서, 행의 깊이와 상관없이
  열이 같은 x에 놓여요.
- `depth * 16` 픽셀만큼의 들여쓰기 여백
- 펼칠 수 있는 행에 붙는 확장 버튼, 또는 나머지 모든 행에 붙는 20px 여백
- 작업 이름. 셀이 존재하는 유일한 이유예요. 셀 자체가 같은 문자열을 네이티브 `title` 속성으로도
  달고 있어서, 패널에 다 들어가지 않는 이름도 호버하면 읽을 수 있어요.
- 한 행이 작업을 여러 개 담을 때 나머지 개수를 세는 `+N` 배지. 레인에서 생기는 일이에요.
  [레인](lanes)을 보세요.

셀은 패널 너비 전체를 차지해요. 그래서 스플리터가 더하는 픽셀은 모두 이름에게 가요. 그래도 들어가지
않는 이름은 말줄임표로 잘려요.

## 패널 크기 조절

| 컨트롤 | 동작 |
|---|---|
| 스플리터 드래그 | 120–800px로 제한, 누른 순간의 너비에 그 뒤 포인터 이동량을 더한 값 |
| 스플리터 더블클릭 | 보이는 행 중 가장 긴 이름 전체에 맞게 패널을 조절, 같은 범위 제한 |
| 스플리터 키보드 | `ArrowLeft` / `ArrowRight`로 16px씩, `Enter`는 더블클릭과 같은 맞춤, 같은 범위 제한 |
| 스플리터 시맨틱 | `role="separator"`, `aria-orientation="vertical"`, 레이블 `Resize task list` |

맞춤은 화면에 보이는 행만 재요. 뷰포트 밖으로 가상화된 행은 DOM에 없어서, 더 아래에 있는 긴
이름은 스크롤로 나타나기 전까지 패널을 넓히지 않아요.

스플리터는 일부러 treegrid 바깥에 놓여 있어요. 그래서 그리드는 탭 정지점을 정확히 하나만 갖고,
스플리터가 별도의 두 번째 정지점이 돼요 — [키보드와 스크린 리더](accessibility)를 보세요.
스플리터는 패널이 보이는 동안에만 렌더링돼요. 그래서
`showTaskList={false}`는 핸들도 함께 없애요.

패널 너비는 컴포넌트 로컬 상태예요. 초기값을 주는 prop도, 값이 바뀔 때의 콜백도 없어요. 리마운트하면
살아남지 않아요.

## parentId로 정해지는 깊이

`hierarchy`는 기본값이 `false`예요. 꺼져 있으면 `parentId`는 렌더링에 아무 영향이 없어요. 눈에
보이는 들여쓰기는 `sequence`의 점 개수에서 나와요.

| | `hierarchy: false` | `hierarchy: true` |
|---|---|---|
| 행 순서 | `sequence` | `sequence` — 그대로 |
| 행 깊이 | `sequence`의 점 개수 | `parentId` 체인을 거슬러 올라간 단계 수 |
| `isSummary` | 항상 아님 | 자식이 하나 이상인 작업 |
| 요약 날짜 | 원래 값 그대로 렌더링 | 자식에서 재계산 |
| 작업 행 접기 | 확장 버튼 없음, 작업 id에 `collapsedIds` 무효 | 동작함 |

행 순서는 두 모드 모두 `sequence`에서 와요. `parentId`는 행을 옮기지 않아요. `sequence`가 어떻게
정렬되는지는 [작업 데이터](task-data)를 보세요.

## 요약 행의 날짜는 무엇인가

요약의 `startDate`는 자식들 중 가장 이른 `startDate`예요. `endDate`는 그중 가장 늦은 `endDate`고요.
데이터에 있던 부모 자신의 날짜는 매 렌더마다 조용히 버려져요.

롤업은 가장 깊은 곳부터 실행돼요. 그래서 손자의 이동이 부모를 거쳐 조부모까지 올라가요. 또
타임라인이 범위를 맞추기 전에 실행돼요. 그래서 부모가 밝힌 날짜를 넘어가는
자식도 타임라인을 넓혀요.

재계산된 값은 완전한 UTC ISO 문자열로 다시 직렬화돼요. `renderDetail`이나 클릭 콜백이 건네받은
작업을 원본 문자열과 비교한다면 이 점이 문제가 돼요 — [트리 헬퍼](ref/core-tree)를 보세요.

자식이 전부 파싱할 수 없는 날짜를 가진 부모는 자기 날짜를 유지하고, 오류도 나지 않아요.

## 요약 행의 진행률은 무엇인가

부모에 `progress`가 명시돼 있으면 그대로 둬요. 값이 없을 때만 자식들의 기간 가중 평균으로
롤업하는데, 가중치와 반올림 규칙은 [트리 헬퍼](ref/core-tree)에 있어요.

## 요약 행이 할 수 없는 것

요약 행에서는 크기 조절과 진행률 드래그가 꺼져 있고, 작업별 플래그로도 다시 켤 수 없어요 —
[GanttInteractionConfig](ref/interaction-config)를 보세요.

진행률 채우기는 여전히 그려져요. 드래그 핸들만 사라져요.

이동은 영향을 받지 않아요. 요약 막대를 드래그하면 그 하위 트리 전체가 같은 델타만큼 움직여요. 범위는
구성원 각자의 드래그 가능 구간의 교집합으로 제한돼요. [작업 편집](editing)을 보세요.

요약 행은 그리드 행과 막대 양쪽에 `summary` 클래스를 달아요. 접근성 이름에는 작업 이름과 날짜 범위
사이에 `summary`라는 단어가 들어가요.

## 행 접기

접힘 상태는 id 목록 하나예요. 제어 모드와 비제어 모드 둘 다 있어요.

| Prop | 모드 | 규칙 |
|---|---|---|
| `collapsedIds` | 제어 | 여기 넘긴 배열이 차트가 보여주는 상태이고, 내부 상태는 갱신을 멈춰요 |
| `defaultCollapsedIds` | 비제어 | 초기 상태에서 한 번만 읽고, 이후 변경은 무시해요 |
| `onCollapsedChange` | 둘 다 | 토글할 때마다 다음 배열 전체와 함께 실행돼요 |

모드를 가르는 것은 `collapsedIds !== undefined`예요. `null`은 이 prop의 타입에 없고, 기능을 끄는
수단도 아니에요. 패널은 그림을 그릴 때 내부 목록으로 되돌아가지만, 거기에 쓰기를 멈춰요. 그래서
`onCollapsedChange`는 계속 실행되는데 모든 확장 버튼은 얼어붙어요. 두 prop을 함께 넘기면
`collapsedIds`가 이기고, `defaultCollapsedIds`는 아무도 읽지 않는 상태만 채워요.

`onCollapsedChange`는 제어 모드와 비제어 모드에서 똑같이 실행돼요. 마운트 시점에는 절대 실행되지
않고, `defaultCollapsedIds` 때문에 실행되지도 않아요. 페이로드는 항상 다음 배열 전체이고 델타가
아니에요. 새로 접힌 id는 끝에 추가되고, 펼친 id는 걸러져요.

거의 모든 쓰기는 토글이에요. 딱 하나 다른 쓰기는 행 이동이에요. 드래그한 행을 접힌 부모 안에
떨어뜨리면 그 부모가 펼쳐져서 옮긴 행이 사라져 보이지 않아요 — 이 펼침에도 `onCollapsedChange`가
실행돼요. [행 순서 바꾸기](reordering)를 보세요.

> [!WARNING]
> 제어 모드에서 차트는 스스로 아무것도 접지 않아요. 새로운 `collapsedIds` 배열을 기다려요.
> `onCollapsedChange`를 처리하지 않고 `collapsedIds`만 넘기면 모든 확장 버튼이 고장 난 것처럼
> 보여요.

접힌 행은 화면에 남고, 그 자손들이 사라져요. 자식이 없는 id를 접으면 조용히 아무 일도 일어나지
않고, 그 id는 목록에 그대로 남아요.

토글은 이름 셀의 확장 버튼에서 오거나, 첫 셀에서 누른 `ArrowRight` / `ArrowLeft`와 행 어디서든 누른
`Enter` / `Space`에서 와요. [키보드와 스크린 리더](accessibility)를 보세요.

한 레인에 작업 여러 개를 담은 행은 `a+b`라는 id를 갖는데, 어떤 작업과도 일치하지 않아요 —
[레인](lanes)을 보세요. 그 행에 확장 버튼이 붙을지는 첫 번째 작업 하나만으로 결정돼요. 그래서
레인을 공유하는 요약은 아무것도 숨기지 못하는 토글을 갖게 돼요.

```tsx title="ProjectChart.tsx"
import { useState } from 'react';
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  { id: 'p1', name: 'Phase 1', parentId: null, sequence: '1',
    startDate: '2025-03-03', endDate: '2025-03-28' },
  { id: 't1', name: 'Design', parentId: 'p1', sequence: '1.1',
    startDate: '2025-03-03', endDate: '2025-03-12', progress: 100 },
  { id: 't2', name: 'Build', parentId: 'p1', sequence: '1.2',
    startDate: '2025-03-12', endDate: '2025-03-28', progress: 40 },
];

export function ProjectChart() {
  const [collapsedIds, setCollapsedIds] = useState<string[]>(['p1']);

  return (
    <ReactGanttChart
      tasks={tasks}
      showTaskList
      hierarchy
      collapsedIds={collapsedIds}
      onCollapsedChange={setCollapsedIds}
      height={420}
    />
  );
}
```

## 예외 상황

**망가진 `parentId`** — 배열에 없는 작업, 자기 참조, 빈 문자열, 순환 — 은 패널이 그리기 전에 조용히
루트로 정규화돼요. 규칙은 [트리 헬퍼](ref/core-tree)에 있어요.

**`progress`가 명시된 요약.** 값은 살아남아요. `0`도 마찬가지예요. 롤업이 nullish 값만 채우기
때문이에요. 지나가는 길에 값을 제한하지도 않아요. 그래서 저장된 `250`은 `renderDetail`과 클릭
콜백이 받는 작업에 `250` 그대로 남고, 막대는 100%로 그려져요. 어느 쪽이든 진행률 핸들은 계속
숨겨져 있어요.

**중복된 `id` 값.** 아무것도 중복을 제거하지 않아요. 중복된 항목은 부모의 자식 목록에 두 번 들어가고,
롤업에서도 두 번 계산돼요.

깊이 제한은 없어요. 25단계 깊이의 체인은 마지막 행의 깊이가 24가 되고, 들여쓰기는 384px이 돼요.

## 한계

패널은 이름을 보여주고, 그 밖의 것을 보여주게 만들 수는 없어요. 열 API도, 정렬도, 필터도 없어요.
이름 셀은 읽기 전용 노드예요. 인라인 편집기도 없고 `onCellChange`도 없어요. 그리드 행을 위한
렌더러도 없어요. `renderDetail`이 차트의 유일한 렌더 prop인데, 행이 아니라 상세 패널을
그려요. 행이 작업에서 가져가는 것은 `className` 하나뿐이에요. [스타일링](styling)을 보세요.

패널 너비에는 prop이 없고 저장되지도 않아요. 언제나 220px로 열리고, 그 값을 바꾸는 것은 스플리터
하나뿐이에요. 레이아웃 상수인 행 높이, 그 시작 너비, 120–800 스플리터 범위, 16px
들여쓰기는 export되지 않아요. 그래서 호스트 앱은 자기 UI에 맞추려고 그 값들을 가져올 수 없어요.

트리는 행을 정렬하지 않고, `sequence`가 `parentId`와 맞는지도 아무도 확인하지 않아요. `sequence`가
부모보다 위로 정렬되는 자식은 부모 위에 들여쓰기된 채로 렌더링돼요. ARIA 위치는 틀리고 경고도
없어요. 끊어진 부모 연결은 조용히 복구돼요. 콜백도, 콘솔 메시지도, 행에 붙는 플래그도 없어요.

롤업은 `startDate`, `endDate`, 그리고 비어 있는 `progress`만 다뤄요. `color`, `className`,
`dependencies`는 롤업하지 않아요.

`hierarchy`가 꺼져 있는 동안 `collapsedIds`와 `defaultCollapsedIds`는 아무 일도 하지
않아요.

그래서 호스트 앱이 책임지는 것은 이래요. `sequence`를 `parentId`와 일관되게 유지하기, 제어 방식으로
접기를 쓰려면 접힌 목록을 상태로 들고 있기, 패널 너비를 직접 저장하기, 패널을 숨기는 컨트롤 만들기,
작업별 상세 정보를 상세 패널에 두기, 렌더 전에 부모 연결을 검증하기. 마지막 항목을 위해 `buildTaskTree`가 export돼 있어요. [헤드리스 코어](headless-core)를
보세요.
