차트는 툴바나 배율 선택기를 그리지 않아요. 오늘 버튼과 전체 보기 버튼, 배율 컨트롤은 호스트 앱이 직접 그려요. 이 컨트롤은 prop이 아니라 ref로 차트를 호출해요. 이 페이지는 ref로 받는 핸들의 스크롤, 배율 변경, 전체 보기 줌, 상세 패널, 작업 생성을 다뤄요.

## 핸들

`ReactGanttChart`는 `forwardRef`로 감싸져 있어요. `useRef<GanttHandle>`를 연결하면 마운트된 뒤 ref에 멤버 9개가 담겨요.

```tsx title="src/ChartWithControls.tsx"
import { useRef } from 'react';
import { ReactGanttChart, type GanttHandle, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function ChartWithControls({ tasks }: { tasks: Task[] }) {
  const ganttRef = useRef<GanttHandle>(null);

  return (
    <>
      <button onClick={() => ganttRef.current?.scrollToToday()}>Today</button>
      <ReactGanttChart ref={ganttRef} tasks={tasks} />
    </>
  );
}
```

`GanttHandle`은 `GanttScrollApi`, `GanttDetailApi`, `GanttTaskCreateApi`를 확장한 타입이에요. 자체 멤버는 없어요.

| 멤버 | 시그니처 | 동작 |
|---|---|---|
| `scrollToDate` | `(date: string \| Date \| Dayjs, options?: GanttScrollOptions) => void` | 날짜 위치로 가로 스크롤해요 |
| `scrollToToday` | `(options?: GanttScrollOptions) => void` | `scrollToDate(dayjs())` |
| `scrollToTask` | `(taskId: string, options?: GanttScrollOptions) => void` | 작업의 막대로 스크롤해요. 행이 화면 밖이면 세로로도 움직여요 |
| `setScale` | `(scale: GanttScaleKey) => void` | 타임라인 가운데 날짜를 그대로 두고 배율을 바꿔요 |
| `zoomToFit` | `() => void` | 모든 작업이 들어가는 가장 촘촘한 배율로 바꾸고 프로젝트 시작을 왼쪽 끝에 고정해요 |
| `getScrollElement` | `() => HTMLDivElement \| null` | 스크롤 컨테이너 DOM 노드를 반환해요 |
| `openDetail` | `(taskId: string) => void` | 상세 패널을 그 작업으로 열어요 |
| `closeDetail` | `() => void` | 상세 패널을 닫아요 |
| `addTask` | `() => void` | `onTaskCreate`에 새 작업 초안을 넘겨요 |

`GanttScrollApi`, `GanttDetailApi`, `GanttTaskCreateApi`, `GanttScrollOptions`, `GanttHandle`의 선언은 [GanttHandle](ref/handle)에 있어요.

## 스크롤

스크롤 메서드는 모두 같은 옵션 객체를 받아요.

| 옵션 | 값 | 기본값 | 규칙 |
|---|---|---|---|
| `smooth` | `boolean` | 애니메이션 적용 | 리터럴 `false`일 때만 애니메이션이 꺼져요. `undefined`는 애니메이션으로 움직여요 |
| `align` | `'start' \| 'center'` | `'center'` | 리터럴 `'start'`일 때만 왼쪽 끝에 맞춰요. 그 외 값은 가운데에 맞춰요 |

`align: 'start'`는 대상을 타임라인 영역의 왼쪽 끝에 놓아요. `align: 'center'`는 뷰포트 너비에서 고정된 작업 목록 패널 너비를 뺀 영역의 가운데에 놓아요.

두 경우 모두 목표 위치가 `0`보다 작아지지 않아요. 그래서 타임라인 앞쪽 날짜는 차트가 갈 수 있는 가장 왼쪽에 놓여요.

```ts
ganttRef.current?.scrollToDate('2026-09-01', { smooth: false, align: 'start' });
ganttRef.current?.scrollToToday();
ganttRef.current?.scrollToTask('task-42');
```

`scrollToDate`와 `scrollToToday`는 가로축만 움직이고 `scrollTop`은 그대로 둬요.

첫 스크롤에는 ref가 필요 없어요. `initialScrollTo="today"`가 첫 렌더링 뒤에 위치를 한 번 잡아요. 자세한 내용은 [타임라인](timeline)을 참고하세요. 그 뒤의 스크롤은 모두 ref로 해요.

`scrollToTask`는 두 축을 모두 움직여요. 가로로는 `align: 'start'`면 막대의 왼쪽 끝을, 그 외에는 막대의 중간을 맞춰요.

세로로는 행이 뷰포트 밖에 있을 때만 움직이고 행을 가운데에 놓아요. `align`은 가로축에만 적용돼요.

스크롤 메서드는 모두 조용히 실패해요. 렌더링 범위 밖의 날짜, 알 수 없는 작업 id, 마운트되지 않은 차트에서는 예외도 콘솔 출력도 없이 바로 반환해요. 그래서 데이터를 불러오는 중에 호출해도 안전해요.

`scrollToTask`는 렌더링된 행에서만 찾아요. 접힌 부모 아래의 작업은 그 목록에 없어요. 호출해도 아무 일도 하지 않으니 행을 먼저 펼치세요. 접힘 상태는 [작업 목록과 계층](task-list)을 참고하세요.

## 배율 바꾸기

차트는 배율 컨트롤을 그리지 않아요. `setScale`로 배율을 바꾸고 `onScaleChange` prop으로 바뀐 배율을 돌려받아요. 시그니처는 [GanttHandle](ref/handle)에 있어요. 배율을 바꾸는 다른 경로는 [타임라인](timeline)을 참고하세요.

네이티브 `<select>`로 만드세요. option 텍스트는 앱이 쓰니 라벨이 나머지 UI와 함께 번역돼요. 키보드와 스크린 리더, 터치 동작은 플랫폼이 제공해요.

```tsx title="src/GanttToolbar.tsx"
import { useRef, useState } from 'react';
import {
  ReactGanttChart,
  type GanttHandle,
  type GanttScaleKey,
  type Task,
} from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const SCALES: GanttScaleKey[] = ['day', 'week', 'month', 'quarter', 'year'];

export function GanttToolbar({ tasks }: { tasks: Task[] }) {
  const ganttRef = useRef<GanttHandle>(null);
  const [scale, setScale] = useState<GanttScaleKey>('month');

  return (
    <>
      <div>
        {/* 차트가 마운트되기 전까지 ref는 null이라, 호출마다 옵셔널 체이닝을 써요 */}
        <button onClick={() => ganttRef.current?.scrollToToday()}>Today</button>
        <button onClick={() => ganttRef.current?.zoomToFit()}>Fit</button>
        <button onClick={() => ganttRef.current?.openDetail('task-42')}>
          Details for 42
        </button>

        <select
          aria-label="Timeline scale"
          value={scale}
          onChange={(e) => ganttRef.current?.setScale(e.target.value as GanttScaleKey)}
        >
          {SCALES.map((s) => (
            <option key={s} value={s}>{s}</option>
          ))}
        </select>
      </div>

      <ReactGanttChart
        ref={ganttRef}
        tasks={tasks}
        defaultScale="month"
        onScaleChange={setScale}
        showDetail
      />
    </>
  );
}
```

select는 자기 상태를 직접 바꾸지 않아요. 고른 값이 차트로 들어가고 `onScaleChange`가 다시 알려줘요. 휠이나 키보드로 바꾼 배율도 같은 경로를 지나서 select가 따라와요.

`zoomToFit()`이 고른 배율도 같은 방식으로 보고되니 **Fit** 버튼을 눌러도 select가 추가 코드 없이 바뀌어요.

버튼은 상태를 갖지 않아요. 메서드는 호출되는 순간의 차트 상태를 읽어요. 값을 가진 건 select 하나고 `onScaleChange`가 그 값을 맞춰 줘요.

[플레이그라운드](/ko/playground)에서 차트 위의 툴바가 이 모양이에요. 이 페이지의 메서드 중 `setScale`을 뺀 나머지는 그 옆 콘솔에 버튼으로 있어요. `setScale`은 위 예시처럼 툴바의 네이티브 `<select>`가 호출해요.

## 줌

`zoomToFit()`은 렌더링된 작업에서 가장 이른 `startDate`와 가장 늦은 `endDate`를 읽어요. 그다음 `day`, `week`, `month`, `quarter`, `year` 순서로 촘촘한 배율부터 시도해서 전체 구간이 타임라인 너비에 들어가는 첫 배율을 골라요. 어느 배율에도 들어가지 않으면 `year`를 써요.

가장 이른 날짜는 타임라인의 왼쪽 끝에 고정돼요. 옵션은 받지 않고 결과 스크롤은 항상 즉시 일어나요. 기준점을 `scrollTo({ behavior })`가 아니라 `scrollLeft`에 직접 대입해서 적용하기 때문이에요.

들어가는지는 실제로 만들어질 눈금이 아니라 배율별 평균 밀리초당 px 값으로 재요. 눈금 길이가 고정된 배율에서는 이 값이 정확해요.

`quarter`와 `year`는 눈금이 달력을 따라가서 근삿값이에요. `quarter`는 월 셀이고 `year`는 분기 셀이에요. 구간 길이가 뷰포트 너비와 몇 퍼센트 안쪽으로 차이 나면 옆 배율이 골라질 수도 있어요.

작업이 없거나 마운트된 스크롤 요소가 없을 때, 최소나 최대 날짜가 유한한 수가 아닐 때는 오류 없이 바로 반환해요.

핸들에는 `zoomIn`과 `zoomOut`이 없어요. 다섯 키를 담은 배열을 직접 만들어 `setScale`로 한 단계씩 옮기거나 `Ctrl`/`Cmd` + 휠과 `Ctrl`/`Cmd` + `ArrowUp`/`ArrowDown`에 맡기세요. 둘 다 [타임라인](timeline)에서 설명해요.

`GanttZoomAnchor`는 패키지에서 내보내는 타입이지만 핸들의 어떤 메서드도 받지 않아요. `setScale`과 `zoomToFit`은 각자 앵커를 만들어요.

## 상세 패널

메서드 두 개가 차트 밖에서 상세 패널을 움직여요. `openDetail(taskId)`는 옆에 붙은 상세 패널을 그 작업으로 열고 `closeDetail()`은 닫아요.

패널이 무엇인지, 무엇이 켜는지, 무엇을 그리는지는 [상세 패널](detail-panel)을 참고하세요. 여기서는 ref 쪽만 다뤄요.

```ts
ganttRef.current?.openDetail('task-42');
ganttRef.current?.closeDetail();
```

패널이 꺼져 있으면 두 메서드 모두 아무 일도 하지 않아요. 기본값은 꺼짐이니 `renderDetail`이나 `showDetail`로 켜세요.

그래서 `openDetail`에 연결한 버튼에는 가드를 두지 마세요. 열 패널이 생기기 전까지는 아무 일도 하지 않아요.

`openDetail`은 어떤 작업도 가리키지 않는 id를 `scrollToTask`처럼 무시해요. 다른 점은 하나예요. id는 렌더링된 행이 아니라 차트가 가진 모든 작업에서 찾아요. 그래서 접힌 부모 아래의 작업도 패널이 열려요.

렌더링된 행이 필요한 쪽은 `scrollToTask`예요. 아래 예시는 둘을 함께 호출해요.

이미 닫힌 패널에 `closeDetail()`을 호출하면 아무 일도 하지 않고 `onDetailChange`도 발생하지 않아요.

```tsx title="src/ChartWithDetail.tsx"
import { useRef } from 'react';
import { ReactGanttChart, type GanttHandle, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function ChartWithDetail({ tasks }: { tasks: Task[] }) {
  const ganttRef = useRef<GanttHandle>(null);

  // 스크롤 먼저, 그다음 열기 — 패널은 차트가 스크롤할 수 없는 id도 해석해요
  const inspect = (taskId: string) => {
    ganttRef.current?.scrollToTask(taskId);
    ganttRef.current?.openDetail(taskId);
  };

  return (
    <>
      <ul>
        {tasks.map((task) => (
          <li key={task.id}>
            <button onClick={() => inspect(task.id)}>{task.name}</button>
          </li>
        ))}
      </ul>

      <ReactGanttChart ref={ganttRef} tasks={tasks} showDetail />
    </>
  );
}
```

`showDetail`을 켜면 행을 선택하는 클릭과 포커스된 행에서 누른 `Enter`로도 패널이 열려요. 직접 만든 버튼은 차트의 트리거를 대체하지 않아요. 트리거를 하나 더 늘릴 뿐이에요.

앱 코드로만 패널을 열려면 `detailTaskId`를 앱 상태로 들고 버튼에서 바꾸세요. 그러면 차트의 클릭은 `onDetailChange`로 알려질 뿐이고 따를지는 호스트 앱이 정해요.

`Escape`는 페이지 어디에서 눌러도 패널을 닫고 행 선택은 남겨요. 어디서든 여는 키는 없어요. `Enter`는 포커스된 행이 필요하니 직접 만든 단축키에서는 `openDetail`을 호출하세요.

`detailTaskId`를 넘기면 차트는 제어 모드가 되고 두 메서드 모두 스스로 패널을 움직이지 않아요. 요청은 `onDetailChange`로 알려요. 패널은 앱 상태가 바뀔 때 따라가요. 이 prop이 없으면 차트가 열린 작업을 직접 들고 있어서 두 메서드가 바로 동작하고 `onDetailChange`도 똑같이 발생해요.

## 작업 추가

`addTask()`는 화면이 아니라 데이터에 관한 유일한 멤버예요. 작업 목록 아래 **Add task** 버튼과 같은 초안을 만들어 `onTaskCreate`에 넘겨요. 초안은 현재 배율에 맞춘 오늘 눈금 하나예요.

```tsx
ganttRef.current?.addTask();
```

**Add task** 버튼이나 그린 범위와 마찬가지로 아무것도 쓰지 않아요. 행은 핸들러가 그 작업을 `tasks` 배열에 넣을 때 생겨요.

`onTaskCreate`가 없거나 생성이 꺼져 있으면 호출해도 아무 일도 하지 않아요. 꺼진 경우는 `allowTaskCreate={false}`이거나 `allowTaskCreate` 없이 `readOnly`인 경우예요. 그래서 `addTask()`에 연결한 버튼에도 `openDetail`에 연결한 버튼처럼 가드를 두지 마세요.

직접 만든 단축키에서도 `addTask()`를 호출하세요. 차트는 작업 생성에 키를 묶지 않아요.

초안의 내용과 생성을 끄는 방법은 [작업 생성](task-creation)을 참고하세요.

## 한계

- `addTask()`는 `onTaskCreate`에 초안 하나를 넘기고 아무것도 쓰지 않아요. 작업을 수정하거나 옮기거나 지우는 메서드는 없어요. 작업의 모든 변경은 `tasks` prop과 `onTasksChange`를 거치게 하세요.
- `getScrollElement()`는 DOM 노드를 그대로 반환하니 직접 다루세요. `scrollToRow`도 스크롤 위치 getter도 없어요.
- 어떤 메서드도 실패를 알리지 않아요. 범위 밖 날짜, 알 수 없는 id나 배율 키, 패널이 꺼진 상태에서 부른 상세 호출은 모두 아무 일도 하지 않아요. 밖에서 보면 성공과 같아요.
- `setScale`에는 짝이 되는 getter가 없어요. `onScaleChange`가 배율을 알려주고 ref로는 읽을 수 없으니 현재 배율은 앱 상태에 있거나 어디에도 없어요.

prop과 기본값은 [GanttProps](ref/props)를 참고하세요.
