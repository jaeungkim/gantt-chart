막대 위의 포인터 제스처 네 가지가 작업 데이터를 바꿔요. 이동, 왼쪽 크기 조절, 오른쪽 크기 조절,
진행률이에요. 이 페이지는 이 네 제스처와 권한 플래그, 드래그 경계, 터치, 자동 스크롤을 다뤄요.
마지막 행 아래에 범위를 그려 작업을 만드는 방법은 [작업 생성](task-creation)에서 설명해요. 작업
목록의 행을 끌어 순서를 바꾸는 방법은 [행 순서 바꾸기](reordering)에 있어요.

## 제스처

| 제스처 | 시작 방법 | 바꾸는 값 |
|---|---|---|
| 이동 | 가장자리 영역 바깥의 막대 위에서 누르기 | `startDate`와 `endDate` |
| 왼쪽 크기 조절 | 막대의 왼쪽 가장자리 영역 안에서 누르기 | `startDate` |
| 오른쪽 크기 조절 | 막대의 오른쪽 가장자리 영역 안에서 누르기 | `endDate` |
| 진행률 | 진행률 핸들 위에서 누르기 | `progress` |

네 제스처 모두 기본으로 켜져 있어요. `tasks` 배열과 `onTasksChange` 핸들러만 넘기면 바로 쓸 수
있어요.

```tsx title="src/App.tsx"
import { useState } from 'react';
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const initial: Task[] = [
  {
    id: 'design',
    name: 'Design',
    startDate: '2026-03-02T00:00:00Z',
    endDate: '2026-03-06T00:00:00Z',
    parentId: null,
    sequence: '1',
    progress: 40,
  },
  {
    id: 'build',
    name: 'Build',
    startDate: '2026-03-09T00:00:00Z',
    endDate: '2026-03-20T00:00:00Z',
    parentId: null,
    sequence: '2',
    progress: 0,
  },
];

export function App() {
  const [tasks, setTasks] = useState<Task[]>(initial);
  return <ReactGanttChart tasks={tasks} onTasksChange={setTasks} />;
}
```

확정된 제스처는 `onTasksChange`를 한 번 호출하고 배열 전체를 넘겨요. 하위 트리 전체를 옮겼을 때도
호출은 한 번이에요. 막대가 움직일 만큼 끌어야 확정되고 콜백도 호출돼요.

포인터를 누르고 있는 동안에는 배열이 바뀌지 않아요. 화면에서 움직이는 막대는 작업 데이터와 따로
두는 픽셀 오프셋이에요. 배열은 손을 뗄 때 바뀌어요. 움직이는 가장자리가 닿은 날짜는 드래그 날짜
표시로 바로 위 눈금 셀에 표시돼요. 표기 형식은 [로케일과 날짜 형식](i18n)을 참고하세요.

### 가장자리 영역

가장자리 영역은 마우스에서 8px, 터치와 펜에서 44px 너비예요. 이 페이지에서 펜은 터치와 같게
취급해요.

마우스에는 이 영역이 항상 있어요. 막대는 24px보다 좁게 렌더링되지 않고 24px이 마우스에 필요한
최소 너비거든요. 터치와 펜은 렌더링 너비가 132px 이상이어야 해요. 그보다 좁으면 막대 전체가 이동
핸들이 되고 크기 조절 영역은 생기지 않아요. 132px은 분기 배율에서 33일, 연 배율에서 132일이라
작업이 작아 보이기 훨씬 전에 터치용 크기 조절 가장자리가 사라져요.

가장자리 영역을 이동 영역보다 먼저 검사해요. 그래서 `allowMove: false`와 `allowResize: true`를
함께 설정한 작업은 가장자리에서 크기가 조절되고 가운데에서는 아무 일도 일어나지 않아요.

### 진행률 드래그

퍼센트는 렌더링된 막대 사각형 안에서 포인터가 있는 위치예요. 0에서 100 사이로 제한하고 정수로
반올림해요. 포인터 경로에 단계 크기는 없어요.

값은 포인터가 움직일 때만 읽어요. 핸들을 누른 채 움직이지 않고 떼면 값이 그대로예요.

취소될 때는 두 종류의 제스처가 다르게 동작해요. 브라우저가 도중에 취소한 진행률 드래그는 마지막
값을 확정해요. 같은 식으로 취소된 막대 이동이나 크기 조절은 원래대로 돌아가고 값을 쓰지 않아요.

### 드래그 임계값

포인터가 드래그 단계의 절반을 지나기 전까지는 아무것도 확정되지 않아요. 그 전에 손을 떼면 제스처는
기록 없이 끝나고 뒤따르는 클릭은 그대로 `onTaskClick`에 전달돼요. 막대가 한 단계 이상 움직였으면
드래그를 끝내는 클릭은 전달되지 않아요. 클릭 콜백은 [이벤트](events)를 참고하세요.

## 드래그 단계

드래그는 절대 그리드 선에 스냅되지 않아요. 차트는 포인터가 이동한 거리를 드래그 단계의 정수 배로
반올림하고 그만큼을 작업의 원래 날짜에 더해요.

09:37에 시작하는 작업은 월 배율에서 4일을 끌어도 그대로 09:37에 시작해요. 시각은 모든 드래그에서
유지돼요. 차트는 막대를 자정이나 눈금 경계에 맞추지 않아요.

단계 수를 반올림하므로 포인터가 반 단계만 움직여도 막대는 다음 단계로 넘어가요. 한 단계의 길이와 한
단계에 필요한 포인터 이동 거리는 배율마다 달라요. [타임라인](timeline)을 참고하세요.

배율은 제스처가 시작될 때 고정돼요. 드래그 도중에 배율을 바꿔도 진행 중인 제스처의 단위는 바뀌지
않아요.

크기 조절은 항상 최소 한 드래그 단계의 너비를 남겨요. 미리보기만이 아니라 단계 수 자체를 제한하므로
종료일이 시작일보다 앞서는 크기 조절은 확정되지 않아요. 이미 한 단계보다 좁은 막대에서는 같은 제한이
반대로 작용해서 막대를 넓혀요.

근무일 달력을 설정하면 끌고 있는 가장자리가 다음 근무일로 한 번 더 스냅돼요. 이동은 양쪽 끝을 함께
스냅해서 막대 길이를 유지해요. [근무일 달력](working-calendar)을 참고하세요.

## 권한

아래 차트는 읽기 전용이에요. 어떤 막대도 드래그에 반응하지 않고 그립과 핸들도 숨겨져 있어요.

<GanttDemo preset="readOnly" />

이동, 크기 조절, 진행률과 의존성 링크 플래그 두 개는 작업마다 네 단계를 거쳐 결정돼요.
`allowReorder`는 기본값이 `false`인 더 짧은 우선순위를 따르므로 플래그를 명시해야만 켜져요.
`allowTaskCreate`는 차트 전체에만 적용되고 작업별 단계가 없어요. 전체 우선순위는
[GanttInteractionConfig](ref/interaction-config)를 참고하세요.

이 순서에서 두 가지 결과가 나와요. 작업의 `readOnly: true`는 차트에서 허용한 `allowMove` prop보다
우선해요. 작업 자신의 `allowMove: true`는 작업과 차트의 `readOnly` 설정 둘 다보다 우선해요.

`minDate`와 `maxDate`는 더 짧은 자체 우선순위를 따라요. 작업에 값이 있으면 그 값을 쓰고 없으면 차트의
값을 써요. 양쪽 끝은 따로 결정되므로 하한은 작업에서, 상한은 차트에서 가져올 수도 있어요.

권한이 없는 제스처는 아예 시작되지 않아요. 누르는 동작이 아무 일도 하지 않고 그 제스처의 그립과 핸들도
숨겨져요. 크기를 조절할 수 없는 막대는 크기 조절 그립을 숨기고 진행률이 고정된 막대는 핸들을 숨겨요.
진행률이 채워진 부분은 읽기 전용 표시로 계속 보여요. 여기 나온 prop의 시그니처와 기본값은
[GanttProps](ref/props)를 참고하세요.

### 요약 행

요약 행은 어느 단계에서 무엇을 설정하든 크기를 조절할 수 없고 진행률도 끌 수 없어요. 규칙과 그
이유는 [GanttInteractionConfig](ref/interaction-config)를 참고하세요.

요약 행 이동은 허용되고 하위 트리 전체가 함께 움직여요. 작업을 두 개 이상 한꺼번에 바꾸는 제스처는
이것뿐이에요.

요약 행은 `hierarchy`가 켜져 있을 때만 있으므로 계층이 없는 차트에는 이 규칙이 적용되지 않아요.
[작업 목록과 계층](task-list)을 참고하세요. 요약 행에 `readOnly`를 설정하면 이동까지 포함해 완전히
잠겨요.

### 작업별 재정의

차트의 `readOnly`는 가장 낮은 단계라서 작업 하나가 편집을 다시 켤 수 있어요.

```tsx title="src/ReviewBoard.tsx"
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  {
    id: 'plan',
    name: 'Plan',
    startDate: '2026-03-02T00:00:00Z',
    endDate: '2026-03-06T00:00:00Z',
    parentId: null,
    sequence: '1',
  },
  {
    id: 'review',
    name: 'Review',
    startDate: '2026-03-09T00:00:00Z',
    endDate: '2026-03-13T00:00:00Z',
    parentId: null,
    sequence: '2',
    // 작업 자신의 플래그 - 아래 차트의 readOnly를 이겨요
    allowMove: true,
    allowResize: true,
  },
];

export function ReviewBoard({ onChange }: { onChange: (tasks: Task[]) => void }) {
  return <ReactGanttChart tasks={tasks} readOnly onTasksChange={onChange} />;
}
```

같은 형태로 더 좁은 경우도 만들 수 있어요. `readOnly: true`와 `allowProgressChange: true`를 함께
설정한 작업은 이동과 크기 조절은 안 되지만 진행률 핸들은 끌 수 있어요.

## 드래그 경계

`minDate`와 `maxDate`는 막대가 움직일 수 있는 범위를 정해요. 둘 다 UTC ISO 문자열을 받고 시간대가
없는 문자열은 UTC로 읽어요. `minDate="2026-03-01"`은 로컬 자정이 아니라 UTC 자정이에요.

경계에 닿았을 때의 동작은 제스처마다 달라요.

- 왼쪽 크기 조절은 시작일을 범위 안으로 제한하고 종료일보다 최소 한 드래그 단계 앞에 두어요.
- 오른쪽 크기 조절은 종료일을 범위 안으로 제한하고 시작일보다 최소 한 드래그 단계 뒤에 두어요.
- 이동은 양쪽 끝을 함께 옮기고 막대 길이를 유지해요. 막대가 범위보다 길면 `minDate`가 우선하고
  막대는 `maxDate` 밖으로 넘어가요.

픽셀 오프셋을 매 프레임 제한된 날짜에서 다시 계산하므로 막대는 경계를 넘었다가 돌아오지 않고 경계에서
멈춰요. `onTasksChange`에 넘어가는 날짜는 경계값 그 자체예요.

요약 행을 이동하면 하위 트리 전체에 같은 이동량이 적용되고 움직이는 작업 중 가장 좁은 경계가
우선해요. 그래서 자식의 `maxDate`가 부모의 드래그를 멈춰요. 이동량은 요청한 방향을 넘어서지 않으므로
이미 범위 밖에 있는 작업은 더 나가지도 않고 안으로 끌려 들어오지도 않아요.

한 단계 최소 너비는 경계 다음에 적용되므로 범위를 이미 지나친 막대도 접히지 않고 유효한 막대로
남아요.

근무일 스냅은 경계 제한보다 먼저 실행되므로 경계에 걸린 막대가 비근무일에 놓일 수 있어요.

경계는 막대 이동과 크기 조절에만 적용돼요. 진행률 드래그와 작업 그리기 제스처는 경계를 읽지 않아요.

## 터치

마우스로 누르면 제스처가 바로 시작돼요. 터치와 펜은 막대 위에서 400ms 동안 누르고 있어야 드래그가
시작돼요.

기다리는 동안 손가락은 10px까지 움직여도 돼요. 움직인 거리는 처음 닿은 지점을 기준으로 가로와 세로
거리를 더해서 재요. 그래서 가로 6px에 세로 6px이면 화면에서는 8.5px이지만 12px로 계산되어 누름이
취소돼요.

드래그가 시작되기 전까지 막대는 페이지의 다른 부분처럼 타임라인과 함께 스크롤돼요. 그래서 빽빽한
차트를 쓸어 넘기면 드래그가 아니라 스크롤이 돼요. 드래그가 시작되면 제스처가 끝날 때까지 터치
스크롤이 막혀요.

드래그는 손가락이 처음 닿은 자리가 아니라 기다린 뒤에 있는 자리에서 시작해요. 대기 중인 드래그를
취소하는 경우는 네 가지예요.

| 원인 | 보통의 경우 |
|---|---|
| 10px를 넘는 움직임 | 누름이 아니라 쓸어 넘기기 |
| 400ms 전에 손 떼기 | 탭 |
| 브라우저의 포인터 취소 | 시스템 제스처가 가로챔 |
| 행 언마운트 | 손가락 아래에서 행이 화면 밖으로 스크롤됨 |

막대는 주 포인터의 왼쪽 버튼에만 반응해요. 두 번째 손가락과 오른쪽 클릭은 대기 상태에 들어가기 전에
무시되므로 제스처를 시작하지도 대기 중인 제스처를 취소하지도 않아요. 진행률 핸들에는 이 보호가
없어요.

호버가 없는 기기에서는 핸들이 10px 점으로 항상 보이고 터치 영역은 44px이에요.

## 자동 스크롤

`autoScrollOnDrag`의 기본값은 `true`예요. `false`를 명시할 때만 꺼져요.

막대 이동이나 크기 조절 중에 포인터가 타임라인 뷰포트의 왼쪽이나 오른쪽 가장자리에서 48px 안으로
들어오면 자동 스크롤이 시작돼요. 왼쪽 가장자리는 작업 목록 패널을 지난 타임라인 자체의 가장자리라서
48px은 창이 아니라 패널이 끝나는 지점부터 재요. 포인터가 패널 위로 넘어가면 가장자리를 지난 것이므로
최대 속도로 왼쪽으로 스크롤해요.

속도는 영역 안쪽 경계에서 0으로 시작해 가장자리에서 프레임당 22px까지 선형으로 올라가고 거기서
멈춰요. 타임라인이 좁으면 영역이 뷰포트 너비의 절반으로 줄어서 두 영역이 겹치지 않아요.

스크롤되는 프레임마다 마지막 포인터 위치에서 이동을 다시 적용해요. 포인터를 가장자리에 가만히 두어도
드래그는 계속 진행돼요.

제스처가 확정되지 않고 끝나면 자동 스크롤을 되돌리고 뷰포트를 시작 위치로 부드럽게 스크롤해요. 취소된
드래그와 한 단계도 움직이지 않은 드롭이 그 경우예요. 확정된 드롭은 뷰포트를 스크롤된 자리에 그대로
둬요.

자동 스크롤은 막대 이동과 크기 조절에서 동작해요. 진행률 드래그와 작업 그리기는 가장자리에서도
스크롤하지 않아요.

## 상세 패널에서 편집하기

상세 패널의 기본 필드에는 끌어야 할 거리가 아니라 이미 아는 날짜를 직접 입력할 수 있어요. 확정된
필드도 제스처와 똑같이 `onTasksChange`를 한 번만 호출하고 같은 권한 단계를 거쳐요. 입력한 날짜는
크기 조절로 취급되므로 요약 행의 날짜는 글자로만 표시돼요. 어떤 필드에 입력할 수 있는지와 잘못된 값이
어떻게 되는지는 [상세 패널](detail-panel)을 참고하세요.

## 한계

포인터 편집은 기존 작업의 날짜와 진행률을 바꿔요. 나머지는 다른 페이지에 있거나 호스트 앱이 직접 해야
해요.

- 세로 드래그는 막대 제스처가 아니에요. 막대는 자기 행에 머물고 작업 목록의 행 그립이 행을 옮겨요.
  [행 순서 바꾸기](reordering) 참고
- 다중 선택 드래그는 없어요. 한 번에 막대 하나만 잡을 수 있고 요약 행 이동만 작업 여러 개를
  움직여요.
- 자정이나 눈금에 스냅되지 않아요. 드래그는 상대적인 단계 이동이라 원래 시각이 유지돼요. 근무일
  스냅도 하루 단위로만 옮기고 시각은 건드리지 않아요.
- 저장은 호스트 앱의 몫이에요. `onTasksChange`가 넘긴 배열을 `tasks` prop으로 다시 넘기세요. 차트는
  아무것도 저장하지 않고 어디에도 보내지 않아요.
- 검증도 호스트 앱의 몫이에요. 차트는 자기 경계와 최소 막대 길이만 지켜요. 업무 규칙은
  `onTasksChange` 핸들러에 두세요.
- 의존성 화살표 그리기는 자체 권한 플래그를 가진 별개의 제스처예요. [의존성](dependencies) 참고
- 드래그 한 단계보다 짧은 막대는 가장자리를 잡으면 넓어져요. 축소 제한에 남은 여유가 없어서 첫 포인터
  움직임이 잡은 방향으로 한 단계를 더하고 이동 거리 없이 그대로 확정돼요. 렌더링이 막대를 24px
  이상으로 유지하고 24px이면 가장자리를 잡을 수 있으므로 마우스로는 이런 막대도 모두 잡을 수 있어요.
  터치는 가장자리가 생기려면 렌더링 너비 132px이 필요해요. 어느 배율에서든 여러 드래그 단계라서 이런
  일이 생기지 않아요.
- 진행률 핸들은 막대보다 보호가 약해요. 주 포인터와 왼쪽 버튼을 검사하지 않아서 오른쪽 버튼으로
  눌러도 시작돼요. 포인터 id로 거르지도 않아서 두 번째 손가락의 움직임이 진행 중인 제스처의 퍼센트를
  덮어써요.

이동, 크기 조절, 진행률은 키보드로도 할 수 있고 같은 권한 검사와 같은 드래그 경계를 따라요. 키
매핑은 [키보드와 스크린 리더](accessibility)를 참고하세요. 의존성 화살표 그리기는 키보드로 할 수
없어요.
