One handler on the `role="treegrid"` element reads every key press inside the chart. It handles
fourteen keys, ten of which write task data, and lets every other key bubble out. This page covers
the key map, the capability checks behind the editing keys, the ARIA tree, the announcements, focus
and the gaps in keyboard parity.

## Key map

The handler runs on the treegrid element only. Every key it handles is `preventDefault`ed before
any work happens, so `Alt+ArrowLeft` never navigates the browser back.

| Key | Modifiers | What happens |
|---|---|---|
| `ArrowDown` | no `Ctrl`/`Cmd`, no `Alt` | Focus the same column one row down. Stops at the last row. |
| `ArrowUp` | no `Ctrl`/`Cmd`, no `Alt` | Focus the same column one row up. Stops at row 0. |
| `ArrowRight` | no `Alt`, `Shift`, `Ctrl`/`Cmd` | On column 0 of a collapsed expandable row, expand it. Otherwise focus the next cell, clamped to the row's last cell. |
| `ArrowLeft` | no `Alt`, `Shift`, `Ctrl`/`Cmd` | On column 0 of an expanded expandable row, collapse it. Otherwise focus the previous cell, clamped to column 0. |
| `ArrowLeft` / `ArrowRight` | `Alt` | Move the focused task one step earlier or later. Both dates shift. |
| `ArrowLeft` / `ArrowRight` | `Shift` | Move the end date one step. Resizes from the right edge. |
| `ArrowLeft` / `ArrowRight` | `Alt`+`Shift` | Move the start date one step. Resizes from the left edge. |
| `ArrowUp` / `ArrowDown` | `Alt` | Move the focused row one place up or down among its siblings. Stops at either end of the sibling list. |
| `ArrowRight` / `ArrowLeft` | `Ctrl` or `Cmd` | Indent the focused row under its previous sibling, or outdent it to its parent's level. |
| `ArrowUp` / `ArrowDown` | `Ctrl` or `Cmd` | Step the timeline scale one place finer or coarser. Clamped at both ends. |
| `Home` | no `Ctrl`/`Cmd` | First cell of the current row. |
| `Home` | `Ctrl` or `Cmd` | First cell of the first row. |
| `End` | no `Ctrl`/`Cmd` | Last cell of the current row. |
| `End` | `Ctrl` or `Cmd` | Last cell of the last row. |
| `Enter` / `Space` | any | An expandable row toggles. Any other row announces its task's label without the progress, and opens the detail panel on that task when the panel is on. |
| `Delete` / `Backspace` | any | Delete the focused row's task and its whole subtree. |
| `+` / `=` | any | Progress up 5 points. |
| `-` / `_` | any | Progress down 5 points. |
| everything else | any | Passed to the browser. `Tab`, `PageUp`, `PageDown`, `F2` and every letter are not handled here. `Escape` is not either. While the detail panel is open a document listener closes it, except inside one of the panel's own inputs, where `Escape` reverts that field's draft and leaves the panel open. |

Arrow navigation clamps and never wraps. `ArrowUp` and `ArrowDown` keep the column they started
with, clamped against the row they left. Of the keys that jump to another row, only `Ctrl`+`End`
reads its column from the row it lands on.

### Modifier precedence

The handler tests `Alt` and `Shift` on a horizontal arrow before it reads that arrow as navigation,
so `Shift+ArrowRight` is a resize. There is no range selection. `Ctrl` and `Cmd` on a horizontal
arrow indent or outdent the row, so `Ctrl+ArrowRight` is not cell navigation. On the vertical
arrows `Ctrl` and `Cmd` step the scale, and `Alt` moves the row.

### Step size

One step is the current scale's drag step, read when the key is pressed. A pointer drag uses the
same step and the same snapping rules. The values per scale are in the scale table in
[The timeline](timeline).

The step is added in calendar units, so a press across a daylight saving boundary keeps the task's
time of day.

Zooming changes what every editing key does. One `Alt+ArrowRight` is one hour on the `day` scale
and 28 days on the `year` scale. A zoom announces the new scale. The new step is not announced.

### Scale stepping

`Ctrl`/`Cmd` + `ArrowUp` moves one scale finer and `Ctrl`/`Cmd` + `ArrowDown` one scale coarser,
in the fixed order `day`, `week`, `month`, `quarter`, `year`. The date at the centre of the timeline
area stays at the centre, so the view does not jump.

The new scale is announced in the live region as `week scale`, and `onScaleChange` fires with the
same key. The binding does not depend on `zoomOnWheel`. The wheel gesture is off by default and the
key binding is always on.

The binding is part of the treegrid handler, so it needs focus inside the chart and at least one
row. At either end of the scale order the key is `preventDefault`ed and nothing happens.

### Row moves

`Alt` + a vertical arrow moves the focused row one place among its siblings. `Ctrl`/`Cmd` +
`ArrowRight` makes it the previous sibling's last child. `Ctrl`/`Cmd` + `ArrowLeft` makes it the
next sibling of its own parent.

None of the four keys does anything unless `allowReorder` is on. Unlike the other editing gestures,
reordering is off by default. See [Reordering rows](reordering). Indent and outdent also need
`hierarchy`. Without it there is no parent link to rewrite, and the keys do nothing.

`Ctrl`/`Cmd` + `ArrowLeft` moves up one level per press. The row is placed directly after the
parent it left, so a row three levels deep takes three presses to reach the root. A drag reaches
the root in one drop, on the top or bottom region of any row at the root, as
[Reordering rows](reordering) describes.

A committed move is announced in the live region. The rows the chart does not move are listed in
[Reordering rows](reordering).

## Capability checks

Every editing key resolves the same capability per task that a drag resolves. The four-level
precedence from `task.allowX` down to `config.readOnly` is explained in [Editing tasks](editing).

| Keys | Capability consulted |
|---|---|
| `Alt`+`ArrowLeft` / `ArrowRight` | `canMove` |
| `Shift` and `Alt`+`Shift` arrows | `canResize` |
| `+` `=` `-` `_` | `canChangeProgress` |
| `Delete` / `Backspace` | `canMove` |
| `Alt` + a vertical arrow, `Ctrl`/`Cmd` + a horizontal arrow | `canReorder` |
| arrows, `Home`, `End`, `Enter`, `Space`, the scale steps | none. Navigation, expand and collapse, and zoom work on a fully read-only chart. |

There is no delete capability. A task that may move may be deleted.

`canReorder` does not run that precedence. It is `false` until a task or the chart sets
`allowReorder`, so the reorder keys do nothing on a chart that never set `allowReorder`, read-only
or not. See [`GanttInteractionConfig`](ref/interaction-config).

A summary row rejects resizes and progress steps. That rule overrides every flag and is described
in [Editing tasks](editing). A task with no `progress` field is also rejected, because the keyboard
steps an existing number.

The example below puts one locked task and one editable task on a `readOnly` chart.

```tsx title="src/App.tsx"
import { useState } from 'react';
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const initial: Task[] = [
  {
    id: 'frozen',
    name: 'Frozen',
    startDate: '2026-03-02T00:00:00Z',
    endDate: '2026-03-06T00:00:00Z',
    parentId: null,
    sequence: '1',
    progress: 0,
  },
  {
    id: 'editable',
    name: 'Editable',
    startDate: '2026-03-09T00:00:00Z',
    endDate: '2026-03-20T00:00:00Z',
    parentId: null,
    sequence: '2',
    progress: 40,
    allowMove: true,
    allowProgressChange: true,
    maxDate: '2026-03-31T00:00:00Z',
  },
];

export default function App() {
  const [tasks, setTasks] = useState<Task[]>(initial);

  // Alt+arrow and +/- work on 'editable' only. On 'frozen', Alt+arrow announces
  // "Frozen cannot be changed" and +/- announces "Frozen progress cannot be changed".
  // Alt+ArrowRight stops once 'editable' ends on its maxDate, and announces
  // "Editable cannot be changed" from then on.
  return <ReactGanttChart tasks={tasks} readOnly onTasksChange={setTasks} />;
}
```

Props and defaults: [GanttProps](ref/props).

## Scale picker

The chart renders the timeline, and the task list when `showTaskList` is on. It renders no scale
picker.

Without a pointer, the scale changes only through `Ctrl`/`Cmd` + the vertical arrows. A pointer
user has no control until you build one.

Build it as a native `<select>`. Call `setScale` from its `onChange` and set its value from
`onScaleChange`.

```tsx title="src/ScalePicker.tsx"
import { useRef, useState } from 'react';
import {
  ReactGanttChart,
  type GanttHandle,
  type GanttScaleKey,
  type Task,
} from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const SCALES: GanttScaleKey[] = ['day', 'week', 'month', 'quarter', 'year'];

export default function ScalePicker({ tasks }: { tasks: Task[] }) {
  const chart = useRef<GanttHandle>(null);
  const [scale, setScale] = useState<GanttScaleKey>('month');

  return (
    <>
      <select
        aria-label="Timeline scale"
        value={scale}
        onChange={(e) => chart.current?.setScale(e.target.value as GanttScaleKey)}
      >
        {SCALES.map((s) => (
          <option key={s} value={s}>{s}</option>
        ))}
      </select>

      <ReactGanttChart
        ref={chart}
        tasks={tasks}
        defaultScale="month"
        onScaleChange={setScale}
      />
    </>
  );
}
```

`<select>` brings keyboard, screen reader and touch behaviour from the platform. You write the
option text, so the five scale keys can be translated instead of being spoken raw. Every header
cell, tick and tooltip in the chart already goes through `Intl`.

Your app is responsible for the accessibility of any other control it builds. The chart exposes
`setScale`, described in [Imperative API](imperative-api), and `onScaleChange`, and renders no
control of its own.

## ARIA tree

The task list and the timeline form one treegrid. Each row is in the task list and references its
bars in the timeline through `aria-owns`.

```text title="Rendered DOM"
section.gantt-container
├─ div.gantt-sr-only                  role=status, aria-live=polite
└─ div.gantt-layout
   ├─ div.gantt-main
   │  ├─ div.gantt-scroll-container
   │  │  └─ div.gantt-body            role=treegrid, aria-label="Gantt chart", aria-rowcount
   │  │     ├─ div.gantt-grid         role=presentation
   │  │     │  ├─ div.gantt-grid-header  role=row, aria-rowindex=1
   │  │     │  │  ├─ div             role=columnheader, "Task name", visually hidden
   │  │     │  │  └─ span             role=columnheader, "Timeline", visually hidden
   │  │     │  └─ div.gantt-grid-body role=rowgroup
   │  │     │     └─ div.gantt-grid-row  role=row, aria-level, aria-posinset, aria-setsize,
   │  │     │        │                aria-rowindex, aria-expanded?, aria-owns
   │  │     │        └─ div          role=gridcell, tabIndex 0 or -1
   │  │     │           └─ button     grip and expander, tabIndex=-1, aria-hidden=true
   │  │     └─ div.gantt-timeline     role=presentation
   │  │        ├─ div.gantt-header-wrapper  the date axis; the drag readout in it is aria-hidden
   │  │        └─ div.gantt-content   role=presentation
   │  │           ├─ div.gantt-rows   role=presentation
   │  │           │  └─ div.gantt-task-row  aria-hidden=true, striping only
   │  │           └─ div#task-<id>    role=gridcell, tabIndex 0 or -1, aria-label
   │  ├─ div.gantt-grid-splitter      role=separator, aria-orientation=vertical, aria-valuenow, tabIndex=0
   │  └─ div.gantt-grid-footer        button "Add task", only when the pane is visible and creation is on
   └─ aside.gantt-detail              role=complementary, aria-label="Task details", only while open
```

`aria-level` starts at 1. `aria-posinset` and `aria-setsize` count only the rows no collapsed
parent hides, so collapsing a parent renumbers its siblings. `aria-rowcount` is that row count plus
one for the header row, not the total in your data.

`aria-expanded` is omitted, not set to `false`, on a row that cannot expand. A summary row counts as
expandable only when `hierarchy` is on. With `hierarchy={false}` the attribute disappears and
`Enter` announces the row instead of toggling it. See [Task list and hierarchy](task-list).

`aria-owns` lists one id per task on the row, so a lane row owns several. Every row carries at least
one task, so the attribute is never omitted. See [Lanes](lanes).

The non-working shading is `aria-hidden`. A holiday's name is hidden by `opacity` rather than
`display`, so it is announced whether or not it is visible. See [The timeline](timeline).

### Hidden task list pane

`showTaskList` defaults to `false`, so the pane is absent unless you set it. Nothing inside the
chart toggles the pane, so the three changes below happen only when you change the prop.

- There is no column header row, so `aria-rowcount` loses its `+1` and the first data row is
  `aria-rowindex={1}`.
- There is no `role="rowgroup"`. The rows sit directly inside `role="presentation"` wrappers.
- Cell column 0 is the first bar rather than the first task list column.

### Omitted attributes

The chart never sets `aria-colindex`, `aria-colcount`, `aria-selected`, `aria-current`,
`aria-multiselectable`, `aria-describedby` or `aria-labelledby`, and no element carries
`role="treeitem"`. A cell never reports its column position, and selection is not exposed to
assistive technology.

The bar's link handles are `role="button"` with `tabIndex={-1}`. Its progress handle is
`role="slider"` with `aria-valuemin`, `aria-valuemax` and `aria-valuenow`, also with
`tabIndex={-1}`, so the keyboard never reaches it.

## Labels and announcements

A bar's `aria-label` has four parts in a fixed order: the name, `summary`, the date range and the
progress. The `summary` part appears only on a summary row, and the progress part only when the
task has a progress.

The dates use the current scale's `tooltip` formatter, the same one the hover card, the detail
panel and the drag announcements use. The label changes with the scale, and overriding
`formats[scale].tooltip` changes what is spoken. See [Locale and date formats](i18n).

| Task | Scale | Emitted `aria-label` |
|---|---|---|
| `Design phase`, 40% | `month` | `Design phase, Mar 3, 2025 to Mar 14, 2025, 40% complete` |
| `Design phase`, 40% | `day` | `Design phase, Mar 3, 2025 00:00 UTC to Mar 14, 2025 00:00 UTC, 40% complete` |
| `Phase 1`, `isSummary`, Mar to May | `quarter` | `Phase 1, summary, Mar 2025 to May 2025` |

A keyboard edit is announced through one `role="status" aria-live="polite"` region, the container's
first child, ahead of the chart body.

| Key | Announcement |
|---|---|
| `Alt`/`Shift` arrow, accepted | `Design phase, Mar 3, 2025 to Mar 15, 2025` |
| `Alt`/`Shift` arrow, rejected | `Design phase cannot be changed` |
| `+` or `-`, accepted | `Design phase, 45% complete` |
| `+` or `-`, rejected | `Design phase progress cannot be changed` |
| `Delete`, accepted | `Design phase deleted` |
| `Delete`, rejected | `Design phase cannot be deleted` |
| a reorder key, accepted | `Design phase moved to 2 of 5 under Phase 1`, or `at the top level` when it has no parent |
| a reorder key, rejected | nothing |
| `Enter` on a non-expandable row | the full label, with the progress omitted |
| `Enter` on an expandable row | nothing |
| `Ctrl`/`Cmd` + a vertical arrow | `week scale`, the key of the scale it landed on |
| the same key at either end of the scale order | nothing |

A pointer drag is announced too, through a second `role="status"` line the bar renders for the
length of the gesture. For a move or a resize it is visually hidden. The visible readout, the dates
written into the tick cells of the date axis, is `aria-hidden`. The line reads `Start: Mar 3, 2025`,
`End: Mar 15, 2025`, or both dates for a move of the whole bar. A progress drag's percentage readout
is that same status line, visible.

`showTooltip={false}` removes the hover card and these drag status lines together, so a chart with
tooltips off announces nothing during a pointer edit. The keyboard announcements above are
unaffected.

## Focus

The treegrid has one tab stop, the cell whose row and column match the chart's focus state. Every
other cell is `tabIndex={-1}`. The rendered component adds up to eight tab stops to the page, five
of them in the open detail panel. A custom `renderDetail` body replaces those five with its own
elements.

| # | Element | Present when |
|---|---|---|
| 1 | the roving treegrid cell | a cell matching the focus state is rendered |
| 2 | the task list splitter | the task list pane is visible |
| 3 | the **Add task** button | the pane is visible and task creation is on |
| 4 | the panel's name input | the name is editable |
| 5 | the panel's **Start** input | the dates are editable |
| 6 | the panel's **End** input | the dates are editable |
| 7 | the panel's **Progress** input | the task has a `progress` and it is editable |
| 8 | the panel's close button | always |

Rows 4 to 8 need the panel open with the built-in body. Each field takes input only when the task's
own flags leave it editable, and [Detail panel](detail-panel) maps the flags to the fields. A field
that is not editable renders as text and is not a tab stop.

A row's cells are numbered left to right, the task list's name cell first, followed by one cell per
bar on the row.

Clicking a cell syncs the focus state to it. A keyboard move does the opposite. It sets the state
and looks for the matching element three times, immediately and on the next two animation frames,
scrolling the row and the task into view between attempts. If no element matches on the third try,
DOM focus stays where it was.

Nothing is focused on mount. The first `Tab` that reaches the treegrid lands on cell `0:0`. If
`tasks` is empty there is no cell to land on.

### Detail panel tab stops

The panel is outside the treegrid, so it does not affect the roving tab stop. Its focusable
elements come after the chart in DOM order. It is `role="complementary"`, not a dialog. There is no
focus trap, and nothing has to be closed before the chart handles keys again. See
[Detail panel](detail-panel).

Closing the panel returns focus to the element that held it when the panel opened, the cell that
received `Enter` or the bar that was clicked. It does so only while focus is in the panel, on
`<body>` or nowhere. A panel closed while you are typing elsewhere on the page does not move focus.
Without the return, `Escape` would leave focus on `<body>` and keyboard navigation of the chart
would end. Moving the panel from one task to another moves no focus, and neither does opening it.

### Focus and selection

Arrowing onto a bar does not select it. `onTaskSelect` does not fire, `selectedTaskId` does not
change, and no `aria-selected` is written. Selection needs a pointer. See [Events](events).

## Keys outside the treegrid

| Keys | Where the listener is | What it does |
|---|---|---|
| `ArrowLeft` / `ArrowRight`, `Enter` | the splitter | Resize the task list, or fit it to the widest visible row. The widths and the step are in [Task list and hierarchy](task-list). |
| `Delete` / `Backspace`, `Escape` | `document`, while a dependency arrow is selected | Delete or deselect the arrow, from anywhere on the page. Skipped inside an `input`, `textarea`, `select` or contenteditable. |
| `Escape` | `document`, while the detail panel is open | Close the detail panel, from anywhere on the page. The row stays selected. Inside one of the panel's own inputs the key stops there. The field reverts to its stored value and the panel stays open. |

## Known gaps

Some pointer gestures have no keyboard equivalent. Drawing a dependency arrow is unreachable. The
link handles are `tabIndex={-1}`. Selecting an arrow, and therefore deleting one, needs a click.
See [Dependencies](dependencies).

Drawing a new task below the last row needs a pointer too, but `onTaskCreate` has a second path.
The **Add task** button under the task list calls `onTaskCreate` with the same draft, and it is an
ordinary tab stop. A chart with the pane hidden has neither, so creation needs a pointer there. No
key is bound to it. A shortcut of your own calls `addTask()` on the ref. See
[Creating tasks](task-creation).

> [!WARNING]
> `Delete` removes the whole subtree, whether or not `hierarchy` is on, and it fires from any cell
> in the row, the name cell included, with no confirmation step. The chart keeps no snapshot to
> restore from.

Not every rejected key is announced. A rejection from a capability check is announced. A rejected
row move is not. Each of these cases `preventDefault`s the key and returns without an announcement:

- `Alt` + a vertical arrow at either end of the sibling list
- an indent with no previous sibling
- an outdent from the root
- a chart that never set `allowReorder`
- an `onTaskMove` that returns `false`

A cell reference can point at nothing. The focus column is not clamped when the row changes.
Moving down from a row with two bars onto a row with one keeps a column index that row does not
have. No element matches, and the chart loses its only tab stop until a cell is clicked. `Home` and
`End` recover it while focus is inside the treegrid. The same failure appears when a bar is
scrolled out horizontally. Bars outside the viewport are not rendered, but the row's `aria-owns`
lists their ids anyway.

An out-of-range column edits the wrong bar. Resolving a task from a cell falls back to the row's
first task. On a row with several lanes a stale column acts on lane 0 instead of doing nothing. The
same fallback is why `Delete` on a task list cell deletes that row's task.

A toggle is not announced. `Enter` on an expandable row changes `aria-expanded` on the row while
focus is on a cell, and writes nothing to the live region.

The hover tooltip is dismissible under SC 1.4.13. `Escape` closes it without moving the pointer.
It is not hoverable. The card is `pointer-events: none`, so moving toward it leaves the bar and
closes it. It opens after a 450ms dwell. Nothing in the card is reachable. It holds no links or
controls, and the same dates and progress are already in the bar's `aria-label`.

Touch shows no hover tooltip. The card opens on `pointerenter` only when `pointerType` is
`"mouse"`. A tap fires a compatibility `mouseenter` and never a `mouseleave`, so without that check
the card would open and stay open under the finger. Drag readouts follow the gesture rather than
hover and are unaffected.

## Limitations

- Key remapping and opt-out are not available. Nothing in the keyboard layer is exported from the
  package. There is no prop to change a binding, to disable keyboard editing separately from
  pointer editing, or to render something other than a treegrid.
- `PageUp`, `PageDown`, type-ahead, an `F2` edit mode, multi-select and `Escape` inside the
  treegrid are not handled.
- Focus trap and skip link are absent. `Tab` leaves the treegrid on the first press, and a chart
  with many rows offers no way to jump past it other than the browser's own.
- High contrast is not supported. The stylesheet carries no `forced-colors` or `prefers-contrast`
  block. `prefers-reduced-motion` is honoured. Inside the chart, transitions and animations are cut
  to 0.01ms and `scroll-behavior` becomes `auto`.
- Confirmation is up to your app. `Delete` removes a subtree immediately. If that needs a dialog,
  keep your own snapshot in `onTasksChange` and pass it back as `tasks` to restore the rows.
- Announcement wording is fixed. The strings above are hardcoded in English, the drag status lines
  included. Only the dates inside them follow the `locale` and `formats` props.
- Screen reader testing is up to your app. Nothing here is verified against a real screen reader
  in this repository. The coverage is unit tests over the key resolver and the ARIA prop builders.
