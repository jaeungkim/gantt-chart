드래그는 포인터를 놓은 자리에서 끝나요. 막대를 하루만 더 끌어다 놓으면 작업이 토요일에 시작해요.
아무도 일하지 않는 날의 시작 날짜가, 손을 떼는 순간 그대로 데이터에 적혀요. `workingCalendar`는 그
착지점을 다음 근무일로 밀어 줘요.

## 근무일 달력

`workingCalendar`는 불리언이고 기본값은 `false`예요. 켜면 차트가 비근무일을 건너뛰는 달력을 만들어서
막대 드래그에 넘겨요. 끄면 드래그는 모든 날을 세는 달력을 받아요. 평범한 달력 산술이에요.

```tsx title="src/WorkWeek.tsx"
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function WorkWeek({ tasks, setTasks }: {
  tasks: Task[];
  setTasks: (next: Task[]) => void;
}) {
  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
      workingCalendar
      holidays={['2026-09-21']}
    />
  );
}
```

차트는 달력을 하나만 만들고, 같은 객체를 음영과 스냅에 함께 넘겨요. `workingWeekdays`에 그 요일이
없거나 `holidays`가 그 날의 UTC `YYYY-MM-DD`를 덮으면 비근무일이에요. 그래서 음영과 건너뛰는 날이
어긋날 수 없어요. 두 prop과 음영 자체는 [타임라인](timeline)이 다뤄요.

휴일의 `label`과 `color`는 여기서 아무 뜻도 없어요. 스냅은 하루에 근무일인지 아닌지만 물어서,
이름 붙은 휴일이든 그냥 토요일이든 드롭을 똑같이 밀어요.

차트가 받지 않는 것은 직접 만든 달력이에요. `workingWeekdays`와 `holidays`로 달력을 설명할 수는
있지만, `WorkingCalendar` 객체를 받는 곳은 패키지에 없어요. 그래서 이 두 가지로 표현할 수 없는
규칙은 — 격주 금요일 휴무나 사람마다 다른 달력 같은 것은 — 스냅에 닿을 수 없어요.
[근무일 달력 헬퍼](ref/core-calendar)의 `createWorkingCalendar`는 호스트 앱의 날짜 계산에 쓰라고 있는
함수예요.

여기 나온 prop의 시그니처와 기본값은 [GanttProps](ref/props)에 있어요.

### 드롭 스냅

스냅은 달력이 제스처에 하는 유일한 일이에요. 움직인 쪽 끝이 근무일에 내려앉고, 함께 움직이는 것은 —
요약 막대의 하위 트리 전체까지 — 같은 일수만큼 따라와요. 요약 막대는
[작업 목록과 계층](task-list)에 있어요.

| 제스처 | 스냅하는 끝 | 반대쪽 끝 |
|---|---|---|
| 이동 | 시작 | 같은 일수만큼 따라와서 폭이 유지돼요 |
| 왼쪽 크기 조절 | 시작 | 그대로 남아서 막대가 짧아져요 |
| 오른쪽 크기 조절 | 끝 | 그대로 남아서 막대가 길어져요 |

스냅은 온전한 일수로 재고 언제나 앞으로만 가요. 그래서 하루 중 시각은 그대로 남아요. 스냅하면 자기 끝을
넘어가 버리는 왼쪽 끝 크기 조절은 아예 스냅하지 않아요.

손을 떼는 순간 튀는 일은 없어요. 스냅은 드래그 중에도 적용돼요. 그래서 포인터가 눌려 있는 동안 막대와
눈금 행의 드래그 판독값이 이미 스냅된 날짜에 가 있어요.

### 무엇이 바뀌지 않나요

막대를 그리는 위치와 폭은 달력을 보지 않아요. 주말을 가로지르는 막대는 화면에서 여전히 주말을
가로질러요. 달력은 드롭이 어디에 내려앉을지만 정해요. 타임라인 눈금과 헤더 셀도 같은 이유로 그대로예요.
음영도 마찬가지고, 음영에는 자기 prop이 따로 있어요.

드래그 자체는 여전히 평범한 달력 시간으로 움직여요. 포인터를 날짜로 바꾸는 계산은 모든 날을 세요.
달력은 그 위에 앞으로 미는 스냅만 얹어요. 그래서 이동은 막대의 근무일 폭이 아니라 달력일 폭을 지켜요.

## 예제로 따라가기

작업 하나, 시각은 전부 UTC예요. `workingCalendar`는 켜져 있고 휴일은 없어요.

```ts
import type { Task } from '@jaeungkim/gantt-chart';

export const tasks: Task[] = [
  {
    id: 'audit', name: 'Content audit', parentId: null, sequence: '1',
    startDate: '2026-09-01T09:00:00Z', endDate: '2026-09-04T17:00:00Z',
  },
];
```

`09-01`은 화요일이고 `09-04`는 금요일이에요. 그래서 막대는 한 근무 주 안에 들어 있어요. 드래그 한
단계가 온전한 하루인 월 배율에서 끌어다 놓아 볼게요:

| 제스처 | `workingCalendar` 없이 | 켰을 때 |
|---|---|---|
| 사흘 뒤로 이동 | `09-04 09:00 - 09-07 17:00` | 같아요. 금요일은 근무일이에요 |
| 나흘 뒤로 이동 | `09-05 09:00 - 09-08 17:00` | `09-07 09:00 - 09-10 17:00` |
| 오른쪽 끝을 하루 뒤로 | `09-01 09:00 - 09-05 17:00` | `09-01 09:00 - 09-07 17:00` |

나흘 이동은 토요일에 내려앉아요. 그래서 시작이 이틀 밀려 월요일로 가고, 끝도 이틀만큼 따라와요. 막대는
사흘 폭을 그대로 지켜요. 크기 조절은 끝만 토요일에서 월요일로 스냅해요. 그래서 그 막대는 포인터가
요구한 것보다 이틀 늦게 끝나요.

`holidays={['2026-09-07']}`를 더하면 나흘 이동은 하루 더 나아가서 `09-08 09:00 - 09-11 17:00`이 돼요.

## 한계

스냅은 포인터 막대 드래그에서만 실행되고 그 밖에서는 실행되지 않아요. 새 `tasks` 배열을 불러오거나,
링크를 그리거나, 마지막 행 아래에 새 작업을 그리거나, [상세 패널](detail-panel)에서 날짜 필드를
고치면 주말이든 아니든 넣은 그대로의 날짜가 남아요.

키보드 편집도 스냅하지 않아요. `Alt` + 화살표 이동과 키보드 크기 조절은 평범한 드래그 단계만큼
움직여요. 그래서 막대를 비근무일에 남겨 둘 수 있어요. 키 바인딩은
[키보드와 스크린 리더](accessibility)에 있어요.

스냅은 앞으로만 가고, 다른 규칙에 밀릴 수 있어요. `minDate` / `maxDate` 제한이 그 뒤에 실행되고
이겨요. 그래서 경계에 고정된 막대는 토요일에 앉을 수 있어요. 이 경계는 [작업 편집](editing)에서
설명해요.

근무일 달력은 차트에서 편집할 수 없어요. 직접 넘기는 데이터예요.

다음: [상세 패널](detail-panel) — 작업 하나의 필드를 보여주고 고치는 도킹된 패널이에요.
