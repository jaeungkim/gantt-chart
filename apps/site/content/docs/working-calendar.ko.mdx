드래그는 포인터를 놓은 자리에서 끝나요. 막대를 하루만 더 끌어다 놓으면 작업이 토요일에 시작해요.
아무도 일하지 않는 날의 시작 날짜가, 손을 떼는 순간 그대로 데이터에 적혀요. `workingCalendar`는 그
착지점을 다음 근무일로 밀어 줘요.

## 근무일 달력

`workingCalendar`는 불리언이고 기본값은 `false`예요. 켜면 차트가 비근무일을 건너뛰는 달력을 만들어서
막대 드래그에 넘겨요. 끄면 드래그는 모든 날을 세는 달력을 받아요. 평범한 달력 산술이에요.

```tsx
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';

export function WorkWeek({ tasks, setTasks }: {
  tasks: Task[];
  setTasks: (next: Task[]) => void;
}) {
  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
      workingCalendar
      holidays={['2026-09-21']}
    />
  );
}
```

이 달력은 타임라인에 음영을 칠하는 것과 같은 판별식으로 만들어져요. `isNonWorkingDay`를 따로 넘기지
않으면 토요일, 일요일, 그리고 `holidays`에 적힌 날짜가 비근무일이에요. 날짜는 UTC 기준
`YYYY-MM-DD`로 맞춰요. 그래서 음영과 건너뛰는 날이 어긋날 수 없어요. 음영 자체와 두 prop은
[타임라인](timeline)이 다뤄요.

`isNonWorkingDay`를 넘기면 이 판별 전체가 대체돼요. 차트는 달력에 항상 판별식을 건네요. 그래서 직접
만든 달력만 설정할 수 있는 옵션인 `workingWeekdays`는 컴포넌트로는 닿을 수 없어요. 월요일부터
금요일이 아닌 근무 주는 `isNonWorkingDay` 함수로 써야 해요. 아니면 `createWorkingCalendar`로 직접
만들면 돼요. 둘 다 [근무일 달력](ref/core-calendar)에 있어요.

### 드롭 스냅

스냅은 달력이 제스처에 하는 유일한 일이에요. 움직인 쪽 끝이 근무일에 내려앉고, 함께 움직이는 것은 같은
일수만큼 따라와요.

| 제스처 | 스냅하는 끝 | 반대쪽 끝 |
|---|---|---|
| 이동 | 시작 | 같은 일수만큼 따라와서 폭이 유지돼요 |
| 왼쪽 크기 조절 | 시작 | 그대로 남아서 막대가 짧아져요 |
| 오른쪽 크기 조절 | 끝 | 그대로 남아서 막대가 길어져요 |

스냅은 온전한 일수로 재고 언제나 앞으로만 가요. 그래서 하루 중 시각은 그대로 남아요. 스냅하면 자기 끝을
넘어가 버리는 왼쪽 끝 크기 조절은 아예 스냅하지 않아요.

### 무엇이 바뀌지 않나요

막대를 그리는 위치와 폭은 달력을 보지 않아요. 주말을 가로지르는 막대는 화면에서 여전히 주말을
가로질러요. 달력은 드롭이 어디에 내려앉을지만 정해요. 타임라인 눈금과 헤더 셀도 같은 이유로 그대로예요.
음영도 마찬가지고, 음영에는 자기 prop이 따로 있어요.

드래그 단계 자체는 여전히 달력일 기준이에요. 포인터를 날짜로 바꾸는 계산은 모든 날을 세요. 달력은 그
위에 앞으로 미는 스냅만 얹어요. 그래서 이동은 막대의 근무일 폭이 아니라 달력일 폭을 지켜요.

## 베이스라인

베이스라인은 오늘의 날짜와 비교하고 싶은 계획이에요. 작업의 두 필드가 이를 담고, 둘 다 UTC ISO
문자열이에요:

```ts
import type { Task } from '@jaeungkim/gantt-chart';

const audit: Task = {
  id: 'audit',
  name: 'Content audit',
  startDate: '2026-09-01T09:00:00Z',
  endDate: '2026-09-04T17:00:00Z',
  parentId: null,
  sequence: '2',
  baselineStart: '2026-09-01T09:00:00Z',
  baselineEnd: '2026-09-03T17:00:00Z',
};
```

베이스라인을 켜는 prop은 없어요. `baselineStart`를 가진 작업이면 다른 무엇이 켜져 있든 실제 막대
아래에 얇은 막대를 그려요. `baselineEnd`는 선택이에요. 없으면 베이스라인은 최소 막대 너비의 짧은
토막으로 줄어들어요. 실제 막대와 같은 하한이라, 마일스톤의 계획도 눈에 보여요.

베이스라인 요소는 막대가 아니라 행에 속해요. 그래서 막대를 끌면 제자리에 남은 베이스라인 위를
미끄러져 지나가요. 그게 이 기능의 핵심이에요. 타임라인 범위는 베이스라인 날짜까지 덮도록 넓어져요.
그래서 실제 막대 밖에 있는 베이스라인도 잘려 나가지 않아요.

`renderBaseline`은 기본 요소를 대체해요:

```tsx
import {
  ReactGanttChart,
  type Task,
  type TaskTransformed,
} from '@jaeungkim/gantt-chart';

export function Plan({ tasks, setTasks }: {
  tasks: Task[];
  setTasks: (next: Task[]) => void;
}) {
  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
      renderBaseline={(task: TaskTransformed) => (
        <div
          className="my-baseline"
          style={{ left: `${task.baselineLeft}px`, width: `${task.baselineWidth}px` }}
          title={`Planned: ${task.baselineStart} - ${task.baselineEnd}`}
        />
      )}
    />
  );
}
```

이 함수는 `baselineStart`를 가진 작업에만 호출돼요. 인자로는 `baselineLeft`와
`baselineWidth`가 이미 계산된 변환 작업을 받아요. 절대 위치 지정은 여전히 직접 해야 해요. 좌표 공간은
행이 제공하기 때문이에요. 기본 요소는 `aria-hidden="true"`지만 커스텀 요소는 그렇지 않아요. 필요한
라벨은 직접 붙여 주세요. 렌더러의 정확한 타입은 [Render prop 타입](ref/renderers)에 있어요.

## 예제로 따라가기

작업 하나, 시각은 전부 UTC예요. `workingCalendar`는 켜져 있고 휴일은 없어요.

```ts
import type { Task } from '@jaeungkim/gantt-chart';

export const tasks: Task[] = [
  {
    id: 'audit', name: 'Content audit', parentId: null, sequence: '1',
    startDate: '2026-09-01T09:00:00Z', endDate: '2026-09-04T17:00:00Z',
  },
];
```

`09-01`은 화요일이고 `09-04`는 금요일이에요. 그래서 막대는 한 근무 주 안에 들어 있어요. 일 배율에서
끌어다 놓아 볼게요:

| 제스처 | `workingCalendar` 없이 | 켰을 때 |
|---|---|---|
| 사흘 뒤로 이동 | `09-04 09:00 - 09-07 17:00` | 같아요. 금요일은 근무일이에요 |
| 나흘 뒤로 이동 | `09-05 09:00 - 09-08 17:00` | `09-07 09:00 - 09-10 17:00` |
| 오른쪽 끝을 하루 뒤로 | `09-01 09:00 - 09-05 17:00` | `09-01 09:00 - 09-07 17:00` |

나흘 이동은 토요일에 내려앉아요. 그래서 시작이 이틀 밀려 월요일로 가고, 끝도 이틀만큼 따라와요. 막대는
사흘 폭을 그대로 지켜요. 크기 조절은 끝만 토요일에서 월요일로 스냅해요. 그래서 그 막대는 포인터가
요구한 것보다 이틀 늦게 끝나요.

`holidays={['2026-09-07']}`를 더하면 나흘 이동은 하루 더 나아가서 `09-08 09:00 - 09-11 17:00`이 돼요.

## 한계

스냅은 드롭에서만 실행되고 그 밖에서는 실행되지 않아요. 새 `tasks` 배열을 불러오거나, 링크를 그리거나,
폼에서 날짜를 고치면 주말이든 아니든 넣은 그대로의 날짜가 남아요.

스냅은 앞으로만 가고, 다른 규칙에 밀릴 수 있어요. `minDate` / `maxDate` 제한이 그 뒤에 실행되고
이겨요. 그래서 경계에 고정된 막대는 토요일에 앉을 수 있어요. 이 경계는 [작업 편집](editing)에서
설명해요.

베이스라인은 차트 입장에서 읽기 전용이에요. 차트는 `baselineStart` / `baselineEnd`를 그릴 뿐 그 이상은
하지 않아요. 계획을 스냅샷으로 남기고, 저장하고, 언제 다시 베이스라인을 잡을지 정하는 일은 모두 호스트
앱의 몫이에요.

근무일 달력은 차트에서 편집할 수 없어요. 직접 넘기는 데이터예요.
