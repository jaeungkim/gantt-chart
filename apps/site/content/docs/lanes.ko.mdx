`lane`은 같은 문자열을 가진 작업을 한 행에 나란히 놓는 작업 필드예요. 이 페이지는 같은 레인의
작업을 묶는 규칙과 레인 행이 다른 기능에 주는 영향, 호스트 앱이 직접 해야 하는 일을 다뤄요.

## 한 행 함께 쓰기

`lane`은 작업의 필드예요. 따로 켜는 prop은 없어요.

```tsx title="src/SupportLanes.tsx"
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  { id: 'spec', name: 'Spec', lane: 'ana', parentId: null, sequence: '1',
    startDate: '2026-03-02T00:00:00Z', endDate: '2026-03-06T00:00:00Z' },
  { id: 'wires', name: 'Wireframes', lane: 'ana', parentId: null, sequence: '2',
    startDate: '2026-03-09T00:00:00Z', endDate: '2026-03-12T00:00:00Z' },
];

export function SupportLanes() {
  return <ReactGanttChart tasks={tasks} height={480} />;
}
```

`lane`이 falsy 값이면 레인이 없는 것과 같아요. `lane: ""`은 필드를 생략했을 때와 같아요. 그
작업은 행 하나를 혼자 차지해요.

차트는 `lane` 문자열을 공백과 대소문자까지 그대로 비교해요. 그래서 `"ana"`, `"Ana"`, `"ana "`가
각각 다른 레인이에요.

## 패킹 규칙

같은 레인의 작업을 시작 날짜 순서로 정렬한 뒤 앞에서부터 들어갈 수 있는 첫 행에 넣어요.

| 규칙 | 효과 |
|---|---|
| 정렬 | `sequence`가 아니라 `startDate` 기준이에요. 시작이 같으면 `sequence` 순서를 지켜요 |
| 배치 | 가장 잘 맞는 행이 아니라 마지막 막대가 이미 끝난 첫 행에 들어가요 |
| 맞닿음 | 앞 막대가 끝나는 시점에 정확히 시작하는 작업은 같은 행을 써요 |
| 겹침 | 겹치는 작업은 행을 하나 더 열어요 |
| 재사용 | 행은 비는 즉시 다시 채워져요 |

패킹은 `parentId`를 보지 않아요. 부모와 자식이 같은 `lane` 문자열을 쓰면 다른 작업과 똑같이 한
행에 묶여요. 행의 깊이는 가장 먼저 시작하는 작업을 따라가요.

묶인 행은 그 레인의 첫 작업이 있던 자리에 들어가요. 첫 작업은 `sequence`가 가장 낮은 작업이에요.
`sequence`는 모든 행의 순서를 정하는 필드예요. [작업 데이터](task-data)를 참고하세요. 뒤에 오는
작업은 자기 자리에 행을 남기지 않아요.

레인 행의 id는 그 행에 있는 작업 id를 `"+"`로 이은 문자열이에요. 행이 작업 하나를 지목하지 않기
때문에 `spec+wires` 같은 형태예요. 작업 목록에는 `tasks[0]`의 이름이 보여요. `sequence`가 가장
낮은 작업이 아니라 그 행에서 가장 먼저 시작하는 작업이에요. 이름 뒤에는 나머지 개수를 세는 `+N`
배지가 붙어요.

형식이 잘못된 `endDate`는 그 작업이 들어간 행을 쓸 수 없게 만들어요. 배치 검사가
`rowEnd <= start`인데 `NaN`과 비교하면 전부 false예요. 그래서 뒤에 오는 작업은 그 행에 들어가지
못해요. 남은 작업은 다음 빈 행으로 가고 빈 행이 없으면 새 행을 열어요.

## 다른 기능에 주는 영향

레인 행에 있는 작업은 모두 `order` 값이 같아요. `order`는 의존성 화살표의 세로 위치를 정하는
값이에요. 그래서 같은 레인의 두 작업을 잇는 링크는 수평선 하나로 그려져요. 레인 행 어디에 링크를
놓아도 가로로 가장 가까운 막대에 붙어요. [의존성](dependencies)을 참고하세요.

레인 행은 순서 바꾸기 대상에서 빠져요. 드래그로 옮기는 동작과 다른 행을 놓는 동작이 모두 막혀요.
레인 행 하나에 작업이 여러 개 있어서 옮길 작업 하나를 지목할 수 없어요.
[작업 목록과 계층](task-list)을 참고하세요.

레인이 있어도 새 작업 그리기는 그대로 동작해요. 이 제스처는 마지막 행 아래 빈 영역에서만
일어나요. 레인 행을 포함해 어떤 행도 대상이 아니에요. [작업 생성](task-creation)을 참고하세요.

### 배지 스타일

| 선택자 | 설명 |
|---|---|
| `.gantt-grid-lane-count` | 작업 여러 개를 담은 행에 붙는 `+N` 배지 |

색은 [테마](theming)의 `--gantt-*` 커스텀 속성이 정해요.

## 동작 예제

작업 네 개 중 세 개가 `ana` 레인을 함께 써요.

```tsx title="src/LaneExample.tsx"
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  { id: 'spec', name: 'Spec', lane: 'ana', parentId: null, sequence: '1',
    startDate: '2026-03-02T00:00:00Z', endDate: '2026-03-06T00:00:00Z' },
  { id: 'api', name: 'API', parentId: null, sequence: '2',
    startDate: '2026-03-02T00:00:00Z', endDate: '2026-03-13T00:00:00Z' },
  { id: 'wires', name: 'Wireframes', lane: 'ana', parentId: null, sequence: '3',
    startDate: '2026-03-09T00:00:00Z', endDate: '2026-03-12T00:00:00Z' },
  { id: 'review', name: 'Review', lane: 'ana', parentId: null, sequence: '4',
    startDate: '2026-03-04T00:00:00Z', endDate: '2026-03-05T00:00:00Z' },
];

export function LaneExample() {
  return <ReactGanttChart tasks={tasks} height={480} />;
}
```

작업 네 개가 행 세 개로 묶여요.

| 행 | `id` | 작업 목록에 보이는 것 | 행에 있는 작업의 `order` |
|---|---|---|---|
| 1 | `spec+wires` | `Spec` `+1` | 둘 다 `1` |
| 2 | `review` | `Review` | `2` |
| 3 | `api` | `API` | `3` |

`spec`은 3월 6일에 끝나고 `wires`는 3월 9일에 시작해요. 그래서 둘이 1행을 함께 써요. `review`는
`spec`과 겹쳐서 2행을 열어요. `api`는 `sequence`로는 두 번째이고 레인도 없어요. 레인 전체가 첫
작업 자리에 들어가면서 `api`가 마지막 행으로 밀려요.

## 한계

레인 패킹은 `order`만 다시 계산해요. 날짜와 막대 배치, `originalOrder`는 그대로예요.

- 레인은 작업에 그 문자열이 있으면 바로 생겨요. 레인을 선언하거나 레인 순서를 정하거나 빈
  레인을 열어 두는 prop은 없어요.
- `lane` 문자열 자체는 어디에도 그려지지 않아요. 행 이름은 가장 먼저 시작하는 작업에서 가져와요.
- 작업 목록에서 레인 행은 `tasks[0]`만 가리켜요. 행의 클릭과 더블클릭, 목록 셀 포커스,
  `showRowNumbers` 번호가 모두 그 작업을 기준으로 동작해요.
- 나머지 작업은 각자의 막대로 다룰 수 있어요. 막대를 클릭하면 그 작업이 대상이 돼요. 막대
  하나하나가 별도의 키보드 셀이에요. [키보드와 스크린 리더](accessibility)를 참고하세요.
- 행 번호가 바뀐 작업은 얕은 복사본으로 넘어가요. 레인이 있는 차트는 렌더러와 콜백에 넘기는
  참조를 바꿔요. 레인이 없으면 받은 객체를 그대로 넘겨요.
- 행 빌더와 레인 패커는 내부 구현이에요. 밖으로 내보내는 것은 [`GanttRow`](ref/rows) 타입뿐이에요.

레인 패킹이 호스트 앱에 남기는 일은 두 가지예요. 어느 작업이 한 레인을 쓸지 정해서 같은 문자열을
각 작업에 적어 주세요. 레인 행의 나머지 작업이 필요하면 앱 데이터에서 직접 찾으세요.

작업 목록에서 발생하는 콜백은 그 행의 첫 작업을 넘겨줘요.

prop의 시그니처와 기본값은 [GanttProps](ref/props)에 있어요.
