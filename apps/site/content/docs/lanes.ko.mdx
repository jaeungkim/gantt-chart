---
title: "레인"
description: "서로 겹치지 않는 작업을 한 행에 모으는 `lane` 작업 필드"
---

하루짜리 지원 작업 열두 개가 각각 한 행씩 차지해요. 어느 행이든 가로로는 거의 다 비어 있는데,
한 줄이면 담길 내용 때문에 차트를 스크롤해야 해요. 작업 필드 `lane`은 같은 문자열을 가진 작업을
한 행에 나란히 놓아요.

## 한 행 함께 쓰기

`lane`은 차트 prop이 아니라 작업의 필드예요. 따로 켤 것은 없어요.

```tsx
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';

const tasks: Task[] = [
  { id: 'spec', name: 'Spec', lane: 'ana', parentId: null, sequence: '1',
    startDate: '2026-03-02T00:00:00Z', endDate: '2026-03-06T00:00:00Z' },
  { id: 'wires', name: 'Wireframes', lane: 'ana', parentId: null, sequence: '2',
    startDate: '2026-03-09T00:00:00Z', endDate: '2026-03-12T00:00:00Z' },
];

<ReactGanttChart tasks={tasks} height={480} />;
```

falsy한 `lane`은 레인이 없는 것과 같아요. `lane: ""`은 필드를 생략했을 때와 똑같이 작업에 자기
행을 하나 줘요.

lane 문자열은 공백도 대소문자도 다듬지 않고 그대로 비교해요. `"ana"`, `"Ana"`, `"ana "`는 서로
다른 레인 셋이에요.

## 패킹이 동작하는 방식

레인 멤버는 시작 날짜 순서대로, 먼저 맞는 행에 그리디하게 채워져요.

| 규칙 | 효과 |
|---|---|
| 정렬 | 입력 순서가 아니라 `startDate` 기준이에요. 시작이 같으면 입력 순서를 지켜요 |
| 배치 | 가장 빈틈없는 행이 아니라, 마지막 막대가 이미 끝난 **첫** 행에 들어가요 |
| 맞닿음 | 앞 막대가 끝나는 시점에 정확히 시작하는 작업은 같은 행을 써요 |
| 겹침 | 겹치는 작업은 행을 하나 더 열어요 |
| 재사용 | 행은 비는 즉시 다시 쓰여요 |

패킹은 `parentId`를 보지 않아요. 부모와 자식이 같은 lane 문자열을 가지면 다른 어떤 짝과도
똑같이 한 행에 묶이고, 그 행의 depth는 첫 작업의 depth를 따라가요.

묶인 행들은 그 레인에서 처음 등장한 멤버의 자리에 들어가요. 뒤에 오는 멤버는 자기 자리에
아무것도 남기지 않아요.

레인 행의 id는 그 행에 있는 작업 id를 `"+"`로 이은 문자열이에요. `spec+wires` 같은 모양이죠.
행이 작업 하나를 지목하지 않기 때문이에요. 작업 목록에서는 `tasks[0]`의 이름을 보여줘요. 입력
배열의 첫 작업이 아니라 그 행에서 가장 먼저 시작하는 작업이에요. 그 뒤에 나머지 개수를 세는
`+N` 배지가 붙어요.

## 레인 행이 치르는 대가

레인 행 위의 모든 작업은 같은 `order`를 보고해요. `order`는 의존성 화살표의 세로 위치를 정해요.
그래서 같은 레인 행에 있는 두 작업 사이의 연결은 수평선 하나로 그려져요. 레인 행 어디에 링크를
떨어뜨리든 가로로 가장 가까운 막대에 붙어요 — [의존성](dependencies) 참고.

레인 행은 끌어서 옮길 수도, 무언가를 떨어뜨릴 수도 없어요. 옮길 작업 하나를 지목하지도, 옮겨
넣을 자리 하나를 지목하지도 않기 때문이에요 — [작업 목록과 계층](task-list) 참고.

새 작업 그리기는 영향을 받지 않아요. 마지막 행 아래 빈 영역에서만 일어나므로 레인 행이든
아니든 행은 대상이 아니에요 — [작업 편집](editing) 참고.

파싱할 수 없는 `endDate`는 그 작업이 연 행을 오염시켜요. 배치 검사는 `rowEnd <= start`인데,
`NaN`과의 비교는 전부 false예요. 그래서 그 행은 다시는 뒤 작업에게 제안되지 않아요. 뒤따르는
레인 멤버는 다음 빈 행으로 밀려가고, 빈 행이 없으면 새 행을 열어요.

### 배지 스타일 주기

| 선택자 | 무엇인지 |
|---|---|
| `.gantt-grid-lane-count` | 여러 레인 메이트를 담은 행에 붙는 `+N` 배지 |

색은 [테마](theming)의 `--gantt-*` 커스텀 속성에서 와요.

## 예제로 따라가 보기

작업 네 개예요. 그중 셋은 `ana` 레인을 함께 써요.

```tsx
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';

const tasks: Task[] = [
  { id: 'spec', name: 'Spec', lane: 'ana', parentId: null, sequence: '1',
    startDate: '2026-03-02T00:00:00Z', endDate: '2026-03-06T00:00:00Z' },
  { id: 'api', name: 'API', parentId: null, sequence: '2',
    startDate: '2026-03-02T00:00:00Z', endDate: '2026-03-13T00:00:00Z' },
  { id: 'wires', name: 'Wireframes', lane: 'ana', parentId: null, sequence: '3',
    startDate: '2026-03-09T00:00:00Z', endDate: '2026-03-12T00:00:00Z' },
  { id: 'review', name: 'Review', lane: 'ana', parentId: null, sequence: '4',
    startDate: '2026-03-04T00:00:00Z', endDate: '2026-03-05T00:00:00Z' },
];

<ReactGanttChart tasks={tasks} height={480} />;
```

작업 네 개에서 행 세 개가 나와요.

| 행 | `id` | 작업 목록에 보이는 것 | 행 위 작업의 `order` |
|---|---|---|---|
| 1 | `spec+wires` | `Spec` `+1` | 둘 다 `1` |
| 2 | `review` | `Review` | `2` |
| 3 | `api` | `API` | `3` |

`spec`은 3월 6일에 끝나고 `wires`는 3월 9일에 시작해서 둘이 1행을 함께 써요. `review`는
`spec`과 겹치니까 2행을 열어요. `api`는 입력에서 두 번째이고 레인도 없지만, 레인 전체가 첫
멤버의 자리에 들어가면서 `api`가 마지막 행으로 밀려요.

## 한계

레인 패킹은 `order`만 다시 쓰고 나머지는 건드리지 않아요. 날짜도, 막대 위치도, `originalOrder`도
그대로예요.

이 영역이 하지 않는 일이에요.

- **레인 선언 없음.** 레인은 작업이 그 문자열을 들고 있어서 존재해요. 레인을 선언하거나, 레인
  순서를 정하거나, 빈 레인을 열어 두는 방법은 없어요.
- **레인 라벨 없음.** lane 문자열 자체는 어디에도 그려지지 않아요. 행 이름은 가장 먼저 시작하는
  작업에서 가져와요.
- **작업 목록에서는 레인 행마다 작업 하나.** 이름 셀은 물론이고 행의 클릭, 더블클릭, 목록 셀
  포커스도 `tasks[0]`만 건드려요. 나머지 멤버는 자기 막대로만 닿을 수 있고, 그 막대 하나하나가
  자기 키보드 셀이에요 — [키보드와 스크린 리더](accessibility) 참고.
- **객체 동일성 보장 없음.** 행 번호가 바뀐 작업은 얕은 복사본으로 넘어가요. 그래서 레인을
  묶으면 차트가 렌더러와 콜백에 넘기는 참조가 바뀌어요. 레인이 없는 차트는 받은 객체를 그대로
  돌려줘요.
- **내보내는 헬퍼 없음.** 행 빌더와 레인 패커는 내부 구현이에요. 밖으로 나가는 건
  [`GanttRow`](ref/rows) 타입뿐이에요.

호스트 앱이 직접 해야 하는 일이에요.

- 어느 작업이 한 레인을 쓸지 정하기. 같은 문자열을 각 작업에 적어 주면 돼요.
- 레인 행의 나머지 멤버가 필요하면 직접 찾기. 작업 목록에서 나가는 콜백은 그 행의 첫 작업을
  넘겨줘요.
