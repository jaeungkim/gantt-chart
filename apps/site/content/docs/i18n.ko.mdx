`locale`, `formats`, `firstDayOfWeek`는 차트의 모든 날짜 라벨을 정하는 세 가지 prop이에요. `locale`은 `Intl.DateTimeFormat`을 써서 라벨 언어를 바꿔요. `formats`는 라벨 하나를 직접 만든 함수로 바꿔요. `firstDayOfWeek`는 한 주가 시작하는 요일을 정해요. 이 페이지는 세 가지 포매터 슬롯과 세 prop, 차트가 현지화하지 않는 부분을 다뤄요.

## 라벨 슬롯

차트의 모든 날짜 라벨은 세 포매터 슬롯 중 하나에서 나와요.

| 슬롯 | 그리는 것 | 받는 값 |
|---|---|---|
| `tick` | 하단 헤더 행의 셀마다 라벨 하나 | 그 셀의 시작 날짜 |
| `header` | 상단 헤더 행의 그룹마다 라벨 하나 | 그룹의 시작 날짜 |
| `tooltip` | 그 밖의 모든 날짜. 호버 툴팁, 막대의 ARIA 라벨, 키보드 알림, 상세 패널의 읽기 전용 `Start`와 `End`, 압축된 형태의 드래그 날짜 표시 | 한 번에 날짜 하나 |

편집할 수 있는 `Start`와 `End`는 포매터를 거치지 않아요. 네이티브 `<input type="date">`라서 값이 `locale`과 상관없이 `YYYY-MM-DD`예요. 어떤 필드가 입력을 받는지는 [상세 패널](detail-panel)을 참고하세요.

스크린 리더가 읽는 값은 `tooltip` 슬롯이에요. 키보드 편집 뒤에 나오는 라이브 영역 알림도 마찬가지예요. 이 알림은 [키보드와 스크린 리더](accessibility)에서 다뤄요.

### 드래그 날짜 표시

이동이나 크기 조절 중에는 드래그하는 구간의 각 끝 날짜가 그 끝이 놓인 눈금 셀에 표시돼요. 그 아래에는 막대 구간이 옅게 칠해져요. 이동이면 양 끝을 모두 표시하고 크기 조절이면 움직이는 끝만 표시해요. 슬롯은 구간이 아니라 끝마다 날짜 하나를 받아요.

로케일이나 내장 라벨을 쓰면 드래그 날짜 표시는 `tooltip` 형식을 압축한 모양이에요. 바로 위 행에 이미 보이는 연도를 빼고 `day` 배율에서는 시각만 남겨요. `month` 배율에서는 `Sep 1`로, `day` 배율에서는 `15:00 UTC`로 표시돼요.

`quarter`와 `year` 배율에서는 구간이 해를 넘길 수 있어서 연도를 남기고 `tooltip` 형식 그대로 표시해요. `tooltip` 재정의는 압축하지 않아요. 재정의 함수가 반환한 값을 그대로 표시해요.

눈금 하나보다 짧은 작업처럼 양 끝이 같은 눈금 셀에 놓이면 라벨 하나로 합쳐서 표시해요. `locale`이 있으면 `Intl.DateTimeFormat.formatRange`가 양 끝을 합치면서 겹치는 부분을 빼요. `month` 배율의 2일짜리 구간은 `Jan 15`와 `17`을 en dash로 이은 모양이에요.

재정의 계층과 내장 계층은 완성된 라벨 두 개를 en dash로 이어요. 두 라벨이 같으면 하나만 표시해요. 하루 안의 구간은 어느 계층에서든 `Jan 7`이에요.

### 라벨 우선순위

각 슬롯은 세 계층 중 값이 있는 첫 번째 계층에서 채워져요.

1. `formats[scale][slot]`. 직접 만든 함수예요.
2. `locale`. `Intl.DateTimeFormat` 포매터예요.
3. 내장 영어 라벨이에요.

세 슬롯은 서로 독립적으로 결정돼요. `locale="ko-KR"`과 함께 `formats.quarter.header`를 넘겨도 `tick`과 `tooltip`은 한국어 출력을 유지해요. 3번 계층이 쓰는 내장 형식 문자열은 [배율과 테마 타입](ref/scales)에 정리돼 있어요.

## locale

`locale`은 BCP 47 태그를 받아서 `Intl.DateTimeFormat`에 넘겨요.

```tsx
<ReactGanttChart tasks={tasks} locale="ko-KR" />
```

<GanttDemo preset="locale" />

설치할 것은 없어요. 차트는 dayjs 로케일 파일을 등록하지 않고 `utc` 플러그인만 써요. 로케일 계층 전체가 플랫폼의 `Intl` 객체예요. 모든 포매터는 `timeZone: 'UTC'`로 만들어져서 라벨이 보는 사람의 시간대로 밀리지 않아요.

같은 시각 `2025-09-01T15:00:00Z`를 두 방식으로 그리면 다음과 같아요.

| 배율 | `locale` 없음 (tick / header / tooltip) | `locale="ko-KR"` |
|---|---|---|
| `day` | `15` / `Sep 1, 2025` / `Sep 1, 2025 15:00 UTC` | `15시` / `2025년 9월 1일` / `2025년 9월 1일 15:00 UTC` |
| `week` | `1` / `Sep 2025` / `Sep 1, 2025` | `1일` / `2025년 9월` / `2025년 9월 1일` |
| `month` | `Sep 1` / `Sep 2025` / `Sep 1, 2025` | `9월 1일` / `2025년 9월` / `2025년 9월 1일` |
| `quarter` | `Sep` / `Q3 2025` / `Sep 2025` | `9월` / `2025년 Q3` / `2025년 9월` |
| `year` | `Sep` / `2025` / `Sep 2025` | `9월` / `2025년` / `2025년 9월` |

`locale`을 생략하면 `Intl.DateTimeFormat`을 만들지 않아요. 빈 문자열도 생략한 것으로 봐요.

`"en-US"`를 넘기면 생략할 때와 라벨 하나가 달라요. `day` 배율의 툴팁에 쉼표가 하나 붙어요. `Intl`은 `Sep 1, 2025, 15:00 UTC`를 만들고 내장 라벨은 `Sep 1, 2025 15:00 UTC`를 만들어요. 나머지 라벨은 모두 같아요.

`Intl`에는 분기 필드가 없어서 `quarter` 헤더는 차트가 직접 조립해요. 현지화된 연도를 먼저 만들어요. 그 문자열이 숫자로 끝나면 `Q3`을 앞에 붙이고 그렇지 않으면 뒤에 붙여요. `2025`는 `Q3 2025`가 되고 `2025년`은 `2025년 Q3`이 돼요.

### 잘못된 태그

밑줄이 들어간 `"en_US"`나 공백이 들어간 `"ko kr"`처럼 구조가 잘못된 태그를 넘기면 `Intl.DateTimeFormat`에서 예외가 발생해요. 차트는 이 예외를 잡고 로케일 계층 전체를 버려요. 그래서 세 슬롯이 모두 내장 영어 라벨로 돌아가요. 콘솔에는 한 줄이 남아요.

```text title="콘솔"
[gantt-chart] Unusable locale "en_US" - falling back to the built-in labels.
```

이 경고는 페이지를 로드할 때 태그마다 한 번만 나와요. 이미 알린 태그 목록은 모듈 스코프에 있어서 같은 태그를 쓰는 두 번째 차트는 아무것도 남기지 않아요.

형식은 맞지만 알 수 없는 태그는 예외를 내지 않아요. `Intl`은 `"xx-YY"`와 `"zz"`를 받아들이고 런타임 기본 로케일로 돌아가요. 차트는 경고 없이 브라우저 언어로 그려져요. 내장 라벨로 돌아가지 않아요. 하이픈만 제대로 쓴 오타는 아무 표시도 나지 않아요.

## formats

`formats`는 배율을 키로 하는 레코드예요. 배율마다 세 슬롯 중 원하는 것만 지정하세요. 생략한 슬롯은 로케일 계층이나 내장 계층이 만든 라벨을 그대로 써요.

```tsx title="formats.ts"
import type { GanttFormatOverrides } from '@jaeungkim/gantt-chart';

export const formats: GanttFormatOverrides = {
  month: {
    tick: (d) => d.format('D'),
    tooltip: (d) => d.format('YYYY-MM-DD'),
  },
  year: {
    header: (d) => `FY${d.year()}`,
  },
};
```

재정의는 `locale`보다 우선해요. 회계 분기처럼 `Intl`이 표현하지 못하는 라벨은 재정의로 만들어야 해요. 그래서 아래 예제도 `quarter` 헤더를 재정의해요. 전체 타입은 [배율과 테마 타입](ref/scales)을 참고하세요.

> [!WARNING]
> 포매터에 넘어오는 `Dayjs`는 UTC 모드라서 `d.format('HH:mm')`, `d.year()`, `d.month()`, `d.day()`는 모두 UTC 값을 반환해요. 현지 시각으로 바꾸는 포매터는 자기 셀과 어긋나는 라벨을 만들어요. `2025-09-01T23:00Z`인 막대는 9월 1일 셀에 속하는데 서울 기준 포매터는 9월 2일로 표시해요.

### 재정의 함수가 받는 값

`header`는 처음 보이는 셀의 날짜가 아니라 그룹의 시작 날짜를 받아요. 월요일 기준으로 묶은 `week` 배율에서 첫 셀이 `2025-08-31`인 그룹은 `2025-08-25T00:00:00Z`를 받아요.

레코드의 키는 파생된 단위가 아니라 화면에 보이는 배율이에요. `firstDayOfWeek`를 설정한 `week` 배율에서 헤더는 `day` 배율 옵션으로 만들어지지만 재정의는 `formats.week.header`에서 읽어요. 거기에 `formats.day.header`를 써도 효과가 없어요.

하단 셀은 그룹 시작 날짜를 기준으로 상단 행 그룹으로 묶여요. 이웃한 그룹의 라벨이 같으면 더 넓은 셀 하나로 합쳐져요.

그래서 두 그룹에 같은 문자열을 반환하는 `header` 재정의는 그 둘을 하나로 합쳐요. 월만 표시하는 `week` 헤더는 그 달의 모든 주를 하나로 합쳐요. 상단 행이 묶는 단위는 [타임라인](timeline)을 참고하세요.

### 객체 동일성 고정

`formats`는 모듈 스코프에 선언하거나 `useMemo`로 감싸세요. 렌더링마다 새로 만든 객체 리터럴은 새 동일성이라서 모든 라벨 메모를 무효화해요. `locale`까지 설정돼 있으면 그 뒤의 `Intl.DateTimeFormat` 인스턴스도 전부 다시 만들어요. 차트는 이 상황을 경고하지 않아요.

## firstDayOfWeek

`firstDayOfWeek`는 일요일 `0`부터 토요일 `6`까지의 숫자예요. 설정하면 `week` 배율의 상단 헤더 행이 월 대신 그 요일에 시작하는 주 단위로 묶여요.

차트는 값이 아니라 prop이 있는지를 봐요. `firstDayOfWeek={0}`도 주 단위 그룹을 켜요.

`week` 배율에서 `2025-08-31`(일요일)부터 `2025-09-07`까지 `day` 셀 8개가 있을 때는 다음과 같아요.

| prop | 상단 헤더 그룹 |
|---|---|
| `firstDayOfWeek={1}` | `Aug 25, 2025`, `Sep 1, 2025` |
| `firstDayOfWeek={0}` | `Aug 31, 2025`, `Sep 7, 2025` |
| *(생략)* | `Aug 2025`, `Sep 2025` |

prop을 설정하면 헤더 라벨의 모양이 달라져요. 주 그룹은 월이 아니라 전체 날짜로 표시돼요. 첫 셀이 `Aug 31`인데도 첫 그룹은 `Aug 25`로 표시돼요. 라벨을 실제 주 시작일에서 만들기 때문이에요.

prop을 생략하면 `week` 배율은 월 단위로 묶여요. 다른 배율에서는 이 prop이 경고 없이 무시돼요. `month` 배율을 보면서 설정하면 화면이 그대로예요.

검증은 없어요. 값이 그대로 나머지 연산에 들어가서 `7`은 `0`처럼, `-1`은 `6`처럼 동작해요. 정수가 아닌 값은 경고 없이 잘못된 오프셋을 만들어요.

`firstDayOfWeek`는 주 단위 그룹만 바꿔요. 어떤 날을 음영 처리할지는 `workingWeekdays`와 `holidays`가 정해요. [타임라인](timeline)을 참고하세요.

이 페이지에 나온 prop의 시그니처와 기본값은 [GanttProps](ref/props)를 참고하세요.

## 한국어 차트

로케일과 주 시작 요일, 초기 배율을 함께 쓴 예제예요.

```tsx title="ProjectChart.tsx"
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  {
    id: 'design',
    name: '설계',
    startDate: '2025-09-01',
    endDate: '2025-09-12',
    parentId: null,
    sequence: '1',
  },
  {
    id: 'build',
    name: '개발',
    startDate: '2025-09-15',
    endDate: '2025-10-10',
    parentId: null,
    sequence: '2',
  },
];

export default function ProjectChart() {
  return (
    <ReactGanttChart
      tasks={tasks}
      locale="ko-KR"
      firstDayOfWeek={1}
      defaultScale="week"
      showTaskList
    />
  );
}
```

작업 목록에는 따로 로케일이 필요 없어요. 앱 데이터인 `task.name`을 보여주고 그 위의 헤더 셀에는 보이는 문구가 없거든요. 차트 주변의 다른 UI는 `locale`을 따르지 않아요. 그 문자열 목록은 [한계](#한계)에 있어요.

## 직접 만든 분기 헤더

4월에 시작하는 회계 연도에는 자체 분기 라벨이 필요한데 `Intl`은 그런 라벨을 만들지 못해요.

```tsx title="FiscalChart.tsx"
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { GanttFormatOverrides, Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

// 모듈 스코프라서 렌더 사이에 객체 동일성이 바뀌지 않아요
const formats: GanttFormatOverrides = {
  quarter: {
    // Dayjs는 UTC 모드예요 - d.month()는 UTC 기준 0-11이에요
    header: (d) => {
      const fiscalMonth = (d.month() + 12 - 3) % 12;
      const fiscalYear = d.month() >= 3 ? d.year() : d.year() - 1;
      return `FY${fiscalYear} Q${Math.floor(fiscalMonth / 3) + 1}`;
    },
    tooltip: (d) => d.format('YYYY-MM-DD'),
  },
};

const tasks: Task[] = [
  {
    id: 'rollout',
    name: 'Rollout',
    startDate: '2026-02-02',
    endDate: '2026-07-31',
    parentId: null,
    sequence: '1',
  },
];

export default function FiscalChart() {
  return (
    <ReactGanttChart
      tasks={tasks}
      formats={formats}
      defaultScale="quarter"
    />
  );
}
```

2026년 2월은 `FY2025 Q4`에 들어가고 2026년 4월은 `FY2026 Q1`에 들어가요. `header` 슬롯은 달력 분기의 시작 날짜를 받아요. 그래서 재정의 함수는 항상 1월, 4월, 7월, 10월만 봐요. `tick` 슬롯은 생략했으니 내장 월 이름을 그대로 써요.

## 입력 날짜 문자열

`locale`과 `formats`는 날짜를 보여주는 방식만 바꿔요. `startDate`와 `endDate`는 태그와 상관없이 UTC로 파싱돼요. 이 문자열의 규칙은 [작업 데이터](task-data)를 참고하세요.

## 한계

세 prop이 바꾸는 것은 날짜뿐이에요. 차트의 나머지 문자열은 모두 하드코딩된 영어예요. 이 문자열을 바꾸는 prop은 없어요. 아래 표의 처음 세 행은 화면에서 읽는 문자열이고 나머지는 스크린 리더가 읽어 주는 문자열이에요.

| 문자열 | 나타나는 곳 |
|---|---|
| `"Add task"` | 작업 목록 아래 버튼 |
| `"Start"`, `"End"`, `"Duration"`, `"Progress"`, `"Depends on"` | 내장 상세 패널의 필드 캡션 |
| `12h`, `3d` | 호버 툴팁과 상세 패널의 기간 축약 표기 |
| `"Gantt chart"`, `"Task name"`, `"Timeline"`, `"Resize task list"`, `"Task details"` | `treegrid`, 그 두 열, 스플리터, 상세 패널의 ARIA 이름 |
| `"summary"`, `"to"`, `"% complete"` | 막대 ARIA 라벨 안의 연결어 |
| `"<scale> scale"` | Ctrl/Cmd + 방향키로 배율을 바꾼 뒤 나오는 라이브 영역 알림. 배율 키 뒤에 영어 단어가 붙어요 |
| `"<name> deleted"`, `"<name> cannot be changed"`, `"<name> moved to 2 of 5 under <parent>"` | 키보드 편집 뒤에 나오는 라이브 영역 알림 |

이 문자열들에서 현지화된 `tooltip` 포매터를 거치는 것은 안에 있는 날짜뿐이에요. `renderDetail`은 캡션과 닫기 버튼을 포함해 상세 패널 본문 전체를 바꿔요. 그 안의 문구는 앱에서 직접 번역할 수 있어요. 패널 자체의 `aria-label`은 영어 그대로예요.

배율 선택기는 이 표에 없어요. 차트는 선택기를 그리지 않아요. 호스트 앱이 선택기를 직접 렌더링하고 옵션 텍스트도 번역하세요. `<select>` 레시피는 [명령형 API](imperative-api)를 참고하세요.

이 영역의 다른 한계는 다음과 같아요.

- 숫자, 통화, 복수형 형식은 지원하지 않아요. `Intl.NumberFormat`, `Intl.RelativeTimeFormat`, `Intl.PluralRules`는 만들지 않아요. 진행률은 숫자 뒤에 `% complete`를 붙여 읽어 줘요. 45인 작업은 `45% complete`예요.
- `locale`은 dayjs까지 닿지 않아요. dayjs 로케일 파일을 등록하지 않아서 `formats` 재정의 안의 `d.format('MMMM')`은 태그와 상관없이 `September`를 반환해요. 현지화된 월 이름이 필요한 재정의는 자체 `Intl.DateTimeFormat`을 만들어야 해요.
- RTL은 지원하지 않아요. `dir`을 설정하지도 읽지도 않고 스타일시트는 모든 요소를 물리 속성으로 배치해요. 오른쪽에서 왼쪽으로 읽는 호스트 앱은 차트를 직접 뒤집거나 왼쪽에서 오른쪽인 하위 트리에 넣어야 해요.
- 로컬 시각 렌더링 모드는 없어요. 위치와 라벨은 UTC이고 이 동작을 바꾸는 prop도 없어요. 로컬 시각 라벨이 필요한 호스트 앱은 날짜 문자열을 직접 옮긴 다음 넘겨야 해요.
- `locale`과 `firstDayOfWeek`는 런타임에 검증하지 않아요. `Intl`이 거부하는 태그에 한 번 나오는 `console.warn`이 이 영역의 유일한 피드백이에요.
- 라벨 로직은 내보내지 않아요. 호스트 앱은 차트가 결정한 포매터를 자체 배율 선택기나 범례에 재사용할 수 없고 그 용도로는 자체 `Intl.DateTimeFormat`을 만들어야 해요.
