차트가 서울에 있는 팀에 배포돼요. 상단 헤더 행은 `Sep 2025`를 쓰고, 그 아래 눈금은 `1 2 3`을 세고, 드래그 툴팁은 `Sep 1, 2025`로 나와요. 프롭 세 개가 이걸 전부 바꿔요. `locale`은 모든 날짜 라벨을 다른 언어로 바꾸고, `formats`는 라벨 하나를 직접 만든 함수로 교체하고, `firstDayOfWeek`는 한 주가 어디서 시작할지 정해요. 셋 다 로케일 패키지가 필요 없어요.

## 세 가지 라벨 자리

모든 배율은 날짜를 정확히 세 곳에 찍어요. 각 자리마다 전용 포매터 슬롯이 있어요.

| 슬롯 | 그리는 것 | 받는 값 |
|---|---|---|
| `tick` | 하단 헤더 행의 셀마다 라벨 하나 | 그 셀의 시작 날짜 |
| `header` | 상단 헤더 행의 그룹마다 라벨 하나 | 그룹의 시작 날짜 |
| `tooltip` | 헤더 드래그 readout, 막대의 스크린 리더 드래그 안내, 그리고 모든 막대 ARIA 라벨 안의 날짜 | 드래그 중인 지점의 날짜, ARIA 라벨일 때는 작업 자체의 시작일과 종료일 |

그래서 스크린 리더가 읽어 주는 값은 `tooltip` 슬롯이에요. 키보드 편집이 만드는 라이브 영역 안내도 여기에 들어가요. 그 안내는 [키보드와 스크린 리더](accessibility)에서 다뤄요.

헤더 드래그 readout은 이 층이 한 지점이 아니라 구간을 찍는 유일한 자리예요. `locale`이 있으면 양 끝이 공유하는 부분을 합쳐서 사흘짜리 이동이 `Jan 15 – 17`로 나오고, 없으면 짧은 내장 라벨 두 개를 en dash로 이어요. 직접 넘긴 `tooltip` 함수도 양 끝을 각각 그린 뒤 같은 방식으로 이어져요. 양 끝이 똑같이 그려지면 같은 라벨을 두 번 찍지 않고 하나만 나와요.

각 슬롯은 세 계층 중 값을 가진 첫 번째 계층에서 채워져요.

1. `formats[scale][slot]` — 직접 만든 함수예요.
2. `locale` — `Intl.DateTimeFormat` 포매터예요.
3. 내장 영어 라벨이에요.

세 체인은 서로 독립적으로 결정돼요. `locale="ko-KR"`과 함께 `formats.quarter.header`를 넘겨도 `tick`과 `tooltip`은 한국어 출력 그대로예요. 3번 계층이 쓰는 내장 포맷 문자열은 [배율](ref/scales)에 정리돼 있어요.

## locale

`locale`은 BCP 47 태그를 받아서 `Intl.DateTimeFormat`에 넘겨요.

```tsx
<ReactGanttChart tasks={tasks} locale="ko-KR" />
```

설치할 건 없어요. 차트는 dayjs 로케일 파일을 하나도 등록하지 않고 `utc` 플러그인만 써요. 로케일 계층 전체가 플랫폼의 `Intl` 객체예요. 모든 포매터는 `timeZone: 'UTC'`를 강제로 넣어서 만들어요. 그래서 라벨이 보는 사람의 시간대로 밀리는 일이 없어요.

같은 시각 `2025-09-01T15:00:00Z`를 두 방식으로 그리면 이래요.

| 배율 | `locale` 없음 — tick / header / tooltip | `locale="ko-KR"` |
|---|---|---|
| `hour` | `15:00` / `Sep 1, 2025` / `Sep 1, 2025 15:00 UTC` | `15:00` / `2025년 9월 1일` / `2025년 9월 1일 15:00 UTC` |
| `day` | `15` / `Sep 1, 2025` / `Sep 1, 2025 15:00 UTC` | `15시` / `2025년 9월 1일` / `2025년 9월 1일 15:00 UTC` |
| `week` | `1` / `Sep 2025` / `Sep 1, 2025` | `1일` / `2025년 9월` / `2025년 9월 1일` |
| `month` | `1` / `Sep 2025` / `Sep 1, 2025` | `1일` / `2025년 9월` / `2025년 9월 1일` |
| `quarter` | `Sep` / `Q3 2025` / `Sep 2025` | `9월` / `2025년 Q3` / `2025년 9월` |
| `year` | `Sep` / `2025` / `Sep 2025` | `9월` / `2025년` / `2025년 9월` |

`locale`을 빼면 `Intl.DateTimeFormat`을 아예 만들지 않아요. 빈 문자열도 뺀 것으로 쳐요.

`"en-US"`를 넘기는 건 빼는 것과 달라요. hour와 day 툴팁에 쉼표가 하나 붙어요. `Intl`은 `Sep 1, 2025, 15:00 UTC`를 내고, 내장 라벨은 `Sep 1, 2025 15:00 UTC`를 내요. 나머지 라벨은 전부 같아요.

`Intl`에는 분기 필드가 없어서 quarter 헤더는 손으로 조립해요. 차트는 현지화된 연도를 먼저 만들어요. 그다음 그 연도 문자열이 숫자로 끝나는지 보고 `Q3`을 앞이나 뒤에 붙여요. `2025`는 `Q3 2025`가 되고, `2025년`은 `2025년 Q3`이 돼요.

### Intl이 쓸 수 없는 태그

구조가 잘못된 태그는 `Intl.DateTimeFormat`을 throw하게 만들어요. 밑줄이 들어간 `"en_US"`, 공백이 들어간 `"ko kr"`가 그런 경우예요. 차트는 이 예외를 잡고 로케일 계층 전체를 버려요. 그래서 `tick`, `header`, `tooltip`이 모두 내장 영어 라벨로 돌아가요. 콘솔에는 한 줄을 남겨요.

```text title="콘솔"
[gantt-chart] Unusable locale "en_US" - falling back to the built-in labels.
```

이 경고는 페이지 로드마다 서로 다른 태그당 한 번씩만 나와요. 이미 알린 태그 목록이 모듈 스코프에 있어서, 같은 잘못된 태그를 쓰는 두 번째 차트는 조용해요.

형식은 맞지만 알 수 없는 태그는 throw하지 않아요. `"xx-YY"`와 `"zz"`는 `Intl`이 받아들이고, 그다음 런타임 기본 로케일로 되돌아가요. 차트는 브라우저 언어로 그려지고, 경고도 내장 폴백도 없어요. 하이픈이 살아 있는 오타는 눈에 보이지 않아요.

## formats

`formats`는 배율별 레코드예요. 배율마다 세 슬롯 중 아무거나 지정할 수 있어요. 빠뜨린 슬롯은 로케일 계층이나 내장 계층이 만든 라벨을 그대로 써요.

```tsx title="formats.ts"
import type { GanttFormatOverrides } from '@jaeungkim/gantt-chart';

export const formats: GanttFormatOverrides = {
  month: {
    tick: (d) => d.format('D'),
    tooltip: (d) => d.format('YYYY-MM-DD'),
  },
  year: {
    header: (d) => `FY${d.year()}`,
  },
};
```

오버라이드는 `locale`을 이겨요. `Intl`이 표현할 수 없는 라벨에 닿는 유일한 방법이라, 아래 예제마다 quarter 헤더에 하나씩 들어 있어요. 전체 타입은 [배율](ref/scales)에 있어요.

> [!WARNING]
> 포매터에 넘어오는 `Dayjs`는 UTC 모드예요. 오버라이드 안에서 `d.format('HH:mm')`, `d.year()`, `d.month()`, `d.day()`는 모두 UTC 벽시계 값을 읽어요. 현지 시각을 그대로 쓰는 포매터를 만들면, 날짜를 변환하든 호스트 앱의 로컬 시각 헬퍼를 쓰든, 라벨이 자기가 놓인 셀과 어긋나요. `2025-09-01T23:00Z`인 막대는 9월 1일 셀에 속하는데, 서울 기준 포매터는 9월 2일로 적어요.

### 오버라이드가 받는 값

`header`는 그룹의 시작 날짜로 호출돼요. 처음 보이는 셀의 날짜가 아니에요. 월요일 기준으로 묶은 week 배율에서, 처음 그려진 셀이 `2025-08-31`인 그룹은 `2025-08-25T00:00:00Z`를 받아요.

레코드의 키는 화면에 있는 배율이에요. 파생된 단위가 아니에요. `firstDayOfWeek`를 준 `week` 배율에서 헤더는 day 배율 옵션으로 만들어지지만, 오버라이드는 여전히 `formats.week.header`에서 읽어요. 거기에 `formats.day.header`를 써도 아무 일도 일어나지 않아요.

붙어 있는 하단 셀들은 그룹 시작 날짜를 기준으로 상단 행 그룹 하나로 합쳐져요. 나온 라벨을 기준으로 합치지 않아요. 두 그룹에 같은 문자열을 돌려주는 `header` 오버라이드는 넓은 셀 하나로 합쳐지지 않고 그 문자열을 나란히 두 번 찍어요. 상단 행이 묶는 단위는 [타임라인](timeline)에 있어요.

### 객체 아이덴티티를 고정하기

`formats`는 모듈 스코프에 선언하거나 `useMemo`로 감싸요. 렌더마다 새로 만드는 객체 리터럴은 새 아이덴티티라서, 모든 라벨 메모를 무효화해요. `locale`까지 설정돼 있으면 그 뒤의 `Intl.DateTimeFormat` 인스턴스도 전부 다시 만들어요. 이걸 알려 주는 경고는 없어요.

## firstDayOfWeek

`firstDayOfWeek`는 숫자예요. 일요일이 `0`이고 토요일이 `6`이에요. 값을 주면 `week` 배율의 상단 헤더 행이 월 대신 그 요일부터 시작하는 주 단위로 묶여요.

판단 기준은 프롭이 있는지지, 값이 truthy한지가 아니에요. `firstDayOfWeek={0}`도 주 단위 그룹을 켜요.

`week` 배율에서 `2025-08-31`(일요일)부터 `2025-09-07`까지 day 셀 여덟 개가 있을 때예요.

| 프롭 | 상단 헤더 그룹 |
|---|---|
| `firstDayOfWeek={1}` | `Aug 25, 2025`, `Sep 1, 2025` |
| `firstDayOfWeek={0}` | `Aug 31, 2025`, `Sep 7, 2025` |
| *(생략)* | `Aug 2025`, `Sep 2025` |

이 표에서 두 가지가 따라와요. 프롭을 주면 헤더 라벨의 모양이 달라져요. 주 그룹은 월이 아니라 전체 날짜로 적히기 때문이에요. 그리고 처음 그려진 셀이 `Aug 31`인데도 첫 그룹은 `Aug 25`로 적혀요. 라벨이 진짜 주 시작일에서 오기 때문이에요.

프롭을 빼면 `week` 배율은 예전 그대로 월 단위로 묶여요. 나머지 배율에서는 이 프롭이 아무 일도 하지 않고, 알려 주지도 않아요. month 배율을 보면서 값을 설정한 사람은 아무 변화도 못 봐요.

검증은 없어요. 값이 그대로 나머지 연산에 들어가서 `7`은 `0`처럼, `-1`은 `6`처럼 동작해요. 정수가 아닌 값은 이상한 오프셋을 만들고 경고도 없어요.

`firstDayOfWeek`는 주 단위 그룹만 바꾸고 다른 건 건드리지 않아요. 주말 음영은 별도의 기본 판별 함수로 돌아가요. 토요일, 일요일, 그리고 `holidays`에 들어 있는 날짜가 대상이에요. 이 판별은 [타임라인](timeline)의 `isNonWorkingDay`로 통째로 바꿀 수 있어요.

## 한국어 차트

로케일, 주 시작 요일, 시작 배율을 함께 써 볼게요.

```tsx title="ProjectChart.tsx"
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  {
    id: 'design',
    name: '설계',
    startDate: '2025-09-01',
    endDate: '2025-09-12',
    parentId: null,
    sequence: '1',
  },
  {
    id: 'build',
    name: '개발',
    startDate: '2025-09-15',
    endDate: '2025-10-10',
    parentId: null,
    sequence: '2',
  },
];

export default function ProjectChart() {
  return (
    <ReactGanttChart
      tasks={tasks}
      locale="ko-KR"
      firstDayOfWeek={1}
      defaultScale="week"
      showTaskList
    />
  );
}
```

작업 목록에는 따로 로케일이 필요 없어요. 보여주는 건 내 데이터인 `task.name`이고, 그 위의 헤더 셀에는 눈에 보이는 문구가 없거든요. 차트 크롬의 나머지는 `locale`을 따르지 않아요. 그 목록은 이 페이지 끝에 있어요.

## 직접 만드는 분기 헤더

4월에 시작하는 회계 연도는 자체 분기 라벨이 필요한데, `Intl`은 그런 라벨을 만들지 못해요.

```tsx title="FiscalChart.tsx"
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { GanttFormatOverrides, Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

// 모듈 스코프라서 렌더 사이에 객체 아이덴티티가 바뀌지 않아요
const formats: GanttFormatOverrides = {
  quarter: {
    // Dayjs는 UTC 모드예요 - d.month()는 UTC 기준 0-11이에요
    header: (d) => {
      const fiscalMonth = (d.month() + 12 - 3) % 12;
      const fiscalYear = d.month() >= 3 ? d.year() : d.year() - 1;
      return `FY${fiscalYear} Q${Math.floor(fiscalMonth / 3) + 1}`;
    },
    tooltip: (d) => d.format('YYYY-MM-DD'),
  },
};

const tasks: Task[] = [
  {
    id: 'rollout',
    name: 'Rollout',
    startDate: '2026-02-02',
    endDate: '2026-07-31',
    parentId: null,
    sequence: '1',
  },
];

export default function FiscalChart() {
  return (
    <ReactGanttChart
      tasks={tasks}
      formats={formats}
      defaultScale="quarter"
    />
  );
}
```

2026년 2월은 `FY2025 Q4`에, 2026년 4월은 `FY2026 Q1`에 들어가요. `header` 슬롯은 달력 분기의 시작 날짜로 호출돼서, 오버라이드는 항상 1월, 4월, 7월, 10월만 봐요. `tick` 슬롯은 비워 뒀으니 내장 월 이름을 그대로 써요.

## 넘기는 날짜 문자열

`locale`과 `formats`는 날짜를 어떻게 보여줄지만 바꿔요. 어떻게 읽을지는 절대 바꾸지 않아요. `startDate`와 `endDate`는 태그와 상관없이 UTC로 파싱되고, 이 문자열의 규칙은 [작업 데이터](task-data)에 있어요.

## 차트가 현지화하지 않는 것

세 프롭이 닿는 건 날짜예요. 차트 크롬의 나머지는 전부 하드코딩된 영어 문자열이고, 이걸 바꾸는 프롭은 없어요.

| 문자열 | 나타나는 곳 |
|---|---|
| `"Gantt chart"` | treegrid의 `aria-label` |
| `"Resize task list"` | 스플리터의 `aria-label` |
| `"Add task"` | 작업 목록 아래 버튼 — 이 표에서 유일하게 듣는 게 아니라 눈으로 읽는 문자열이에요 |
| `"summary"`, `"to"`, `"% complete"` | 모든 막대 ARIA 라벨 안의 연결어 |
| `"<scale> scale"` | Ctrl/Cmd + 방향키로 배율을 바꾼 뒤 나오는 라이브 영역 안내 — 배율 키 그대로에 영어 단어가 붙어요 |
| `"<name> cannot be deleted"`, `"<name> deleted"`, `"<name> cannot be changed"`, `"<name> progress cannot be changed"` | 키보드 편집 뒤에 나오는 라이브 영역 안내 |

이 ARIA 문장에서 현지화된 `tooltip` 포매터를 거치는 건 안에 있는 날짜뿐이에요. 호스트 앱이 바꿀 수 있는 문자열은 `ungroupedLabel`([그룹과 스윔레인](grouping)) 하나고, 기본값은 영어예요.

예전에는 배율 선택기가 이 표에서 가장 눈에 띄는 항목이었어요. 헤더 셀도, 눈금도, 툴팁도 전부 `Intl`을 거치는 차트 안에서, 배율 선택기만 `hour`, `day`, `week` 같은 키를 그대로 버튼 여섯 개에 찍었거든요. 그 선택기와 이를 감싸던 툴바가 사라지면서 이 구멍은 구조적으로 막혔어요. 이제 선택기는 호스트 앱이 그리는 것이고, 그래서 옵션 텍스트도 호스트 앱이 번역해요.

```tsx
const scaleLabels: Record<GanttScaleKey, string> = {
  hour: '시간', day: '일', week: '주', month: '월', quarter: '분기', year: '년',
};

<select value={scale} onChange={(e) => chart.current?.setScale(e.target.value as GanttScaleKey)}>
  {Object.entries(scaleLabels).map(([key, label]) => (
    <option key={key} value={key}>{label}</option>
  ))}
</select>
```

`scale`은 `onScaleChange` prop에서 와요. 그래서 선택기는 자기 클릭뿐 아니라 휠 제스처와 키보드 단축키도 따라가요. 전체 배선은 [명령형 API](imperative-api)에 있어요.

이 영역의 다른 한계예요.

- **숫자, 통화, 복수형 포맷은 없어요.** `Intl.NumberFormat`, `Intl.RelativeTimeFormat`, `Intl.PluralRules`는 한 번도 만들지 않아요. 진행률은 숫자 그대로 뒤에 `% complete`를 붙여서 읽어 줘요. 그래서 45인 작업은 항상 `45% complete`로 나와요.
- **`locale`은 dayjs까지 닿지 않아요.** dayjs 로케일 파일을 등록하지 않아서, `formats` 오버라이드 안의 `d.format('MMMM')`은 태그와 상관없이 `September`를 찍어요. 현지화된 월 이름이 필요한 오버라이드는 자체 `Intl.DateTimeFormat`을 만들어야 해요.
- **RTL 지원은 없어요.** `dir`을 설정하지도 읽지도 않고, 스타일시트는 모든 걸 물리 속성으로 배치해요. 오른쪽에서 왼쪽으로 읽는 호스트 앱은 차트를 직접 뒤집거나, 왼쪽에서 오른쪽인 하위 트리에 넣어야 해요.
- **로컬 시각 렌더링 모드는 없어요.** 위치와 라벨은 UTC이고, 이걸 끄는 프롭도 없어요. 로컬 벽시계 라벨이 필요한 호스트 앱은 날짜 문자열을 직접 옮긴 다음 넘겨야 해요.
- **`locale`과 `firstDayOfWeek`에 런타임 검증은 없어요.** `Intl`이 거부하는 태그에 한 번 나오는 `console.warn`이 이 영역이 내는 유일한 피드백이에요.
- **라벨 로직은 밖으로 내보내지 않아요.** 호스트 앱은 차트가 결정한 포매터를 자기 배율 선택기나 범례에 재사용할 수 없고, 그 용도로는 자체 `Intl.DateTimeFormat`을 만들어야 해요.
