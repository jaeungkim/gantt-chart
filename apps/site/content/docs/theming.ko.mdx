차트의 테마는 `theme` prop 하나와 스타일시트의 CSS 커스텀 속성 26개로 정해져요. 이 페이지는
스타일시트를 불러오는 방법, 테마가 결정되는 순서, 토큰 전체 목록, 토큰을 덮어쓰는 방법을 다뤄요.

차트의 색, 그림자, 트랜지션은 거의 전부 `--gantt-*` 커스텀 속성을 읽어요. 읽지 않는 것은 한계 절에
정리했어요. JS 테마 객체나 `tokens` prop은 없어요.

## 스타일시트

패키지는 빌드된 CSS를 별도 서브패스로 내보내요.

```tsx title="src/main.tsx"
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';
```

이 서브패스는 `dist/gantt-chart.css`를 가리켜요. 패키지 엔트리가 스타일시트를 가져오긴 하지만
라이브러리 빌드는 이를 인라인하지 않고 별도 파일로 내보내요. 컴포넌트만 가져오면 스타일은 하나도
딸려오지 않아요.

스타일시트를 불러오지 않아도 차트는 마운트되고 클릭에도 반응해요. 다만 스타일이 하나도 없어요.
토큰 선언과 색은 물론 고정 헤더, 막대 지오메트리, 컨테이너의 flex 컬럼, 레이아웃 계산이 전제하는
`box-sizing: border-box`까지 모두 이 파일에 있어요. 불러오지 않으면 차트를 읽기 어려워요.

`box-sizing`은 `.gantt-container`와 그 하위 요소에만 적용돼요. 라이브러리는 전역 리셋을 넣지
않으니 자체 리셋이 있는 앱에 불러와도 충돌하지 않아요.

## theme prop

`theme`은 생략할 수 있고 `'light'`, `'dark'`, `'system'` 중 하나를 받아요.

```tsx
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  { id: 'spec', name: 'Spec', parentId: null, sequence: '1',
    startDate: '2026-03-02T00:00:00Z', endDate: '2026-03-06T00:00:00Z' },
];

export function DarkChart() {
  return <ReactGanttChart tasks={tasks} theme="dark" height={480} />;
}
```

아래 데모는 `theme="dark"`로 고정돼 있어요. 명시한 prop이 호스트 페이지보다 우선하니 사이트의
테마 스위치를 눌러도 바뀌지 않아요.

<GanttDemo preset="dark" />

컨테이너에는 항상 결정된 `data-theme`이 붙고 스타일시트는 이 속성만 읽어요. 무엇이 값을 정하는지는
아래 표에 정리했어요.

| `theme` | `data-theme` | 결정하는 것 |
|---|---|---|
| `'light'` | `"light"` | prop |
| `'dark'` | `"dark"` | prop |
| `'system'` | `"light"` / `"dark"` | OS의 `prefers-color-scheme` |
| *(생략)* | `"light"` / `"dark"` | 호스트 페이지의 `color-scheme` |
| `'system'` 또는 생략, 서버 렌더와 첫 하이드레이션 렌더 | `"light"` | 고정값이에요. 문서가 없으면 OS 설정도 호스트 페이지의 `color-scheme`도 읽을 수 없어요 |

`className`은 클래스 속성 뒤에 붙을 뿐 테마와는 무관해요. `className="my-chart"`는
`gantt-container my-chart`가 돼요. 테마는 `data-theme`에만 실리니 `dark`나 `light`라는 호스트
클래스가 prop과 충돌하지 않아요.

props와 기본값은 [GanttProps](ref/props)에 있어요.

### 호스트 페이지 따라가기

`theme`을 생략하는 것과 `theme="light"`는 달라요. prop이 없으면 `<html>`에서 읽은 페이지의
`color-scheme`을 따라가요.

```css title="호스트 앱"
:root { color-scheme: light; }
.dark { color-scheme: dark; }
```

`color-scheme`은 플랫폼이 정한 라이트와 다크 신호이고 상속돼요. 주요 테마 스위치는 이미 이 값을
써요. `next-themes`는 `<html>`에 이 값을 쓰고 그 위에 올린 Tailwind나 fumadocs 구성도 마찬가지예요.
따라서 `theme` prop이 없는 차트는 추가 설정 없이 앱의 토글을 따라가요.

```tsx
// 앱이 가진 스위치가 이미 이 차트를 움직여요.
<ReactGanttChart tasks={tasks} height={480} />
```

`MutationObserver`가 `<html>`의 `class`, `style`, `data-theme` 변화를 감시해요. 토글을 누르면
새로고침이나 리마운트 없이 다음 렌더에서 차트가 다시 칠해져요.

읽고 감시하는 대상은 `<html>`뿐이에요. `color-scheme`은 상속되니 `:root`에 쓴 규칙 하나로 페이지
전체를 덮을 수 있어요. `<body>`나 래퍼에만 설정한 값은 차트에 적용되지 않아요.

페이지의 `color-scheme`이 `light dark`면 어느 쪽이든 괜찮다는 뜻이라 `theme="system"`처럼 OS
설정이 결정해요. 한 번도 설정하지 않은 페이지는 `normal`로 계산되고 차트는 이를 라이트로 읽어요.

### system 감지

`theme="system"`은 `useSyncExternalStore`로 `window.matchMedia('(prefers-color-scheme: dark)')`를
읽고 호스트 페이지는 무시해요. 앱 테마가 고정된 화면에서도 차트만 OS를 따라가야 할 때 쓰세요.
차트를 앱에 맞추려면 `theme`을 생략하세요.

서버 스냅샷은 `"light"`로 고정돼요. 문서가 없으면 호스트의 `color-scheme`도 OS도 읽을 수 없기
때문이에요. `'light'`나 `'dark'`를 명시하면 감지를 건너뛰고 서버에서도 그 값으로 렌더링돼요.
`'system'`이거나 prop을 생략한 경우에는 `next-themes`처럼 페인트 전에 테마를 정하는 호스트에서 첫
클라이언트 렌더부터 정확해요. 정적 HTML만 라이트 상태를 잠깐 보여줘요.

## 커스텀 속성

토큰 26개는 모두 `.gantt-container`에 선언돼요. `:root`에 두면 호스트 앱의 `--background`나
`--border`와 충돌하기 때문이에요.

다크 블록은 그중 20개를 다시 정의해요. 나머지 6개는 다시 정의하지 않고 아래 표의 다크 열에 같음으로
표시했어요.

스타일시트는 컨테이너에 `color-scheme`도 설정해요. 기본은 `light`이고 다크 블록에서는 `dark`예요.
그래서 차트 안의 스크롤바와 캐럿 같은 브라우저 요소도 테마에 맞게 칠해져요.

### 진행률

| 토큰 | 라이트 | 다크 | 칠하는 곳 |
|---|---|---|---|
| `--gantt-progress-bg` | `#8e8e97` | `#6c6c76` | 막대 안의 진행률 채움. 두 테마 모두 전경 쪽으로 한 단계 가까워서 채워진 부분이 막대와 구분되고 위의 라벨도 읽혀요 |
| `--gantt-progress-handle` | `#52525b` | `#a1a1aa` | 진행률 핸들 테두리. 채움은 `--gantt-background`예요 |

요약 행의 롤업 채움은 `--gantt-progress-bg`를 읽지 않아요. `--gantt-foreground`를 25% 불투명도로
써서 작업 막대의 채움보다 한 단계 차분해요. 진행률 토큰을 덮어써도 바뀌지 않아요.

### 의존성 화살표

| 토큰 | 라이트 | 다크 | 칠하는 곳 |
|---|---|---|---|
| `--gantt-arrow` | `#a1a1aa` | `#71717a` | 화살표 선과 화살촉 채움 |

화살표는 평소 45% 불투명도로 그려져서 조밀한 차트가 링크에 묻히지 않아요. 선택되거나 호버될 때,
그리고 호버되거나 선택된 작업에 붙어 있을 때는 불투명도가 100%가 돼요. 선택되거나 호버된 화살표는
색도 `--gantt-accent`로 바뀌어요.

### 비근무일

| 토큰 | 라이트 | 다크 | 칠하는 곳 |
|---|---|---|---|
| `--gantt-non-working-bg` | `rgba(0, 0, 0, 0.035)` | `rgba(255, 255, 255, 0.03)` | 음영 처리된 비근무일 열. 자체 `color`가 없는 휴일도 포함돼요 |

어떤 날을 음영 처리할지는 `showNonWorkingDays`, `workingWeekdays`, `holidays`가 정해요.
[타임라인](timeline)을 참고하세요.

휴일의 `color`는 그 휴일이 차지하는 열에서만 이 토큰을 대신해요. 진하게 칠하지 않고 비근무일 음영과
같은 세기로 옅게 물들여요. 토큰이 아니라 prop이라 색 하나가 두 테마에 함께 쓰여요. 휴일 이름이
표시되는 셀은 `.gantt-holiday-cell`이고 자기가 놓인 눈금 행처럼 `--gantt-muted`와
`--gantt-foreground`를 써요.

### 상세 패널

| 토큰 | 라이트 | 다크 | 칠하는 곳 |
|---|---|---|---|
| `--gantt-detail-width` | `320px` | 같음 | 도킹된 상세 패널의 너비 |

레이아웃 토큰이라 다크 블록은 이 값을 다시 정의하지 않아요. 열린 패널의 flex-basis이고 패널은 `0`과
이 값 사이를 오가요. 패널 색은 위의 토큰들에서 가져와요. [상세 패널](detail-panel)을 참고하세요.

### 타이포그래피와 모션

| 토큰 | 라이트 | 다크 | 칠하는 곳 |
|---|---|---|---|
| `--gantt-font-sans` | `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", "Geist", system-ui, sans-serif` | 같음 | 컨테이너의 `font-family` |
| `--gantt-duration-fast` | `150ms` | 같음 | 막대 툴팁의 페이드인에만 쓰여요. `animation` 단축 속성은 이징이 포함된 값을 거부해서 지속 시간만 담아요 |
| `--gantt-transition-fast` | `150ms ease` | 같음 | 막대 배경, 펼침 버튼 화살표의 회전, 크기 조절 그립, 행 그립, 링크 핸들, 진행률 핸들의 페이드 |
| `--gantt-transition-normal` | `200ms ease` | 같음 | 막대의 box-shadow 트랜지션 |

폰트는 번들에 포함되지 않고 어디서 받아오지도 않아요. 스타일시트가 Pretendard를 이름으로 지정하기
때문에 이 폰트를 제공하는 호스트에서는 Pretendard가 쓰이고 그 외에는 시스템 폰트로 넘어가요. 폰트
제공은 호스트 앱의 몫이에요. 문서 사이트는 서브셋한 가변 폰트를 `next/font`로 직접 호스팅해요.
기본 폰트 크기는 `13px`이고 토큰이 아니에요.

`@media (prefers-reduced-motion: reduce)` 아래에서는 컨테이너 안의 모든 트랜지션과 애니메이션이
`0.01ms`로 강제되고 `scroll-behavior`는 `auto`가 돼요. 모션 토큰을 어떻게 설정했든 마찬가지예요.

## 토큰 덮어쓰기

덮어쓸 값은 `.gantt-container`에 선언하고 스타일시트는 라이브러리 스타일시트 뒤에 불러오세요. 두
규칙의 명시도가 같아서 소스 순서가 결정해요.

```css title="app.css"
.gantt-container {
  --gantt-font-sans: "Inter", system-ui, sans-serif;
}
```

다크 블록이 다시 정의하지 않는 토큰 6개는 규칙 하나로 충분해요. `--gantt-font-sans`,
`--gantt-accent`, `--gantt-detail-width`와 모션 토큰 세 개예요. 나머지 20개는 규칙 두 개가
필요해요.

> [!WARNING]
> `.gantt-container`에 한 줄로 쓴 덮어쓰기는 라이트 모드에서는 이기고 다크 모드에서는 져요.
> 라이브러리의 다크 규칙은 `.gantt-container[data-theme="dark"]`로 명시도가 `(0,2,0)`이고
> `.gantt-container`만 쓴 규칙은 `(0,1,0)`이라 여기에 밀려요.

테마가 적용된 토큰은 테마당 하나씩 규칙 두 개가 필요해요.

```css title="app.css"
.gantt-container {
  --gantt-bar-bg: #dbeafe;
  --gantt-bar-bg-hover: #bfdbfe;
}

.gantt-container[data-theme="dark"] {
  --gantt-bar-bg: #1e3a5f;
  --gantt-bar-bg-hover: #2b4f7d;
}
```

토큰을 `:root`에 설정하면 효과가 없어요. 토큰은 `.gantt-container` 자체에 선언돼 있고 요소에 직접
붙은 선언이 상속된 값보다 우선해요.

소스 순서는 같은 캐스케이드 레이어 안에서 명시도가 같을 때만 우선순위를 정해요.
`@import '@jaeungkim/gantt-chart/style.css' layer(gantt)`처럼 라이브러리 스타일시트를 레이어로
가져오면 레이어 순서가 우선순위를 대신 정하고 레이어 없이 쓴 규칙이 이겨요.

### 차트 하나에만 적용하기

`className`을 넘기고 모든 선택자에 그 클래스를 덧붙이세요. 선택자마다 라이브러리보다 클래스가 하나
더 붙어서 대응하는 블록을 이겨요.

```tsx
<ReactGanttChart tasks={tasks} className="planning-chart" height={480} />
```

```css title="app.css"
.gantt-container.planning-chart {
  --gantt-bar-bg: #dbeafe;
}

.gantt-container.planning-chart[data-theme="dark"] {
  --gantt-bar-bg: #1e3a5f;
}
```

### 작업별 색

작업의 `color`는 그 막대에 인라인 `--gantt-bar-color`로 쓰이고 막대는 테마 토큰보다 이 값을 먼저
읽어요. 색을 지정한 작업은 막대 토큰을 무시해요. 라벨 색도 같은 값에서 파생되므로 `--gantt-bar-text`는
작업 색이 없는 막대에만 적용돼요. [스타일링](styling)을 참고하세요.

## 한계

테마가 다루지 않는 것은 다음과 같아요.

- `GanttTheme`은 값 세 개짜리 유니온이에요. `tokens` prop이나 테마 객체, 내보내는 기본 팔레트는
  없어요.
- 의존성 삭제 글리프의 선은 `#fff`로 하드코딩돼 있어 테마로 바꿀 수 없어요. 하드코딩된 색은 이것
  하나예요.
- 지오메트리는 토큰이 아니에요. 상단 헤더 행 `44px`, 하단 행 `28px`, 기본 폰트 크기 `13px`는
  변수가 아닌 고정값이에요. 행 높이는 `--gantt-row-height`로 나타나지만 컴포넌트가 JS 상수를
  인라인으로 쓰기 때문에 스타일시트로 덮어써도 밀려요.
- 상세 패널의 슬라이드는 고정된 `200ms ease`로 동작해요. 모션 토큰 세 개는 여기에 영향을 주지
  않아요.
- `--top-group-inset`은 컨테이너가 아니라 `.gantt-top-group`에 선언돼 있고 `--gantt-` 접두사도
  없어요. 호스트 앱은 이 값을 `.gantt-top-group`에서만 설정할 수 있어요.
- `light`와 `dark` 클래스는 아무 의미가 없어요. 예전 버전은 결정된 테마를 컨테이너 클래스로도
  썼지만 지금은 `data-theme`만 읽어요. `.gantt-container.dark { ... }`처럼 쓴 규칙은 라이브러리가
  붙이는 어떤 클래스에도 걸리지 않아요.
- 테마 프로바이더는 없어요. `theme`은 차트마다 넘기는 prop이지만 생략한 차트는 모두 페이지의
  `color-scheme`을 따라가니 `color-scheme` 규칙 하나로 전부 테마가 정해져요.
- 저장하는 값은 없어요. 결정된 테마도 배율도 어디에도 저장하지 않고 `sessionStorage`도 쓰지 않아요.
- RTL은 지원하지 않아요. `dir`을 읽거나 설정하지 않고 스타일시트는 전부 물리 속성을 써요.
- `theme` 값은 검증하지 않아요. 알 수 없는 값을 넘겨도 경고 없이 생략한 것처럼 동작해요.

호스트 앱이 직접 해야 하는 일은 다음과 같아요.

- `@jaeungkim/gantt-chart/style.css`를 자체 스타일시트보다 먼저 불러오세요.
- 테마가 적용된 덮어쓰기는 라이브러리의 선택자 두 개 아래에 모두 반복하세요.
- 새로고침 후에도 배율을 유지하려면 직접 저장하세요. `onScaleChange`로 받은 값을 다음 마운트에
  `defaultScale`로 넘기면 돼요. [타임라인](timeline)을 참고하세요.
- 앱의 라이트와 다크 상태를 바꿀 때 `color-scheme`도 함께 설정하세요. `theme` prop이 없는 차트는 이
  값을 따라가요. 차트별로 덮어쓸 때만 `theme`을 넘기세요.
- 토큰으로 표현할 수 없는 변경은 작업의 `className`으로 처리하세요. [스타일링](styling)을
  참고하세요.
