When one task depends on another, connect their bars with an arrow. People can see the relationship and add or remove links directly on the timeline.

Dependencies describe the plan; they do not reschedule it. Connecting Design to Build does not move Build's start date.

## Add a dependency to your data

Store the dependency on the task that waits. If Build waits for Design, put the entry on Build and set `targetId` to Design's id.

```tsx
const tasks: Task[] = [
  {
    id: 'design',
    name: 'Design',
    startDate: '2026-03-02',
    endDate: '2026-03-06',
    parentId: null,
    sequence: '1',
  },
  {
    id: 'build',
    name: 'Build',
    startDate: '2026-03-06',
    endDate: '2026-03-13',
    parentId: null,
    sequence: '2',
    dependencies: [{ targetId: 'design', type: 'FS' }],
  },
];
```

This draws an arrow from Design to Build. Import `Task` from `@jaeungkim/gantt-chart`; see [task types](ref/task) for the complete data shape.

The name `targetId` can be surprising: it identifies the predecessor, not the task at the arrowhead. Each entry also requires a link `type`.

## Choose the relationship

The first letter names the predecessor's edge; the second names the successor's edge. `S` is start and `F` is finish.

| Type | Relationship to represent |
|---|---|
| `FS` | Build starts after Design finishes |
| `SS` | Build starts after Design starts |
| `FF` | Build finishes after Design finishes |
| `SF` | Build finishes after Design starts |

These are scheduling meanings, not date constraints enforced by the chart. Your app decides whether the dates satisfy the relationship.

Each arrow leaves the predecessor's start or finish sideways, away from the bar. Its head enters the successor's start from the left (`FS`, `SS`) or its finish from the right (`FF`, `SF`).

## Draw a link

1. Hover or select the predecessor bar to reveal its connector dots.
2. Drag from its start or finish dot. A dashed line follows the pointer.
3. Move onto the successor bar or within 24px of either end. The line turns solid and a label shows the link type.
4. Release to create the link.

Where you release decides the type. The finish zone is the last third of the bar, at most 24px, plus the 24px to its right. The rest of the bar and the 24px to its left count as start. Releasing anywhere else creates nothing. In a lane containing several bars, the nearest bar within reach receives the link.

The timeline scrolls when you drag near its edges. Press `Escape` to cancel. On touch devices without hover, the connector dots remain visible.

In a lane, a start dot within 26px of the previous bar appears only while you hover its own bar, never on selection or touch. While it shows, it covers the previous bar's end. To resize that end, move off the hovered bar first, then approach the end from elsewhere. A hovered bar also rises above the next bar, so its finish dot stays reachable when the two touch. On touch, neither dot between two touching bars can be pressed.

Drawing rejects duplicate links between the same ordered pair and circular dependencies, and the source bar is never a target. A rejected target shows the reason in red and does not change the data. Those checks apply to drawing only; validate imported dependencies in your app.

## Save or reject changes

Keep `onTasksChange` connected to your state to retain created and deleted links. Add a synchronous guard when your app permits only certain relationships. This example accepts finish-to-start links only:

```tsx
<ReactGanttChart
  tasks={tasks}
  onTasksChange={setTasks}
  onDependencyCreate={({ type }) => {
    if (type !== 'FS') return false;
  }}
/>
```

Returning exactly `false` from `onDependencyCreate` cancels the change. `onDependencyDelete` works the same way, and a rejected delete leaves the arrow selected with its menu open. These guards do not await promises; perform server validation in your application's save flow.

Use `allowLinkCreate` and `allowLinkDelete` to control whether links can be edited. Disabling creation on a task blocks both incoming and outgoing links. Deletion permission belongs to the successor, which owns the entry.

See [props](ref/props) for callback signatures and [interaction configuration](ref/interaction-config) for permission precedence.

## Remove a link

Click an arrow to select it. It turns accent-colored, and a small menu with one delete button (×) opens at the click point.

The delete button removes the link. Clicking anywhere else closes the menu and clears the selection. An arrow is clickable only when its successor allows link deletion.

There is no way to change a link's type in place. Delete the link and draw it again: the dot you start from sets the type's first letter, and where you release sets the second. You can also edit the entry's `type` in your `tasks` array.

Keep one entry per predecessor and successor pair. A deletion removes every entry for that pair, even if their types differ.

## When an arrow is missing

Both tasks must be visible for their arrow to render. Filtering out a task or collapsing its parent hides the arrow without removing the dependency. An entry referring to an unknown task id is also skipped.

Arrows cannot be selected as a group. Routes are automatic and may cross other bars.
