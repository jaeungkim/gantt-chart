A drag ends wherever the pointer let go. Drop a bar one day too far and the task starts on a
Saturday — a start date on a day nobody works, written into your data the moment you release.
`workingCalendar` moves that landing forward onto the next working day.

## The working calendar

`workingCalendar` is a boolean and defaults to `false`. On, the chart builds a calendar that skips
non-working days and hands it to the bar drag. Off, the drag gets a calendar that counts every day,
which is plain calendar arithmetic.

```tsx
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';

export function WorkWeek({ tasks, setTasks }: {
  tasks: Task[];
  setTasks: (next: Task[]) => void;
}) {
  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
      workingCalendar
      holidays={['2026-09-21']}
    />
  );
}
```

The calendar is built from the same predicate that shades the timeline. Without a custom
`isNonWorkingDay`, a day is non-working when it is a Saturday, a Sunday, or a date listed in
`holidays`, matched as `YYYY-MM-DD` in UTC. So what is shaded and what is skipped cannot drift apart.
The shading itself, and both of those props, belong to [The timeline](timeline).

`isNonWorkingDay` replaces that whole check when you pass it. The chart always hands the calendar a
predicate, so `workingWeekdays` — the option a hand-built calendar can set — is unreachable through
the component. A work week that is not Monday to Friday has to be written as an `isNonWorkingDay`
function, or built directly with `createWorkingCalendar`; both are in
[Working calendar](ref/core-calendar).

### The drop snap

The snap is the only thing the calendar does to a gesture. The edge that moved lands on a working
day, and whatever moves with it follows by the same number of days.

| Gesture | Edge that snaps | The other edge |
|---|---|---|
| Move | the start | follows by the same days, so the span is kept |
| Left resize | the start | stays, so the bar comes out shorter |
| Right resize | the end | stays, so the bar comes out longer |

The snap is measured in whole days and only ever goes forward, so the time of day survives it. A
left-edge resize that would snap past the bar's own end does not snap at all.

### What it does not change

Bar geometry never sees the calendar. A bar that spans a weekend still spans it on screen; the
calendar only decides where a drop lands. The timeline ticks and the header cells are untouched for
the same reason. So is the shading, which has its own prop.

The drag step itself is still calendar-day based. The pointer-to-date conversion counts every day and
the calendar only adds the forward snap on top of it, so a move preserves the bar's calendar-day span
rather than its working-day span.

## A worked example

One task, all times UTC, `workingCalendar` on and no holidays.

```ts
import type { Task } from '@jaeungkim/gantt-chart';

export const tasks: Task[] = [
  {
    id: 'audit', name: 'Content audit', parentId: null, sequence: '1',
    startDate: '2026-09-01T09:00:00Z', endDate: '2026-09-04T17:00:00Z',
  },
];
```

`09-01` is a Tuesday and `09-04` a Friday, so the bar sits inside one work week. Drag it at the day
scale and let go:

| Gesture | Without `workingCalendar` | With it |
|---|---|---|
| move 3 days later | `09-04 09:00 - 09-07 17:00` | the same: Friday is a working day |
| move 4 days later | `09-05 09:00 - 09-08 17:00` | `09-07 09:00 - 09-10 17:00` |
| right edge 1 day later | `09-01 09:00 - 09-05 17:00` | `09-01 09:00 - 09-07 17:00` |

The four-day move lands on a Saturday, so the start snaps two days on to Monday and the end follows
by two days as well. The bar keeps its three-day span. The resize snaps the end alone, from Saturday
to Monday, so that bar ends two days later than the pointer asked for.

Add `holidays={['2026-09-07']}` and the four-day move goes one day further still, to
`09-08 09:00 - 09-11 17:00`.

## Limits

The snap runs on a drop and nowhere else. Loading a new `tasks` array, drawing a link, or editing a
date in a form all leave the dates exactly where you put them, weekend or not.

It is forward-only, and it can be overruled. The `minDate` / `maxDate` clamp runs after it and wins,
so a bar pinned to a bound can sit on a Saturday. Those bounds are described in
[Editing tasks](editing).

The working calendar cannot be edited from the chart. It is data you pass in.
