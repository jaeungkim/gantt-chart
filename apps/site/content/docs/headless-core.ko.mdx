한 주치 타임시트가 들어오면 야간 배치가 부모 행을 다시 집계해요. 어떤 테스트는 손자 작업의 이동이
할아버지 작업까지 올라가는지 검증해요. 어떤 API 엔드포인트는 누가 브라우저를 열기도 전에 단계(phase)의
종료일을 돌려줘요. 셋 다 React 트리도, 스타일시트도, DOM도 필요 없어요. 차트가 돌리는 트리 계산과
달력 계산은 평범한 함수 묶음이고, 그 함수들은 밖으로 export돼 있어요.

## 코어는 React를 import하지 않고 DOM을 건드리지 않아요

`src/core/` 아래는 전부 데이터와 순수 함수예요. 런타임 의존성은 `dayjs`와 `utc` 플러그인뿐이에요. 이
디렉터리에서 `react`, `window`, `document`, `localStorage`, `navigator`, `requestAnimationFrame`을
grep하면 import도 전역도 하나도 안 나와요. 산문 주석 하나가 전부예요.

이 경계는 관례가 아니에요. `src/core/**/*.{ts,tsx}`에 걸린 eslint 블록이 `react`, `react-dom`,
`zustand`, `@tanstack/*`, 그리고 렌더 쪽 도메인 폴더 전부 - `shared/`, `timeline/`, `bars/`,
`dependencies/`, `rows/`, `task-list/`, `interaction/`, `detail/` - 의 import를 막아요. 두 번째
규칙은 `window`, `document`, `navigator`, `localStorage`, `sessionStorage`,
`requestAnimationFrame` 전역을 금지해요. 규칙에 달린 메시지는 "src/core must stay free of React,
the DOM and pixel math - keep render-side code in the domain folder it belongs to"예요.

호스트 앱은 이 함수들을 패키지 루트에서 가져와요. 컴포넌트를 가져올 때와 같은 지정자예요.

```ts
import { rollUpTasks, createWorkingCalendar, type Task } from '@jaeungkim/gantt-chart';
```

> [!IMPORTANT]
> `@jaeungkim/gantt-chart/core` 같은 서브패스는 없어요. `package.json`이 선언하는 건 `.`,
> `./style.css`, `./package.json` 셋뿐이에요. 번들 하나는 `src/index.ts`에서 빌드되고, 거기에
> React 컴포넌트가 딸려 들어와요. `react`, `react-dom`, `react/jsx-runtime`은 빌드 시점에
> external로 표시돼요. 그래서 `rollUpTasks`만 import하는 Node 스크립트도 peer dependency
> (`react`와 `react-dom`, `^18.0.0 || ^19.0.0`)가 설치돼 있고 해석돼야 해요. 소스는 헤드리스예요.
> 배포되는 산출물은 파일 하나고요.

## 역할별 export 목록

코어에서 런타임 값 8개와 타입 7개가 나와요. 함수는 세 그룹으로 나뉘어요. 모두가 다루는 작업 모델은
[작업 데이터](task-data)에서 설명해요.

### 트리 순회하기

`buildTaskTree`와 `collectSubtreeIds`는 `parentId`만 읽어요. `rollUpTasks`는 자식의 날짜와
`progress`까지 읽고요. 부모와 자식, 깊이를 한 번에 정규화하고 싶으면 `buildTaskTree`를 쓰세요. 한 행
아래 전부를 포함해야 하는 일괄 작업에는 `collectSubtreeIds`를 쓰고요. 차트가 그리는 요약 행 날짜를
리포트에도 그대로 써야 하면 `rollUpTasks`예요. 셋 다 순수 함수라, 서버도 브라우저가 보여 줄 구간을
그대로 만들어 낼 수 있어요.

```ts
type TaskNode = Pick<Task, 'id' | 'parentId'>;

function buildTaskTree(tasks: TaskNode[]): TaskTree;
function collectSubtreeIds(tasks: TaskNode[], rootId: string, tree?: TaskTree): string[];
function rollUpTasks(tasks: Task[], tree?: TaskTree): Task[];
```

`TaskNode`는 구조적 타입이고 그 자체로는 export되지 않아요. 위의 `Pick`을 직접 쓰거나 진짜 `Task`
객체를 넘기세요. 뒤의 두 함수에 있는 선택 인자 `tree`는 기본값이 새 `buildTaskTree(tasks)`예요.
반복문 안에서는 호출마다 다시 만들지 말고 미리 만든 트리를 넘기세요. 요약 행이 무엇을 덮어쓰는지는
[작업 목록과 계층](task-list)에, 전체 시그니처는 [트리 헬퍼](ref/core-tree)에 있어요.

### 행 옮기기

`sortTasksBySequence`, `validateMove`, `moveTask`는 행 순서를 담당하는 절반이에요. 차트가 행을 새
자리로 드래그할 때 돌리는 함수와 똑같아서, 서버가 적용한 이동은 차트가 놓았을 자리에 정확히 떨어져요.
행 순서는 `sequence`에 들어 있어요. `"2.1"`이 `"2"`의 첫 자식인 점(.) 경로라서,
`sortTasksBySequence`는 각 구간을 숫자로 비교하고(`"1.10"`은 `"1.9"` 뒤로 정렬돼요), `moveTask`는
배열에 끼워 넣는 대신 자리가 바뀐 모든 작업의 번호를 다시 매겨요.

```ts
function sortTasksBySequence<T extends Pick<Task, 'sequence'>>(tasks: T[]): T[];
function validateMove(
  tasks: Task[],
  move: GanttTaskMove,
  options: GanttMoveOptions
): GanttMoveRejection | null;
function moveTask(
  tasks: Task[],
  move: GanttTaskMove,
  options: GanttMoveOptions
): { tasks: Task[]; change: GanttTaskMoveChange } | null;
```

`validateMove`는 거부 사유를 돌려주고, 이동이 허용되면 `null`을 돌려줘요. `moveTask`는 이동을
적용해서 새 배열과, 이전 자리와 새 자리를 담은 `GanttTaskMoveChange`를 돌려줘요. `validateMove`가
거부하는 이동에는 `null`을 돌려주니, 이유가 필요하면 그쪽을 먼저 부르세요. 차트 안에서 이 함수들로
굴러가는 행 드래그는 [행 순서 바꾸기](reordering)에서 다뤄요. 필드와 옵션, 거부 사유 전부는
[트리 헬퍼](ref/core-tree)에 있어요.

### 달력 만들기

코어의 나머지 함수는 `WorkingCalendar`를 받지 않아요. 트리 헬퍼와 이동 헬퍼는 날짜를 아예 세지 않고요. 달력은
호스트 앱이 직접 호출하는 객체예요. 차트가 `workingWeekdays`와 `holidays` prop으로
만드는 객체와 같은 것이라, 리포트가 세는 날과 차트가 음영으로 칠하는 날이 어긋날 수 없어요.
`CALENDAR_DAYS`는 이레를 모두 세기 때문에 평범한 달력 계산이 돼요. `createWorkingCalendar`는 주말과
휴일을 건너뛰는 달력을 만들어요. 주말을 낀 닷새 구간이 사흘로 세지는 건 이 덕분이에요.

```ts
const CALENDAR_DAYS: WorkingCalendar;
function createWorkingCalendar(options?: WorkingCalendarOptions): WorkingCalendar;
```

반환되는 객체는 공개 API예요. `isWorkingDay`, `addDays`, `daysBetween`, `daysUntil`, `daysUpTo`,
`snapForward`와 `skipsNonWorkingDays` 플래그를 각각 따로 호출할 수 있어요. 호스트 앱이 자체 날짜
계산에 필요한 건 대개 이게 전부예요. 이 두 prop이 무엇을 음영으로 칠하는지는
[타임라인](timeline)에 있어요. 달력이 차트에서 무엇을 바꾸고 무엇을 그대로 두는지는
[근무일 달력](working-calendar)에서 다뤄요. 옵션과 우선순위는
[근무일 달력 헬퍼](ref/core-calendar)에 있고요. 여기 나온 prop의 시그니처와 기본값은
[GanttProps](ref/props)에 있어요.

## 전체 스크립트

단계 하나와 자식 셋을 넣는데, 단계에 적힌 날짜는 그 아래 내용과 맞지 않아요. 스크립트는 단계를 자식에서
다시 만들고, 각 행의 구간을 근무일 수로 출력해요.

```ts title="report.ts"
import dayjs from 'dayjs';
import utc from 'dayjs/plugin/utc';
import {
  buildTaskTree,
  collectSubtreeIds,
  createWorkingCalendar,
  rollUpTasks,
  type Task,
} from '@jaeungkim/gantt-chart';

dayjs.extend(utc);

const tasks: Task[] = [
  {
    id: 'P',
    name: 'Phase 1',
    startDate: '2025-06-02',
    endDate: '2025-06-03',
    parentId: null,
    sequence: '1',
  },
  {
    id: 'A',
    name: 'Survey',
    startDate: '2025-06-02',
    endDate: '2025-06-05',
    parentId: 'P',
    sequence: '1.1',
    progress: 100,
  },
  {
    id: 'B',
    name: 'Frame',
    startDate: '2025-06-05',
    endDate: '2025-06-10',
    parentId: 'P',
    sequence: '1.2',
    progress: 40,
  },
  {
    id: 'C',
    name: 'Wiring',
    startDate: '2025-06-06',
    endDate: '2025-06-13',
    parentId: 'P',
    sequence: '1.3',
  },
];

const calendar = createWorkingCalendar({ holidays: ['2025-06-06'] });
const tree = buildTaskTree(tasks);
const rolled = rollUpTasks(tasks, tree);

console.log('subtree:', collectSubtreeIds(tasks, 'P', tree).join(', '));

for (const task of rolled) {
  const days = calendar.daysBetween(
    dayjs.utc(task.startDate),
    dayjs.utc(task.endDate)
  );
  console.log(
    [
      '  '.repeat(tree.depthOf.get(task.id) ?? 0) + task.id,
      task.startDate.slice(0, 10),
      task.endDate.slice(0, 10),
      `${days}wd`,
      task.progress === undefined ? '-' : `${task.progress}%`,
    ].join('  ')
  );
}
```

출력은 이래요.

```text title="rollUpTasks 출력"
subtree: P, A, B, C
P  2025-06-02  2025-06-13  8wd  33%
  A  2025-06-02  2025-06-05  3wd  100%
  B  2025-06-05  2025-06-10  2wd  40%
  C  2025-06-06  2025-06-13  5wd  -
```

`P`는 `2025-06-03`에 끝난다고 적혀 있었지만 `2025-06-13`에 끝나는 것으로, 적어 준 적 없는 33%까지
달고 돌아와요. 두 숫자를 만든 집계 규칙은 [트리 헬퍼](ref/core-tree)에 있어요. `B`는 달력으로
닷새지만 근무일로는 이틀이에요. `2025-06-06`이 `holidays`에 들어 있고, 그 뒤 주말도 근무일이
아니니까요. 반복문의 `.slice(0, 10)`은 빈말이 아니라 실제로 일을 해요.
`A`, `B`, `C`는 손대지 않아서 넘긴 객체 그대로고 짧은 문자열을 그대로 갖고 있어요.
반면 `P`는 다시 쓰여서 완전한 ISO 문자열로 돌아와요.

## 코어가 하지 않는 일

**렌더링하지 않아요.** 막대 좌표도, 화살표 경로도, 눈금도, 음영도, 색도 없어요. 막대 위치는 렌더
레이어가 원본 날짜에서 계산하고, 그 코드는 여기에 하나도 없어요.

**메모이제이션하지 않아요.** `collectSubtreeIds`와 `rollUpTasks`의 `tree` 인자는 기본값이 새
`buildTaskTree(tasks)`예요. 그래서 반복문 안에서 부르면 호출할 때마다 트리를 다시 지어요. 위
스크립트처럼 트리를 한 번 만들어서 넘기세요. `validateMove`와 `moveTask`는 그런 인자가 아예 없어서
호출마다 작업을 다시 정렬하고 형제 목록을 다시 지어요. 캐싱은 전부 호스트 앱의 몫이에요.

**의존성을 읽지 않아요.** `Task.dependencies`는 데이터로 그냥 실려 갈 뿐이고, 코어의
어떤 함수도 이걸 들여다보지 않아요. 화살표를 그리는 건 렌더 레이어의 일이에요.
[의존성](dependencies)을 보세요.

**포맷하지 않아요.** 로케일도 없고 `Intl`도 없어요. 날짜는 문자열로 들어가서 문자열로 나와요. 읽는
사람이 보는 건 전부 차트가 만들거나 호스트 앱이 직접 만들어요. [로케일과 날짜 형식](i18n)을
보세요.

**날짜를 검증하지 않아요.** `startDate`보다 앞선 `endDate`, 파싱되지 않는 날짜 문자열. 어느 것도
검사하거나 거부하지 않아요. `rollUpTasks`는 읽을 수 없는 자식 날짜를 건너뛰고, 유한한 날짜를 내놓는
자식이 하나도 없으면 부모를 그대로 둬요. 그래서 잘못된 입력은 오류가 아니라 낡은 요약 행으로 나타나요.
넘기기 전에 데이터를 확인하세요.

**이동을 스케줄링하지 않아요.** `validateMove`가 검사하는 건 구조뿐이에요. 모르는 id, 순환,
`hierarchy`가 꺼진 상태의 부모 변경. 날짜나 의존성은 절대 보지 않아요. `moveTask`는 `sequence`와
`parentId`만 다시 쓰고 그 외에는 손대지 않아서, 행은 예전 날짜를 그대로 든 채 새 자리에 놓여요.

**부모 링크가 망가지면 실패 대신 끊어 버려요.** 데이터에 없는 작업을 가리키는 `parentId`, 자기 자신을
부모로 둔 작업, 순환하는 부모 사슬은 모두 링크가 끊기고 루트가 돼요. 그래서 `parentOf`와 `childIds`는
언제나 비순환이고, 위아래로 걸어도 무한 루프에 빠지지 않아요. 그런 일이 있었다고 알려 주지는 않아요.

**달력이 망가져도 실패하는 대신 슬그머니 어긋나요.** `workingWeekdays`를 빈 배열로 주면 모든 날이
비근무일이 되고, `addDays`는 평범한 달력 날짜로 되돌아가고 `snapForward`는 입력을 그대로 돌려줘요. 숫자는 틀리게 나오지만 아무것도 던지지 않아요.

**일부 헬퍼는 내부용이에요.** `getVisibleTasks`, `normalizeProgress`, 드롭 위치 헬퍼인
`buildTaskOrder`와 `moveForDrop`, 그리고 UTC `dayjs` 인스턴스는
`src/core`에 있지만 패키지 밖으로 다시 export되지 않아요. 이것들을 import하는 걸 전제로 설계하지
마세요. 달력 메서드에 `Dayjs`를 넘겨야 하는 호스트 앱은 위 스크립트처럼 자기 `dayjs`를 직접
가져와요.

**모든 날짜는 UTC예요.** 코어는 `dayjs.utc`로 파싱해요. 그래서 타임존이 없는 문자열(`'2025-06-02'`,
`'2025-06-02T09:00'`)은 서버의 로컬 시간이 아니라 UTC 벽시계예요. Asia/Seoul에서
오프셋 없이 로컬 타임스탬프를 쓰는 프로세스는 의도한 자리에서 아홉 시간 어긋나요.
`holidays` 항목이 UTC `YYYY-MM-DD`와 대조되는 것도 같은 이유예요.
날짜 계약 전체는 [작업 데이터](task-data)에 있어요.

다음: [트리 헬퍼](ref/core-tree). `TaskTree`의 필드, 거부 사유, 그리고 트리 함수와 이동 함수의 예외
상황이 하나도 빠짐없이 정리돼 있어요.
