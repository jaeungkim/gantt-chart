프로젝트 타임라인은 표 옆에 색깔 사각형이 늘어선 화면처럼 보여요. 그러다 첫 막대를 끌게 돼요.
드래그는 배율마다 달라지는 단위에 맞춰 붙어야 해요. 놓은 자리가 토요일인데, 아무도 토요일에 작업을
시작하지 않으니 착지점은 앞으로 밀려야 해요. 뒤에 있는 막대로 이어지는 화살표는 그 사이 행들을 피해
다시 그려야 해요. 그리고 프로젝트에 행이 4,000개라, 이 중 무엇도 DOM 노드를 4,000개 만들면 안 돼요.

표처럼 보이던 것 아래에는 가상화된 그리드, 드래그 시스템, 의존성 라우터, 근무일 달력이 깔려 있어요.

`@jaeungkim/gantt-chart`는 그 스택을 React 컴포넌트 하나로 묶은 것이에요. 차트를 그리고, 제스처를
처리하고, 무언가 확정될 때마다 호스트 앱에 새 `tasks` 배열을 넘겨요. 막대가 어디에 놓일지 정하는
날짜 연산은 같은 패키지 안에 있는 별도 계층이고, React를 쓰지 않아요. 그래서 서버나 워커가 아무것도
렌더링하지 않고 호출할 수 있어요.

```ts
import { ReactGanttChart, createWorkingCalendar, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';
```

런타임 의존성은 `dayjs`와 `zustand` 둘뿐이에요. `react`와 `react-dom`은
peer dependency로 받고, `^18` 또는 `^19`예요. 모든 prop은 선택이고, `tasks`의 기본값은 빈 배열이에요.
설치 명령과 처음 동작하는 차트는 [빠른 시작](quick-start)에 있어요.

## 무엇이 들어 있나요

### 렌더링

- 행과 시간 셀은 하나의 창에서 함께 가상화되고, 오버스캔은 5칸이에요. 그 창 밖의 막대도 함께 걸러내요.
- 왼쪽에는 작업 목록 패널이 있고, 끌 수 있는 분할선 뒤에 작업 이름을 나열해요 — [작업 목록과 계층](task-list) 참고.
- 타임라인 배율은 시간부터 연까지 여섯 가지이고, 배율마다 눈금 단위와 드래그 단위, 라벨 형식이 따로 있어요 — [타임라인](timeline) 참고.
- 의존성 화살표는 꺾은선으로 그려지고, 네 가지 링크 타입을 모두 지원해요 — [의존성](dependencies) 참고.
- 오늘 선과 비근무일 음영을 그려요 — [타임라인](timeline) 참고.

### 편집

- 막대를 끌어 옮기고, 양쪽 가장자리를 끌어 크기를 바꾸고, 핸들을 끌어 진행률을 정해요 — [작업 편집](editing) 참고.
- 마지막 행 아래 빈 공간을 끌면 새 작업을 그려요. 차트는 초안을 제안할 뿐, 행을 직접 추가하지는 않아요.
- 막대의 링크 핸들에서 다른 막대로 끌면 의존성이 생겨요. 화살표를 클릭해 선택한 뒤 Delete를 누르면 지워져요 — [의존성](dependencies) 참고.

### 날짜

- 근무일 달력은 놓은 자리가 주말이나 공휴일이면 착지점을 앞으로 밀어요 — [근무일 달력](working-calendar) 참고.
- 의존성 화살표는 그리고 편집할 뿐, 강제하지는 않아요. 움직이는 건 끌어 옮긴 그 막대뿐이에요.
- 트리와 달력 연산은 일반 함수로도 export되어, 렌더링 없이 호출할 수 있어요 — [헤드리스 코어](headless-core) 참고.

### 접근성

- 차트 전체가 하나의 ARIA treegrid예요. 각 행은 `aria-level`, `aria-posinset`/`aria-setsize`, `aria-rowindex`를 가져요.
- 그리드 본문은 로빙 탭 스톱 하나예요. 방향키로 행 사이를, 그리고 한 행의 셀 사이를 오가요. 나머지 탭 스톱은 패널 분할선 하나뿐이에요.
- 막대는 키보드로 옮기고, 크기를 바꾸고, 진행률을 단계별로 조절해요 — [키보드와 스크린 리더](accessibility) 참고.
- Ctrl/Cmd + ArrowUp과 ArrowDown이 타임라인 배율을 더 촘촘하게, 더 성기게 옮기고 새 배율을 알려 줘요.
- 막대의 접근성 이름은 작업 이름과 날짜, 진행률로 만들어져요.

### 테마

- `theme`은 `'light'`, `'dark'`, `'system'`을 받아요. 생략하면 테마 클래스가 붙지 않고, 직접 쓴 CSS가 결정해요 — [테마](theming) 참고.
- 테마 토큰은 `--gantt-*` 커스텀 속성이고, `:root`가 아니라 `.gantt-container`에 한정돼요. 그래서 앱의 변수와 충돌하지 않아요. box-shadow 두 개와 `#fff` 값 두 개는 리터럴로 남아 있어요.
- 작업별 `color` 값 하나로 막대와 진행률 채움, 호버 음영 색이 정해져요 — [커스텀 렌더링](custom-rendering) 참고.
- `renderTooltip`과 `renderHeaderCell`이 기본 요소를 대체해요.
- `locale`은 헤더와 툴팁, 드래그 readout 날짜를 `Intl.DateTimeFormat`으로 그려요. `formats`는 그 셋을 배율마다 덮어써요 — [로케일과 날짜 형식](i18n) 참고.

## 하지 않는 것

**서버도 없고, 데이터 페칭도 없어요.** 소스 어디에도 `fetch`, `XMLHttpRequest`, `WebSocket`이 없어요.
작업은 prop으로 들어와요. 렌더링된 타임라인 범위가 바뀌면 `onRangeChange`가 발생하고, 더 불러오는
지점이 바로 여기예요.

**크롬이 없어요.** 차트는 타임라인을 그리고, 요청했을 때 작업 목록 패널을 그려요. 자기 컨트롤은
하나도 그리지 않아요. 툴바도, 배율 선택기도, 확대 버튼도, 접기 버튼도 없어요. 배율은 ref의
`setScale`이나 Ctrl/Cmd + ArrowUp / ArrowDown으로 바꿔요. 그리고 `onScaleChange`가 모든 변경을
알려 주니 직접 만든 컨트롤이 차트를 따라갈 수 있어요. 여기에 맞물리는 `<select>`는
[빠른 시작](quick-start)에 있어요.

**아무것도 저장하지 않아요.** 작업 데이터도, 배율도, 패널 너비도, 접힌 행도, 스크롤 위치도,
테마도요. 예전에는 배율이 `sessionStorage`를 거쳐 다시 마운트해도 살아남았어요. 그 경로도, 키
이름을 정하던 `storageKey` prop도 지금은 없어요. 배율은 이제 차트 인스턴스의 평범한 상태예요.

**리소스나 비용 모델이 없어요.** `Task`에는 담당자도, 공수도, 단가도, 비용 필드도 없어요 —
[작업 데이터](task-data) 참고. 리소스 패널도, 히스토그램도, 부하 평준화도 없어요. 스윔레인은
넘겨준 문자열로 행을 묶을 뿐, 사람이 무엇인지는 몰라요.

**검증도 거의 하지 않아요.** id가 유일한지, `endDate`가 `startDate` 뒤인지, 날짜 문자열이 파싱되는지
아무것도 확인하지 않아요. 잘못된 값은 예외를 던지지 않고 조용히 어긋나요. 파싱되지 않는 날짜는
타임라인 전체를 가로지르는 막대를 그려요. 유일한 예외는 `sequence`예요. 이 값이 없는 작업은 렌더링
도중 `TypeError`를 던지는데, 행 정렬이 그 문자열을 split하기 때문이에요.
[작업 데이터](task-data)를 참고하세요.

**일정을 자동으로 다시 잡지 않아요.** 막대를 끌면 그 막대가 움직이고, 요약 행이면 하위 트리까지
따라와요. 선행 작업이 움직였다고 후행 작업이 따라 움직이는 일은 링크가 무엇이든 없어요.
[의존성](dependencies)을 참고하세요.

**내보내기도, 인쇄 경로도 없어요.** 차트를 PNG나 SVG, PDF, CSV, 클립보드로 바꿔 주는 것은 아무것도
없고, 스타일시트에 인쇄용 규칙도 없어요. 차트에서 나가는 것은 `tasks` 배열이에요.

**React 전용이에요.** `react`와 `react-dom`은 peer dependency예요. 헤드리스 코어는 React도 DOM 접근도
쓰지 않고 만들었어요. 하지만 패키지는 진입점이 하나뿐이고 `./core` 서브패스가 없어요. 그래서 Node에서
`createWorkingCalendar`를 import해도 React peer가 있어야 하는 번들로 이어져요.

**내장 문구는 영어이고, 대부분 고정이에요.** ARIA 라벨과 스크린 리더 안내는 하드코딩되어 있어요 —
`"Gantt chart"`, `"Resize task list"`, `"Delete FS dependency"`, 그리고 배율이 바뀌면
`"week scale"`처럼 키를 그대로 읽어 줘요 — 문자열 번들도 `messages` prop도 없어요. prop으로 바꿀
수 있는 라벨은 `ungroupedLabel` 하나뿐이에요. 차트 바깥에 직접 그린 것은 전부 내 문구라,
배율 컨트롤의 옵션 라벨은 나머지 UI와 함께 번역돼요. RTL도 지원하지 않아요. 스타일시트가 전부 물리
속성을 쓰기 때문이에요.

### 호스트 앱이 하는 일

- `tasks` 배열을 소유하고 저장해요. 차트는 스스로 행을 추가하지 않아요.
- 커밋을 하나씩 반영해요. 확정된 제스처는 새 배열과 함께 `onTasksChange`로 끝나요.
- 차트에서 그려진 작업에 `id`, `parentId`, `sequence`를 채워 줘요.
- 날짜와 id를 `tasks` prop에 닿기 전에 검증해요.
- `onRangeChange`에서 데이터를 더 불러와요.
- 배율 컨트롤을 비롯해 차트 주위의 크롬을 직접 그려요.

## 어디부터 읽을까요

먼저 [개념과 용어](concepts)부터 읽어 보세요. 나머지 문서가 쓰는 말을 여기서 고정해요. 작업, 막대,
행, 눈금, 레인, 선행 작업 같은 말들이요. 그래서 뒤 페이지들이 짧게 끝나요.

그다음은 [빠른 시작](quick-start)이에요. 패키지를 설치하고 실제 데이터로 차트를 그려요.

그 뒤로는 만들려는 것에 해당하는 페이지로 가면 돼요.

| 만들려는 것 | 읽을 페이지 |
|---|---|
| 읽기 전용 타임라인 뷰 | [작업 데이터](task-data), 그다음 [타임라인](timeline) |
| 편집 가능한 계획 | [작업 편집](editing), 그다음 [이벤트](events) |
| 링크와 근무 주간이 있는 계획 | [의존성](dependencies), 그다음 [근무일 달력](working-calendar) |
| WBS 형태의 개요 | [작업 목록과 계층](task-list) |
| 팀별 또는 단계별 보드 | [그룹화와 스윔레인](grouping) |
| 디자인 시스템에 맞춘 차트 | [테마](theming), 그다음 [커스텀 렌더링](custom-rendering) |
| 차트 없는 날짜 연산 | [헤드리스 코어](headless-core) |

모든 prop은 [Props](ref/props) 한 곳에 정리되어 있어요.
