`@jaeungkim/gantt-chart`는 제어 컴포넌트처럼 동작하는 React 간트 차트예요. 컴포넌트 하나가 차트를
그리고 제스처를 처리해요. 편집이 확정될 때마다 다음 `tasks` 배열 전체를 넘겨줘요. 이 페이지는 패키지에 들어 있는
기능과 호스트 앱이 맡는 일을 다뤄요.

```ts
import { ReactGanttChart, createWorkingCalendar, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';
```

런타임 의존성은 `dayjs`와 `zustand` 둘뿐이에요. `react`와 `react-dom`은 peer dependency예요.
`^18`과 `^19`를 지원해요. 모든 prop은 선택이고 `tasks`의 기본값은 빈 배열이에요. 설치 명령과 처음
동작하는 차트는 [빠른 시작](quick-start)에 있어요.

## 패키지에 들어 있는 것

### 렌더링

- 행과 시간 열은 같은 스크롤 컨테이너를 기준으로 가상화돼요. 화면에 보이는 범위와 오버스캔 5칸만 그리고 오버스캔은 스크롤이 향하는 쪽으로 두 배가 돼요. 항목이 24개 이하이거나 이미 화면에 다 들어가는 축은 통째로 그려요. 막대와 의존성 화살표도 같은 범위를 기준으로 걸러내서 행이 4,000개인 계획도 화면에 들어가는 만큼만 마운트해요.
- 왼쪽 [작업 목록](task-list) 패널이 작업 이름을 나열해요. 끌 수 있는 스플리터가 그 뒤에 있고 행 번호도 선택해서 붙일 수 있어요.
- [타임라인 배율](timeline)은 일부터 연까지 다섯 가지이고 배율마다 눈금 단위와 드래그 단계, 라벨 형식이 따로 있어요.
- [의존성 화살표](dependencies)는 꺾은선으로 그려지고 네 가지 링크 타입을 모두 지원해요.
- 오늘 선과 비근무일 음영을 그려요. 휴일에는 색을 입히고 눈금 행에 이름을 적을 수 있어요. [타임라인](timeline) 참고

### 편집

- 막대를 끌어 옮기고 양쪽 가장자리를 끌어 크기를 조절하고 핸들을 끌어 진행률을 정해요. [작업 편집](editing) 참고
- 드래그하는 동안 바뀌는 날짜는 그 날짜가 놓일 눈금 셀에 표시돼요. 차트 위에 떠 있는 표시는 없어요.
- 마지막 행 아래를 끌면 새 작업을 그려요. 차트는 `onTaskCreate`에 초안을 넘길 뿐 행을 직접 추가하지 않아요. [작업 생성](task-creation) 참고
- 막대의 링크 핸들에서 다른 막대로 끌면 의존성이 생겨요. 화살표를 클릭해 선택한 뒤 Delete를 누르면 지워져요. [의존성](dependencies) 참고
- 상세 패널을 켜 두면 클릭 한 번으로 열리고 기본 본문에서 이름과 날짜, 진행률을 그 자리에서 고쳐요. [상세 패널](detail-panel) 참고

### 날짜

- [근무일 달력](working-calendar)은 놓은 날이 주말이나 휴일이면 다음 근무일로 옮겨요.
- 의존성 화살표는 그리거나 편집할 수 있어요. 다만 차트가 날짜를 강제하지는 않아요. 끌어 옮긴 막대만 움직여요.
- 트리와 달력 연산은 일반 함수로 내보내서 렌더링 없이 호출할 수 있어요. [헤드리스 코어](headless-core) 참고

### 접근성

- 차트 전체가 하나의 ARIA `treegrid`예요. 각 행은 `aria-level`과 `aria-posinset`/`aria-setsize`, `aria-rowindex`를 가져요.
- 그리드 본문은 로빙 탭 스톱 하나이고 나머지 탭 스톱은 패널 스플리터 하나예요. 방향키로 행 사이와 한 행의 셀 사이를 오가요.
- 막대는 키보드로 옮기고 크기를 조절하고 진행률을 단계별로 바꿔요. [키보드와 스크린 리더](accessibility) 참고
- Ctrl/Cmd + ArrowUp과 ArrowDown은 타임라인 배율을 더 촘촘하게 또는 더 성기게 바꾸고 새 배율을 알려요.
- 막대의 접근성 이름은 작업 이름과 날짜, 진행률로 만들어요.

### 테마

- `theme`은 `'light'`와 `'dark'`, `'system'`을 받아요. 생략하면 호스트 페이지의 `color-scheme`을 따라가요. 앱의 테마 토글이 이미 설정하는 값이에요. [테마](theming) 참고
- 테마 토큰은 `--gantt-*` 커스텀 속성이에요. `:root`가 아니라 `.gantt-container`에만 적용해서 앱의 변수와 충돌하지 않아요. `#fff` 값 하나는 리터럴로 남아 있어요.
- 작업별 `color` 값 하나에서 막대와 진행률 채움, 호버 음영, 잘 읽히는 라벨 색이 만들어져요. [스타일링](styling) 참고
- `renderDetail`은 상세 패널 본문을 대체해요. 커스텀 렌더러를 받는 자리는 여기 말고는 없어요. [상세 패널](detail-panel) 참고
- `locale`은 모든 날짜 라벨을 `Intl.DateTimeFormat`으로 그려요. `formats`는 배율마다 눈금과 헤더, 툴팁 라벨을 덮어써요. [로케일과 날짜 형식](i18n) 참고

## 제한 사항

네트워크 코드는 실행하지 않아요. 소스에 `fetch`나 `XMLHttpRequest`, `WebSocket` 호출이 없고 작업은
prop으로 들어와요. 렌더링된 타임라인 범위가 바뀌면 `onRangeChange`가 발생하니 여기에서 더 불러오세요.

차트는 타임라인을 그리고 호스트 앱이 요청하면 작업 목록 패널을 그려요. 자체 컨트롤은 그리지 않으니
툴바나 배율 컨트롤은 직접 만드세요. 배율은 ref의 `setScale`이나 Ctrl/Cmd + ArrowUp / ArrowDown으로
바꿔요. `zoomOnWheel`을 켜면 Ctrl/Cmd + 휠도 쓸 수 있어요. `onScaleChange`가 모든 변경을 알려 주니 그
컨트롤이 차트를 따라갈 수 있어요. 여기에 맞물리는 `<select>`는 [명령형 API](imperative-api)에 있어요.

작업 데이터와 배율, 패널 너비, 접힌 행, 스크롤 위치, 테마 중 무엇도 저장하지 않아요. 배율은 차트
인스턴스의 평범한 상태라 다시 마운트하면 `defaultScale`부터 다시 시작해요.

리소스나 비용 모델은 없어요. `Task`에는 담당자와 공수, 단가, 비용 필드가 없고 리소스 패널과
히스토그램, 부하 평준화도 없어요. `lane`은 호스트 앱이 넘긴 문자열로 작업을 한 행에 담을 뿐 사람이라는
개념은 없어요. [작업 데이터](task-data)와 [레인](lanes)을 참고하세요.

검증은 거의 하지 않아요. id가 유일한지, `endDate`가 `startDate` 뒤인지, 날짜 문자열이 파싱되는지
확인하지 않아요. 잘못된 값은 예외를 던지지 않고 그대로 그려져요. 파싱되지 않는 날짜는 타임라인 전체를
가로지르는 막대를 그려요. 예외는 `sequence` 하나예요. 이 값이 없는 작업은 렌더링 도중 `TypeError`를
던져요. 행 정렬이 그 문자열을 `split`으로 나누기 때문이에요. [작업 데이터](task-data)를 참고하세요.

일정을 자동으로 다시 잡지 않아요. 막대를 끌면 그 막대가 움직이고 요약 행이면 하위 트리까지 따라와요.
링크가 무엇이든 선행 작업이 움직였다고 후행 작업이 따라 움직이지는 않아요.
[의존성](dependencies)을 참고하세요.

내보내기와 인쇄 경로는 없어요. 차트를 PNG나 SVG, PDF, CSV, 클립보드 데이터로 바꿔 주는 기능이 없고
스타일시트에도 인쇄용 규칙이 없어요. 차트에서 나가는 것은 `tasks` 배열이에요.

React 전용이에요. `react`와 `react-dom`은 peer dependency예요. 헤드리스 코어는 React도 DOM도 쓰지
않고 만들었어요. 다만 패키지는 진입점이 하나뿐이고 `./core` 서브패스가 없어서 Node에서
`createWorkingCalendar`를 가져와도 React peer가 필요한 번들로 이어져요.

내장 문구는 영어이고 대부분 고정이에요. ARIA 라벨과 스크린 리더 알림은 `"Gantt chart"`나
`"Resize task list"`, `"Delete FS dependency"`처럼 하드코딩돼 있어요. 배율이 바뀌면 `"week scale"`처럼
키를 그대로 읽어요. 문자열 번들도 `messages` prop도 없어요. prop으로 바꿀 수 있는 라벨은 하나도
없어요. 차트 바깥에 직접 그린 것은 전부 앱의 문구라 배율 컨트롤의 옵션 라벨은 나머지 UI와 함께
번역돼요. 스타일시트가 전부 물리 속성을 써서 RTL은 지원하지 않아요.

## 호스트 앱의 역할

- `tasks` 배열을 저장하세요. 차트는 스스로 행을 추가하지 않아요.
- 확정된 편집을 반영하세요. 확정된 제스처는 새 배열과 함께 `onTasksChange`로 끝나요.
- 차트에 그릴 작업에 `id`와 `parentId`, `sequence`를 채워 주세요.
- 날짜와 id는 `tasks` prop에 닿기 전에 검증하세요.
- `onRangeChange`에서 데이터를 더 불러오세요.
- 배율 컨트롤을 비롯한 차트 주변 UI를 직접 그리세요.

쓰는 말을 여기에서 고정해요. 그래서 뒤 페이지가 짧게 끝나요.

그다음은 [빠른 시작](quick-start)이에요. 패키지를 설치하고 실제 데이터로 차트를 그려요.
