`GanttRow` describes the row model the chart renders — one entry per rendered row, in screen
order. It comes from the package root.

```ts
import type { GanttRow } from '@jaeungkim/gantt-chart';
```

For what a lane does and how lane-mates pack onto one row, see [Lanes](../lanes).

## GanttRow

```ts
/** One rendered row: one task, or several sharing a `lane` */
export interface GanttRow {
  /** Stable key - the ids on the row, joined with "+" */
  id: string;
  tasks: TaskTransformed[];
  /** Indentation level, 0-based */
  depth: number;
  /** `aria-level`, 1-based */
  level: number;
  /** `aria-posinset` among the rows that share a parent */
  posinset: number;
  /** `aria-setsize` for that same set */
  setsize: number;
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | `string` | See [Row ids](#row-ids). |
| `tasks` | `TaskTransformed[]` | One entry on a plain row, several when tasks share a `lane`. Never empty — every row is built from at least one task. |
| `depth` | `number` | 0-based, taken from the row's first task. Equal to that task's `depth`. |
| `level` | `number` | `aria-level`. Always `depth + 1`. |
| `posinset` | `number` | `aria-posinset` among the rows sharing this row's parent. A row's parent is the nearest row above it one `depth` shallower. |
| `setsize` | `number` | `aria-setsize` for that same set. Counts visible rows only — collapsing is applied before the rows are built. |

### Row ids

| Row kind | `id` | Example |
|---|---|---|
| Plain row | the task id | `"a"` |
| Lane row | the packed task ids joined with `"+"` | `"a+b"` |

One rule, really: an id is the row's task ids joined with `"+"`, and a one-task row leaves nothing
to join. On a lane row the tasks sit in start order, ties keeping their incoming order, and the ids
join in that same order.

A row id and a task id are therefore the same string on every plain row, which is what lets a
`collapsedIds` / `defaultCollapsedIds` entry name a row.

## Not exported

`src/rows/utils/rows.ts` also holds `buildGanttRows`, `packLanes` and `isRowExpandable`. None of
them are re-exported from the package, and none are part of the headless core — lane packing runs
on the render side.

## Notes

- No prop or callback hands you a `GanttRow`. The type is exported so host code can name the shape
  the chart works in — for reading `TaskTransformed.order`, or for matching a `collapsedIds` entry.
- `order` on a `TaskTransformed` is rewritten to the 1-based row number. Every task on a lane row
  reports the same `order`, because they share the row.
