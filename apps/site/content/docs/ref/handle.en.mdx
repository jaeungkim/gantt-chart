`GanttHandle` is the object a `ref` on the chart receives. It combines `GanttScrollApi`,
`GanttDetailApi` and `GanttTaskCreateApi`, so it carries the scroll and zoom methods, the two
detail panel methods and `addTask`. All six types on this page are type-only exports of the
package.

```ts
import type {
  GanttDetailApi,
  GanttHandle,
  GanttScrollApi,
  GanttScrollOptions,
  GanttTaskCreateApi,
  GanttZoomAnchor,
} from '@jaeungkim/gantt-chart';
```

## `GanttHandle`

```ts
/** Imperative API exposed through the ref */
export interface GanttHandle
  extends GanttScrollApi,
    GanttDetailApi,
    GanttTaskCreateApi {}
```

It declares no member of its own. Every method below is defined in one of the three interfaces it
extends. The chart builds the handle by spreading the scroll API and adding the two detail methods
and `addTask`.

### Members

| Member | Signature | Effect |
|---|---|---|
| `scrollToDate` | `(date: string \| Date \| Dayjs, options?: GanttScrollOptions) => void` | Scrolls horizontally so the date lands at the requested position. Does nothing when the date is outside the rendered timeline. |
| `scrollToToday` | `(options?: GanttScrollOptions) => void` | `scrollToDate` with the current instant. |
| `scrollToTask` | `(taskId: string, options?: GanttScrollOptions) => void` | Scrolls horizontally to the task's bar, and vertically only when its row is off screen. Does nothing for an id that no row shows. |
| `setScale` | `(scale: GanttScaleKey) => void` | Switches the scale and keeps the centre date in place. |
| `zoomToFit` | `() => void` | Switches to the finest scale at which the whole project fits the timeline width and pins the earliest task date to the left edge. |
| `getScrollElement` | `() => HTMLDivElement \| null` | Returns the chart's scroll container element, or `null` when the chart is not mounted. |
| `openDetail` | `(taskId: string) => void` | Opens the detail panel on that task. Does nothing for an id that names no task, or while the panel is off. |
| `closeDetail` | `() => void` | Closes the detail panel. |
| `addTask` | `() => void` | Calls `onTaskCreate` with a draft one tick long at today, snapped to the current scale. Does nothing while task creation is off. |

Every method except `getScrollElement` returns `void`.

## `GanttScrollApi`

```ts
/** Imperative scroll and zoom API */
export interface GanttScrollApi {
  /** Scroll horizontally to a given date */
  scrollToDate: (date: string | Date | Dayjs, options?: GanttScrollOptions) => void;
  /** Scroll horizontally to today */
  scrollToToday: (options?: GanttScrollOptions) => void;
  /** Scroll horizontally and vertically to a given task */
  scrollToTask: (taskId: string, options?: GanttScrollOptions) => void;
  /**
   * Switch the timeline scale
   *
   * The date at the centre of the timeline stays at the centre, so the view does not
   * jump the way a raw scale swap would. An unknown key is ignored, the way an unknown
   * task id is.
   */
  setScale: (scale: GanttScaleKey) => void;
  /**
   * Switch to the finest scale at which the whole project fits the viewport width
   *
   * Also scrolls the project into view. Does nothing while there are no tasks.
   */
  zoomToFit: () => void;
  /** The scroll container DOM node (null when unavailable) */
  getScrollElement: () => HTMLDivElement | null;
}
```

`Dayjs` is the object type from `dayjs`. The package does not re-export it, so import it from
`dayjs`. A plain string or `Date` is accepted and parsed as UTC. See [Task data](../task-data).

`GanttScaleKey` is the union of the five scale keys, listed in
[Scale and theme types](scales). The scale table that `setScale` checks its argument against is
internal and not exported.

## `GanttDetailApi`

```ts
/** Opening and closing the detail panel from outside the chart */
export interface GanttDetailApi {
  /**
   * Opens the detail panel on a task
   *
   * An unknown id is ignored, the way `scrollToTask` ignores one. Does nothing while
   * the panel is off - that is, while `showDetail` is false, or omitted with no `renderDetail`.
   */
  openDetail: (taskId: string) => void;
  /** Closes the detail panel */
  closeDetail: () => void;
}
```

The panel is on when `showDetail` is `true`. With `showDetail` omitted, it is on when
`renderDetail` is given. Both props, and the rest of the detail surface, are in
[GanttProps](props). While the panel is off, both methods do nothing, so a toolbar button wired
to `openDetail` needs no guard.

## `GanttTaskCreateApi`

```ts
/** Proposing a new task from outside the chart */
export interface GanttTaskCreateApi {
  /**
   * Proposes a new task, exactly as the "Add task" button under the task list does
   *
   * The draft is one tick at today, snapped to the current scale, and it goes to
   * `onTaskCreate` - the chart still adds nothing itself. Does nothing while task
   * creation is off - without `onTaskCreate`, or with the interaction props disallowing it.
   */
  addTask: () => void;
}
```

`addTask()` is the ref counterpart of the **Add task** button under the task list. It sends the
same draft to the same callback and does nothing while creation is off. When today is outside the
rendered timeline, the draft moves to the first tick. The row appears when the `tasks` array your
`onTaskCreate` builds includes it. [Creating tasks](../task-creation) describes the draft and what
turns creation off.

## `GanttScrollOptions`

```ts
/** Options for the scrollTo* methods */
export interface GanttScrollOptions {
  /** Whether to animate the scroll (default true) */
  smooth?: boolean;
  /** Where the target lands inside the viewport (default 'center') */
  align?: "start" | "center";
}
```

| Field | Type | Default | Effect |
|---|---|---|---|
| `smooth` | `boolean` | `true` | `false` scrolls with `behavior: "auto"`. Any other value, `undefined` included, animates with `behavior: "smooth"`. |
| `align` | `"start" \| "center"` | `"center"` | `"start"` puts the target at the left edge of the timeline area. `"center"` centres it in the timeline area, measured against the width that remains beside the task list pane. |

Horizontal targets are clamped with `Math.max(0, ...)`, so a target left of the timeline origin
scrolls to `0`.

`align` applies to the horizontal axis only. When `scrollToTask` scrolls vertically, it always
centres the row.

## `GanttZoomAnchor`

```ts
/** A date pinned at a fixed distance from the timeline's visible left edge */
export interface GanttZoomAnchor {
  date: Dayjs;
  /** px from the left edge of the timeline area (the task list pane excluded) */
  viewportX: number;
}
```

The package exports this type, but no member of `GanttHandle` accepts it. It describes the date
the chart keeps fixed on screen while the scale changes. `setScale`, `zoomToFit` and wheel zoom
each build their own anchor.

## Attaching the ref

```tsx title="TimelinePane.tsx"
import { useRef } from 'react';
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { GanttHandle, Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  {
    id: '1', name: 'Design', parentId: null, sequence: '1',
    startDate: '2025-06-01', endDate: '2025-06-10',
  },
  {
    id: '2', name: 'Build', parentId: null, sequence: '2',
    startDate: '2025-06-11', endDate: '2025-06-30',
  },
];

export function TimelinePane() {
  const chart = useRef<GanttHandle>(null);

  return (
    <>
      <button onClick={() => chart.current?.scrollToToday({ align: 'start' })}>
        Today
      </button>
      <button onClick={() => chart.current?.zoomToFit()}>Fit</button>
      <ReactGanttChart ref={chart} tasks={tasks} height={400} />
    </>
  );
}
```

## Early calls

`ref.current` is `null` until React commits the chart, and `null` again after it unmounts. A read
during the parent's render sees `null`. By the time the parent's `useEffect` or
`useLayoutEffect` runs, the handle is set. Guard with `?.` rather than `!`.

After the handle exists, the methods tolerate calls made before their data is ready. Each case
below returns without throwing and without a console warning.

| Call | Condition | Result |
|---|---|---|
| `scrollToDate` | the timeline has no ticks, or the date is before the first tick or past the end of the last | no scroll |
| `scrollToToday` | today is outside the rendered range | no scroll |
| `scrollToTask` | no row shows the id, because it is unknown or hidden under a collapsed parent | no scroll |
| `setScale` | the key is not one of the five scales | no scale change |
| `setScale` | the scroll container is not mounted, or the centre of the timeline area is not over a tick | the scale changes, with no anchor |
| `zoomToFit` | `tasks` is empty, or the scroll container is not mounted | no scale change, no scroll |
| `getScrollElement` | the chart is not mounted | `null` |
| `openDetail` | the id names no task in `tasks` | no open |
| `openDetail` | the panel is off, with neither `renderDetail` nor `showDetail` turning it on | no open |
| `closeDetail` | the panel is off, or already closed | nothing, and no `onDetailChange` |
| `addTask` | `onTaskCreate` is not given, `allowTaskCreate` is `false`, or `readOnly` is set without an overriding `allowTaskCreate` | no draft, no callback |
| `addTask` | the timeline has no ticks, because there are no tasks and no window pinned with `visibleStart` and `visibleEnd` | no draft, no callback |

## Notes

- The handle is rebuilt whenever the scroll API, either detail method or `addTask` changes
  identity. `getScrollElement` reads the ref on each call, so a handle captured earlier returns
  the current element.
- `scrollToDate` and `scrollToToday` never change `scrollTop`. Only `scrollToTask` scrolls
  vertically, and only when the target row is outside the viewport.
- No prop sets the scale after mount. `setScale` sets an exact scale from code. `defaultScale` is
  read once when the store is created, so a later change to it is ignored.
- The chart renders no scale picker. A picker in your app calls `setScale`. The `onScaleChange`
  prop in [GanttProps](props) reports a change made by the keyboard or the wheel.
- `zoomToFit` takes no `GanttScrollOptions`. Its scroll is instant, with no animation.
- `zoomToFit` tries the five scales in the order `day`, `week`, `month`, `quarter`, `year`, and
  falls back to `year` when the project fits none of them. See [The timeline](../timeline).
- Row height for the vertical `scrollToTask` math is a fixed 38px.
- `openDetail` resolves the id against every task, collapsed rows included. `scrollToTask` needs
  the row to be rendered. Collapsing a parent hides the row without closing the panel that
  describes it.
- With `detailTaskId` given, the chart is controlled and the two detail methods change nothing on
  their own. They report the request through `onDetailChange` and wait for the prop to follow.
  Without it they move the panel themselves and fire `onDetailChange` too.
- `addTask` does not scroll or change the scale. It calls `onTaskCreate` and the chart never
  writes to `tasks`.
- [Imperative API](../imperative-api) covers these methods in use.
