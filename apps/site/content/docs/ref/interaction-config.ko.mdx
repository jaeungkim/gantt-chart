`GanttInteractionConfig`는 상호작용 설정 중 차트 전체에 걸리는 쪽이에요. 권한 플래그 일곱 개,
전체를 덮는 `readOnly` 하나, 드래그 경계 두 개로 이루어져요. 타입은 패키지 루트에서 export되지만,
차트는 이 열 개 필드를 각각 별도 prop으로 받아 객체를 직접 조립해요. `interaction` prop은 없어요.

```ts
import type { GanttInteractionConfig } from '@jaeungkim/gantt-chart';
```

## GanttInteractionConfig

```ts title="src/shared/task.ts"
/** 차트 전체에 걸리는 상호작용 설정 - 기본으로 모든 제스처가 허용되고(작업 생성은 `onTaskCreate`도 필요해요), 같은 이름의 작업 필드가 이 값을 이겨요. */
export interface GanttInteractionConfig {
  readOnly?: boolean;
  allowMove?: boolean;
  allowResize?: boolean;
  allowProgressChange?: boolean;
  allowLinkCreate?: boolean;
  allowLinkDelete?: boolean;
  allowTaskCreate?: boolean;
  /** 행 순서 바꾸기를 켜요 - opt-in이에요(기본값 false). */
  allowReorder?: boolean;
  minDate?: string;
  maxDate?: string;
}
```

| 필드 | 타입 | 기본값 | 의미 |
|---|---|---|---|
| `readOnly` | `boolean` | `undefined` | 모든 작업의 모든 제스처를 막고, 상세 패널의 기본 필드도 읽기만 되는 텍스트로 남겨요. 어느 단계에서든 권한 플래그를 설정하면 그 플래그가 이겨요. 다만 패널의 **Name**은 예외예요. `readOnly` 단계만 읽어서, 권한 플래그를 어떻게 두든 읽기만 되는 텍스트로 남아요. |
| `allowMove` | `boolean` | `undefined` | 타임라인을 따라 막대를 끌어 옮기는 동작이에요. |
| `allowResize` | `boolean` | `undefined` | 막대의 어느 쪽 끝이든 끌어 크기를 바꾸는 동작이에요. 상세 패널의 **Start**와 **End**가 편집 가능한 날짜 입력이 되는지도 이 플래그가 정해요. |
| `allowProgressChange` | `boolean` | `undefined` | 진행률 핸들을 끄는 동작이에요. 상세 패널의 **Progress**가 편집 가능한 숫자 입력이 되는지도 이 플래그가 정해요. |
| `allowLinkCreate` | `boolean` | `undefined` | 막대의 핸들에서 의존성 드래그를 시작하는 동작이에요. |
| `allowLinkDelete` | `boolean` | `undefined` | 의존성 화살표를 선택해 지우는 동작이에요. |
| `allowTaskCreate` | `boolean` | `undefined` | 새 작업을 제안하는 동작이에요. **Add task** 버튼, `addTask()`, 그린 범위 모두요. 차트 전체 설정만 있어요. |
| `allowReorder` | `boolean` | `undefined` | 작업 목록 행을 끌어 다른 자리나 다른 부모로 옮기는 동작과, 같은 일을 하는 키보드 바인딩이에요. |
| `minDate` | `string` | `undefined` | 막대를 끌어 갈 수 있는 가장 이른 날짜예요. UTC ISO 문자열이에요. 상세 패널에 입력한 날짜도 이 경계로 잘려요. |
| `maxDate` | `string` | `undefined` | 막대를 끌어 갈 수 있는 가장 늦은 날짜예요. UTC ISO 문자열이에요. 상세 패널에 입력한 날짜도 이 경계로 잘려요. |

모든 필드를 비워 두면 모든 제스처가 허용되고 드래그 경계도 없어요. 예외가 둘 있어요.
`allowTaskCreate`는 `onTaskCreate` 콜백까지 있어야 해요 — 아래 [작업 생성](#작업-생성)을 보세요.
`allowReorder`는 비워 둔다고 허용되는 것이 전혀 아니에요 —
[canReorder는 이 사슬을 타지 않아요](#canreorder는-이-사슬을-타지-않아요)를 보세요.

같은 이름을 가진 `GanttProps`의 prop 열 개가 이 객체를 채워요.
[GanttProps](props)를 참고하세요. 이 값을 덮어쓰는 작업별 필드는
[Task와 작업 타입](task)에 있어요.

## 권한 해석

작업별 권한 여섯 가지는 각각 내부 함수 `resolveTaskInteraction`이 해석해요. 이 함수는 패키지
루트에서 **export되지 않아요**. 해석 순서를 여기 적는 이유는 호출할 수 있어서가 아니라, 이 순서가
차트의 동작을 결정하기 때문이에요.

```ts title="src/shared/task.ts"
// 우선순위: `task.allowX` > `task.readOnly` > `config.allowX` > `config.readOnly` > 허용.
// 요약 행은 크기를 바꿀 수 없고 진행률도 끌 수 없어요 - 둘 다 자식에서 집계돼요.
// 순서 바꾸기만 예외예요: 바닥이 `false`라서, 명시적인 플래그만 이것을 켜요.
export function resolveTaskInteraction(
  task: Pick<
    Task,
    | 'readOnly'
    | 'allowMove'
    | 'allowResize'
    | 'allowProgressChange'
    | 'allowLinkCreate'
    | 'allowLinkDelete'
    | 'allowReorder'
    | 'minDate'
    | 'maxDate'
  > & { isSummary?: boolean },
  config: GanttInteractionConfig = NO_INTERACTION_CONFIG
): ResolvedTaskInteraction {
  const resolve = (
    taskFlag: boolean | undefined,
    configFlag: boolean | undefined
  ): boolean => {
    if (taskFlag !== undefined) return taskFlag;
    if (task.readOnly !== undefined) return !task.readOnly;
    if (configFlag !== undefined) return configFlag;
    return !config.readOnly;
  };

  const canReorder =
    task.allowReorder ??
    (task.readOnly === true ? false : (config.allowReorder ?? false));

  const derived = task.isSummary === true;

  return {
    canMove: resolve(task.allowMove, config.allowMove),
    canResize:
      !derived &&
      resolve(task.allowResize, config.allowResize),
    canChangeProgress:
      !derived &&
      resolve(task.allowProgressChange, config.allowProgressChange),
    canCreateLink: resolve(task.allowLinkCreate, config.allowLinkCreate),
    canDeleteLink: resolve(task.allowLinkDelete, config.allowLinkDelete),
    canReorder,
    minDate: task.minDate ?? config.minDate,
    maxDate: task.maxDate ?? config.maxDate,
  };
}
```

아래 순서는 여섯 중 다섯이 밟는 순서예요. `canReorder`는 더 짧은 사슬을 따로 타요.
[canReorder는 이 사슬을 타지 않아요](#canreorder는-이-사슬을-타지-않아요)에서 다뤄요.

가장 구체적인 것부터, 순서는 이래요:

1. `task.allowX` — 작업이 이 권한의 플래그를 직접 들고 있으면, 그 값이 답이에요.
2. `task.readOnly` — 설정돼 있으면 그 값을 뒤집은 것이 답이에요.
3. `config.allowX` — 차트 전체에 걸리는 이 권한의 플래그예요.
4. `config.readOnly` — 이 값을 뒤집은 것이 답이에요. 비어 있으면 `false`로 읽혀서, 손대지 않은 차트는 제스처를 허용해요.

아래 표의 `—`는 그 필드가 `undefined`라는 뜻이에요.

| `task.allowX` | `task.readOnly` | `config.allowX` | `config.readOnly` | 결과 | 결정 단계 |
|---|---|---|---|---|---|
| `true` | 무엇이든 | 무엇이든 | 무엇이든 | 허용 | 1 |
| `false` | 무엇이든 | 무엇이든 | 무엇이든 | 차단 | 1 |
| — | `true` | 무엇이든 | 무엇이든 | 차단 | 2 |
| — | `false` | 무엇이든 | 무엇이든 | 허용 | 2 |
| — | — | `true` | 무엇이든 | 허용 | 3 |
| — | — | `false` | 무엇이든 | 차단 | 3 |
| — | — | — | `true` | 차단 | 4 |
| — | — | — | `false` | 허용 | 4 |
| — | — | — | — | 허용 | 4 |

이 사다리를 스니펫 하나로 보면 이래요. 차트는 잠겨 있고, 작업 하나의 플래그가 제스처 하나를 다시
열어요:

```tsx title="잠긴 차트, 살아 있는 진행률 핸들 하나"
<ReactGanttChart
  readOnly
  tasks={[
    {
      id: 'design',
      name: 'Design',
      startDate: '2026-03-02',
      endDate: '2026-03-06',
      parentId: null,
      sequence: '1',
    },
    {
      id: 'build',
      name: 'Build',
      startDate: '2026-03-09',
      endDate: '2026-03-20',
      parentId: null,
      sequence: '2',
      progress: 40,
      allowProgressChange: true,
    },
  ]}
/>
```

두 번째 작업의 `allowProgressChange`는 1단계에서 결정돼서, 그 진행률 핸들은 여전히 끌려요.
두 작업의 나머지 제스처는 모두 4단계까지 떨어지고, 거기서 `readOnly`가 막아요.

### 여섯 가지 권한

여섯 중 다섯은 위 사슬을 따라 필드 한 쌍을 읽고, 마지막 열의 구조적 마스크가 그 결과 앞에
`&&`로 붙어요. `canReorder`는 표 아래에서 설명하는 더 짧은 사슬로 자기 쌍을 읽어요.

| 해석된 권한 | `Task` 필드 | `GanttInteractionConfig` 필드 | 구조적 마스크 |
|---|---|---|---|
| `canMove` | `allowMove` | `allowMove` | 없음 |
| `canResize` | `allowResize` | `allowResize` | `!isSummary` |
| `canChangeProgress` | `allowProgressChange` | `allowProgressChange` | `!isSummary` |
| `canCreateLink` | `allowLinkCreate` | `allowLinkCreate` | 없음 |
| `canDeleteLink` | `allowLinkDelete` | `allowLinkDelete` | 없음 |
| `canReorder` | `allowReorder` | `allowReorder` | 없음 |

해석기는 이 값들을 `ResolvedTaskInteraction`에 담아 돌려줘요. 이 타입도 패키지 루트에서
**export되지 않아요**. 필드 이름이 소스와 이 표에 나오기 때문에 여기 옮겨 적었어요.

```ts title="src/shared/task.ts"
interface ResolvedTaskInteraction {
  canMove: boolean;
  canResize: boolean;
  canChangeProgress: boolean;
  canCreateLink: boolean;
  canDeleteLink: boolean;
  canReorder: boolean;
  minDate?: string;
  maxDate?: string;
}
```

### canReorder는 이 사슬을 타지 않아요

순서 바꾸기는 opt-in이라, 사슬의 바닥이 `!config.readOnly`가 아니라 `false`예요.

```ts title="src/shared/task.ts"
const canReorder =
  task.allowReorder ??
  (task.readOnly === true ? false : (config.allowReorder ?? false));
```

`config.readOnly`는 아예 읽히지 않아요. 잠긴 차트도 손대지 않은 차트도 순서 바꾸기를 거부하고,
어느 단계에서든 명시적인 `allowReorder`만 이것을 켜요. 위의 두 단계는 그대로예요. 작업 자신의
플래그가 이기고, 자신의 `readOnly`로 잠긴 작업은 차트 전체 플래그로도 끌 수 없어요.

| `task.allowReorder` | `task.readOnly` | `config.allowReorder` | 결과 |
|---|---|---|---|
| `true` | 무엇이든 | 무엇이든 | 허용 |
| `false` | 무엇이든 | 무엇이든 | 차단 |
| — | `true` | 무엇이든 | 차단 |
| — | `false` 또는 — | `true` | 허용 |
| — | `false` 또는 — | `false` | 차단 |
| — | `false` 또는 — | — | 차단 |

### 드래그 경계

`minDate`와 `maxDate`는 이 사슬을 쓰지 않아요. 한 단계만 nullish 병합해요:

```ts title="src/shared/task.ts"
minDate: task.minDate ?? config.minDate,
maxDate: task.maxDate ?? config.maxDate,
```

작업 자신의 경계가 차트의 경계를 대신해요. `readOnly`와 권한 플래그는 둘 중 어느 쪽에도 영향을 주지
않아요. 드래그 중에 이 경계가 무엇을 어디까지 제한하는지는 [작업 편집](../editing)에서 다뤄요.

### 작업 생성

작업 생성은 차트 전체 설정만 있어서, 두 단계짜리 해석기를 따로 써요. 이것도 내부용이고 export되지
않아요:

```ts title="src/shared/task.ts"
// 차트 전체 설정만 있어요 - 어느 입구도 작업에서 시작하지 않으니 작업별 단계가 없어요
export function canCreateTasks(
  config: GanttInteractionConfig = NO_INTERACTION_CONFIG
): boolean {
  return config.allowTaskCreate ?? !config.readOnly;
}
```

| `config.allowTaskCreate` | `config.readOnly` | 결과 |
|---|---|---|
| `true` | 무엇이든 | 허용 |
| `false` | 무엇이든 | 차단 |
| — | `true` | 차단 |
| — | `false` | 허용 |
| — | — | 허용 |

`Task`에는 `allowTaskCreate` 필드가 없어서 작업별 단계가 없어요. 차트는 이 결과를 콜백이 있는지와
AND로 묶어요:

```ts title="src/Gantt.tsx"
const canCreateTask = onTaskCreate !== undefined && canCreateTasks(interaction);
```

이 값 하나가 세 입구를 모두 여닫아요. 이게 없으면 **Add task** 띠가 그려지지 않고, `addTask()`는
곧바로 돌아가고, 그리기 제스처도 꺼져 있어요. 그래서 `onTaskCreate`가 없으면 플래그를 어떻게 두든
작업을 만들 길이 없어요. [작업 생성](../task-creation)을 참고하세요.

## 제약

규칙 한 가지가 해석기 결과 앞에 `&&`로 붙어요. 그래서 어느 단계의 플래그로도 다시 켤 수 없어요.

**요약 행은 절대 크기를 바꿀 수 없고 진행률도 끌 수 없어요.** `isSummary`가 `true`면
`canResize`와 `canChangeProgress`가 둘 다 `false`예요. 작업이 `allowResize: true`와
`allowProgressChange: true`를 줘도 그대로예요. `canMove`는 영향을 받지 않아요. 요약 행 이동은
허용되고, 하위 트리 전체를 함께 데려가요.

두 값 다 파생된 값이에요. `rollUpTasks`가 렌더링할 때마다 요약 행의 시작과 끝을 자식에서 다시
계산하고, 요약 행이 자기 진행률을 들고 있지 않으면 진행률도 자식에서 롤업해요. 그래서 여기서 고친
값은 다음 렌더링에서 버려지거나 파생된 값을 붙박이로 만들어요. 어떤 플래그로도 이것을 다시 켤 수
없는 이유가 이거예요.

`isSummary`는 `hierarchy` prop이 켜져 있을 때만 설정돼요. 그래서 이 규칙은 계층 없는 차트에는 해당하지
않아요. `readOnly`는 여전히 요약 행 전체를 잠가요.

## 참고

패키지 루트에서 export되는 것: `GanttInteractionConfig`(타입만).

다음은 export되지 않아요. 차트의 동작을 설명하려고 이 문서에서만 이름을 꺼냈어요:
`resolveTaskInteraction`, `canCreateTasks`, `ResolvedTaskInteraction`,
`NO_INTERACTION_CONFIG`. import하지 마세요.

이 플래그들이 다루는 제스처는 [작업 편집](../editing)과
[의존성](../dependencies)에서 설명해요. 이 플래그들이 여닫는 패널 필드는
[상세 패널](../detail-panel)에서 다뤄요.
