`GanttRow`는 차트가 렌더링하는 행 모델을 설명해요. 화면에 보이는 순서대로, 행 하나에 항목
하나예요. 패키지 루트에서 가져와요.

```ts
import type { GanttRow } from '@jaeungkim/gantt-chart';
```

레인이 무엇을 하고 같은 레인의 작업이 어떻게 한 행으로 채워지는지는 [레인](../lanes)을
참고하세요.

## GanttRow

```ts
/** One rendered row: one task, or several sharing a `lane` */
export interface GanttRow {
  /** Stable key - the ids on the row, joined with "+" */
  id: string;
  tasks: TaskTransformed[];
  /** Indentation level, 0-based */
  depth: number;
  /** `aria-level`, 1-based */
  level: number;
  /** `aria-posinset` among the rows that share a parent */
  posinset: number;
  /** `aria-setsize` for that same set */
  setsize: number;
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | `string` | [행 id](#행-id)를 참고하세요. |
| `tasks` | `TaskTransformed[]` | 보통 행에는 항목이 하나, 작업이 `lane`을 공유하면 여러 개예요. 비어 있는 경우는 없어요. 모든 행은 최소 한 개의 작업에서 만들어지니까요. |
| `depth` | `number` | 0부터 시작해요. 행의 첫 작업에서 가져오고, 그 작업의 `depth`와 같아요. |
| `level` | `number` | `aria-level`이에요. 언제나 `depth + 1`이에요. |
| `posinset` | `number` | 이 행과 부모가 같은 행들 사이에서의 `aria-posinset`이에요. 행의 부모는 위쪽에서 가장 가까운, `depth`가 한 단계 얕은 행이에요. |
| `setsize` | `number` | 같은 집합에 대한 `aria-setsize`예요. 보이는 행만 세어요. 접기는 행을 만들기 전에 적용되니까요. |

### 행 id

| 행 종류 | `id` | 예시 |
|---|---|---|
| 보통 행 | 작업 id | `"a"` |
| 레인 행 | 묶인 작업 id들을 `"+"`로 이은 값 | `"a+b"` |

사실 규칙은 하나예요. id는 그 행에 있는 작업 id들을 `"+"`로 이은 값이고, 작업이 하나뿐인 행은
이을 것이 없어요. 레인 행 위의 작업은 시작일 순서로 놓이고, 같으면 들어온 순서를 지켜요. id도
그 순서대로 이어져요.

그래서 보통 행에서는 행 id와 작업 id가 같은 문자열이에요. `collapsedIds` /
`defaultCollapsedIds` 항목이 행을 가리킬 수 있는 이유예요.

## 내보내지 않는 것들

`src/rows/utils/rows.ts`에는 `buildGanttRows`, `packLanes`, `isRowExpandable`도 들어 있어요. 이
중 어느 것도 패키지에서 다시 내보내지 않고, 헤드리스 코어에 속하지도 않아요. 레인 채우기는
렌더링 쪽에서 돌아가요.

## 참고 사항

- `GanttRow`를 넘겨주는 prop이나 콜백은 없어요. 이 타입을 내보내는 건 호스트 앱이 차트가 다루는
  형태를 이름으로 부를 수 있게 하려는 거예요. `TaskTransformed.order`를 읽을 때, 또는
  `collapsedIds` 항목을 맞춰 볼 때 쓰여요.
- `TaskTransformed`의 `order`는 1부터 시작하는 행 번호로 다시 쓰여요. 레인 행 위의 작업들은 행을
  공유하니까 모두 같은 `order`를 보고해요.

다음: `TaskTransformed`는 [Task](task), prop 목록은 [GanttProps](props)를 보세요.
