`WorkingCalendar`는 날짜 계산이 날을 세는 단위예요. 기본값인 `CALENDAR_DAYS`는 7일을 모두 세기
때문에, 평범한 달력 계산도 아무것도 건너뛰지 않는 달력으로 같은 코드 경로를 타요. 근무일 달력을
켜면 차트가 어떻게 달라지는지는 [근무일 달력](../working-calendar)에 있어요.

```ts
import {
  CALENDAR_DAYS,
  createWorkingCalendar,
  type WorkingCalendar,
  type WorkingCalendarOptions,
} from '@jaeungkim/gantt-chart';
```

이 메서드들이 받고 돌려주는 `Dayjs` 값은 패키지의 런타임 의존성인 `dayjs`에서 와요. `dayjs`는
`@jaeungkim/gantt-chart`에서 다시 내보내지 **않아요**. `dayjs`에서 직접, UTC 모드로 가져와요.

## `createWorkingCalendar`

```ts title="src/core/calendar.ts"
/**
 * 주말과 공휴일을 건너뛰는 달력이에요.
 *
 * 차트가 비근무일을 음영 처리할 때 이미 쓰는 설정(`holidays` / `isNonWorkingDay`)을
 * 그대로 받아요. 그래서 음영과 건너뛰기가 서로 어긋날 수 없어요.
 */
export function createWorkingCalendar(
  options: WorkingCalendarOptions = {}
): WorkingCalendar
```

| 매개변수 | 타입 | 필수 | 의미 |
|---|---|---|---|
| `options` | `WorkingCalendarOptions` | 아니요 | 기본값은 `{}`이고, 공휴일 없는 월–금 주간이에요 |

돌려받은 달력은 언제나 `skipsNonWorkingDays: true`예요. 결과적으로 모든 날이 근무일로 남는
설정이어도 마찬가지예요.

## `WorkingCalendarOptions`

```ts title="src/core/calendar.ts"
export interface WorkingCalendarOptions {
  /** 근무 요일을 UTC 요일 번호로. 0은 일요일이에요 (기본값 월–금) */
  workingWeekdays?: number[];
  /** 비근무일을 UTC `YYYY-MM-DD` 문자열로 */
  holidays?: string[];
  /** 요일 + 공휴일 검사를 통째로 대체해요 */
  isNonWorkingDay?: (date: Dayjs) => boolean;
}
```

| 옵션 | 타입 | 기본값 | 의미 |
|---|---|---|---|
| `workingWeekdays` | `number[]` | `[1, 2, 3, 4, 5]` (월–금) | UTC 요일 번호예요. `0`은 일요일이고, 배열에 없는 날은 비근무일이에요 |
| `holidays` | `string[]` | `[]` | UTC `YYYY-MM-DD` 문자열이에요. `date.format('YYYY-MM-DD')` 결과와 문자열이 정확히 같아야 걸려요 |
| `isNonWorkingDay` | `(date: Dayjs) => boolean` | `undefined` | 검사 전체를 맡는 판별 함수 하나예요. `true`면 그 날은 비근무일이에요 |

`isNonWorkingDay`가 무조건 이겨요. 이 값을 넘기면 `workingWeekdays`와 `holidays`는 아예 읽지
않아요. 셋을 다 넣어 만든 달력도 판별 함수만 써요.

## `CALENDAR_DAYS`

```ts title="src/core/calendar.ts"
/**
 * 기본 달력이에요. 모든 날을 세요.
 * 이 달력을 거친 날짜 계산은 평범한 달력 계산이에요. 그래서 호스트 앱이 근무일을 켜기
 * 전까지 스케줄링 기능의 동작을 그대로 유지해 줘요.
 */
export const CALENDAR_DAYS: WorkingCalendar
```

팩토리가 아니라 공유되는 인스턴스 하나예요. `workingCalendar`가 꺼져 있는 동안 차트가 쓰는 달력이
이거예요. 직접 만든 코드가 달력 인자를 요구하는데 호출부는 평범한 달력 날짜를 쓰고 싶을 때
넘겨요.

## `WorkingCalendar`

```ts title="src/core/calendar.ts"
/**
 * 코어의 모든 날짜 계산이 거쳐 가는 달력이에요.
 *
 * 엔진에서 "하루"의 정의는 하나뿐이고, 이 객체가 말하는 것이 곧 그 정의예요.
 * 기본 달력은 모든 날을 세요. 그래서 평범한 달력 날짜 동작은 별도 코드 경로가 아니라,
 * 아무것도 건너뛰지 않는 달력으로 돌리는 같은 코드예요.
 * 근무일 달력을 켜면 이 객체만 바뀌고 나머지는 그대로예요.
 */
export interface WorkingCalendar {
  /** 기본 달력에서는 false예요 (모든 날을 세요). 호출부가 빠른 경로를 타게 해 줘요 */
  readonly skipsNonWorkingDays: boolean;
  isWorkingDay(date: Dayjs): boolean;
  /** 비근무일을 건너뛰며 `days`만큼 앞으로(또는 뒤로) 옮겨요 */
  addDays(date: Dayjs, days: number): Dayjs;
  /** `from`에서 `to`까지의 일수예요. `addDays`가 움직이는 방식대로 세고, 부호가 있어요 */
  daysBetween(from: Dayjs, to: Dayjs): number;
  /** `addDays(from, d) >= target`인 가장 작은 d - 작업이 어떤 날짜를 넘기려면 얼마나 움직여야 하는지 */
  daysUntil(from: Dayjs, target: Dayjs): number;
  /** `addDays(from, d) <= target`인 가장 큰 d - 작업이 날짜를 어기기 전까지 얼마나 밀릴 수 있는지 */
  daysUpTo(from: Dayjs, target: Dayjs): number;
  /** 근무일이면 그 날짜 그대로, 아니면 다음 근무일이에요 (시각은 유지) */
  snapForward(date: Dayjs): Dayjs;
}
```

### 멤버

| 멤버 | 시그니처 | `CALENDAR_DAYS` | 근무일 달력 |
|---|---|---|---|
| `skipsNonWorkingDays` | `readonly boolean` | `false` | `true` |
| `isWorkingDay` | `(date: Dayjs) => boolean` | 항상 `true` | 요일·공휴일 검사를 통과하거나 `isNonWorkingDay` 판별 함수가 `false`를 돌려주면 `true` |
| `addDays` | `(date: Dayjs, days: number) => Dayjs` | `date.add(days, 'day')` | 달력 하루씩 옮기면서 근무일에서만 남은 일수를 줄여요. 시각은 유지돼요 |
| `daysBetween` | `(from: Dayjs, to: Dayjs) => number` | `to.startOf('day').diff(from.startOf('day'), 'day')` | 하루씩 걸으며 밟은 근무일만 세요. 출발한 날은 절대 세지 않아요 |
| `daysUntil` | `(from: Dayjs, target: Dayjs) => number` | `addDays(from, d) >= target`인 가장 작은 `d` | 같아요, 단위만 근무일이에요 |
| `daysUpTo` | `(from: Dayjs, target: Dayjs) => number` | `addDays(from, d) <= target`인 가장 큰 `d` | 같아요, 단위만 근무일이에요 |
| `snapForward` | `(date: Dayjs) => Dayjs` | `date`를 그대로 돌려줘요 | `date` 당일이나 그 뒤의 첫 근무일이고, 시각은 유지돼요 |

`daysBetween`은 날짜 단위로 비교해요. 양끝에 `startOf('day')`를 부르니 같은 날짜의 두 시각은
`0`만큼 떨어져 있어요. `daysUntil`과 `daysUpTo`는 시각까지 따져요. `daysBetween`의 답을 최대 두
걸음까지 보정하는 방식이에요.

근무일에서 출발하면 `addDays`와 `daysBetween`은 정확히 서로의 역이에요.
`daysBetween(from, addDays(from, n))`은 `n`이에요. `from`은 근무일이어야 해요. 비근무일에서
출발하면 왕복하는 동안 첫 걸음을 잃어요. 이 항등식에는 걷기 한계 안의 구간과 근무일이 하나
이상인 달력도 필요해요. 두 한계 모두 아래 제약 절에 있어요.

## 계산 예시

2025년 6월이에요. 2일이 월요일, 6일이 금요일, 7일과 8일이 주말, 9일이 그다음 월요일이에요.
`workweek`은 `createWorkingCalendar()`이고, `withHoliday`는
`createWorkingCalendar({ holidays: ['2025-06-09'] })`예요.

| 호출 | 결과 |
|---|---|
| `workweek.addDays('2025-06-06', 1)` | `2025-06-09` |
| `workweek.addDays('2025-06-02', 10)` | `2025-06-16` |
| `workweek.addDays('2025-06-09', -1)` | `2025-06-06` |
| `workweek.addDays('2025-06-06T14:30', 1)` | `2025-06-09T14:30` |
| `workweek.daysBetween('2025-06-02', '2025-06-09')` | `5` |
| `workweek.daysBetween('2025-06-06', '2025-06-08')` | `0` (금요일에서 일요일) |
| `workweek.daysBetween('2025-06-07', '2025-06-09')` | `1` (토요일에서 출발) |
| `workweek.daysBetween('2025-06-09', '2025-06-02')` | `-5` |
| `workweek.daysUntil('2025-06-06T09:00', '2025-06-09T17:00')` | `2` |
| `workweek.daysUpTo('2025-06-06T09:00', '2025-06-09T08:00')` | `0` |
| `workweek.snapForward('2025-06-07T09:00')` | `2025-06-09T09:00` |
| `withHoliday.addDays('2025-06-06', 1)` | `2025-06-10` |
| `withHoliday.daysBetween('2025-06-06', '2025-06-13')` | `4` |
| `CALENDAR_DAYS.daysBetween('2025-06-02', '2025-06-09')` | `7` |

## 예제

```ts
import dayjs from 'dayjs';
import utc from 'dayjs/plugin/utc';
import { createWorkingCalendar } from '@jaeungkim/gantt-chart';

dayjs.extend(utc);

const calendar = createWorkingCalendar({ holidays: ['2025-06-09'] });

// 금요일에서 근무일 하루 뒤로. 주말과 월요일 공휴일을 둘 다 건너뛰어요.
calendar.addDays(dayjs.utc('2025-06-06'), 1).toISOString(); // 2025-06-10T00:00:00.000Z
calendar.daysBetween(dayjs.utc('2025-06-06'), dayjs.utc('2025-06-13')); // 4
calendar.isWorkingDay(dayjs.utc('2025-06-09')); // false
calendar.skipsNonWorkingDays; // true
```

패키지에는 달력 인자를 받는 것이 하나도 없어요. 차트는 `workingCalendar`와 `holidays` /
`isNonWorkingDay` prop으로 자기 달력을 직접 만들어요. 그래서 직접 만든 달력은 내 날짜 계산에
쓰는 물건이에요 — [근무일 달력](../working-calendar) 참고.

## 제약

`src/core/calendar.ts`는 `Dayjs` 타입만 가져오고 dayjs 자체는 절대 가져오지 않아요. 요일은
`date.day()`에서 나오고, 공휴일은 `date.format('YYYY-MM-DD')`와 맞춰 봐요. 그래서 둘 다 넘긴
`Dayjs` 인스턴스의 모드를 그대로 따라요.

차트 안에서는 항상 UTC예요. 코어가 달력에 건네는 날짜는 모두 `src/core/dates.ts`에서 오고, 이
파일은 `dayjs.utc`예요. 로컬 모드 `Dayjs`로 달력을 직접 호출하면 로컬 요일과 로컬
`YYYY-MM-DD`를 읽어요. 그러니 위 예제처럼 UTC 모드 인스턴스를 넘겨요.

근무일이 하나도 없는 달력은 실패하지도 멈추지도 않아요. `addDays`는 요청한 하루마다 367걸음의
예산을 받고, 예산이 떨어지면 평범한 달력 날짜로 물러나요. `snapForward`는 366번 시도한 뒤 입력을
그대로 돌려줘요. 모든 날을 비근무일로 표시하는 판별 함수는 오류가 아니라 틀린 숫자를 내요.

`daysBetween`이 하루씩 걷는 범위는 18,263일(약 50년)까지예요. 그 너머로는 평범한 달력 일수 차이를
돌려줘요. 그래서 그만큼 긴 구간에서는 근무일 달력의 단위가 조용히 바뀌어요.

근무일이 하나도 없는 역방향 구간에서 `daysBetween`은 `-0`이 아니라 언제나 `0`을 돌려줘요.

`daysUntil`과 `daysUpTo`는 `daysBetween`의 답을 방향마다 최대 두 걸음까지만 보정해요. 스케줄러가
만드는 하루 길이 구간에서는 정확하지만, 임의의 하루 미만 계산에서는 그렇지 않아요.

달력에는 시간 개념이 없어요. 같은 날짜에서 `09:00`부터 `17:00`까지인 작업은 `daysBetween`이
`0`으로 나와요.

건너뛰기 한계(366)와 걷기 한계(18,263)는 `src/core/calendar.ts`의 내부 상수예요.
`@jaeungkim/gantt-chart`에서 내보내지 않고 설정할 수도 없어요. `CALENDAR_DAYS`와
`createWorkingCalendar`가 둘 다 결과를 받아 오는 내부 팩토리 `build`도 내보내지 않아요.

`WorkingCalendar`는 평범한 인터페이스예요. 호스트 앱은 `createWorkingCalendar` 대신 직접 구현해도
돼요. 다만 `addDays`와 `daysBetween`이 서로의 역으로 남아야 해요. `daysUntil`과 `daysUpTo`가 한
쪽으로 다른 쪽을 보정하거든요.

달력은 날짜를 바꿀 뿐, 도형은 바꾸지 않아요. 막대 도형, 타임라인 눈금, 비근무일 음영은 달력 인자를
받지 않아요. 그래서 막대는 자기가 걸친 주말과 공휴일 위를 그대로 지나가요. 음영은 별개인
`showNonWorkingDays` prop이고, [타임라인](../timeline)에서 설명해요.

차트가 달력을 읽는 곳은 막대 드래그 하나뿐이에요. `skipsNonWorkingDays`가 `true`면 놓은 쪽
끝이 `snapForward`되고, 막대의 나머지가 같은 일수만큼 따라와요. 그게 전부예요 —
[근무일 달력](../working-calendar) 참고.
