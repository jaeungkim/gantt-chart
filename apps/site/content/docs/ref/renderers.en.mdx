`renderDetail` is the chart's one render prop. It replaces the body of the detail panel, and its
types come from `@jaeungkim/gantt-chart`. Behaviour and worked examples live in
[Detail panel](../detail-panel).

```ts
import type {
  GanttDetailRenderer,
  GanttDetailRenderProps,
} from '@jaeungkim/gantt-chart';
```

`TaskTransformed` is documented in [Task](task) and `GanttScaleKey` in [Scales](scales).
`ReactNode` comes from `react`.

## GanttDetailRenderer

```ts title="src/shared/types.ts"
/** Props handed to a `renderDetail` override */
export interface GanttDetailRenderProps {
  task: TaskTransformed;
  /** Closes the panel - wire it to your own close control */
  close: () => void;
  scale: GanttScaleKey;
}

export type GanttDetailRenderer = (props: GanttDetailRenderProps) => ReactNode;
```

### Fields

| Field | Type | Value |
|---|---|---|
| `task` | `TaskTransformed` | The open task, as the chart transformed it |
| `close` | `() => void` | Closes the panel — the same function the built-in close button calls |
| `scale` | `GanttScaleKey` | The scale currently selected |

### Example

```tsx
const renderDetail: GanttDetailRenderer = ({ task, close, scale }) => (
  <>
    <button type="button" onClick={close} aria-label="Close task details">
      ✕
    </button>
    <h2>{task.name}</h2>
    <p>
      {task.startDate.slice(0, 10)} → {task.endDate.slice(0, 10)} · {scale}
    </p>
  </>
);
```

### Constraints

Only the panel's children are the renderer's, so there is no props bag to spread.

- The `<aside class="gantt-detail" role="complementary" aria-label="Task details">` stays the
  chart's, and so does its width — that comes from the `--gantt-detail-width` custom property
  (`320px`), not from the renderer.
- The close button is not carried over. `close` is the same function the built-in one calls, and
  `Escape` closes the panel from anywhere whether or not a replacement renders a control of its own.
- Returning `null` or `undefined` renders an **empty** panel, not the default body.
- Passing the renderer turns the panel on when `showDetail` is omitted, the way `showTaskList`
  turns the task list on. An explicit `showDetail={false}` still wins.
- The renderer runs only while a task is open. With nothing open there is no `<aside>` in the DOM at
  all, so it is never called without a task — `detailTrigger="none"` included.
- The renderer is the only way to put a task's other fields in the panel. The default body shows
  the name and the dates, and there is no prop that adds a row to it.

Every prop named here is indexed in [Props](props).
