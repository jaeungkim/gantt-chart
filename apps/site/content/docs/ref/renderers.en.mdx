`renderDetail` is the chart's one render prop. It replaces the body of the detail panel, and its
types come from `@jaeungkim/gantt-chart`. Behaviour and worked examples live in
[Detail panel](../detail-panel).

```ts
import type {
  GanttDetailRenderer,
  GanttDetailRenderProps,
  Task,
} from '@jaeungkim/gantt-chart';
```

`Task` and `TaskTransformed` are documented in [Task and task types](task) and `GanttScaleKey` in
[Scale and theme types](scales). `ReactNode` comes from `react`.

## GanttDetailRenderer

```ts title="src/shared/types.ts"
/** Props handed to a `renderDetail` override */
export interface GanttDetailRenderProps {
  task: TaskTransformed;
  /** Closes the panel - wire it to your own close control */
  close: () => void;
  scale: GanttScaleKey;
  /**
   * Patches the open task through the chart's normal commit path (the store, then
   * `onTasksChange`), so a custom body can commit edits in uncontrolled mode. Applies NO
   * permission checks - a custom body enforces its own rules.
   */
  update: (patch: Partial<Omit<Task, 'id'>>) => void;
}

export type GanttDetailRenderer = (props: GanttDetailRenderProps) => ReactNode;
```

### Fields

| Field | Type | Value |
|---|---|---|
| `task` | `TaskTransformed` | The open task, as the chart transformed it |
| `close` | `() => void` | Closes the panel — the same function the built-in close button calls |
| `scale` | `GanttScaleKey` | The scale currently selected |
| `update` | `(patch: Partial<Omit<Task, 'id'>>) => void` | Patches the open task through the chart's commit path |

### Example

```tsx
const renderDetail: GanttDetailRenderer = ({ task, close, scale, update }) => (
  <>
    <button type="button" onClick={close} aria-label="Close task details">
      ✕
    </button>
    <h2>{task.name}</h2>
    <p>
      {task.startDate.slice(0, 10)} → {task.endDate.slice(0, 10)} · {scale}
    </p>
    <button type="button" onClick={() => update({ progress: 100 })}>
      Mark done
    </button>
  </>
);
```

### Constraints

Only the panel's children are the renderer's, so there is no props bag to spread.

- The `<aside class="gantt-detail" role="complementary" aria-label="Task details">` stays the
  chart's, and so does its width — that comes from the `--gantt-detail-width` custom property
  (`320px`), not from the renderer.
- The close button is not carried over. `close` is the same function the built-in one calls, and
  `Escape` closes the panel from anywhere whether or not a replacement renders a control of its own.
- Returning `null` or `undefined` renders an **empty** panel, not the default body.
- Passing the renderer turns the panel on when `showDetail` is omitted, the way `showTaskList`
  turns the task list on. An explicit `showDetail={false}` still wins.
- The renderer is never called without a task, but closing does not unmount it at once. The panel
  keeps the last task rendered through the 200ms close transition, and a 400ms timer releases it if
  `transitionend` never fires, so a body with mount side effects sees extra render passes while the
  panel slides shut. The `<aside>` leaves the DOM only once that transition finishes.
- `update` is the same commit path the built-in body's inputs use — the store, then
  `onTasksChange` — so an edit lands in uncontrolled mode without wiring `tasks` back yourself.
- `update` applies **no** checks of its own. The interaction flags, the date clamping and the
  progress normalization gate only the built-in body; a patch passed here reaches the store and
  `onTasksChange` as given, so a custom body enforces its own rules.
- The patch cannot rename the task's `id` — the type strips it, and the patch always lands on the
  open task.
- The renderer is the only way to put a task's other fields in the panel. The default body shows
  the name, the dates and the duration; progress and predecessors appear only when the task has
  them. No prop adds a row to it or translates its captions.

Every prop named here is indexed in [GanttProps](props).
