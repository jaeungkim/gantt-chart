Five types describe how the timeline is measured and how the chart is painted: `GanttScaleKey`
names one of the five scales, `GanttScaleFormat` and `GanttFormatOverrides` replace the labels
of a scale, `GanttTheme` picks the palette, and `Holiday` marks a day off. All five are exported
from the package root.

```tsx
import type {
  GanttScaleKey,
  GanttScaleFormat,
  GanttFormatOverrides,
  GanttTheme,
  Holiday,
} from '@jaeungkim/gantt-chart';
```

## GanttScaleKey

```ts
export type GanttScaleKey = 'day' | 'week' | 'month' | 'quarter' | 'year';
```

The declaration order is the ladder, finest first. Ctrl/Cmd + ArrowUp steps one rung finer and
Ctrl/Cmd + ArrowDown one rung coarser, clamped at both ends. Ctrl/Cmd + wheel walks the same ladder
when `zoomOnWheel` is on. `defaultScale` takes one of these values and defaults to `'month'`.

The chart renders no scale picker of its own, and remembers no scale across a remount. A host that
wants a picker renders it, drives it through `setScale` on the ref, and follows every change —
wheel and keyboard included — with `onScaleChange`. See [GanttHandle](handle).

The key appears in several other shapes: `formats` is keyed by it, and
`GanttDetailRenderProps.scale` carries it. See [Detail renderer](renderers).

### Per-scale configuration

Each key maps to one row of a fixed table. The row decides what the header cells say, how much time
one tick covers, and how many pixels one drag step is worth. The five rows' values are laid out in
[The timeline](../timeline); this page describes the shape of one row:

```ts
export interface GanttScaleConfig {
  labelUnit: GanttLabelUnit;
  tickUnit: 'minute' | 'hour' | 'day' | 'week' | 'month';
  unitPerTick: number;
  /** Boundary the first cell snaps to, when a cell holds more than one tickUnit */
  tickAlign?: GanttLabelUnit;

  dragStepUnit: 'minute' | 'hour' | 'day' | 'week';
  dragStepAmount: number;

  basePxPerDragStep: number;

  formatTickLabel?: (date: Dayjs) => string;
  formatHeaderLabel?: (date: Dayjs) => string;
}
```

```ts
/** Unit the top header row groups by ('quarter' has no dayjs equivalent - see core/dates) */
export type GanttLabelUnit =
  | 'hour'
  | 'day'
  | 'week'
  | 'month'
  | 'quarter'
  | 'year';
```

`GanttScaleConfig`, `GanttLabelUnit` and the `GANTT_SCALE_CONFIG` object itself are **not exported
from the package** — they are module-internal. The table cannot be imported, extended or
replaced, and no prop adds a sixth scale. Tick widths are derived from
`basePxPerDragStep / dragStepAmount`; see [The timeline](../timeline) for the arithmetic and
[Editing tasks](../editing) for the drag grid the same two fields define.

### Built-in labels

`formatTickLabel` and `formatHeaderLabel` are the last layer of the label chain — what renders when
no `formats` override and no `locale` applies.

| scale | `formatTickLabel` | `formatHeaderLabel` | tooltip format string | readout format string |
|---|---|---|---|---|
| `day` | `d.format('HH')` | `d.format('MMM D, YYYY')` | `'MMM D, YYYY HH:mm [UTC]'` | `'HH:mm [UTC]'` |
| `week` | `d.format('D')` | `d.format('MMM YYYY')` | `'MMM D, YYYY'` | `'MMM D'` |
| `month` | `d.format('MMM D')` | `d.format('MMM YYYY')` | `'MMM D, YYYY'` | `'MMM D'` |
| `quarter` | `d.format('MMM')` | `` `Q${quarterOfYear(d)} ${d.format('YYYY')}` `` | `'MMM YYYY'` | `'MMM YYYY'` |
| `year` | `d.format('MMM')` | `d.format('YYYY')` | `'MMM YYYY'` | `'MMM YYYY'` |

The tooltip and readout strings live in separate `DATE_FORMATS` and `RANGE_FORMATS` constants,
neither exported. `[UTC]` in the hour and day strings is a dayjs escaped literal, not a resolved
zone name.

The tooltip string is the chart's general-purpose date label. The hover tooltip, the bar's ARIA
label, the drag and keyboard announcements and the built-in detail panel's Start and End fields
all print it — the panel only where those two fields are not editable, an editable one being a
native `<input type="date">` showing `YYYY-MM-DD`. See [Detail panel](../detail-panel).

The readout string is the compact per-scale variant used by the header drag readout. What the
readout writes, where it writes it, and why the shorter strings drop the year are in
[Locale and date formats](../i18n).

## GanttScaleFormat

```ts
/**
 * Replaces the generated labels of one scale
 * Every entry is optional - whatever is left out keeps the built-in (or locale) label
 */
export interface GanttScaleFormat {
  /** Bottom header row - one label per tick */
  tick?: (date: Dayjs) => string;
  /** Top header row - one label per group */
  header?: (date: Dayjs) => string;
  /**
   * Every date the chart writes as a single date: the bar's hover tooltip, its live drag readout
   * and aria-label, the header's drag guide labels (through `edge` and `range`, which follow this
   * slot), and the detail panel's Start and End where they are not editable - an editable date is
   * a native `<input type="date">` and never reaches a formatter.
   */
  tooltip?: (date: Dayjs) => string;
}
```

| Field | Type | Required | Applies to |
|---|---|---|---|
| `tick` | `(date: Dayjs) => string` | no | one label per tick, bottom header row |
| `header` | `(date: Dayjs) => string` | no | one label per group, top header row |
| `tooltip` | `(date: Dayjs) => string` | no | every date off the header rows: the hover tooltip, the bar's ARIA label, the drag and keyboard announcements, and the built-in detail panel's dates where they are not editable |

The three are resolved independently, so supplying `header` alone leaves `tick` and `tooltip` on
whatever the `locale` or the built-in labels produce.

A `tooltip` override also formats each end of the header drag readout. Without one, the readout
keeps its own compact per-scale strings — the readout column under Built-in labels.

## GanttFormatOverrides

```ts
/** Per-scale label overrides, e.g. `{ quarter: { header: (d) => ... } }` */
export type GanttFormatOverrides = Partial<
  Record<GanttScaleKey, GanttScaleFormat>
>;
```

This is the type of the `formats` prop. A scale left out of the record keeps its resolved labels
whole.

```tsx title="QuarterHeader.tsx"
import { ReactGanttChart } from '@jaeungkim/gantt-chart';
import type { GanttFormatOverrides, Task } from '@jaeungkim/gantt-chart';

const formats: GanttFormatOverrides = {
  quarter: {
    header: (d) => `${d.year()} Q${Math.floor(d.month() / 3) + 1}`,
  },
  month: {
    tooltip: (d) => d.format('YYYY-MM-DD'),
  },
};

const tasks: Task[] = [
  {
    id: 'design',
    name: 'Design',
    startDate: '2026-01-05',
    endDate: '2026-02-20',
    parentId: null,
    sequence: '1',
  },
];

export default function QuarterHeader() {
  return <ReactGanttChart tasks={tasks} formats={formats} locale="en-US" />;
}
```

`formats` is declared at module scope here on purpose. Which layer wins for each of the three
labels, and why the object's identity matters, are in [Locale and date formats](../i18n).

## GanttTheme

```ts
/** Chart theme - 'system' follows the OS setting; omit the prop to follow the host page's `color-scheme`. */
export type GanttTheme = 'light' | 'dark' | 'system';
```

This is the type of the `theme` prop, which has no default. Whatever it resolves to is written to
`data-theme` on the container, and that attribute is what the stylesheet reads. How each value
resolves, and what the palette behind it is, are in [Theming](../theming).

There is no theme object and no token prop. `GanttTheme` is a three-value union; every color is a
CSS custom property.

## Holiday

```ts
/** A day off beyond the weekend. A bare `YYYY-MM-DD` string is the same thing with no label. */
export interface Holiday {
  /** UTC `YYYY-MM-DD` */
  date: string;
  /** Inclusive last day - omit for a single day */
  endDate?: string;
  /** Written in the tick row over the holiday's band, when the band is wide enough to hold it */
  label?: string;
  /** Any CSS colour. Tinted onto the grid at the weekend shade's weight, never painted over it. */
  color?: string;
}
```

| Field | Type | Required | Meaning |
|---|---|---|---|
| `date` | `string` | yes | the first day off, as a UTC `YYYY-MM-DD` string |
| `endDate` | `string` | no | inclusive last day of the span; omit for a single day |
| `label` | `string` | no | text written in the tick row over the holiday's band |
| `color` | `string` | no | any CSS color, tinted onto the grid at the weekend shade's weight |

What a holiday draws, when the label appears and how the entries are supplied are in
[The timeline](../timeline).

## Notes

How the three slots resolve, what each formatter receives, and the identity rule are in
[Locale and date formats](../i18n).

- `GanttScaleFormat` functions must return a `string`. There is no `ReactNode` escape hatch, and no
  prop replaces a header cell. A header cell is text, and CSS on `.gantt-top-group` and
  `.gantt-bottom-cell` is the only way to change how one looks.
- The chart's UTC `dayjs` instance is not exported from the package. Import `dayjs` and its `utc`
  plugin directly if an override needs the same instance.
