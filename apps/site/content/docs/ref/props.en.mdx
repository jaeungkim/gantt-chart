`GanttProps` is the full prop surface of `ReactGanttChart`. It and every type named in the tables
below are exported from the package root, apart from `Dayjs`, `ReactNode` and `React.MouseEvent`,
which come from `dayjs` and `react`:

```tsx
import { ReactGanttChart, type GanttProps } from '@jaeungkim/gantt-chart';
```

Every prop is optional. The Default column carries the value the component actually falls back to;
`none` means the prop has no fallback and the feature it drives stays off.

## Data

| Prop | Type | Default | Description |
|---|---|---|---|
| `tasks` | `Task[]` | `[]` | The task array. See [Task data](../task-data). |
| `onTasksChange` | `(updatedTasks: Task[]) => void` | none | Fires with the whole array after any committed edit. See [Editing tasks](../editing). |

## Layout and size

|---|---|---|---|

| `width` | `number \| string` | `"100%"` | Chart width, a number in px or any CSS length. See [Quick start](../quick-start). |
| `className` | `string` | none | Appended to the container's `gantt-container` class. See [Theming](../theming). |

## Timeline and range

|---|---|---|---|

| `visibleStart` | `string` | none — the range fits the tasks | Pins the timeline's start to this ISO date. See [The timeline](../timeline). |

| Prop | Type | Default | Description |

## Defaults that are not what they look like

- **`selectable`** has no fixed default either. Left out, selection is on exactly when
  `onTaskSelect` is given. Pass `true` for the highlight without a callback, `false` to turn it
  off entirely.
- **`showDetail`** works the same way. Left out, the detail panel exists exactly when
  `renderDetail` is given — the renderer is the switch. Turning the panel on
  also turns row selection on, unless `selectable` says otherwise. See
  [Detail panel](../detail-panel).
- **`detailTrigger`** defaults to `'selection'`, and that is a single click, not the double click
  other gantt libraries open a task editor with. Pass `'doubleClick'` for that, or `'none'` to leave
  opening to `detailTaskId` and the ref. See [Detail panel](../detail-panel).
- **`allowMove`, `allowResize`, `allowProgressChange`, `allowTaskCreate`, `allowLinkCreate`,
  `allowLinkDelete`** default to `!readOnly`, not to `true`. A task's own flag of the same name
  wins over the chart-level one, and a task's own `readOnly` sits between them. See
  [GanttInteractionConfig](interaction-config).
- **`allowTaskCreate`** on its own creates nothing: `onTaskCreate` must also be given. Without it
  there is no button, no gesture, and `addTask()` is inert.
- **`allowReorder`** is the one `allow*` flag that does not default to `!readOnly`. It is `false`
  until it is set, so an untouched chart has no row grips and answers no reorder key. A task's own
  `allowReorder` still wins, and a task's `readOnly: true` blocks it — but the chart's `readOnly` is
  never consulted. See [GanttInteractionConfig](interaction-config).
- **`defaultScale`** is a seed, not a controlled value. It is read once, when the chart is
  constructed, so the first paint is already at that scale. Later changes to the prop are ignored,
  `onScaleChange` does not fire for it, and nothing is persisted — a remount starts from the seed
  again.
- **`collapsedIds`** and **`defaultCollapsedIds`** are the controlled and uncontrolled halves of
  one value. Passing `collapsedIds` makes the chart show that list and stop tracking its own;
  `onCollapsedChange` still fires in both modes.
- **`theme`** left out follows the host page's `color-scheme`, read off `<html>` and watched for
  changes, so the chart moves with an app's own light/dark toggle. `'system'` ignores the host and
  asks the OS instead. Every value resolves to `'light'` during server rendering and the first
  hydration render, then to the real setting.
- **`visibleStart`** and **`visibleEnd`** are independent. Pinning one end also stops
  `infiniteScroll` from extending the range on that side; the other side still extends.
- **`workingCalendar`** builds its calendar from `holidays` and `isNonWorkingDay`, the same
  configuration that drives `showNonWorkingDays` shading.

## Notes

- The task list has no column API. It shows `task.name` at a starting pane width of 220px, and
  everything else about a task belongs in the detail panel. See
  [Task list and hierarchy](../task-list).
- `GanttTaskMoveChange` is what `onTaskMove` receives. It is exported from the package root and
  its fields are described in [Tree helpers](core-tree), next to the `moveTask` function that
  builds it.
- `Dayjs` comes from the `dayjs` package, and `ReactNode` / `React.MouseEvent` from `react`.
  None of the three is re-exported from this package.
- The chart renders no controls of its own — no toolbar and no scale picker. A host that wants one
  renders it, drives it with `setScale` on the ref and keeps it honest with `onScaleChange`. See
  [The timeline](../timeline).
- `ReactGanttChart` also takes a `ref` of type `GanttHandle` for scrolling, zooming, switching
  scale and opening or closing the detail panel. It is not part of `GanttProps` — see
  [GanttHandle](handle).
