`renderDetail`은 차트에 하나 남은 render prop이에요. 상세 패널의 본문을 대체하고, 타입은
`@jaeungkim/gantt-chart`에서 가져와요. 동작과 실제 예제는 [상세 패널](../detail-panel)에
있어요.

```ts
import type {
  GanttDetailRenderer,
  GanttDetailRenderProps,
  Task,
} from '@jaeungkim/gantt-chart';
```

`Task`와 `TaskTransformed`는 [Task와 작업 타입](task)에, `GanttScaleKey`는
[배율과 테마 타입](scales)에 정리돼 있어요. `ReactNode`는 `react`에서 와요.

## GanttDetailRenderer

```ts title="src/shared/types.ts"
/** `renderDetail` 오버라이드에 전달되는 props */
export interface GanttDetailRenderProps {
  task: TaskTransformed;
  /** 패널을 닫아요 - 직접 만든 닫기 컨트롤에 연결하세요 */
  close: () => void;
  scale: GanttScaleKey;
  /**
   * 차트의 일반 커밋 경로(스토어, 그다음 `onTasksChange`)로 열린 작업을 패치해요.
   * 그래서 커스텀 본문이 비제어 모드에서 편집을 커밋할 수 있어요. 권한 검사는 전혀
   * 하지 않아요 - 규칙은 커스텀 본문이 직접 지켜야 해요.
   */
  update: (patch: Partial<Omit<Task, 'id'>>) => void;
}

export type GanttDetailRenderer = (props: GanttDetailRenderProps) => ReactNode;
```

### 필드

| 필드 | 타입 | 값 |
|---|---|---|
| `task` | `TaskTransformed` | 열려 있는 작업이에요. 차트가 변환한 형태 그대로예요 |
| `close` | `() => void` | 패널을 닫아요 — 내장 닫기 버튼이 호출하는 것과 같은 함수예요 |
| `scale` | `GanttScaleKey` | 현재 선택된 배율 |
| `update` | `(patch: Partial<Omit<Task, 'id'>>) => void` | 차트의 커밋 경로로 열린 작업을 패치해요 |

### 예제

```tsx
const renderDetail: GanttDetailRenderer = ({ task, close, scale, update }) => (
  <>
    <button type="button" onClick={close} aria-label="Close task details">
      ✕
    </button>
    <h2>{task.name}</h2>
    <p>
      {task.startDate.slice(0, 10)} → {task.endDate.slice(0, 10)} · {scale}
    </p>
    <button type="button" onClick={() => update({ progress: 100 })}>
      Mark done
    </button>
  </>
);
```

### 제약

렌더러의 몫은 패널의 자식뿐이에요. 그래서 spread 할 props 묶음이 없어요.

- `<aside class="gantt-detail" role="complementary" aria-label="Task details">`는 차트의 것으로
  남아요. 너비도 마찬가지예요. 너비는 렌더러가 아니라 `--gantt-detail-width` 커스텀 속성(`320px`)이
  정해요.
- 닫기 버튼은 딸려오지 않아요. `close`는 내장 버튼이 호출하는 것과 같은 함수예요. 대체 노드가 닫기
  컨트롤을 직접 그리든 안 그리든 `Escape`는 어디서나 패널을 닫아요.
- `null`이나 `undefined`를 반환하면 기본 본문이 아니라 **빈** 패널이 렌더링돼요.
- `showDetail`을 생략했다면 이 렌더러를 넘기는 것이 패널을 켜는 스위치예요. `showTaskList`가 작업
  목록을 켜는 것과 같아요. 명시한 `showDetail={false}`가 항상 이겨요.
- 렌더러가 작업 없이 호출되는 일은 없어요. 다만 닫는다고 바로 언마운트되지는 않아요. 패널은 200ms
  닫기 트랜지션이 끝날 때까지 마지막 작업을 그대로 들고 있고, `transitionend`가 오지 않으면 400ms
  타이머가 놓아줘요. 그래서 마운트 사이드 이펙트가 있는 본문은 패널이 닫히는 동안 렌더가 몇 번 더
  돌아요. `<aside>`는 그 트랜지션이 끝나야 DOM에서 사라져요.
- `update`는 내장 본문의 입력이 쓰는 것과 같은 커밋 경로예요 — 스토어, 그다음 `onTasksChange`.
  그래서 비제어 모드에서도 `tasks`를 직접 되돌려 넣지 않고 편집이 반영돼요.
- `update`는 자체 검사를 **전혀** 하지 않아요. 상호작용 플래그, 날짜 클램프, 진행률 정규화는 내장
  본문에만 적용돼요. 여기로 넘긴 패치는 그대로 스토어와 `onTasksChange`에 도달하니, 규칙은 커스텀
  본문이 직접 지켜야 해요.
- 패치로 작업의 `id`는 바꿀 수 없어요 — 타입이 `id`를 제외하고, 패치는 항상 열린 작업에만 적용돼요.
- 작업의 나머지 필드를 패널에 넣는 방법은 렌더러뿐이에요. 기본 본문은 이름, 날짜, 기간을 보여주고,
  진행률과 선행 작업은 값이 있을 때만 나타나요. 거기에 줄을 더하거나 캡션을 번역하는 prop은 없어요.

여기 나온 모든 prop은 [GanttProps](props)에 정리돼 있어요.
