다른 작업에 의존하는 작업이 있다면 막대 사이에 화살표를 연결해요. 타임라인에서 관계를 확인하고 연결을 추가하거나 삭제할 수 있어요.

의존 관계는 계획을 표현해요. 일정을 자동으로 조정하지는 않아요. Design을 Build에 연결해도 Build의 시작일은 바뀌지 않아요.

## 데이터에 의존 관계 넣기

선행 작업을 기다리는 작업에 의존 관계를 저장해요. Build가 Design을 기다린다면 Build에 항목을 넣고 `targetId`를 Design의 id로 지정해요.

```tsx
const tasks: Task[] = [
  {
    id: 'design',
    name: 'Design',
    startDate: '2026-03-02',
    endDate: '2026-03-06',
    parentId: null,
    sequence: '1',
  },
  {
    id: 'build',
    name: 'Build',
    startDate: '2026-03-06',
    endDate: '2026-03-13',
    parentId: null,
    sequence: '2',
    dependencies: [{ targetId: 'design', type: 'FS' }],
  },
];
```

이 데이터는 Design에서 Build로 향하는 화살표를 그려요. `Task`는 `@jaeungkim/gantt-chart`에서 가져와요. 전체 데이터 구조는 [작업 타입](ref/task)에서 확인해요.

`targetId`는 이름과 달리 화살표가 도착하는 작업이 아니라 선행 작업을 가리켜요. 각 항목에는 연결 유형인 `type`도 필요해요.

## 관계 유형 고르기

첫 글자는 선행 작업의 끝점을, 두 번째 글자는 후행 작업의 끝점을 뜻해요. `S`는 시작, `F`는 종료예요.

| 유형 | 표현하려는 관계 |
|---|---|
| `FS` | Design이 끝난 뒤 Build를 시작해요 |
| `SS` | Design이 시작한 뒤 Build를 시작해요 |
| `FF` | Design이 끝난 뒤 Build를 끝내요 |
| `SF` | Design이 시작한 뒤 Build를 끝내요 |

일정 계획에서 사용하는 의미이며, 차트가 강제하는 날짜 제한은 아니에요. 실제 날짜가 관계에 맞는지는 앱에서 판단해요.

화살표는 선행 작업의 시작이나 종료에서 막대 바깥쪽 옆으로 나가요. 화살촉은 후행 작업의 시작(`FS`, `SS`)에는 왼쪽에서, 종료(`FF`, `SF`)에는 오른쪽에서 들어가요.

## 연결 그리기

1. 선행 작업 막대에 마우스를 올리거나 선택해 연결점을 표시해요.
2. 시작점이나 종료점에서 드래그해요. 점선이 포인터를 따라와요.
3. 후행 작업 막대 위나 막대 양 끝에서 24px 이내로 포인터를 옮겨요. 선이 실선으로 바뀌고 연결 유형을 알려주는 라벨이 나타나요.
4. 놓으면 연결이 만들어져요.

놓는 위치가 연결 유형을 정해요. 막대의 마지막 3분의 1(최대 24px)과 그 오른쪽 24px이 종료 영역이에요. 나머지 막대와 그 왼쪽 24px은 시작으로 처리해요. 그 밖의 곳에서 놓으면 아무것도 만들지 않아요. 여러 막대가 있는 레인에서는 닿는 범위 안에서 가장 가까운 막대에 연결해요.

타임라인 가장자리로 드래그하면 스크롤돼요. `Escape`로 취소할 수 있어요. 호버가 없는 터치 기기에서는 연결점이 계속 보여요.

레인에서 앞 막대와 26px 이내인 시작 연결점은 자기 막대에 마우스를 올린 동안에만 나타나고, 선택한 상태나 터치 기기에서는 나타나지 않아요. 나타난 동안에는 앞 막대의 끝을 덮어요. 그 끝의 크기를 조절하려면 마우스를 올린 막대에서 먼저 벗어난 뒤 다른 쪽에서 다가가요. 마우스를 올린 막대는 다음 막대 위로 올라오므로, 두 막대가 맞닿아 있어도 끝 연결점을 잡을 수 있어요. 터치 기기에서는 맞닿은 두 막대 사이의 연결점을 누를 수 없어요.

같은 방향의 중복 연결과 순환 의존 관계는 만들 수 없고, 드래그를 시작한 막대는 대상이 되지 않아요. 허용되지 않는 대상에는 빨간색으로 이유를 표시하고 데이터를 바꾸지 않아요. 이 검사는 그리기로 연결할 때만 적용하므로 가져온 데이터는 앱에서 검증해요.

## 변경 저장하거나 거절하기

생성하거나 삭제한 연결을 유지하려면 `onTasksChange`를 상태에 연결해요. 앱에서 특정 관계만 허용하려면 동기 콜백으로 검사해요. 다음 예제는 종료-시작 연결만 허용해요.

```tsx
<ReactGanttChart
  tasks={tasks}
  onTasksChange={setTasks}
  onDependencyCreate={({ type }) => {
    if (type !== 'FS') return false;
  }}
/>
```

`onDependencyCreate`에서 정확히 `false`를 반환하면 변경을 취소해요. `onDependencyDelete`도 같은 방식으로 동작하고, 삭제를 거부하면 화살표는 선택된 채 메뉴도 열려 있어요. 콜백의 Promise를 기다리지 않으므로 서버 검증은 앱의 저장 과정에서 처리해요.

`allowLinkCreate`와 `allowLinkDelete`로 연결 편집을 제어해요. 작업의 연결 생성을 끄면 들어오는 연결과 나가는 연결을 모두 막아요. 삭제 권한은 의존 관계 항목을 가진 후행 작업을 기준으로 판단해요.

콜백 시그니처는 [props](ref/props), 권한 우선순위는 [상호작용 설정](ref/interaction-config)을 참고해요.

## 연결 삭제하기

화살표를 클릭하면 선택돼요. 선택한 화살표는 강조 색으로 바뀌고, 클릭한 위치에 삭제 버튼(×) 하나만 있는 작은 메뉴가 열려요.

삭제 버튼은 연결을 삭제해요. 다른 곳을 클릭하면 메뉴가 닫히고 선택이 해제돼요. 후행 작업이 연결 삭제를 허용할 때만 화살표를 클릭할 수 있어요.

연결 유형을 그 자리에서 바꾸는 방법은 없어요. 연결을 삭제하고 다시 그리면 되는데, 드래그를 시작한 연결점이 유형의 첫 글자를, 놓는 위치가 두 번째 글자를 정해요. `tasks` 배열에서 항목의 `type`을 직접 바꿔도 돼요.

선행 작업과 후행 작업 쌍마다 항목을 하나만 유지해요. 삭제는 유형이 달라도 같은 쌍의 항목을 모두 제거해요.

## 화살표가 보이지 않을 때

양쪽 작업이 모두 보여야 화살표를 그려요. 작업을 필터로 숨기거나 부모를 접으면 의존 관계 데이터는 유지한 채 화살표만 숨겨요. 존재하지 않는 작업 id를 가리키는 항목도 건너뛰어요.

여러 화살표를 함께 선택할 수는 없어요. 경로는 자동으로 정하며 다른 막대를 가로지를 수 있어요.
