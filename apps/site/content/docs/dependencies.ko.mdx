의존성은 두 막대를 잇는 화살표예요. 항목은 기다리는 쪽인 후행 작업(successor)에 놓여요. `targetId`에는 화살표가 향하는 작업이 아니라 기다리는 대상인 선행 작업(predecessor)의 id가 들어가요.

이 페이지는 항목의 모양과 네 가지 링크 타입을 다뤄요. 링크를 그리고 지우는 방법, 차트가 검사하지 않는 부분도 함께 다뤄요.

## 의존성 항목

기다리는 쪽 작업에 항목을 하나 두세요.

```tsx title="src/DependencyExample.tsx"
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  {
    id: 'design',
    name: 'Design',
    startDate: '2025-06-02',
    endDate: '2025-06-05',
    parentId: null,
    sequence: '1',
  },
  {
    id: 'build',
    name: 'Build',
    startDate: '2025-06-05',
    endDate: '2025-06-12',
    parentId: null,
    sequence: '2',
    // Build가 Design을 기다리므로 항목은 Build에 놓여요
    dependencies: [{ targetId: 'design', type: 'FS' }],
  },
];

export function DependencyExample() {
  return <ReactGanttChart tasks={tasks} height={300} />;
}
```

이 코드는 Design에서 Build로 화살표 하나를 그려요. `design`에는 `dependencies` 필드가 없어요. 필드 타입은 [Task와 작업 타입](ref/task)에 정리돼 있어요.

`targetId`가 배열의 어떤 작업과도 맞지 않으면 화살표를 만들 때 경고 없이 건너뛰어요. 데이터를 검사하는 곳은 그 외에 없어요. [상호작용 함정](#상호작용-함정)을 참고하세요.

## 링크 타입

두 글자는 화살표가 나가는 끝과 들어오는 끝을 가리켜요. 첫 번째 글자는 선행 작업 쪽 끝이고 두 번째 글자는 후행 작업 쪽 끝이에요. 막대의 오른쪽 끝이 finish, 왼쪽 끝이 start예요.

`type`은 모든 항목에 필수고 기본값은 없어요. 네 가지 값은 [Task와 작업 타입](ref/task)에 정리돼 있어요.

이 이름은 일정 관리 도구에서 왔어요. `FS`는 선행 작업이 끝나기 전에는 후행 작업을 시작할 수 없다는 뜻이에요. 차트는 이 규칙을 적용하지 않아요. 날짜가 타입과 어긋나는 링크도 들어맞는 링크와 똑같이 그려져요.

화살표는 45% 불투명도로 그려져요. 작업에 호버하거나 작업을 선택하면 그 작업에 이어진 화살표가 모두 진해져요.

## 링크 그리기

막대마다 양쪽 끝에 연결 점이 하나씩 있어요. 막대 끝에서 18px 바깥에 놓인 12px 원이에요. 클릭 영역은 보이지 않고 원보다 넓어요.

마우스를 쓰면 막대에 호버하거나 막대를 선택할 때 점이 나타나요. 호버가 없는 기기에서는 점이 옅게 계속 보이고 누를 수 있어요.

점은 그 작업의 `allowLinkCreate`가 true일 때만 렌더링돼요. 작업에 지정한 필드가 같은 이름의 차트 prop보다 우선해요. 우선순위는 [GanttInteractionConfig](ref/interaction-config)를 참고하세요. `allowLinkDelete`도 같은 순서를 따라요.

점을 누른 채로 드래그하세요. 포인터가 4px 움직인 뒤에 드래그가 시작되므로 점을 그냥 클릭하면 링크가 생기지 않아요.

대상 작업의 행 아무 곳에나 놓으세요. 막대 옆 빈 공간을 포함해 행 전체가 드롭을 받아요. 막대가 여럿인 레인 행에서는 가로로 가장 가까운 막대에 링크가 연결돼요.

대상은 행 모델에서 계산돼요. 차트가 포인터 아래 요소를 무시하므로 호스트 앱의 오버레이가 드롭을 가로챌 수 없어요.

누른 점이 타입의 첫 번째 글자를 정해요. 놓은 위치가 두 번째 글자를 정해요.

대상 막대의 마지막 24px과 그 오른쪽 전체가 finish 영역이고 이 폭은 막대의 3분의 1을 넘지 않아요. 행의 나머지는 start예요. finish 영역 바깥에 놓으면 `FS`가 돼요.

| 드래그 시작 지점 | 놓는 위치 | 타입 |
|---|---|---|
| 끝 점 | 행에서 finish 영역 바깥 | `FS` |
| 시작 점 | 행에서 finish 영역 바깥 | `SS` |
| 끝 점 | finish 영역 | `FF` |
| 시작 점 | finish 영역 | `SF` |

드래그하는 동안 점선이 포인터를 따라와요. 유효한 대상 위에서는 선이 실선으로 바뀌어요. 이때 경로는 확정된 화살표가 쓸 꺾인 경로와 같아요. 두 글자 타입이 옆에 표시되고 받는 쪽 점이 채워져요.

뷰포트 가장자리로 드래그하면 타임라인이 스크롤돼요. 그래서 한 화면에 함께 들어오지 않는 두 막대도 이을 수 있어요. `Escape`를 누르면 드래그가 취소돼요.

### 거부되는 대상

포인터가 후보 위에 있는 동안 차트가 두 작업을 이을 수 있는지 검사해요. 거부된 대상은 외곽선과 미리보기 선이 빨갛게 바뀌고 이유가 포인터 옆에 표시돼요. 그 자리에서 놓아도 아무것도 확정되지 않아요.

| 거부 | 조건 | 표시되는 문구 |
|---|---|---|
| 자기 참조 | 두 id가 같음 | `Cannot link a task to itself` |
| 중복 | 후행 작업에 이 선행 작업을 가리키는 항목이 이미 있음 | `These tasks are already linked` |
| 순환 | 선행 작업의 선행 작업들을 따라가면 후행 작업에 닿음 | `That would create a circular dependency` |

검사는 표에 적힌 순서대로 실행돼요.

중복 검사는 `targetId`만 비교하고 `type`은 무시해요. `design`에서 `build`로 가는 링크가 어떤 타입으로든 이미 있으면 같은 방향의 두 번째 링크는 막혀요. 반대 방향은 순환 규칙이 검사해요.

세 문구는 영어로 하드코딩돼 있고 `locale`이나 `formats`를 거치지 않아요.

`allowLinkCreate`가 false인 작업은 후보가 되지 않아요. 강조도 이유 문구도 나타나지 않아요. 그 자리에 놓아도 아무 일이 없어요.

### 생성 콜백

드래그가 거부하지 않은 링크는 모두 `onDependencyCreate`로 전달돼요. 레인을 가로지르는 링크와 요약 행으로 향하는 링크, 날짜가 타입과 어긋나는 링크도 포함돼요.

```tsx title="src/LinkGuard.tsx"
import { useState } from 'react';
import {
  ReactGanttChart,
  type GanttDependencyChange,
  type Task,
} from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function LinkGuard({ initial }: { initial: Task[] }) {
  const [tasks, setTasks] = useState<Task[]>(initial);

  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={setTasks}
      onDependencyCreate={(change: GanttDependencyChange) => {
        // 정확히 false일 때만 중단돼요
        if (change.type === 'SF') return false;
      }}
      onDependencyDelete={({ predecessorId, successorId }) =>
        window.confirm(`Unlink ${predecessorId} -> ${successorId}?`)
      }
    />
  );
}
```

반환값은 `=== false`로 비교돼요. `true`, `undefined`, `null`, `0`은 모두 확정돼요.

반환된 `Promise`도 확정돼요. 두 콜백은 동기라서 기다리지 않거든요. 비동기 가드는 링크가 이미 데이터에 들어간 뒤에 끝나요.

`GanttDependencyChange`에는 `predecessorId`, `successorId`, `type` 세 필드가 있어요.

확정된 링크는 작업 배열에 기록되고 `onTasksChange`가 새 배열과 함께 호출돼요. 되돌리려면 이전 배열을 다시 넘기세요.

prop과 기본값은 [GanttProps](ref/props)를 참고하세요.

## 링크 삭제

화살표마다 경로를 따라 12px 폭의 보이지 않는 클릭 영역이 있어요. 후행 작업의 `allowLinkDelete`가 true일 때만 그려져요. 여기에 호버하면 화살표가 강조 색으로 바뀌고 커서가 포인터 모양이 돼요.

호버 색이 화살표를 지울 수 있다는 표시예요. 클릭 영역을 누르면 화살표가 선택돼요. 선택된 화살표는 강조 색으로 바뀌고 양 끝점의 중간에 원 안에 X가 든 삭제 버튼이 생겨요.

화살표가 선택된 동안에는 다음 입력이 동작해요.

| 입력 | 동작 |
|---|---|
| `Delete` 또는 `Backspace` | 선택된 링크를 삭제해요 |
| `Escape` | 선택을 해제해요 |
| 아무 곳에서나 포인터 누르기 | 선택을 해제해요 |

포커스가 `input`, `textarea`, `select`, `contentEditable` 요소에 있으면 키 입력은 무시돼요.

`allowLinkDelete`는 항목이 빠지는 쪽인 후행 작업에서 읽어요. 선행 작업에 같은 필드를 false로 줘도 달라지는 것은 없어요. 플래그가 false면 삭제는 변화도 경고도 없이 끝나요.

삭제할 때는 `targetId`만 보고 항목을 걸러 내요. 한 후행 작업에 같은 선행 작업을 가리키는 항목이 둘 있으면 화살표 두 개가 함께 선택돼요. 한 번 삭제하면 둘 다 사라져요.

막대 셀에 키보드 포커스가 있고 화살표도 선택돼 있으면 `Delete`를 두 핸들러가 모두 받아요. 링크가 지워지고 포커스된 작업도 삭제돼요. 이 둘은 서로 다른 변경이에요. 작업 삭제 키는 [키보드와 스크린 리더](accessibility)에 정리돼 있어요.

## 상호작용 함정

작업에 `allowLinkCreate: false`를 주면 양방향이 모두 막혀요. 점을 렌더링할 때 출발 쪽에서 읽고 드래그하는 동안 대상 쪽에서 또 읽어요. 그래서 그 작업은 링크를 시작할 수도 받을 수도 없어요.

자기 참조와 중복, 순환 검사는 드래그하는 동안에만 실행돼요. `tasks` 배열은 검사하지 않으므로 데이터에 이미 있는 자기 참조 링크나 순환은 경고 없이 그대로 그려져요.

데이터에 순환이 있어도 드래그 검사는 그대로 동작해요. 탐색이 이미 본 id를 건너뛰기 때문에 끝까지 진행되고 새로 생기는 순환도 잡아내요.

링크는 막대를 움직이지 않아요. 새 `FS` 링크를 걸어도 겹쳐 있던 후행 작업은 그대로 남아요. 그 뒤에 둘 중 하나를 드래그해도 나머지는 제자리에 있어요.

## 한계

차트는 링크를 그리고 지우지만 관리하지는 않아요.

- 타입은 그 자리에서 바꿀 수 없어요. `FS`를 `SS`로 바꾸려면 `tasks` 배열의 항목을 다시 써야 해요.
- 링크는 강제되지 않아요. `FS` 링크를 추가해도 후행 작업은 움직이지 않고 그 뒤로 날짜를 검사하는 곳도 없어요.
- 링크에는 키보드 경로가 없어요. 연결 점은 `tabIndex={-1}`이고 링크 드래그를 시작하는 키도 없어서 `Delete`를 쓰려면 먼저 포인터로 화살표를 선택해야 해요.
- 화살표는 한 번에 하나만 선택돼요. 다중 선택은 없어요.
- 화살표에는 호버 툴팁과 컨텍스트 메뉴, 라벨이 없어요. 화살표는 클릭 영역과 선택된 화살표의 삭제 버튼으로 조작해요. 그 밖의 조작 수단은 없어요.
- 화살표 경로는 고정이에요. 꺾임은 양 끝점과 타입으로만 정해져서 화살표가 다른 막대를 가로지를 수 있어요.
- 숨은 작업으로 가는 화살표는 그려지지 않아요. 선행 작업이 필터로 빠졌거나 접힌 부모 아래 숨어 있으면 화살표가 없고 항목은 데이터에 그대로 남아요.
- 이미 있는 링크를 바꿀 때 호출되는 콜백은 없어요. 생성과 삭제는 `onDependencyCreate`와 `onDependencyDelete`로 받아요.
- 링크 검증 함수는 내보내지 않아요. 자기 참조와 중복, 순환을 똑같이 검사하려면 호스트 앱에서 직접 작성하세요.
