이벤트는 차트가 클릭과 선택, 편집을 알리는 콜백이에요. 드래그나 키보드 편집은 먼저 차트 쪽 작업
사본에 기록되고 `onTasksChange`가 배열 전체를 받아요. 이 페이지는 모든 콜백과 각각이 받는 인자,
변경을 거부할 수 있는 콜백 세 개를 다뤄요.

## 클릭과 선택

클릭은 콜백 네 개와 플래그 하나가 담당해요. 앞의 세 개는 막대와 작업 목록의 행 양쪽에 연결돼 있어서
어느 패널을 클릭하든 같은 콜백이 같은 인자로 호출돼요. `onDetailChange`는 그 뒤에 와요. 상세 패널이
켜져 있으면 행을 선택하는 클릭이 패널도 열기 때문이에요.

| prop | 시그니처 |
|---|---|
| `onTaskClick` | `(task: TaskTransformed, event: React.MouseEvent) => void` |
| `onTaskDoubleClick` | `(task: TaskTransformed, event: React.MouseEvent) => void` |
| `onTaskSelect` | `(task: TaskTransformed \| null) => void` |
| `onDetailChange` | `(task: TaskTransformed \| null) => void` |
| `selectable` | `boolean` |

`TaskTransformed`는 작업에 차트가 계산한 레이아웃 필드를 더한 타입이에요. 형태는
[Task와 작업 타입](ref/task)에 있어요. 여기 나온 prop의 시그니처와 기본값은
[GanttProps](ref/props)를 참고하세요.

```tsx title="src/ProjectGantt.tsx"
import { useState } from 'react';
import {
  ReactGanttChart,
  type Task,
  type TaskTransformed,
} from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function ProjectGantt({ initial }: { initial: Task[] }) {
  const [tasks, setTasks] = useState<Task[]>(initial);
  const [inspected, setInspected] = useState<TaskTransformed | null>(null);

  return (
    <>
      <ReactGanttChart
        tasks={tasks}
        onTasksChange={setTasks}
        onTaskClick={(task) => console.log('clicked', task.id)}
        onTaskDoubleClick={(task) => console.log('open editor for', task.id)}
        onTaskSelect={setInspected}
      />
      <aside>{inspected ? inspected.name : 'Nothing selected'}</aside>
    </>
  );
}
```

### 선택 기본값

`selectable`에는 고정된 기본값이 없어요. `onTaskSelect`를 넘기면 선택이 켜지고 상세 패널을 켜도 같이
켜져요. `selectable`을 직접 넘기면 그 값이 우선이에요. 켜는 쪽이든 끄는 쪽이든 마찬가지예요.

| `selectable` | `onTaskSelect` | 선택 |
|---|---|---|
| 생략 | 생략 | 꺼짐, 상세 패널이 켜져 있으면 켜짐 |
| 생략 | 전달 | 켜짐 |
| `true` | 생략 | 켜짐, 하이라이트만 |
| `true` | 전달 | 켜짐 |
| `false` | 전달 | 꺼짐, `onTaskSelect`는 호출되지 않음 |

`selectable={false}`면 선택 처리가 아예 실행되지 않아서 `onTaskSelect`를 넘겨도 호출되지 않아요.

패널은 선택된 행을 보여 주는 것이라서 패널을 켜면 선택도 같이 켜져요. `renderDetail`이나
`showDetail`을 넘기고 `selectable`을 생략하면 `onTaskSelect` 없이도 행이 선택돼요. 차트는
`selectable ?? (detailEnabled ? true : undefined)`로 결정하니까 `selectable={false}`가 여전히
우선이에요. 패널은 클릭하면 그대로 열리지만 행에는 하이라이트가 붙지 않아요. 패널을 켜는 방법은
[상세 패널](detail-panel)을 참고하세요.

클릭 한 번 안에서 순서는 고정이에요. `onTaskClick`이 먼저 호출되고 그다음 선택이 바뀌어요.
`onTaskSelect`는 선택된 id가 바뀔 때만 호출돼요. 이미 선택된 행을 클릭하면 `onTaskClick`만 호출되고
`onTaskSelect`는 호출되지 않아요.

하이라이트는 CSS 클래스예요. 선택된 행에는 `.gantt-grid-row.selected`가 붙고 선택된 막대에는
`.gantt-task-bar.selected`가 붙어요.

### 빈 타임라인 클릭

타임라인 배경을 클릭하면 선택이 풀려요. 작업이 선택돼 있었다면 `onTaskSelect(null)`이 호출돼요.
배경을 다시 클릭하면 바뀌는 id가 없어서 콜백이 호출되지 않아요. 행 배경과 비근무일 음영은 포인터
이벤트를 받지 않아서 클릭을 막지 않아요.

작업 목록 패널의 빈 영역과 날짜 축 헤더는 선택을 풀지 않아요. 선택을 푸는 핸들러는 타임라인 본문에만
붙어 있어요.

### 드래그 뒤의 클릭

브라우저는 드래그를 끝내는 `pointerup` 다음에 클릭 이벤트를 한 번 발생시켜요. 막대에서는 차트가 그
클릭을 버려요. 끝난 드래그는 `onTaskClick`을 호출하지 않고 선택도 바꾸지 않아요. 차트가 확인하는
플래그는 스냅된 드래그 단계 수가 바뀌었을 때만 세워져요. 한 단계도 넘지 않은 누름은 여전히
클릭이에요. 드래그 단계는 배율마다 다르고 [작업 편집](editing)에서 다뤄요.

작업 목록의 행에는 이런 플래그가 없어요. 접기 토글은 자기 클릭을 막아서 행을 펼쳐도 선택되지 않아요.
순서 바꾸기 그립은 `pointerdown`만 막기 때문에 뒤따르는 클릭은 행까지 닿아요. 그립을 누르면 행이
움직였든 아니든 `onTaskClick`이 호출되고 행이 선택돼요.

### 더블 클릭

차트에는 클릭 횟수 디바운스가 없어요. 막대를 더블 클릭하면 `onTaskClick`이 두 번 호출되고 그다음
`onTaskDoubleClick`이 한 번 호출돼요. 싱글 클릭이 실제 작업을 하고 더블 클릭이 에디터를 연다면
에디터가 열리기 전에 그 작업이 두 번 실행돼요.

### 상세 패널 콜백

`onDetailChange`는 패널이 열리고 닫힐 때마다 작업이나 `null`을 받아요. 제어 모드와 비제어 모드 모두
같아요. 패널은 행을 선택하는 클릭에서 열리므로 `onTaskClick`이 먼저 호출되고 패널은 그 뒤에 열려요.
포커스된 행에서 `Enter`나 `Space`를 눌러도 같은 방식으로 열려요. 더블 클릭은 `onTaskClick` 두 번과
`onTaskDoubleClick` 한 번을 호출하고 패널은 첫 번째 클릭에서 열려요.

`Escape`와 패널의 닫기 버튼, 빈 타임라인 클릭은 모두 `onDetailChange(null)`을 호출해요. 이 콜백은
제스처와 ref 호출만 알리기 때문에 `detailTaskId` prop을 직접 바꿔도 호출되지 않아요. `tasks`에서 빠진
작업의 패널은 닫히지만 `onDetailChange`는 호출되지 않아요. 패널을 여는 조건과 `renderDetail`,
제어용 `detailTaskId`는 [상세 패널](detail-panel)을 참고하세요.

## 제스처 확정

이동과 크기 조절, 진행률 드래그는 모두 `pointerup`에서 확정돼요. 차트는 결과를 자기 쪽 작업 사본에
기록하고 옮긴 작업이 몇 개든 배열 전체로 `onTasksChange`를 한 번 호출해요. 요약 막대를 끌면 하위
트리가 함께 움직이고 그 작업들도 모두 배열에 들어 있어요. 기록 전에 실행되는 콜백은 없고 기록을 막을
수 있는 콜백도 없어요.

드래그 단계를 한 번도 넘지 않은 제스처는 기록도 호출도 없이 끝나요.

`onTasksChange`는 배열만 받아요. 제스처 종류와 잡은 모서리, 움직인 id 목록은 들어 있지 않아요.
무엇이 바뀌었는지 알아야 하면 마지막으로 넘긴 배열과 비교하세요.

변경을 거부하려면 예전 데이터를 다시 넘기세요. `tasks` prop은 내용이 차트가 가진 것과 다를 때
우선이에요. 그래서 제스처 전의 배열을 다시 넘기면 막대가 원래 자리로 돌아가요.

### 낙관적 업데이트

차트는 핸들러가 실행되기 전에 변경을 이미 적용해요. 그래서 요청을 보내는 시점에 화면은 이미 바뀌어
있어요. 요청이 실패하면 이전 배열을 다시 넘겨서 되돌리세요.

```tsx title="src/ServerBackedGantt.tsx"
import { useState } from 'react';
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

async function save(tasks: Task[]): Promise<void> {
  const response = await fetch('/api/tasks', {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(tasks),
  });

  if (!response.ok) throw new Error(`save failed: ${response.status}`);
}

export function ServerBackedGantt({ initial }: { initial: Task[] }) {
  const [tasks, setTasks] = useState<Task[]>(initial);
  const [error, setError] = useState<string | null>(null);

  return (
    <>
      {error ? <p role="alert">{error}</p> : null}
      <ReactGanttChart
        tasks={tasks}
        onTasksChange={(next) => {
          // 이 제스처 직전에 차트가 보여 주던 배열
          const previous = tasks;

          setError(null);
          setTasks(next);

          save(next).catch(() => {
            setError('Could not reach the server. Your change was undone.');
            // 차트가 들고 있는 것과 내용이 달라서 막대가 되돌아가요
            setTasks(previous);
          });
        }}
      />
    </>
  );
}
```

`onTasksChange`는 제스처당 한 번 전체 배열로 호출되니까 요청 하나에 잡은 막대와 하위 트리가 다
담겨요. 방금 받은 배열을 그대로 `tasks`로 돌려주면 차트는 같은 내용으로 인식하고 덮어쓰지 않아요.
그래서 제어 모드로 상태를 다시 넘겨도 화면의 드래그 결과는 그대로예요.

## 편집 경로

| 경로 | 콜백 | 취소 가능 |
|---|---|---|
| 이동, 크기 조절, 진행률 드래그 | `onTasksChange` | 아니오 |
| 키보드 이동, 진행률 단계, 삭제 | `onTasksChange` | 아니오 |
| 상세 패널 필드 편집 또는 `renderDetail`의 `update()` | `onTasksChange` | 아니오 |
| 행을 새 자리나 새 부모로 드래그, 또는 그 키보드 동작 | `onTaskMove`, 그다음 `onTasksChange` | 예, 동기 |
| **Add task** 버튼, ref의 `addTask()`, 마지막 행 아래에 그린 범위 | `onTaskCreate` | 취소할 것 없음, 차트는 스스로 추가하지 않아요 |
| 의존성 화살표 그리기 | `onDependencyCreate`, `false`를 반환하면 취소 | 예, 동기 |
| 의존성 화살표 삭제 | `onDependencyDelete`, `false`를 반환하면 취소 | 예, 동기 |

키보드로도 포인터 없이 편집할 수 있어요. `Alt`와 좌우 방향키는 막대를 옮기고 `Shift`는 크기를
조절해요. `+`와 `-`는 진행률을 한 단계씩 바꾸고 `Delete`는 막대를 지워요. 모두 곧바로 작업에
확정되고 같은 일을 하는 제스처와 똑같이 `onTasksChange`를 호출해요. 편집이 일어나기 전에 막으려면
[작업 편집](editing)의 권한 우선순위로 그 제스처를 끄세요. 전체 키 맵은
[키보드와 스크린 리더](accessibility)를 참고하세요.

상세 패널도 같은 방식으로 편집해요. 내장 필드는 블러나 `Enter`에서 확정되고 커스텀 본문은
`update(patch)`로 확정해요. 둘 다 작업에 곧바로 기록되고 배열 전체로 `onTasksChange`를 호출해요.
어떤 필드가 입력을 받는지와 거부된 값이 어떻게 되는지는 [상세 패널](detail-panel)을 참고하세요.

행 이동은 이 순서의 예외예요. `onTaskMove`는 적용 전에 호출되고 `false`를 반환하면 아무것도 기록하지
않은 채 이동을 버려요. 그립 드래그와 그 키보드 동작 모두 여기를 거쳐요. 페이로드와 이동이 통과해야
하는 규칙은 [행 순서 바꾸기](reordering)를 참고하세요.

취소할 수 있는 콜백 세 개는 동기로 동작해요. 차트가 반환값을 즉시 확인하기 때문에 프로미스를
반환하면 참으로 판단해서 변경이 그대로 확정돼요. 서버에 먼저 물어보려고 `onDependencyCreate`에서
프로미스를 반환해도 동작하지 않아요. 의존성 페이로드는 [의존성](dependencies)을 참고하세요.

## 한계

- 선택은 id 하나이고 차트 내부에만 있어요. 다중 선택과 `selectedTaskId` prop이 없어서 선택을
  설정하거나 리마운트 뒤에 복원하거나 직접 풀 수 없어요. 차트 밖에서 필요하면 `onTaskSelect`로 직접
  추적하세요.
- 컨텍스트 메뉴와 호버, 포커스에는 콜백이 없어요. 오른쪽 클릭은 보고되지 않아요. 컨텍스트 메뉴가
  필요하면 차트 컨테이너에 리스너를 붙이고 이벤트 타깃에서 `data-task-id`를 읽으세요.
- 날짜와 진행률은 변경 전에 확인하는 콜백이 없어요. 드래그와 키보드 편집, 상세 패널 편집은 코드가
  알기 전에 기록돼요. 모든 편집에 공통으로 적용할 규칙은 `onTasksChange`에서 사후에 처리해야 해요.
  변경 전에 콜백이 호출되는 것은 의존성 변경과 행 이동뿐이에요.
- 되돌리기는 앱 상태의 몫이에요. 예전 `tasks` 배열을 다시 넘기는 것이 방법의 전부이고
  애니메이션은 없어요. 막대는 다음 렌더에서 예전 날짜에 다시 그려져요.
- 드래그 생명주기 콜백은 없어요. `onDragStart`와 `onDragMove`, `onDragEnd`가 없고 `onTasksChange`는
  제스처가 끝날 때만 호출돼요.
- 저장은 앱의 몫이에요. 차트는 아무것도 저장하거나 전송하지 않아요. `onTasksChange`는 배열을 건네고
  그 배열이 `tasks` prop으로 다시 들어와야 해요.
- 브라우저가 취소한 진행률 드래그는 확정되고 같은 방식으로 취소된 막대 드래그는 되돌아가요. 이
  비대칭은 [작업 편집](editing)을 참고하세요.

| 사용자 동작 | 콜백 | 취소 가능 |
|---|---|---|
| 막대나 그 행을 클릭 | `onTaskClick`, 그다음 `onTaskSelect`, 패널이 켜져 있으면 `onDetailChange` | 아니오 |
| 막대나 그 행을 더블 클릭 | `onTaskClick` 두 번, 그다음 `onTaskDoubleClick`. 패널은 첫 번째 클릭에서 열려요 | 아니오 |
| 빈 타임라인을 클릭 | 선택된 작업이 있었으면 `onTaskSelect(null)`, 패널이 열려 있었으면 `onDetailChange(null)` | 아니오 |
| 막대에서 드래그를 끝냄 | 없음, 뒤따르는 클릭은 버려져요 | 취소할 것 없음 |
| 막대를 이동하거나 크기를 조절 | `onTasksChange` | 아니오 |
| 진행률 핸들을 드래그 | `onTasksChange` | 아니오 |
| 키보드로 편집 | `onTasksChange` | 아니오 |
| 상세 패널에서 필드를 편집 | `onTasksChange` | 아니오 |
| 행을 새 자리나 새 부모로 드래그 | `onTaskMove`, 그다음 `onTasksChange` | 예, 동기 |
| 부모 행을 펼치거나 접음 | `onCollapsedChange`. [작업 목록과 계층](task-list) 참고 | 아니오 |
| **Add task**를 누르거나 `addTask()`를 호출하거나 마지막 행 아래에 범위를 그림 | `onTaskCreate` | 취소할 것 없음, 차트는 기록하지 않아요 |
| 의존성 화살표를 그림 | `onDependencyCreate`, 그다음 `onTasksChange` | 예, 동기 |
| 의존성 화살표를 삭제 | `onDependencyDelete`, 그다음 `onTasksChange` | 예, 동기 |
| `Enter`/`Space`, `Escape`, 닫기 버튼, ref로 상세 패널을 열거나 닫음 | `onDetailChange` | 아니오 |
| ref, `Ctrl`/`Cmd` + 휠, 키보드로 배율을 바꿈 | `onScaleChange`. [타임라인](timeline) 참고 | 아니오 |
| 렌더링된 타임라인 범위가 바뀜 | `onRangeChange`. [타임라인](timeline) 참고 | 아니오 |
