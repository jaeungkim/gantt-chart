사용자가 막대를 3일 뒤로 끌어다 놓아요. 차트는 새 날짜를 자기 쪽 작업 사본에 기록하고 배열 전체와
함께 `onTasksChange`를 실행해요. 먼저 물어보는 것도 없고, 어딘가에 저장되는 것도 없어요. 이 페이지는
차트가 실행하는 모든 콜백과 각각이 받는 인자, 그리고 아직 변경을 거부할 수 있는 콜백 두 개를 다뤄요.

## 클릭과 선택

사용자가 포인터로 무엇을 가리키는지는 콜백 네 개와 플래그 하나가 담당해요. 앞의 세 개는 막대와 작업
목록의 해당 작업 행 양쪽에 연결돼 있어요. 그래서 어느 쪽을 클릭하든 같은 인자를 받는 같은 이벤트예요.
`onDetailChange`가 그 뒤를 따라요. 기본 트리거에서는 그 같은 클릭이 상세 패널을 열기 때문이에요.

| 프로퍼티 | 시그니처 |
|---|---|
| `onTaskClick` | `(task: TaskTransformed, event: React.MouseEvent) => void` |
| `onTaskDoubleClick` | `(task: TaskTransformed, event: React.MouseEvent) => void` |
| `onTaskSelect` | `(task: TaskTransformed \| null) => void` |
| `onDetailChange` | `(task: TaskTransformed \| null) => void` |
| `selectable` | `boolean` |

`TaskTransformed`는 작업에 차트가 계산한 레이아웃 필드를 더한 타입이에요. 그 형태는
[작업](ref/task)에 있어요.

```tsx title="src/ProjectGantt.tsx"
import { useState } from 'react';
import {
  ReactGanttChart,
  type Task,
  type TaskTransformed,
} from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

export function ProjectGantt({ initial }: { initial: Task[] }) {
  const [tasks, setTasks] = useState<Task[]>(initial);
  const [inspected, setInspected] = useState<TaskTransformed | null>(null);

  return (
    <>
      <ReactGanttChart
        tasks={tasks}
        onTasksChange={setTasks}
        onTaskClick={(task) => console.log('clicked', task.id)}
        onTaskDoubleClick={(task) => console.log('open editor for', task.id)}
        onTaskSelect={setInspected}
      />
      <aside>{inspected ? inspected.name : 'Nothing selected'}</aside>
    </>
  );
}
```

### 선택은 물어보는 순간 켜져요

외워야 할 `selectable` 기본값은 없어요. `onTaskSelect`를 넘겨도, 상세 패널을 켜도 선택이 켜지고,
`selectable`은 그 둘을 양방향으로 덮어써요.

| `selectable` | `onTaskSelect` | 선택 |
|---|---|---|
| 생략 | 생략 | 꺼짐, 상세 패널이 켜져 있으면 켜짐 |
| 생략 | 전달 | 켜짐 |
| `true` | 생략 | 켜짐, 하이라이트만 |
| `true` | 전달 | 켜짐 |
| `false` | 전달 | 꺼짐, `onTaskSelect`는 호출되지 않음 |

다들 의외라고 느끼는 건 마지막 행이에요. `selectable={false}`는 조용한 선택이라는 뜻이 아니에요.
선택 경로 전체가 핸들러에 닿기 전에 빠져나간다는 뜻이에요.

패널은 하이라이트된 행을 설명하는 것이라서, 패널을 켜면 선택도 같이 켜져요. `renderDetail`이나
`showDetail`을 넘기고 `selectable`을 생략하면 `onTaskSelect`를 한 번도 넘기지 않았어도 행이 선택돼요.
차트가 `selectable ?? (detailEnabled ? true : undefined)`로 결정하거든요. 그래서 `selectable={false}`는
여기서도 이겨요. 패널은 클릭할 때 그대로 열리고, 행만 하이라이트되지 않아요. 패널을 켜는 방법은
[상세 패널](detail-panel)에서 다뤄요.

한 번의 클릭 안에서 순서는 고정이에요. `onTaskClick`이 먼저 실행되고, 그다음 선택이 바뀌어요. 그리고
`onTaskSelect`는 선택된 id가 실제로 바뀔 때만 실행돼요. 이미 선택된 행을 클릭하면 `onTaskClick`만
실행되고 그걸로 끝이에요.

하이라이트는 콜백이 아니라 클래스예요. 선택된 행에는 `.gantt-grid-row.selected`가, 선택된 막대에는
`.gantt-task-bar.selected`가 붙어요.

### 빈 타임라인을 클릭하면 선택이 풀려요

타임라인의 배경 자체에 클릭이 닿으면 선택이 풀려요. 작업이 선택돼 있었다면 `onTaskSelect(null)`이
호출돼요. 배경을 두 번 클릭해도 한 번만 실행되는데, id가 바뀌어야 하기 때문이에요. 행 배경과
비근무일 음영은 클릭을 막지 않아요. 둘 다 포인터 이벤트를 받지 않기 때문이에요.

선택이 풀리지 않는 곳이 두 군데 있어요. 작업 목록 창의 빈 영역을 클릭하면 아무 일도 일어나지 않아요.
타임라인에 그려진 그룹 레이블을 클릭해도 마찬가지예요. 그 레이어에서 포인터 이벤트를 다시 받는 유일한
요소이고, 작업 목록 창이 숨겨져 있을 때만 렌더링돼요.

### 드래그 뒤에 따라오는 클릭은 삼켜져요

브라우저는 드래그를 끝낸 pointerup 다음에 클릭을 발생시켜요. 막대 위에서는 차트가 그 클릭을 버려요.
그래서 끝난 드래그는 `onTaskClick`을 실행하지 않고 선택도 바꾸지 않아요. 차트가 확인하는 플래그는
스냅된 드래그 스텝 수가 실제로 바뀌었을 때만 세워져요. 한 스텝도 넘지 못한 누름과 흔들림은 여전히
클릭이에요. 드래그 스텝은 배율마다 다르고 [작업 편집](editing)에서 다뤄요.

작업 목록의 행은 아예 드래그되지 않아서, 그쪽에는 뒤따르는 클릭이 오지 않아요. 접기 토글은 이벤트가
선택으로 이어지기 전에 막아요. 그래서 행을 펼쳐도 선택되지 않아요.

### 더블 클릭은 두 번의 클릭을 모두 실행해요

차트 어디에도 클릭 횟수 디바운스는 없어요. 막대를 더블 클릭하면 `onTaskClick`이 두 번, 그다음
`onTaskDoubleClick`이 한 번 실행돼요. 싱글 클릭이 실제 작업을 하고 더블 클릭이 에디터를 연다면,
에디터가 열리기 전에 그 작업이 두 번 실행돼요.

### 상세 패널은 같은 클릭을 타고 열려요

`onDetailChange`는 패널이 열릴 때마다, 닫힐 때마다 실행돼요. 제어 모드든 비제어 모드든 똑같고,
작업이나 `null`을 받아요. `detailTrigger` 기본값인 `'selection'`에서는 행을 선택하는 바로 그 클릭이
패널을 열어요. 그래서 패널을 여는 클릭에서도 `onTaskClick`은 늘 그렇듯 가장 먼저 실행되고, 패널은 그
뒤에 열려요. 더블 클릭도 다르지 않아요. `onTaskClick` 두 번과 `onTaskDoubleClick` 한 번이 먼저
실행되고 나서야 무언가 열려요. `detailTrigger="doubleClick"`에서는 그 묶음이 패널을 여는 동작이에요.

`Escape`와 패널의 닫기 버튼, 빈 타임라인 공간 클릭은 모두 `onDetailChange(null)`을 실행해요.
`tasks`에서 사라진 작업은 자기 패널을 함께 데려가는데, 그때는 아무것도 실행되지 않아요. 직접 바꾼
데이터가 원인이니까요. 무엇이 패널을 여는지, `renderDetail`, 제어용 `detailTaskId`는
[상세 패널](detail-panel)에 있어요.

## 제스처는 곧바로 기록돼요

이동과 크기 조절, 진행률 드래그는 모두 pointerup에서 커밋돼요. 차트는 결과를 자기 쪽 작업 사본에
기록하고, 제스처가 옮긴 작업이 몇 개든 배열 전체와 함께 `onTasksChange`를 한 번 실행해요. 요약 막대를
끌면 그 하위 트리가 함께 움직이고, 그 하위 트리의 작업이 모두 배열에 들어 있어요. 기록 전에 실행되는
건 아무것도 없고, 기록을 막을 수 있는 콜백도 없어요.

드래그 스텝을 한 번도 커밋하지 못한 제스처는 아무것도 기록하지 않고 아무것도 호출하지 않아요.

`onTasksChange`는 배열만 받아요. 제스처 종류도, 잡은 모서리도, 움직인 id 목록도 없어요. 무엇이
바뀌었는지 알아야 한다면 마지막으로 넘긴 배열과 비교하세요.

변경을 거부하려면 예전 데이터를 다시 돌려놓아야 해요. `tasks` 프로퍼티는 그 내용이 차트가 지금 들고
있는 것과 다를 때 이겨요. 그래서 제스처 전에 들고 있던 배열을 다시 건네면 막대가 원래 자리로
돌아가요.

### 서버 왕복이 있는 낙관적 업데이트

핸들러가 실행될 때 제스처는 이미 화면에 있어요. 그게 낙관이에요. 왕복은 그걸 그대로 두거나 도로
가져가요.

```tsx title="src/ServerBackedGantt.tsx"
import { useState } from 'react';
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

async function save(tasks: Task[]): Promise<void> {
  const response = await fetch('/api/tasks', {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(tasks),
  });

  if (!response.ok) throw new Error(`save failed: ${response.status}`);
}

export function ServerBackedGantt({ initial }: { initial: Task[] }) {
  const [tasks, setTasks] = useState<Task[]>(initial);
  const [error, setError] = useState<string | null>(null);

  return (
    <>
      {error ? <p role="alert">{error}</p> : null}
      <ReactGanttChart
        tasks={tasks}
        onTasksChange={(next) => {
          // 이 제스처 직전에 차트가 보여 주던 배열
          const previous = tasks;

          setError(null);
          setTasks(next);

          save(next).catch(() => {
            setError('Could not reach the server. Your change was undone.');
            // 차트가 들고 있는 것과 내용이 달라서 막대가 되돌아가요
            setTasks(previous);
          });
        }}
      />
    </>
  );
}
```

짚어 둘 만한 게 두 가지 있어요. `onTasksChange`는 제스처당 한 번 전체 배열과 함께 실행돼요. 그래서
요청 하나에 잡은 막대와 그 하위 트리가 다 담겨요. 그리고 `onTasksChange`가 방금 건네준 것을 그대로
돌려주면 차트는 그걸 메아리로 알아봐요. 그래서 평범한 제어 루프는 화면에 남아 있는 드래그와 다투지
않아요.

## 편집 경로마다 알리는 것

| 경로 | 콜백 | 취소할 수 있나요? |
|---|---|---|
| 이동, 크기 조절, 진행률 드래그 | `onTasksChange` | 아니오 |
| 키보드 미세 이동, 키보드 진행률 스텝, 키보드 삭제 | `onTasksChange` | 아니오 |
| **Add task** 버튼, ref의 `addTask()`, 마지막 행 아래에 그린 범위 | `onTaskCreate` | 해당 없음, 차트가 스스로 아무것도 추가하지 않아요 |
| 의존성 화살표 그리기 | `onDependencyCreate`, `false`를 반환하면 취소 | 예, 동기 |
| 의존성 화살표 삭제 | `onDependencyDelete`, `false`를 반환하면 취소 | 예, 동기 |

키보드 행은 포인터 없이 편집해요. `Alt`와 방향키는 막대를 옮기고, `Shift`는 크기를 조절하고, `+`와
`-`는 진행률을 한 단계씩 바꾸고, `Delete`는 막대를 지워요. 이들 모두 작업에 곧바로 커밋하고
`onTasksChange`를 실행해요. 대신하는 제스처와 똑같아요. 편집이 일어나기 전에 막으려면
[작업 편집](editing)의 권한 체인으로 그 제스처를 꺼 두세요. 전체 키 맵은
[키보드와 스크린 리더](accessibility)에 있어요.

의존성 콜백 두 개는 취소할 수 있지만 동기예요. 차트가 반환값을 즉시 읽어서, 프로미스를 넘기면 참으로
보고 그대로 커밋해요. 서버에 먼저 물어보려고 `onDependencyCreate`에서 프로미스를 반환해도 동작하지
않아요. 각 페이로드는 [의존성](dependencies)에서 다뤄요.

## 한계

- **선택은 id 하나이고, 차트 내부에만 있어요.** 다중 선택도 `selectedTaskId` 프로퍼티도 없어요. 선택을
  설정하거나, 리마운트 뒤에 복원하거나, 직접 해제할 수 없어요. 차트 밖에서 필요하면 `onTaskSelect`로
  직접 추적하세요.
- **컨텍스트 메뉴, 호버, 포커스 콜백은 없어요.** 오른쪽 클릭은 보고되지 않아요. 컨텍스트 메뉴가
  필요하면 차트 컨테이너에 직접 리스너를 붙이고 이벤트 타깃에서 `data-task-id`를 읽으세요.
- **변경 전에 걸리는 관문은 없어요.** 제스처는 코드가 소식을 듣기 전에 기록돼요. 그래서 모든 편집에서
  지켜야 하는 규칙은 사후에, `onTasksChange`에서 강제해야 해요.
- **변경을 되돌리는 건 차트가 아니라 앱의 상태예요.** 예전 `tasks` 배열을 다시 건네는 게 방법의
  전부이고, 거기에 애니메이션은 없어요. 막대는 다음 렌더에서 예전 날짜에 다시 그려져요.
- **드래그 생명주기 콜백은 없어요.** `onDragStart`, `onDragMove`, `onDragEnd`는 없어요.
  `onTasksChange`는 제스처가 끝날 때만 실행돼요.
- **저장은 직접 해야 해요.** 아무것도 저장되지 않고 어디로도 전송되지 않아요. `onTasksChange`는 배열을
  건네고, 그게 `tasks` 프로퍼티로 돌아오길 기대해요.
- **브라우저가 취소한 진행률 드래그는 커밋돼요.** 같은 방식으로 취소된 막대 드래그는 되돌아가요. 그
  비대칭은 [작업 편집](editing)에 있어요.

## 모든 이벤트를 한 표로

| 사용자의 동작 | 콜백 | 취소할 수 있나요? |
|---|---|---|
| 막대나 그 행을 클릭 | `onTaskClick`, 그다음 `onTaskSelect`, 기본 상세 트리거에서는 그다음 `onDetailChange` | 아니오 |
| 막대나 그 행을 더블 클릭 | `onTaskClick` 두 번, 그다음 `onTaskDoubleClick`, `detailTrigger="doubleClick"`에서는 그다음 `onDetailChange` | 아니오 |
| 빈 타임라인을 클릭 | 선택된 게 있었다면 `onTaskSelect(null)`, 패널이 열려 있었다면 `onDetailChange(null)` | 아니오 |
| 막대에서 드래그를 끝냄 | 없음 - 뒤따르는 클릭은 버려져요 | 해당 없음 |
| 막대를 이동하거나 크기를 조절 | `onTasksChange` | 아니오 |
| 진행률 핸들을 드래그 | `onTasksChange` | 아니오 |
| 키보드로 편집 | `onTasksChange` | 아니오 |
| **Add task**를 누르거나, `addTask()`를 부르거나, 마지막 행 아래에 범위를 그림 | `onTaskCreate` | 해당 없음, 차트는 아무것도 기록하지 않아요 |
| 의존성 화살표를 그림 | `onDependencyCreate`, 그다음 `onTasksChange` | 예, 동기 |
| 의존성 화살표를 삭제 | `onDependencyDelete`, 그다음 `onTasksChange` | 예, 동기 |
| 키나 닫기 버튼, `detailTaskId`, ref로 상세 패널을 열거나 닫음 | `onDetailChange` | 아니오 |
| 렌더링된 타임라인 범위가 바뀜 | `onRangeChange` - [타임라인](timeline) 참고 | 아니오 |
