`Task`는 `tasks` prop에 넘기는 객체의 형태예요. 이 페이지는 필드 목록과 날짜 파싱, `sequence`와 `parentId` 규칙, `progress`, 새 `tasks` 배열을 현재 배열과 비교하는 방식을 다뤄요. 차트는 검증을 하지 않아서 잘못된 필드는 오류 대신 틀린 그림으로 나타나요.

## 필수 필드

작업마다 필수 필드가 여섯 개 있어요. 나머지는 선택 사항이에요.

```tsx title="src/TaskDataExample.tsx"
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';
import '@jaeungkim/gantt-chart/style.css';

const tasks: Task[] = [
  {
    id: 'design',
    name: 'Design',
    startDate: '2025-06-01',
    endDate: '2025-06-10',
    parentId: null,
    sequence: '1',
  },
  {
    id: 'build',
    name: 'Build',
    startDate: '2025-06-10',
    endDate: '2025-06-24',
    parentId: null,
    sequence: '2',
    progress: 40,
    dependencies: [{ targetId: 'design', type: 'FS' }],
  },
];

export function TaskDataExample() {
  return <ReactGanttChart tasks={tasks} height={400} />;
}
```

`tasks` 자체는 컴포넌트에서 선택 사항이에요. 생략하거나 `[]`를 넘기면 빈 차트가 그려져요.

## 작업 필드

| 필드 | 타입 | 필수 | 기본값 | 의미 |
|---|---|---|---|---|
| `id` | `string` | 예 | `none` | 의존성과 롤업이 작업을 찾을 때 쓰는 값이에요. 고유한지는 검사하지 않아요. |
| `name` | `string` | 예 | `none` | 막대와 작업 목록 셀, ARIA 라벨에 붙는 이름이에요. 텍스트로 렌더링돼요. |
| `startDate` | `string` | 예 | `none` | 막대의 왼쪽 끝이에요. dayjs가 파싱하는 문자열이면 돼요. [날짜와 시간대](#날짜와-시간대) 참고 |
| `endDate` | `string` | 예 | `none` | 막대의 오른쪽 끝이에요. |
| `parentId` | `string \| null` | 예 | `none` | 부모 작업의 id이고 최상위 작업은 `null`이에요. `hierarchy`를 켰을 때만 읽어요. |
| `sequence` | `string` | 예 | `none` | `'1'`, `'2.1'`, `'2.10'`처럼 점으로 구분한 숫자예요. 행 순서를 정해요. |
| `progress` | `number` | 아니요 | `none` | 0에서 100 사이의 백분율이에요. 생략하면 진행률 채움을 그리지 않아요. |
| `color` | `string` | 아니요 | `none` | CSS 색상 값이에요. 진행률 채움과 호버 음영, 라벨 글자색이 이 값에서 파생돼요. 생략하면 테마 토큰을 따라요. |
| `className` | `string` | 아니요 | `none` | 막대 요소와 작업 목록 행에 덧붙는 클래스예요. |
| `lane` | `string` | 아니요 | `none` | 같은 레인의 작업은 한 행에 나란히 그려져요. 생략하면 자기 행을 써요. 빈 문자열은 없는 값으로 취급해요. |
| `dependencies` | `TaskDependency[]` | 아니요 | `[]` | 이 작업이 기다리는 선행 작업 목록이에요. |
| `readOnly` | `boolean` | 아니요 | `none` | 이 작업의 모든 제스처를 막아요. |
| `allowMove` | `boolean` | 아니요 | `none` | 막대를 좌우로 끄는 동작을 허용하거나 막아요. |
| `allowResize` | `boolean` | 아니요 | `none` | 양쪽 끝을 끄는 동작을 허용하거나 막아요. |
| `allowProgressChange` | `boolean` | 아니요 | `none` | 진행률 핸들을 허용하거나 막아요. |
| `allowLinkCreate` | `boolean` | 아니요 | `none` | 이 작업에서 의존성 드래그를 시작하는 동작을 허용하거나 막아요. |
| `allowLinkDelete` | `boolean` | 아니요 | `none` | 이 작업이 가진 의존성을 지우는 동작을 허용하거나 막아요. |
| `allowReorder` | `boolean` | 아니요 | `none` | 이 행을 새 위치나 새 부모로 끌어 옮기는 동작을 허용하거나 막아요. |
| `minDate` | `string` | 아니요 | `none` | 드래그로 갈 수 있는 가장 이른 날짜예요. 생략하면 차트의 `minDate`를 따라요. |
| `maxDate` | `string` | 아니요 | `none` | 드래그로 갈 수 있는 가장 늦은 날짜예요. 생략하면 차트의 `maxDate`를 따라요. |

`allowX` 플래그 여섯 개와 `readOnly`는 구체적인 쪽이 우선이라 작업의 값이 차트 값보다 앞서요. 전체 우선순위는 [GanttInteractionConfig](ref/interaction-config)에 있어요. `allowReorder`는 기본으로 꺼져 있어요. [행 순서 바꾸기](reordering)를 참고하세요.

`minDate`와 `maxDate`는 이 우선순위를 타지 않아요. 작업에 값이 있으면 차트 값을 그대로 대체해요.

`parentId`는 `hierarchy`를 켰을 때만 읽어요. 끄면 트리를 만들지 않아요. 깊이는 `sequence`에서 나오고 요약 행도 생기지 않아요. [작업 목록과 계층](task-list)을 참고하세요.

`lane`은 따로 켤 prop이 없어요. 같은 레인의 작업은 목록 전체에서 날짜가 겹치지 않는 것끼리 묶여 가장 적은 행에 들어가요. [레인](lanes)을 참고하세요.

`color`와 `className`, 색이 지정된 막대가 설정하는 CSS 커스텀 속성 네 개는 [스타일링](styling)에서 다뤄요. 여기 나온 prop의 시그니처와 기본값은 [GanttProps](ref/props)에 있어요.

### TaskDependency 필드

| 필드 | 타입 | 필수 | 기본값 | 의미 |
|---|---|---|---|---|
| `targetId` | `string` | 예 | `none` | 선행 작업의 `id`예요. |
| `type` | `'FS' \| 'SS' \| 'FF' \| 'SF'` | 예 | `none` | 첫 글자는 선행 작업의 끝, 둘째 글자는 후행 작업의 끝이에요. |

네 가지 타입의 뜻과 화살표를 그리고 지우는 방법은 [의존성](dependencies)에 있어요.

`targetId`가 `tasks`에 없는 항목은 경고 없이 버려져요. 자기 자신을 가리키는 항목은 그대로 남아요. 자기 참조는 검사하지 않아서 같은 행으로 되돌아오는 화살표를 그려요.

알 수 없는 `type`은 화살표를 건너뛰어요. 이 동작과 네 글자의 뜻은 [Task와 작업 타입](ref/task)에 있어요.

## 날짜와 시간대

차트는 모든 날짜를 UTC 모드로 고정한 dayjs 인스턴스로 파싱해요. `timezone` 플러그인은 로드하지 않아서 보는 사람마다 로컬 시간으로 바꾸는 모드는 없어요.

| 입력 | 표시되는 값 |
|---|---|
| `'2025-06-01T09:00:00Z'` | 그 시점의 UTC 시각인 09:00 |
| `'2025-06-01T18:00:00+09:00'` | 같은 시점이라 역시 09:00 |
| `'2025-06-01T09:00'` | UTC 시각으로 읽어서 누가 보든 09:00 |
| `'2025-06-01'` | `2025-06-01T00:00:00.000Z`, UTC 자정 |

`YYYY-MM-DD`만 넘기면 안전해요. 어느 시간대에서 보든 적힌 그 날짜에 놓여요.

차트가 내보내는 형태는 UTC ISO 문자열이지만 입력은 dayjs가 파싱하는 문자열이면 무엇이든 받아요. 시간대가 없는 문자열은 UTC 시각으로 읽어요.

그리드가 UTC라서 시간 셀은 모두 60분 폭이고 날짜 셀도 모두 같은 폭이에요. 서머타임으로 로컬 하루가 23시간이나 25시간이 되는 날에도 같아요.

작업의 날짜는 검증하지 않아요. 파싱할 수 없는 `startDate`는 행을 숨기지도 예외를 던지지도 않아요. 그 막대는 타임라인 왼쪽 끝에서 시작해 `endDate`까지 이어져요.

`endDate`가 `startDate`와 같아도 돼요. 막대 폭은 최소 1px로 제한돼요. 길이가 0인 작업도 거부하거나 숨기지 않고 1px 막대로 그려요.

차트가 되돌려주는 값은 모두 `toISOString()`으로 직렬화돼요. `'2025-06-01'`로 넘긴 작업은 첫 드래그 뒤에 `'2025-06-01T00:00:00.000Z'`로 돌아와요. 아래 비교 규칙에서 이 점이 중요해요.

## sequence와 parentId

`sequence`는 어떤 모드에서든 행 순서를 정해요. `parentId`는 중첩을 정해요. `hierarchy`를 켰을 때만 읽어요. 둘을 맞춰 주는 장치는 없어요.

구간은 왼쪽부터 숫자로 비교해요. `'1.10'`은 `'1.2'`보다 뒤에 와요. 없는 구간은 `0`으로 쳐서 `'1'`과 `'1.0'`은 같은 값이에요. 값이 같으면 배열 순서를 유지해요. 입력 배열은 정렬 전에 복사하고 원본은 바꾸지 않아요.

숫자가 아닌 구간은 `0`이 돼요. `'abc'`, `'1a'`, `''`는 모두 `'0'`처럼 정렬돼서 `'1'`보다 앞에 오고 경고는 없어요. `sequence`가 중복돼도 오류는 아니에요. 두 행이 같은 값이 되고 배열 순서가 앞뒤를 정해요.

> [!WARNING]
> `sequence`가 없으면 예외가 나요. 타임라인을 만드는 레이아웃 이펙트 안에서 `undefined`에 `sequence.split('.')`을 호출해서 차트 전체가 렌더링에 실패해요. TypeScript가 이 필드를 필수로 표시하니 손으로 만든 JSON이나 타입 없이 매핑한 데이터에서만 생기는 문제예요.

`hierarchy`가 꺼져 있으면 들여쓰기 깊이는 `sequence`의 점 개수예요. 그래서 `'2.1.1'`은 두 단계 안쪽에 그려져요. `hierarchy`를 켜면 깊이는 `parentId` 체인에서 나오고 `sequence`는 순서만 정해요.

`sequence`가 부모보다 앞서는 자식은 부모 위에 그려져요.

이 두 필드를 함께 다시 쓰는 제스처가 하나 있어요. 행 순서 바꾸기가 확정되면 모든 `sequence`가 새 행 순서대로 다시 매겨지고 `hierarchy`가 켜져 있으면 옮긴 작업의 `parentId`도 바뀌어요.

결과는 다른 편집과 똑같이 `onTasksChange`로 나가요. 제스처를 켜는 방법은 [행 순서 바꾸기](reordering)를 참고하세요.

## progress

`progress`는 0에서 100 사이의 숫자예요. 범위를 벗어난 값은 가까운 쪽 끝으로 제한해요.

| 넘긴 값 | 실제 값 |
|---|---|
| `42` | `42` |
| `33.7` | `33.7`, 반올림 없음 |
| `-10` | `0` |
| `150` | `100` |
| `Infinity` | `100` |
| `-Infinity` | `0` |
| `undefined` | 없음, 채움을 그리지 않아요 |
| `NaN` | 없음 |
| `'50'` | 없음, 문자열은 변환하지 않고 버려요 |

API에서 문자열로 온 백분율은 파싱하지 않아요. 막대는 채움 없이 그려지고 아무것도 문제를 알리지 않아요.

반올림은 차트가 값을 만들어 내는 곳에서만 해요. 진행률 핸들을 끌면 정수가 나오고 요약 행의 롤업 백분율도 반올림돼요. 직접 넘긴 소수 값은 소수 그대로 남아요.

부모가 가진 `progress`는 자식에서 롤업한 값보다 우선해요. 롤업 공식은 [작업 목록과 계층](task-list)을 참고하세요.

## tasks prop 업데이트하기

제어 모드에서는 `onTasksChange`로 받은 배열이 다시 `tasks`로 들어와요. 되돌아온 배열인지 새로 교체한 배열인지는 비교 한 번으로 구분해요.

차트는 들어온 `tasks` 배열과 마지막으로 받아들인 배열을 양쪽 다 `JSON.stringify`로 만들어 비교해요. 구조 비교나 필드별 비교는 없어요.

두 문자열이 같으면 업데이트를 버리고 차트 상태를 유지해요. 방금 한 드래그가 되돌아가지 않는 이유예요. 문자열이 다르면 데이터를 교체해요.

문자열 비교에는 구조 비교라면 없었을 결과가 두 가지 따라와요.

키 순서가 중요해요. 아래 두 객체는 같은 작업을 나타내지만 서로 다른 문자열이 돼요.

```ts
JSON.stringify({ id: 'a', name: 'Design' }); // '{"id":"a","name":"Design"}'
JSON.stringify({ name: 'Design', id: 'a' }); // '{"name":"Design","id":"a"}'
```

값이 `undefined`인 키는 보이지 않아요. `{ id: 'a', progress: undefined }`와 `{ id: 'a' }`는 똑같이 직렬화돼서 둘을 오가도 변경이 아니에요.

같은 코드에서 두 가지가 더 따라와요. 직접 붙인 추가 속성도 비교에 들어가요. 배열 참조를 그대로 두고 작업을 제자리에서 수정하면 비교 자체가 실행되지 않아서 보이지 않아요.

### onTasksChange 핸들러

이 핸들러는 모든 작업을 다른 키 순서로 다시 만들고 날짜 형식을 바꾸고 필수 필드 여섯 개만 남겨요.

```tsx
// 잘못된 방식
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';

function Wrong({ tasks, setTasks }: {
  tasks: Task[];
  setTasks: (next: Task[]) => void;
}) {
  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={(updated) => {
        setTasks(
          updated.map((task) => ({
            name: task.name,
            id: task.id,
            startDate: task.startDate.slice(0, 10), // '2025-06-01T00:00:00.000Z' -> '2025-06-01'
            endDate: task.endDate.slice(0, 10),
            parentId: task.parentId,
            sequence: task.sequence,
          }))
        );
      }}
    />
  );
}
```

모든 문자열이 차트가 내보낸 것과 달라져서 차트는 교체로 받아들여요. 빠뜨린 진행률과 의존성, 색은 사라져요.

받은 배열을 그대로 돌려주세요. 이미 새 배열이고 안에 든 객체도 이미 차트가 내보낸 형태예요.

```tsx
// 올바른 방식
import { ReactGanttChart, type Task } from '@jaeungkim/gantt-chart';

function Right({ tasks, setTasks }: {
  tasks: Task[];
  setTasks: (next: Task[]) => void;
}) {
  return (
    <ReactGanttChart
      tasks={tasks}
      onTasksChange={(updated) => setTasks(updated)}
    />
  );
}
```

API에 맞춘 변형은 prop으로 되돌아가는 길이 아니라 저장 호출 안에서 하세요. 앱이 작업을 넣거나 지워서 데이터를 직접 바꿀 때는 차트가 마지막으로 내보낸 배열에서 새 배열을 만드세요.

어떤 제스처가 어떤 콜백을 발생시키는지는 [이벤트](events)를 참고하세요.

## 한계

차트는 배열을 읽기만 하고 검증하지 않아요.

- 필수 필드 검사와 날짜 파싱 검사, id 고유성 검사, `progress` 범위 검사, `DependencyType` 소속 검사 중 무엇도 하지 않아요.
- 중복 id는 감지하지 않아요. 배열 항목마다 행은 생기지만 의존성과 롤업처럼 id로 찾는 조회는 마지막 항목을 가리켜요. 배열을 넘기기 전에 중복을 제거하세요.
- 입력을 정규화하지 않아요. 날짜를 다시 직렬화하지 않고 `sequence`를 다시 매기지 않으며 `parentId`도 고쳐 쓰지 않아요. 부모를 잃은 작업이나 순환은 트리를 만들 때 최상위로 취급하지만 필드 값은 넘긴 그대로 남아요.
- 로컬 시간대 모드가 없어요. UTC로 고정돼 있어요. 사용자에게 로컬 시각이 필요하면 호스트 앱에서 변환하세요.
- 작업 생성은 호스트 앱의 몫이에요. **Add task** 버튼과 `addTask()`, 그린 범위는 모두 `onTaskCreate`에 초안을 넘겨요. 초안에는 날짜만 들어 있고 `id`와 `name`, `parentId`, `sequence`는 호스트 앱이 채워요.
- 삭제는 차트가 직접 해요. 포커스된 행에서 `Delete`를 누르면 그 작업과 하위 트리 전체가 지워져요. [키보드와 스크린 리더](accessibility)를 참고하세요.
- 메타데이터 필드가 없어요. 타입이 구조적이라 추가 속성은 살아남지만 타입이 붙지 않고 `tasks` 비교에도 들어가요.
- `TaskTransformed`는 출력 전용이에요. 차트가 렌더러에 넘기는 타입이고 `tasks`는 `Task`만 받아요. 필드 목록은 [Task와 작업 타입](ref/task)에 있어요.
- `sequence`와 `parentId`는 맞춰 주지 않아요. `sequence`가 부모보다 앞서는 자식은 계속 부모 위에 그려져요.

넘긴 객체는 차트가 직접 고치지 않아서 앱이 가진 사본은 교체하기 전까지 그대로예요. 드래그와 키보드 이동, [상세 패널](detail-panel)에서 고친 필드까지 모든 변경은 새 배열이 되어 `onTasksChange`로 나가요.
