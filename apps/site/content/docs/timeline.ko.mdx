타임라인은 하루를 몇 픽셀로 그릴지, 첫 칸과 마지막 칸을 어디에 둘지 정하는 계층이에요. 이 페이지는 다섯 가지 배율과 범위, 줌, 오늘 선, 비근무일 음영을 다뤄요.

## 배율

배율은 고정된 표의 한 행이에요. 이 행이 헤더 칸에 적을 내용과 눈금 하나가 덮는 시간, 드래그 한 단계의 픽셀 값을 정해요. 표는 모듈 상수이고 행은 다섯 개예요.

`GanttScaleKey`는 `'day' | 'week' | 'month' | 'quarter' | 'year'`예요. 차트는 `month`로 시작해요.

| 배율 | `labelUnit` | `tickUnit` | `unitPerTick` | `tickAlign` | `dragStepUnit` | `dragStepAmount` | `basePxPerDragStep` |
|---|---|---|---:|---|---|---:|---:|
| `day` | `day` | `hour` | 6 | `day` | `hour` | 1 | 12 |
| `week` | `month` | `day` | 1 | none | `hour` | 6 | 18 |
| `month` | `month` | `day` | 7 | `week` | `day` | 1 | 18 |
| `quarter` | `quarter` | `month` | 1 | none | `day` | 7 | 28 |
| `year` | `year` | `month` | 3 | `quarter` | `day` | 28 | 28 |

`unitPerTick`은 칸 하나가 담는 시간이에요. 축소할수록 이 값이 커져서 6시간, 1일, 1주, 1개월, 1분기 순으로 늘어나요.

`tickAlign`은 첫 칸을 맞추는 경계이고 칸 하나가 `tickUnit` 여러 개를 담을 때만 쓰여요. 이 값이 없으면 주 단위 칸이 범위가 시작하는 요일에 열려요.

`dragStepUnit`과 `dragStepAmount`는 막대 드래그가 걸리는 스냅 단위이기도 해요. 스냅은 [작업 편집](editing)에서 설명해요. 배율마다 라벨 포매터를 바꿀 수 있어요. [로케일과 날짜 형식](i18n)을 참고하세요. 타입은 [배율과 테마 타입](ref/scales)에 있어요.

### 눈금 너비

픽셀 너비를 가진 배율은 없어요. 눈금 너비는 칸을 만들 때 다음처럼 계산해요.

```ts title="src/timeline/utils/geometry.ts, createBottomRowCells"
const dragStepRatio = basePxPerDragStep / dragStepAmount;
const nextTick = current.add(unitPerTick, tickUnit);
const tickDuration = nextTick.diff(current, dragStepUnit);
const widthPx = tickDuration * dragStepRatio;
```

실제 숫자는 다음과 같아요.

| 배율 | 드래그 단계 단위당 px | 눈금 하나가 덮는 범위 | 눈금 너비 | 하루당 px | 1200px에 들어오는 범위 |
|---|---|---|---|---:|---|
| `day` | 12 px/h | 6시간 | 72px | 288 | 4일 |
| `week` | 3 px/h | 24시간 | 72px | 72 | 17일 |
| `month` | 18 px/day | 7일 | 126px | 18 | 2개월 |
| `quarter` | 4 px/day | 달력상 1개월 | 112~124px | 4 | 10개월 |
| `year` | 1 px/day | 달력상 1분기 | 90~92px | 1 | 3년 |

이 표에는 규칙이 두 가지 있어요.

헤더 칸은 대략 60~130px을 유지해요. 그 정도 너비여야 날짜를 읽고 막대 가장자리를 잡을 수 있어요. 그래서 축소할 때는 칸을 좁히는 대신 칸이 담는 시간을 늘려요.

한 단계 축소할 때마다 하루당 픽셀이 4배씩 줄어요. 288, 72, 18, 4, 1px 순이에요. Ctrl과 휠, 방향키 모두 같은 배율 순서를 따라요. 어느 입력으로 바꾸든 한 단계의 뜻은 같아요.

`quarter`와 `year` 배율은 `month` 눈금을 쓰기 때문에 칸 너비가 실제 달력 기간을 따라요. 2025년 2월은 `quarter` 배율에서 112px이고 31일짜리 달은 124px이에요.

### 초기 배율

`defaultScale`은 초기값이에요. 차트 스토어를 만들 때 적용돼서 처음 렌더링할 때부터 그 배율로 그려요. 그 뒤에 prop을 바꿔도 무시해요.

배율은 저장되지 않아요. `storageKey` prop이 없고 패키지가 `sessionStorage`나 `localStorage`에도 쓰지 않아요. 새로고침하거나 라우트를 옮기거나 다시 마운트하면 사용자가 무엇을 골랐든 `defaultScale`에서 다시 시작해요.

배율은 차트 하나에 속한 React 상태예요. 배율을 유지하려면 값을 직접 저장했다가 `defaultScale`로 다시 넘기세요.

### 배율 바꾸기

차트는 배율 선택기를 그리지 않아요. 타임라인을 그리고, 켜 두었다면 [작업 목록 패널](task-list)까지 그려요. 그 주변 UI는 만들지 않아요. 직접 만든 선택기는 다음 두 가지로 차트와 이어져요.

- 차트 ref의 `setScale(scale)`이 배율을 바꿔요. 시그니처는 [GanttHandle](ref/handle)에 있어요.
- `onScaleChange`는 확정된 변경마다 한 번 호출돼요. `setScale`, Ctrl과 휠, `zoomToFit()`, 키보드 중 무엇으로 바꿨든 같아요. 인자로는 지금 렌더링된 새 `GanttScaleKey`를 받아요. 시작 배율을 초기값으로 들고 있어서 마운트할 때와 StrictMode로 다시 마운트할 때는 호출되지 않아요. 제스처가 끝나고 확정된 값만 알려요.

기본 `<select>`가 여기에 잘 맞아요. `<select>`로 배율을 바꾸고, `onScaleChange`로 실제 배율을 돌려받아요.

휠 줌과 키보드도 배율을 바꾸니까 콜백에서 값을 돌려받으세요. 그래야 직접 만든 컨트롤이 렌더링된 배율을 계속 보여줘요. 완성된 컴포넌트는 [명령형 API](imperative-api)에 있어요.

## 범위

범위 prop이 없으면 차트가 데이터에 맞춰 타임라인을 잡아요. 모든 작업에서 `startDate`의 최솟값과 `endDate`의 최댓값을 찾아요. [롤업](task-list)이 먼저 실행되니까 자식 때문에 넓어진 요약 행은 범위도 넓혀요.

그다음 양쪽에 현재 배율의 눈금 5개씩 여백을 붙여요. 눈금 하나의 폭은 배율마다 달라요.

| 배율 | 눈금 하나 | 한쪽 버퍼 |
|---|---|---|
| `day` | 6시간 | 30시간 |
| `week` | 1일 | 5일 |
| `month` | 7일 | 35일 |
| `quarter` | 1개월 | 5개월 |
| `year` | 3개월 | 15개월 |

칸은 여백을 붙인 시작점부터 놓이고 눈금 경계로 내려 맞춰요. `tickAlign`이 있는 배율은 그 경계를 쓰기 때문에 `month` 칸은 일요일에 열려요. 반복은 눈금 시작이 여백 붙인 끝보다 앞인 동안 계속돼서 마지막 칸은 그 끝을 넘어갈 수 있어요.

`2025-01-10`부터 `2025-01-12`까지의 작업은 `month` 배율에서 `2024-12-06`부터 `2025-02-16`까지로 넓어져요. 시작은 일요일인 `2024-12-01`로 내려 맞춰져요. 그래서 주 단위 칸 11개가 생기고 막대는 왼쪽에서 720px 지점에 36px 너비로 놓여요.

### 범위 고정

`visibleStart`와 `visibleEnd`는 ISO 문자열이에요. 고정한 끝은 그대로 쓰여요. 작업 날짜와 버퍼는 그 끝을 옮기지 않아요.

양쪽을 다 고정하면 작업 날짜는 레이아웃에 영향을 주지 않아요. 표시 범위 밖의 작업도 행은 생기지만 막대는 가장 가까운 가장자리에 최소 막대 너비로 붙어요. 한쪽만 고정하면 반대쪽은 눈금 5개 버퍼를 붙여 자동으로 맞춰요.

고정한 시작도 눈금 경계로 내려 맞춰요. `visibleStart`가 `2025-03-14`이면 `quarter` 배율에서는 `2025-03-01`이 되고, 눈금 하나가 분기 전체인 `year` 배율에서는 `2025-01-01`이 돼요. 마지막 칸은 `visibleEnd`를 넘어갈 수 있어요.

> [!WARNING]
> 작업이 없고 한쪽 끝만 고정하면 차트는 빈 요소만 렌더링하고 오류도 내지 않아요. 빈 달력을 그리려면 양쪽 끝을 모두 고정하세요.

### 무한 스크롤

`infiniteScroll`의 기본값은 `false`예요. 꺼져 있으면 범위는 작업에 버퍼를 더한 만큼이고 스크롤 컨테이너도 거기서 끝나요.

켜면 차트가 스크롤할 때마다 `scrollLeft`를 읽어요. 뷰가 어느 한쪽 끝에서 뷰포트 절반 안으로 들어오면 그쪽에 뷰포트 하나 분량의 눈금을 더해요.

더하는 양은 `ceil(viewportPx / pxPerTick)` 눈금이고 최소 1개예요. 여기서 `pxPerTick`은 현재 배율의 평균 눈금 너비예요. 앞쪽을 먼저 확인하니까 한 번에 양쪽이 같이 늘어나지는 않아요.

확장은 한쪽당 눈금 2000개까지예요. 앞쪽에 칸이 추가되면 차트가 추가된 너비만큼 `scrollLeft`를 옮겨서 화면에 보이던 날짜가 그대로 유지돼요.

그래서 다음 세 가지가 생겨요.

- 확인은 리스너가 붙는 즉시 한 번 실행돼요. 아직 스크롤하기 전이에요. `scrollLeft: 0`으로 마운트한 차트는 이미 앞쪽 뷰포트 절반 안에 있어서 바로 확장돼요.
- 고정한 끝은 늘어나지 않아요. `visibleStart`와 `visibleEnd`를 둘 다 넘기면 `infiniteScroll`은 아무 일도 하지 않아요.
- 누적된 확장량은 눈금 단위로 세고 측정한 배율이 함께 붙어요. 배율을 바꾸면 그 값을 버리고 작업 기준으로 다시 맞춰요.

### onRangeChange

`onRangeChange`는 `Dayjs` 값 두 개가 담긴 `GanttDateRange`를 받아요. `start`는 첫 칸의 시작이에요. `end`는 마지막 칸의 끝이고 그 값은 포함하지 않아요. 마지막 칸 시작에 눈금 하나를 더한 값이에요. `[start, end]`를 닫힌 구간으로 조회하면 마지막 눈금을 두 번 세게 돼요.

```tsx title="Roadmap.tsx"
import { useCallback } from "react";
import {
  ReactGanttChart,
  type GanttDateRange,
  type Task,
} from "@jaeungkim/gantt-chart";
import "@jaeungkim/gantt-chart/style.css";

const tasks: Task[] = [
  {
    id: "spec",
    name: "Spec",
    startDate: "2025-06-10",
    endDate: "2025-06-13",
    parentId: null,
    sequence: "1",
  },
];

export function Roadmap() {
  const handleRangeChange = useCallback((range: GanttDateRange) => {
    const from = range.start.toISOString();
    const to = range.end.toISOString();
    void fetch(`/api/tasks?from=${from}&to=${to}`);
  }, []);

  return (
    <ReactGanttChart
      tasks={tasks}
      defaultScale="month"
      infiniteScroll
      zoomOnWheel
      onRangeChange={handleRangeChange}
    />
  );
}
```

콜백은 칸이 처음 만들어진 렌더에서 호출되고 그 뒤로는 두 날짜가 바뀔 때마다 호출돼요. 시작과 끝의 밀리초 값으로 중복을 걸러서 같은 날짜로 다시 만들어지면 호출되지 않아요.

줌은 중복 제거에 걸리지 않아요. 배율마다 여백과 정렬이 달라서 배율이 바뀌면 두 날짜도 거의 항상 움직여요. 콜백이 `onScaleChange`와 나란히 호출된다고 보면 돼요.

핸들러는 의존성이 아니라 ref로 읽어요. 핸들러의 참조가 바뀌어도 다시 호출되지 않고, 첫 렌더 뒤에 넘긴 핸들러는 다음 변경부터 받아요.

## 줌

`zoomOnWheel`의 기본값은 `false`라서 Ctrl과 휠은 브라우저의 페이지 줌으로 남아요. 켜면 차트가 자기 영역 안에서 이 제스처를 처리해요. 아래의 키보드 조합은 따로 켜지 않아도 동작해요.

<GanttDemo preset="zoom" />

배율 순서는 배율 표 그대로예요. 촘촘한 쪽부터 `day`, `week`, `month`, `quarter`, `year`예요. 휠을 아래로 굴리면 축소되고 브라우저와 방향이 같아요. 순서는 양쪽 끝에서 멈춰서 `day`에서 더 확대해도 아무 일도 일어나지 않아요.

차트는 휠 이벤트의 `deltaY`를 누적해요. 제스처 하나가 한 단계를 움직이려면 누적값이 24에 닿아야 해요. 한 단계를 넘기면 제스처가 잠기고 120ms 쉴 때까지 이후 이벤트는 무시돼요.

이벤트 20개짜리 트랙패드 핀치는 한 단계예요. 160ms 간격으로 휠을 두 번 굴리면 두 단계예요.

커서 아래의 날짜는 배율이 바뀌어도 같은 x 위치에 남아요. 작업 목록 패널 위의 커서는 타임라인 왼쪽 가장자리로 범위 제한돼요. 마지막 칸을 지난 커서에는 기준 삼을 날짜가 없어서 줌이 취소돼요.

`zoomOnWheel`이 켜져 있든 꺼져 있든 휠만 굴리면 세로로, Shift와 함께 굴리면 가로로 스크롤해요. 뜻이 바뀌는 조합은 Ctrl과 Cmd뿐이에요.

Ctrl이나 Cmd와 함께 ArrowUp을 누르면 한 단계 촘촘해지고, ArrowDown을 누르면 한 단계 넓어져요. 이 조합은 차트 키보드 맵의 일부예요. 차트 안에 포커스가 있어야 하지만 포인터는 필요 없고 `zoomOnWheel`과 무관하게 동작해요.

양쪽 끝에서 멈추는 것은 휠 줌과 같아요. 커서 대신 타임라인 가운데를 기준으로 삼고, 바뀐 배율은 차트의 `role="status"` 요소로 알려요. [키보드와 스크린 리더](accessibility)를 참고하세요.

보이는 막대를 전부 뷰포트에 한 번에 맞추려면 차트 ref의 `zoomToFit()`을 호출하세요. [명령형 API](imperative-api)에서 설명해요.

## 오늘 선

차트는 오늘 날짜에 세로선 하나를 그려요. 마감일이나 스프린트 구간 같은 다른 마커를 위한 prop은 없어요.

선 위쪽에는 작은 점이 하나 있어요. 같은 x 위치에서 헤더 아래 경계선에 걸쳐 있어요. 점은 헤더 안에 있으니 행이 그 아래로 스크롤돼도 제자리에 있어요.

마커를 숨기거나 옮기거나 라벨을 붙이는 prop도 없어요. 선은 `.gantt-today-marker`, 점은 `.gantt-today-dot`이고 둘 다 [테마](theming)에 있는 토큰 하나에서 색을 받아요. 스타일을 바꾸거나 숨기려면 이 두 클래스에 CSS를 적용하세요.

날짜는 타임라인을 다시 계산할 때 읽어요. 타이머가 없어서 자정에 선이 저절로 움직이지 않고, 오늘이 렌더링 범위 밖이면 사라져요.

## 비근무일

`showNonWorkingDays`의 기본값은 `true`예요. 비근무일을 막대 뒤의 배경 레이어로 칠해요.

어떤 날이 비근무일인지는 prop 두 개가 정해요. `workingWeekdays`는 주 단위 규칙이에요. UTC 요일 번호를 받고 `0`이 일요일이에요. 기본값은 월요일부터 금요일까지예요. `holidays`는 그 위에 얹는 예외 목록이고 각 눈금의 UTC 날짜와 대조해요.

```tsx title="NonWorkingDays.tsx"
import { ReactGanttChart, type Task } from "@jaeungkim/gantt-chart";
import "@jaeungkim/gantt-chart/style.css";

const tasks: Task[] = [
  {
    id: "spec",
    name: "Spec",
    startDate: "2025-06-10",
    endDate: "2025-06-13",
    parentId: null,
    sequence: "1",
  },
];

// 두 배열 모두 참조로 비교하니 컴포넌트 밖에 두어요.
const WORKING_WEEKDAYS = [1, 2, 3, 4, 5, 6];
```

### 휴일 이름 붙이기

문자열 하나는 이름 없는 휴일이에요. 객체 형태로 쓰면 이름과 색, 종료일을 더할 수 있어요.

```tsx
holidays={[
  "2025-06-06",
  { date: "2025-09-24", endDate: "2025-09-26", label: "추석", color: "#7c3aed" },
]}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `date` | `string` | UTC `YYYY-MM-DD`예요. 필수예요. |
| `endDate` | `string` | 마지막 날이고 그날도 포함해요. 생략하면 하루짜리예요. |
| `label` | `string` | 휴일 띠 위 눈금 행에 표시돼요. |
| `color` | `string` | CSS 색이면 무엇이든 돼요. 그 띠에 옅게 칠해져요. |

`Holiday` 타입은 [배율과 테마 타입](ref/scales)에 있어요.

이름은 휴일 띠 위 눈금 행에서 눈금 숫자가 있던 칸에 표시돼요. 드래그하는 끝이 날짜를 표시하는 방식과 같아요. 띠가 44px 이상일 때만 이름이 계속 보여요. 그래서 하루짜리 휴일은 `week` 배율에서는 이름이 보이고 하루가 칸의 7분의 1인 `month` 배율에서는 보이지 않아요.

더 좁은 띠는 마우스를 올렸을 때 이름을 보여줘요. 헤더에서 포인터가 휴일 띠 위에 오면 눈금 칸 위로 이름이 나타나요. 이름이 덮는 눈금 칸보다 넓으면 잘려요. 드래그하는 동안에는 드래그 날짜 표시가 그 위를 덮어요. 어느 경우든 색은 그날을 계속 표시해요.

이름 붙은 휴일 두 개의 띠가 같은 눈금 칸에서 시작하면 이름이 겹치므로 앞쪽 하나만 이름을 계속 보여줘요. 뒤쪽은 띠가 아무리 넓어도 마우스를 올려야 보여요.

마우스 올리기는 타임라인 헤더에서만 동작해요. 차트 본문의 음영은 새 작업을 그리는 표면 아래에 깔려 있어서 거기에 감지 영역을 두면 그 제스처를 가로채요. 이름은 어느 쪽이든 `display`가 아니라 `opacity`로 숨기니까 보이든 안 보이든 스크린 리더는 읽어요.

`color`는 주말 음영과 같은 세기로 옅게 입혀요. 그래서 휴일은 색만 다른 토요일처럼 보이고 아래 그리드도 가리지 않아요. 띠는 맞닿은 주말과 따로 유지돼서 둘이 합쳐지지 않고 색과 이름도 남아요.

주 단위 규칙으로 이미 비근무일인 날에 휴일이 겹쳐도 이름과 색은 휴일 항목을 따라요. 항목 두 개가 같은 날을 덮으면 배열에서 앞선 항목이 그날의 라벨과 색을 정해요. 하루는 한 번만 배정되고 다시 덮어쓰지 않으므로 겹칠 때는 배열 순서가 기준이에요.

기간은 최대 366일까지 펼쳐져요. `endDate`가 `date`보다 앞서거나 파싱되지 않으면 그 항목은 오류 대신 시작일 하루로 줄어요. `date`가 파싱되지 않으면 그 항목은 버려져요.

<GanttDemo preset="holidays" />

위 데모는 `month` 배율이에요. 3일짜리 휴일은 띠가 이름을 담을 만큼 넓고 하루짜리 휴일은 마우스를 올려야 이름이 보여요.

음영은 배율 이름이 아니라 배율의 `tickUnit`으로 정해져요.

| 배율 | `tickUnit` | 음영 |
|---|---|---|
| `day` | `hour` | 예 |
| `week` | `day` | 예 |
| `month` | `day` | 예 |
| `quarter` | `month` | 아니요 |
| `year` | `month` | 아니요 |

`quarter`나 `year`로 축소하면 음영이 사라져요. 한 달짜리 눈금은 절반만 비근무일일 수 없으므로 그 배율에서는 레이어를 건너뛰어요.

칸이 하루보다 넓어도 음영은 하루 단위예요. `month` 칸은 7일을 담고 검사는 하루마다 따로 해요. 칸은 일요일에 열리니까 주말은 칸 왼쪽 끝 18px과 오른쪽 끝 18px이에요. 한 칸의 토요일은 다음 칸의 일요일과 합쳐져 36px 영역 하나가 돼요.

`day` 배율에서는 6시간 눈금마다 한 번 검사하고 이웃한 비근무 눈금은 합쳐져요. 비근무일 하루는 눈금 4개가 합쳐진 288px 블록 하나예요.

음영은 날짜를 바꾸지 않아요. 드래그 결과를 비근무일에서 비켜 놓는 것은 `workingCalendar`예요. [근무일 달력](working-calendar)을 참고하세요.

prop과 기본값은 [GanttProps](ref/props)에 있어요.

## 한계

- 하루당 픽셀은 prop이 아니에요. 눈금 너비는 `basePxPerDragStep / dragStepAmount`에서 나오고 둘 다 prop이 아니에요. 줌은 다섯 배율 사이를 단계별로 건너뛰어서 `pxPerDay`나 줌 퍼센트, 소수 단위 줌, 애니메이션 줌은 없어요.
- 배율 표는 모듈 상수예요. 2주 단위 컬럼이 필요해도 호스트 앱이 배율을 추가할 수 없어요.
- 차트는 배율 선택기를 제공하지 않아요. 직접 만든 선택기에서 `setScale`을 호출하고 `onScaleChange`를 읽으세요.
- 배율은 저장되지 않아요. 새로고침하면 `defaultScale`에서 다시 시작해요.
- 타임라인 내부는 내보내지 않아요. 배율 설정, 배율 순서, 칸을 만드는 유틸리티는 패키지 안에 남아요. `GanttDateRange`와 `GanttScaleKey`는 내보내지만 기하 계산은 내보내지 않아요.
- 오늘 선은 prop으로 끌 수 없어요. 두 클래스에 CSS를 적용하는 것이 숨기는 유일한 방법이고 자정에 업데이트해 주는 것도 없어요.
- 날짜는 여기서 검증하지 않아요. 날짜가 전부 파싱되지 않는 작업은 오류 대신 빈 타임라인을 만들어요.
- 음영과 드롭 스냅은 별개 스위치예요. `showNonWorkingDays={false}`는 음영과 휴일 이름만 숨겨요. `workingCalendar`가 켜져 있으면 같은 날이 드래그가 놓일 자리를 정해요. [근무일 달력](working-calendar)을 참고하세요.
- `firstDayOfWeek`는 음영을 옮기지 않아요. `week` 배율 상단 헤더의 묶음만 바꾸고 `month` 배율의 주 단위 칸은 언제나 일요일에 열려요. 어떤 날이 비근무일인지는 `workingWeekdays`가 정하고 둘은 무관해요.
- 휴일이 바꾸는 스타일은 색뿐이에요. 휴일별 클래스나 아이콘은 없고 이름은 `.gantt-holiday-cell`로만 꾸밀 수 있어요.
- `zoomOnWheel`은 Ctrl과 Cmd 휠 이벤트를 전부 가져가요. `preventDefault`가 누적기보다 먼저 실행되므로 배율 단계를 만들지 않는 이벤트에서도 차트 안에서는 페이지 줌이 막혀요.
- `visibleStart`, `visibleEnd`, `infiniteScroll`은 가로 방향만 다뤄요. 행에는 영향을 주지 않아요.
- 스크롤 위치는 제어하지 않아요. `scrollLeft` prop도 `onScroll`도 없어요. `initialScrollTo`가 첫 렌더 뒤 한 번 위치를 잡아요. 그 뒤로 `onRangeChange`는 픽셀이 아니라 날짜를 알리고 프로그램으로 스크롤하려면 차트 ref를 거쳐요.
